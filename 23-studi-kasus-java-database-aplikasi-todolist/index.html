Perjalanan dari aplikasi sederhana (array di memori) menuju arsitektur berlapis yang profesional dengan MySQL & HikariCP — cara nyata Java digunakan di dunia kerja.

Chapter 1 • V1 Monolithic
🗃️ AplikasiTodolist V1 — showTodoList & addTodoList
Memahami logika paling dasar: menyimpan data di array dan menampilkannya ke konsol.
📄 AplikasiTodolist.java
public class AplikasiTodolist {

    // Array statis sebagai "database" sementara di memori
    public static String[] model = new String[10];

    // Scanner untuk membaca input pengguna dari konsol
    public static java.util.Scanner scanner = new java.util.Scanner(System.in);

    public static void main(String[] args) {
        viewShowTodoList(); // Entry point: langsung tampilkan UI
    }

    /**
     * Menampilkan todo list ke konsol
     */
    public static void showTodoList() {
        System.out.println("TODOLIST");
        for (var i = 0; i < model.length; i++) {
            var todo = model[i];
            var no = i + 1; // Nomor tampilan mulai dari 1 (bukan 0)

            if (todo != null) { // Hanya tampilkan slot yang terisi
                System.out.println(no + ". " + todo);
            }
        }
    }
}
static String[] model
Array String bertipe static — satu instance digunakan oleh semua method di class ini. Ukuran awal 10, tapi bisa di-resize nanti. Semua slot awalnya null. Ini adalah "database" sederhana di memori — data hilang saat program berhenti.
java.util.Scanner
Class bawaan Java untuk membaca input dari berbagai sumber. Di sini dipakai untuk membaca dari System.in (keyboard). scanner.nextLine() membaca satu baris teks yang diakhiri Enter.
if (todo != null)
Array belum tentu semua slotnya terisi. Slot yang belum diisi tetap null. Pengecekan ini memastikan hanya todo yang ada yang ditampilkan — bukan slot kosong.
var no = i + 1
Index array mulai dari 0, tapi tampilan ke pengguna mulai dari 1. Selisih antara "index internal" dan "nomor yang ditampilkan" ini harus konsisten — akan dipakai juga di removeTodoList().
➕ addTodoList — Dynamic Array Resize

Logika paling menarik di V1: menambah item ke array dan memperbesar array jika penuh.

public static void addTodoList(String todo) {

    // ─── Langkah 1: Cek apakah array penuh ───
    var isFull = true;
    for (int i = 0; i < model.length; i++) {
        if (model[i] == null) {
            isFull = false; // Masih ada slot kosong
            break;          // Tidak perlu cek sisanya
        }
    }

    // ─── Langkah 2: Jika penuh, resize 2x lipat ───
    if (isFull) {
        var temp = model;                         // Simpan referensi ke array lama
        model = new String[model.length * 2];     // Buat array baru, 2x lebih besar

        for (int i = 0; i < temp.length; i++) {  // Salin semua data lama ke array baru
            model[i] = temp[i];
        }
        // Sisa slot baru (temp.length sampai model.length-1) tetap null
    }

    // ─── Langkah 3: Tambahkan ke slot null pertama yang ditemukan ───
    for (var i = 0; i < model.length; i++) {
        if (model[i] == null) {
            model[i] = todo;
            break; // Hentikan setelah menemukan slot pertama
        }
    }
}
Langkah 1 — Cek Penuh
Iterasi seluruh array. Jika ditemukan slot null, berarti masih ada ruang → set isFull = false dan hentikan pencarian (break). Jika sampai akhir tidak ada null, isFull tetap true.
var temp = model
Di Java, variabel objek menyimpan referensi, bukan nilai langsung. temp = model membuat temp menunjuk ke array yang sama. Lalu model = new String[model.length * 2] membuat model menunjuk ke array baru — sementara temp masih menunjuk ke array lama yang berisi data.
model.length * 2
Strategi resize ×2: ini adalah strategi yang digunakan oleh ArrayList di Java Standard Library! Mengalikan dua setiap kali penuh membuat operasi resize semakin jarang terjadi seiring data bertambah — efisien secara amortized.
Langkah 3 — Tambah ke slot null
Cari slot pertama yang null, isi dengan data baru, lalu break. Ini memastikan urutan data terjaga dan tidak ada gap null di tengah-tengah (karena semua penambahan ke slot berikutnya).
🐘 Analogi PHP: ini seperti kamu implementasi push() dari scratch

Di PHP: $array[] = $item atau array_push($array, $item) — otomatis resize, tidak perlu pikir. Di Java, ArrayList sudah melakukan hal ini (list.add(item)). Kode di V1 ini sedang mendemonstrasikan cara kerja internal dynamic array — ini yang sesungguhnya terjadi di balik layar ArrayList!

🗑️ removeTodoList — Shift Array
public static boolean removeTodoList(Integer number) {

    // ─── Validasi 1: Nomor di luar range array ───
    if ((number - 1) >= model.length) {
        return false;
    }
    // ─── Validasi 2: Slot yang diminta sudah null (tidak ada data) ───
    else if (model[number - 1] == null) {
        return false;
    }
    // ─── Hapus dan shift ke kiri ───
    else {
        for (int i = (number - 1); i < model.length; i++) {
            if (i == (model.length - 1)) {
                model[i] = null; // Slot terakhir dikosongkan (null)
            } else {
                model[i] = model[i + 1]; // Geser elemen berikutnya ke kiri
            }
        }
        return true;
    }
}
number - 1
Pengguna memasukkan nomor berbasis 1 (tampilan), tapi index array berbasis 0. Konversi: index = number - 1. Ini harus konsisten dengan showTodoList() yang menampilkan no = i + 1.
Shift ke kiri — Cara Kerja
Misalnya ada 5 item dan hapus nomor 2 (index 1): model[1] = model[2], model[2] = model[3], model[3] = model[4], model[4] = null. Setiap elemen di kanan posisi yang dihapus bergeser satu slot ke kiri — tidak ada "lubang" di tengah.
return boolean
Method mengembalikan true jika berhasil, false jika gagal (validasi tidak lolos). Ini pola yang baik: caller bisa tahu apakah operasi berhasil dan menampilkan pesan yang sesuai.

🖥️ View Methods — UI Loop Interaktif
// Utility: membaca input dari konsol
public static String input(String info) {
    System.out.print(info + " : "); // Tampilkan prompt (tanpa newline)
    String data = scanner.nextLine(); // Baca satu baris, tunggu Enter
    return data;
}

// Main UI: loop tak terbatas sampai user pilih 'x'
public static void viewShowTodoList() {
    while (true) {        // Loop terus sampai ada break
        showTodoList();   // Tampilkan daftar terkini setiap iterasi

        System.out.println("MENU : ");
        System.out.println("1. Tambah");
        System.out.println("2. Hapus");
        System.out.println("x. Keluar");

        var input = input("Pilih"); // Tunggu input user

        if (input.equals("1")) {
            viewAddTodoList();
        } else if (input.equals("2")) {
            viewRemoveTodoList();
        } else if (input.equals("x")) {
            break; // Keluar dari while loop → program berakhir
        } else {
            System.out.println("Pilihan tidak dimengerti");
        }
    }
}

// Sub-view: menambah item
public static void viewAddTodoList() {
    System.out.println("MENAMBAH TODOLIST");
    var todo = input("Todo (x Jika Batal)");

    if (todo.equals("x")) {
        // batal — tidak ada action, langsung kembali ke menu utama
    } else {
        addTodoList(todo);
    }
}

// Sub-view: menghapus item
public static void viewRemoveTodoList() {
    System.out.println("MENGHAPUS TODOLIST");
    var number = input("Nomor yang Dihapus (x Jika Batal)");

    if (number.equals("x")) {
        // batal
    } else {
        boolean success = removeTodoList(Integer.valueOf(number)); // String → Integer
        if (!success) {
            System.out.println("Gagal menghapus todolist : " + number);
        }
    }
}
while (true) + break
Pola "game loop": program terus berjalan menunggu input, baru berhenti saat kondisi tertentu terpenuhi (break ketika user pilih 'x'). Di Java console app, ini cara standar membuat menu interaktif.
input.equals("1")
Di Java, String dibandingkan dengan .equals(), bukan ==. Operator == membandingkan referensi objek, bukan isi String. Ini salah satu perbedaan fundamental Java vs PHP (di PHP == membandingkan nilai).
Integer.valueOf(number)
Mengkonversi String ke Integer. scanner.nextLine() selalu mengembalikan String — untuk mendapatkan angka, harus di-parse manual. Integer.valueOf("5") = 5. Jika bukan angka, throw NumberFormatException.
⚠️ Bug Tersembunyi di V1: NumberFormatException

Jika user memasukkan teks bukan angka di menu Hapus (misalnya "abc"), Integer.valueOf("abc") akan throw NumberFormatException dan program crash! V1 tidak menangani kasus ini. Ini adalah salah satu alasan V2 perlu dibuat dengan penanganan yang lebih baik.

Chapter 2 • Transisi
⚠️ Masalah V1 & Kenapa Butuh V2
Identifikasi masalah arsitektur monolithic dan prinsip desain yang diperbaiki di V2.
🐛 5 Masalah Utama Arsitektur V1
1
Data tidak persisten
Semua data ada di String[] model yang merupakan variabel di memori. Saat program ditutup, semua data hilang. Tidak cocok untuk aplikasi nyata.
2
Satu file — semua campur jadi satu
Logika tampilkan UI, logika bisnis (validasi), dan logika data (array manipulation) semua di satu class. Melanggar Single Responsibility Principle. Susah dibaca, susah di-maintain.
3
Tidak bisa di-test unit
Karena UI, bisnis, dan data bercampur, tidak bisa menulis unit test untuk addTodoList() tanpa mempengaruhi state global (model static). Testing yang ada hanya manual via testXxx() methods.
4
Kapasitas terbatas (meski ada resize)
Meski ada dynamic resize, implementasi manual ini perlu dikelola sendiri. Database mengelola ini secara otomatis dan jauh lebih efisien.
5
State global (static) berbahaya
static String[] model adalah shared mutable state. Di aplikasi multi-thread, ini sangat berbahaya (race condition). Tidak ada encapsulation.
✅ Prinsip Desain yang Diterapkan di V2
PrinsipPenerapan di V2
Single ResponsibilitySetiap class punya satu tanggung jawab: Repository untuk data, Service untuk bisnis, View untuk UI
Dependency InjectionSetiap class menerima dependency-nya via constructor, bukan membuat sendiri
Programming to InterfaceTodoListRepository dan TodoListService adalah interface — bisa diganti implementasinya
Separation of ConcernsData access (SQL), bisnis, dan UI dipisahkan ke layer yang berbeda
🐘 Analogi Laravel: Script PHP vs MVC

V1 itu seperti "spaghetti PHP" zaman lama — satu file dengan HTML, SQL, dan logika campur. V2 itu seperti aplikasi Laravel proper: Controller (View), Service Class (Service), Repository/Eloquent (Repository), Migration/Model (Entity). Evolusinya sama persis.

Chapter 3 • V2 — Entity
📦 Entity: Todolist.java
Representasi data sebagai objek Java — mapping antara baris database dan objek program.
📄 entity/Todolist.java
package entity;

public class Todolist {

    private Integer id;   // Mapping ke kolom "id" di database (PRIMARY KEY, AUTO_INCREMENT)
    private String todo;  // Mapping ke kolom "todo" di database (VARCHAR)

    // Default constructor (wajib untuk mapping manual dari ResultSet)
    public Todolist() {
    }

    // Convenience constructor: buat Todolist hanya dengan todo (id diisi DB)
    public Todolist(String todo) {
        this.todo = todo;
    }

    // Getter & Setter
    public String getTodo()        { return todo; }
    public void setTodo(String t)  { this.todo = t; }
    public Integer getId()         { return id; }
    public void setId(Integer id)  { this.id = id; }
}
package entity
Package entity mengorganisir semua class yang merepresentasikan data/domain. Konvensi Java: package dengan nama yang deskriptif membantu navigasi kode di proyek besar.
private Integer id
Menggunakan Integer (wrapper class) bukan int (primitive) karena Integer bisa bernilai null. Saat object baru dibuat sebelum di-insert ke DB, id belum ada nilainya — harus bisa null.
Two constructors
Constructor kosong Todolist() wajib ada untuk mapping dari database (Repository perlu membuat objek dulu, lalu set field satu per satu via setter). Constructor Todolist(String todo) untuk kemudahan saat membuat objek baru di kode.

Chapter 4 • V2 — Database Layer
🗄️ DatabaseUtil & HikariCP Connection Pool
Mengelola koneksi ke MySQL secara efisien dengan connection pooling — agar tidak membuka koneksi baru untuk setiap query.
📄 util/DatabaseUtil.java
package util;

import com.zaxxer.hikari.HikariConfig;
import com.zaxxer.hikari.HikariDataSource;

public class DatabaseUtil {

    // Satu instance HikariDataSource untuk seluruh aplikasi (Singleton via static)
    private static HikariDataSource hikariDataSource;

    // static block: dieksekusi sekali saat class pertama kali dimuat
    static {
        HikariConfig configuration = new HikariConfig();

        // ─── Konfigurasi koneksi database ───
        configuration.setDriverClassName("com.mysql.cj.jdbc.Driver"); // MySQL JDBC Driver
        configuration.setUsername("root");
        configuration.setPassword("");
        configuration.setJdbcUrl(
            "jdbc:mysql://localhost:3306/belajar_java_todolist?serverTimezone=Asia/Jakarta"
        );

        // ─── Konfigurasi Connection Pool ───
        configuration.setMaximumPoolSize(10);        // Maks 10 koneksi aktif sekaligus
        configuration.setMinimumIdle(5);              // Pertahankan min 5 koneksi standby
        configuration.setIdleTimeout(60_000);         // Koneksi idle > 60 detik akan ditutup
        configuration.setMaxLifetime(60 * 60 * 1000); // Maks hidup koneksi: 1 jam

        hikariDataSource = new HikariDataSource(configuration);
    }

    public static HikariDataSource getDataSource() {
        return hikariDataSource;
    }
}
static { ... } — Static Initializer Block
Kode di dalam static { } dieksekusi sekali saja saat class pertama kali di-load oleh JVM. Ini adalah cara Java melakukan inisialisasi yang butuh lebih dari satu baris (tidak bisa langsung di deklarasi field). Mirip seperti konstruktor, tapi untuk static context.
HikariCP — Connection Pool
Masalah tanpa pool: membuka koneksi database itu mahal (handshake TCP, autentikasi, alokasi resource). Jika setiap query membuka koneksi baru dan langsung menutupnya, performa sangat buruk. Connection Pool: HikariCP membuka sejumlah koneksi di awal, lalu "meminjamkan" ke query dan mengambilnya kembali — jauh lebih cepat.
setMaximumPoolSize(10)
Maks 10 koneksi aktif bersamaan. Jika 11 request datang, request ke-11 menunggu salah satu dari 10 selesai. Nilai ini harus disesuaikan dengan kemampuan server database.
setMinimumIdle(5)
Pertahankan minimal 5 koneksi "siap pakai" meski sedang tidak ada request. Ini menghindari latensi pembuatan koneksi saat tiba-tiba ada traffic. Trade-off: konsumsi resource server DB lebih tinggi.
jdbc:mysql://localhost:3306/...
Format JDBC URL: jdbc:[driver]://[host]:[port]/[database]?[params]. serverTimezone=Asia/Jakarta memastikan server MySQL dan aplikasi Java menggunakan timezone yang sama — penting untuk operasi datetime.
60_000 dan 60 * 60 * 1000
Java memperbolehkan underscore dalam literal angka (60_000 = 60000 ms = 1 menit). 60 * 60 * 1000 = 3.600.000 ms = 1 jam — ditulis sebagai ekspresi untuk keterbacaan. Compiler menghitung hasilnya saat kompilasi.
💡 Mengapa HikariCP?

HikariCP adalah connection pool library tercepat untuk Java — bahkan dijadikan default di Spring Boot! Fitur utama: ultra-fast, zero-overhead, minimal footprint. Alternatif lain: Apache DBCP2, c3p0, Tomcat JDBC Pool.

🐘 Analogi Laravel: config/database.php + Laravel Connection Pool
// Laravel: config/database.php

Di PHP/Laravel, connection pooling dikelola oleh PHP-FPM di level proses — setiap worker punya koneksi sendiri. Di Java long-running process (tidak per-request), HikariCP mengelola pool secara eksplisit.

Chapter 5 • V2 — Repository Layer
🏛️ Repository Pattern — Interface & Implementasi
Layer yang bertanggung jawab atas semua interaksi dengan database — menggunakan JDBC dengan try-with-resources dan PreparedStatement.
📄 repository/TodoListRepository.java
package repository;
import entity.Todolist;

public interface TodoListRepository {
    Todolist[] getAll();             // Ambil semua todo dari DB
    void add(Todolist todolist);     // Insert todo baru ke DB
    boolean remove(Integer number);  // Hapus todo berdasarkan ID, return status
}
💡 Kenapa Interface? — Programming to Interface

Dengan mendefinisikan TodoListRepository sebagai interface, TodoListService hanya tahu apa yang bisa dilakukan repository (getAll, add, remove) — tidak peduli bagaimana implementasinya. Ini membuat:

  • Bisa ganti implementasi (dari MySQL ke PostgreSQL, atau ke in-memory untuk test) tanpa ubah Service
  • Testing lebih mudah — bisa pakai mock implementation
  • Loose coupling antar layer
📄 repository/TodoListRepositoryImpl.java
Method 1: getAll() — SELECT semua data
@Override
public Todolist[] getAll() {
    String sql = "SELECT id, todo FROM todolist";

    // try-with-resources: Connection, Statement, ResultSet otomatis ditutup!
    try (Connection connection = dataSource.getConnection();
         Statement statement = connection.createStatement();
         ResultSet resultSet = statement.executeQuery(sql)) {

        List<Todolist> list = new ArrayList<>();

        while (resultSet.next()) { // Iterasi baris per baris
            Todolist todolist = new Todolist();
            todolist.setId(resultSet.getInt("id"));
            todolist.setTodo(resultSet.getString("todo"));
            list.add(todolist);
        }

        return list.toArray(new Todolist[]{}); // Konversi List ke Array
    } catch (SQLException exception) {
        throw new RuntimeException(exception); // Wrap ke unchecked exception
    }
}
try-with-resources
Fitur Java 7+. Resource yang dideklarasikan di try(...) akan otomatis ditutup (.close() dipanggil) saat blok try selesai — baik berhasil maupun exception. Ini menggantikan finally { connection.close(); } yang verbose dan rawan lupa. Connection, Statement, ResultSet semua implement AutoCloseable.
dataSource.getConnection()
HikariCP "meminjamkan" satu koneksi dari pool. Saat connection.close() dipanggil (otomatis via try-with-resources), HikariCP tidak benar-benar menutup koneksi ke DB — hanya mengembalikannya ke pool untuk dipakai lagi.
Statement vs PreparedStatement
Statement untuk SQL statis tanpa parameter. PreparedStatement untuk SQL dengan parameter (mencegah SQL Injection). Di getAll() tidak ada parameter user input → Statement aman. Di add() dan remove() ada parameter user → wajib PreparedStatement.
resultSet.next()
ResultSet seperti cursor. Awalnya berada sebelum baris pertama. .next() menggeser cursor ke baris berikutnya dan return true jika ada baris, false jika sudah habis. Pola while(resultSet.next()) adalah cara standar iterasi hasil query.
throw new RuntimeException(exception)
SQLException adalah checked exception — harus ditangani. Karena interface TodoListRepository tidak mendeklarasikan throws SQLException, kita wrap ke RuntimeException (unchecked). Ini pola umum di Java modern untuk menghindari propagasi checked exception ke layer atas.
Method 2: add() — INSERT dengan PreparedStatement
@Override
public void add(Todolist todolist) {
    String sql = "INSERT INTO todolist(todo) VALUES (?)";
    //                                               ↑ Placeholder parameter

    try (Connection connection = dataSource.getConnection();
         PreparedStatement statement = connection.prepareStatement(sql)) {

        statement.setString(1, todolist.getTodo()); // Isi parameter ke-1 dengan todo
        statement.executeUpdate();                   // Jalankan INSERT

    } catch (SQLException exception) {
        throw new RuntimeException(exception);
    }
}
VALUES (?) — Placeholder
Tanda ? adalah placeholder yang akan diisi oleh JDBC. Ini adalah parameterized query — cara yang benar untuk menyisipkan data dari user ke SQL. Mengapa tidak langsung string concatenation? Karena rentan SQL Injection!
setString(1, value)
Index parameter mulai dari 1 (bukan 0). setString(1, ...) mengisi placeholder pertama. Tersedia juga: setInt(), setLong(), setDate(), dll. JDBC otomatis melakukan escaping — aman dari SQL Injection.
executeUpdate()
Untuk SQL yang memodifikasi data (INSERT, UPDATE, DELETE). Return jumlah baris yang terpengaruh. Berbeda dari executeQuery() yang return ResultSet (untuk SELECT).
❌ String Concatenation — SQL Injection!
// JANGAN PERNAH LAKUKAN INI
String todo = userInput; // bisa = "x'; DROP TABLE todolist; --"
String sql = "INSERT INTO todolist(todo) VALUES ('" + todo + "')";
statement.executeUpdate(sql);
// SQL jadi: INSERT INTO todolist(todo) VALUES ('x'); DROP TABLE todolist; --')
// Tabel dihapus!
✅ PreparedStatement — Aman
// Selalu gunakan PreparedStatement untuk input user
String sql = "INSERT INTO todolist(todo) VALUES (?)";
PreparedStatement stmt = conn.prepareStatement(sql);
stmt.setString(1, userInput); // JDBC otomatis escape karakter berbahaya
stmt.executeUpdate();
Method 3 & 4: isExists() + remove()
// Private helper: cek apakah todo dengan ID tertentu ada di DB
private boolean isExists(Integer number) {
    String sql = "SELECT id FROM todolist WHERE id = ?";
    try (Connection connection = dataSource.getConnection();
         PreparedStatement statement = connection.prepareStatement(sql)) {

        statement.setInt(1, number);

        // ResultSet di-buka di dalam try-with-resources terpisah (nested)
        try (ResultSet resultSet = statement.executeQuery()) {
            if (resultSet.next()) {
                return true;  // Ada baris → ID ada
            } else {
                return false; // Tidak ada baris → ID tidak ada
            }
        }

    } catch (SQLException exception) {
        throw new RuntimeException(exception);
    }
}

@Override
public boolean remove(Integer number) {
    if (isExists(number)) { // Cek dulu apakah ada
        String sql = "DELETE FROM todolist WHERE id = ?";
        try (Connection connection = dataSource.getConnection();
             PreparedStatement statement = connection.prepareStatement(sql)) {

            statement.setInt(1, number);
            statement.executeUpdate();
            return true;

        } catch (SQLException exception) {
            throw new RuntimeException(exception);
        }
    } else {
        return false; // ID tidak ada → hapus gagal
    }
}
isExists() — Private Helper
Method private yang hanya digunakan internal oleh remove(). Memisahkan logika "cek keberadaan" ke method tersendiri membuat remove() lebih bersih. Tidak ada duplikasi kode jika logika cek dipakai di tempat lain.
Nested try-with-resources
Di isExists(), ResultSet dibuka di dalam try terpisah karena harus dibuka setelah PreparedStatement di-set parameternya. Java memperbolehkan nesting try-with-resources — keduanya otomatis ditutup.
Pola cek sebelum hapus
Validasi dilakukan di Java sebelum query DELETE. Alternatif: langsung DELETE dan cek executeUpdate() return 0 (tidak ada baris terpengaruh). Tapi pendekatan cek dulu membuat return value lebih eksplisit.

package service;

📄 service/TodoListServiceImpl.java
package service;

import entity.Todolist;
import repository.TodoListRepository;

public class TodoListServiceImpl implements TodoListService {

    // Dependency ke Repository — menerima via constructor (Dependency Injection)
    private TodoListRepository todoListRepository;

    public TodoListServiceImpl(TodoListRepository todoListRepository) {
        this.todoListRepository = todoListRepository; // Inject dari luar
    }

    @Override
    public void showTodoList() {
        Todolist[] model = todoListRepository.getAll(); // Minta data dari Repository

        System.out.println("TODOLIST");
        for (var todolist : model) {
            System.out.println(todolist.getId() + "." + todolist.getTodo());
        }
    }

    @Override
    public void addTodoList(String todo) {
        Todolist todolist = new Todolist(todo);    // Buat entity dari data
        todoListRepository.add(todolist);           // Delegasikan ke Repository
        System.out.println("SUKSES MENAMBAH TODO : " + todo);
    }

    @Override
    public void removeTodoList(Integer number) {
        boolean success = todoListRepository.remove(number); // Delegasikan ke Repo
        if (success) {
            System.out.println("SUKSES MENGHAPUS TODO : " + number);
        } else {
            System.out.println("GAGAL MENGHAPUS TODO : " + number);
        }
    }
}
private TodoListRepository todoListRepository
Service menyimpan referensi ke Repository melalui interface, bukan concrete class. Ini artinya Service tidak peduli apakah ini TodoListRepositoryImpl (MySQL) atau implementasi lain (PostgreSQL, in-memory untuk test) — selama mengimplementasikan interface yang sama.
Constructor Injection
Repository tidak dibuat di dalam Service (new TodoListRepositoryImpl()). Sebaliknya, diterima dari luar via constructor. Ini adalah Dependency Injection — membuat class lebih testable dan tidak tightly coupled dengan implementasi konkret.
Service sebagai orchestrator
Service tidak melakukan query SQL langsung (itu tanggung jawab Repository). Service tidak menampilkan UI (itu tanggung jawab View). Service hanya mengkoordinasikan: ambil data dari Repository → proses → kembalikan hasil ke View. Ini adalah separation of concerns.

📄 view/TodoListView.java
package view;

import service.TodoListService;
import util.InputUtil;

public class TodoListView {

    // Dependency ke Service — via interface, bukan concrete class
    private TodoListService todoListService;

    public TodoListView(TodoListService todoListService) {
        this.todoListService = todoListService;
    }

    // Main loop — sama seperti V1 tapi delegasi ke Service
    public void showTodoList() {
        while (true) {
            todoListService.showTodoList(); // Delegasi tampilkan data ke Service

            System.out.println("MENU : ");
            System.out.println("1. Tambah");
            System.out.println("2. Hapus");
            System.out.println("x. Keluar");

            var input = InputUtil.input("Pilih"); // Gunakan utility terpisah

            if (input.equals("1"))      addTodoList();
            else if (input.equals("2")) removeTodoList();
            else if (input.equals("x")) break;
            else System.out.println("Pilihan tidak dimengerti");
        }
    }

    public void addTodoList() {
        System.out.println("MENAMBAH TODOLIST");
        var todo = InputUtil.input("Todo (x Jika Batal)");

        if (!todo.equals("x")) {
            todoListService.addTodoList(todo); // Delegasi ke Service
        }
    }

    public void removeTodoList() {
        System.out.println("MENGHAPUS TODOLIST");
        var number = InputUtil.input("Nomor yang Dihapus (x Jika Batal)");

        if (!number.equals("x")) {
            todoListService.removeTodoList(Integer.valueOf(number)); // Delegasi ke Service
        }
    }
}
View hanya "delegasi" ke Service
View tidak punya logika bisnis apapun. Tugasnya: baca input → teruskan ke Service → tampilkan hasil. Tidak ada manipulasi data, tidak ada query SQL. Jika logika bisnis berubah, View tidak perlu diubah.
Instance methods (bukan static)
Di V2, semua method di View adalah instance method (tidak pakai static). Ini memungkinkan dependency (todoListService) disimpan sebagai field instance. Di V1, semua static karena tidak ada OOP yang proper.
🐘 Analogi Laravel: Controller

Di Laravel, Controller bertugas menerima HTTP request, memanggil Service/Repository, dan mengembalikan response. TodoListView di Java melakukan hal yang sama — tapi untuk console app (input dari keyboard, output ke konsol) bukan web app (input dari HTTP request, output JSON/HTML).

Chapter 8 • Dependency Injection
🔌 Wiring — Menghubungkan Semua Layer
Di sinilah semua keping puzzle dirakit — titik masuk aplikasi yang menghubungkan semua dependency secara manual.
📄 AplikasiTodolistV2.java
import repository.TodoListRepository;
import repository.TodoListRepositoryImpl;
import service.TodoListService;
import service.TodoListServiceImpl;
import util.DatabaseUtil;
import view.TodoListView;

import javax.sql.DataSource;

public class AplikasiTodolistV2 {

    public static void main(String[] args) {
        // ─── Step 1: Dapatkan DataSource (HikariCP pool) ───
        DataSource dataSource = DatabaseUtil.getDataSource();

        // ─── Step 2: Buat Repository, inject DataSource ───
        TodoListRepository todoListRepository = new TodoListRepositoryImpl(dataSource);

        // ─── Step 3: Buat Service, inject Repository ───
        TodoListService todoListService = new TodoListServiceImpl(todoListRepository);

        // ─── Step 4: Buat View, inject Service ───
        TodoListView todoListView = new TodoListView(todoListService);

        // ─── Step 5: Jalankan aplikasi ───
        todoListView.showTodoList();
    }
}
Manual Dependency Injection
Ini disebut "Poor Man's DI" atau manual wiring. Semua dependency dibuat dan dihubungkan secara eksplisit di main(). Keuntungan: jelas, tidak ada magic. Kekurangan: di aplikasi besar dengan puluhan class, ini sangat verbose. Di sinilah DI Container seperti Spring berguna!
Urutan pembuatan (Bottom-up)
Dependency dibuat dari yang paling bawah ke atas: DataSource → Repository → Service → View. Setiap layer menerima layer di bawahnya sebagai dependency. Ini adalah grafik dependency yang berjalan searah (tidak ada circular dependency).
Interface sebagai tipe variabel
TodoListRepository todoListRepository = new TodoListRepositoryImpl(...): variabel bertipe interface, objek bertipe concrete class. Ini "programming to interface" — jika besok ganti ke TodoListRepositoryMongo, hanya baris ini yang berubah.

package util;

import com.zaxxer.hikari.HikariDataSource;

    @Test

        HikariDataSource dataSource = DatabaseUtil.getDataSource();

        Connection connection = dataSource.getConnection(); // Pinjam dari pool
        // Lakukan assertion atau hanya verifikasi tidak throw exception

@Test
Anotasi dari JUnit 5 yang menandai method sebagai test case. JUnit akan menjalankan semua method dengan anotasi ini saat test suite dieksekusi (via Maven: mvn test, atau klik run di IDE).
throws SQLException
Di test method, boleh mendeklarasikan throws checked exception — JUnit akan menangkapnya dan menandai test sebagai failed with exception. Lebih bersih daripada try-catch di setiap test.
dataSource.close()
Saat pool ditutup, semua koneksi ke database benar-benar ditutup. Ini harus dilakukan di akhir test/aplikasi. Di test, idealnya ini di @AfterEach atau @AfterAll — bukan di dalam test method sendiri.
📄 test/repository/TodolistRepositoryImplTest.java
package repository;

import com.zaxxer.hikari.HikariDataSource;
import entity.Todolist;
import org.junit.jupiter.api.AfterEach;
import org.junit.jupiter.api.BeforeEach;
import org.junit.jupiter.api.Test;
import util.DatabaseUtil;

import javax.sql.DataSource;

public class TodolistRepositoryImplTest {

    private HikariDataSource dataSource;
    private TodoListRepository todoListRepository;

    // ─── Setup: dijalankan SEBELUM setiap test ───
    @BeforeEach
    void setUp() {
        dataSource = DatabaseUtil.getDataSource();
        todoListRepository = new TodoListRepositoryImpl(dataSource);
    }

    // ─── Teardown: dijalankan SETELAH setiap test ───
    @AfterEach
    void tearDown() {
        dataSource.close(); // Tutup pool setelah setiap test
    }

    @Test
    void testAdd() {
        Todolist todolist = new Todolist();
        todolist.setTodo("Kurniawan");

        todoListRepository.add(todolist);
        // Assertion: verifikasi data masuk ke DB
    }

    @Test
    void testRemove() {
        System.out.println(todoListRepository.remove(1)); // Hapus ID 1
        System.out.println(todoListRepository.remove(2)); // Hapus ID 2
        System.out.println(todoListRepository.remove(3)); // Hapus ID 3
        System.out.println(todoListRepository.remove(4)); // Hapus ID 4
    }

    @Test
    void testGetAll() {
        todoListRepository.add(new Todolist("EKo"));
        todoListRepository.add(new Todolist("Kurniawan"));
        todoListRepository.add(new Todolist("Khannedy"));

        Todolist[] todolists = todoListRepository.getAll();
        for (var todo : todolists) {
            System.out.println(todo.getId() + " : " + todo.getTodo());
        }
    }
}
@BeforeEach
Method dengan anotasi ini dijalankan sebelum setiap test method. Digunakan untuk inisialisasi yang dibutuhkan setiap test: buat koneksi, buat objek yang di-test, reset state. Memastikan setiap test mulai dari kondisi bersih.
@AfterEach
Method dengan anotasi ini dijalankan setelah setiap test method — bahkan jika test gagal. Digunakan untuk cleanup: tutup koneksi, hapus file sementara, reset state. Pasangan dari @BeforeEach.
Integration Test vs Unit Test
Test ini adalah Integration Test karena benar-benar terhubung ke database MySQL nyata. Unit Test idealnya tidak terhubung ke resource eksternal — menggunakan mock. Tapi untuk belajar dasar, Integration Test lebih mudah dipahami.
