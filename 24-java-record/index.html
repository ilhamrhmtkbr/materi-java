Java Record

Fitur Java 16 (GA) yang memperkenalkan cara ringkas mendefinisikan kelas data immutable — tanpa boilerplate getter, equals, hashCode, dan toString. Seperti readonly class di bahasa modern.

Java 16 (GA)

Immutable Data Carrier

PHP/Laravel Analogy

Mini Quiz

🧠 Record itu Apa, Tepatnya?

Record adalah kelas data immutable yang dideklarasikan secara ringkas. Dengan satu baris deklarasi, compiler Java otomatis menghasilkan: konstruktor, accessor (getter), equals(), hashCode(), dan toString(). Record sangat cocok untuk membawa data antar lapisan aplikasi — DTO, response API, value object, dll.

1
Sebelum Record: Class Biasa (boilerplate)
Untuk membuat kelas data sederhana, kamu harus menulis: field, constructor, getter untuk setiap field, equals(), hashCode(), toString(). Bisa 50–100 baris hanya untuk 3 field data.
Java < 16
2
Workaround: Lombok @Data
Library Lombok dengan @Data atau @Value mengurangi boilerplate via annotation processing. Masih butuh dependency eksternal dan kadang menyebabkan masalah dengan IDE/build tool.
Java 8+ (workaround)
3
Java 16: Record — Solusi Native
Record hadir sebagai fitur bahasa native. record Point(int x, int y) {} = satu baris untuk kelas data lengkap. Tidak butuh library eksternal, langsung didukung compiler dan semua tools Java.
Java 16 (GA) ✨
4
Java 21: Record Patterns
Record Patterns di pattern matching (instanceof) memungkinkan destructuring langsung dari instanceof check — fitur yang sangat powerful untuk kode yang lebih ekspresif.
Java 21 (GA)
🔗 Titik Tolak dari PHP/Laravel

Di PHP 8.2+, ada Readonly Class: readonly class Point { public function __construct(public int $x, public int $y) {} }. Di Laravel, kamu sering pakai array asosiatif atau DTO sederhana untuk membawa data antar lapisan. Java Record adalah solusi yang jauh lebih terstruktur dan type-safe dari keduanya — otomatis immutable, otomatis punya equals/hashCode yang benar, dan otomatis bisa di-destructure dengan pattern matching.

Chapter 1
😩 Masalah Tanpa Record: Boilerplate Class

Untuk memahami nilai Record, lihat dulu betapa banyak kode yang harus ditulis hanya untuk membuat kelas data sederhana di Java klasik. Ini adalah pain point yang sudah lama dikeluhkan developer Java.

Kelas Data Tanpa Record — Versi Penuh

Bayangkan kamu butuh kelas Customer dengan 4 field: id, name, email, phone. Berikut yang harus kamu tulis tanpa Record:

// ❌ SEBELUM RECORD — boilerplate yang menyiksa
// Ini untuk 4 field saja! Bayangkan kalau 10 field...
public class Customer {
    private final String id;
    private final String name;
    private final String email;
    private final String phone;

    // Constructor
    public Customer(String id, String name, String email, String phone) {
        this.id = id;
        this.name = name;
        this.email = email;
        this.phone = phone;
    }

    // Getter untuk setiap field (4 method!)
    public String getId()    { return id; }
    public String getName()  { return name; }
    public String getEmail() { return email; }
    public String getPhone() { return phone; }

    // equals — harus cover semua field secara manual
    @Override
    public boolean equals(Object o) {
        if (this == o) return true;
        if (!(o instanceof Customer)) return false;
        Customer c = (Customer) o;
        return Objects.equals(id, c.id) &&
               Objects.equals(name, c.name) &&
               Objects.equals(email, c.email) &&
               Objects.equals(phone, c.phone);
    }

    // hashCode — harus konsisten dengan equals
    @Override
    public int hashCode() {
        return Objects.hash(id, name, email, phone);
    }

    // toString — biar debugging lebih mudah
    @Override
    public String toString() {
        return "Customer[id=" + id + ", name=" + name +
               ", email=" + email + ", phone=" + phone + "]";
    }
}
// Total: ~40 baris hanya untuk 4 field data 😰
😩 Tanpa Record — ~40 baris
public class Customer {
    private final String id;
    private final String name;
    private final String email;
    private final String phone;
    // constructor, 4 getter,
    // equals, hashCode, toString
    // ... 40 baris total
}
✅ Dengan Record — 1 baris!
// Semua yang di atas, tapi 1 baris:
public record Customer(
    String id,
    String name,
    String email,
    String phone
) {}
// Compiler auto-generate SEMUA boilerplate ✅
✅ Apa yang Otomatis Dihasilkan Record?

Dengan deklarasi record Customer(String id, String name, String email, String phone), compiler Java otomatis membuat: (1) field private final untuk setiap komponen, (2) canonical constructor yang menginisialisasi semua field, (3) accessor method (bukan getter biasa!) dengan nama sama persis dengan field, (4) equals() yang membandingkan semua komponen, (5) hashCode() yang konsisten, (6) toString() yang menampilkan semua komponen.

🔗 Analogi PHP Readonly Class

PHP 8.2: readonly class Customer { public function __construct(public string $id, public string $name, public string $email, public string $phone) {} }. Ini adalah padanan terdekat PHP untuk Record Java. Perbedaan: PHP readonly class tidak otomatis menghasilkan equals() dan hashCode() — PHP tidak memiliki konsep ini secara native. Java Record lebih lengkap karena semua tersedia otomatis.

Chapter 2
📦 Sintaks Dasar Record

Pelajari cara mendeklarasikan Record, cara mengaksesnya, dan bagaimana equals/hashCode/toString bekerja secara otomatis — semuanya dari kode CustomerTest.java.

Deklarasi & Penggunaan Dasar
// Customer.java — deklarasi Record paling dasar
// Sintaks: public record NamaRecord(TipeParam namaParam, ...) { }
public record Customer(String id, String name, String email, String phone) {
  // body bisa kosong — semua sudah di-generate compiler
}

// CustomerTest.java — cara menggunakan Record
@Test
void createNewRecord() {
    // Instansiasi persis sama dengan class biasa
    var customer = new Customer("1", "Eko", "eko@localhost", "082131231");
    assertNotNull(customer);

    // toString() otomatis → "Customer[id=1, name=Eko, email=eko@localhost, phone=082131231]"
    System.out.println(customer);
}

@Test
void getProperty() {
    var customer = new Customer("1", "Eko", "eko@localhost", "082131231");

    // ⚠️ PENTING: Accessor bukan getId() tapi langsung id()!
    // Tidak ada prefix "get" — ini berbeda dari JavaBean convention
    assertEquals("1",            customer.id());      // bukan customer.getId()
    assertEquals("Eko",          customer.name());    // bukan customer.getName()
    assertEquals("eko@localhost",customer.email());   // bukan customer.getEmail()
    assertEquals("082131231",    customer.phone());   // bukan customer.getPhone()
}

@Test
void recordEquals() {
    var customer1 = new Customer("1", "Eko", "eko@localhost", null);
    var customer2 = new Customer("1", "Eko", "eko@localhost", null);

    // equals() otomatis membandingkan SEMUA komponen
    // Dua customer dengan nilai yang sama → equals() return true
    assertTrue(customer1.equals(customer2));       // ✅

    // hashCode() juga konsisten — same data = same hashCode
    assertEquals(customer1.hashCode(), customer2.hashCode()); // ✅

    // toString() menghasilkan representasi yang sama
    assertEquals(customer1.toString(), customer2.toString()); // ✅
}
Anggota yang Otomatis Dibuat — Referensi Cepat
🔒
Field private final
private final String id;
Setiap komponen record menjadi field private final. Tidak bisa diubah setelah konstruksi — ini yang membuat Record immutable.
🏗️
Canonical Constructor
Customer(String id, String name, ...)
Constructor yang menerima semua komponen sebagai parameter. Ini adalah satu-satunya constructor yang bisa juga di-custom (lihat Chapter 3).
📖
Accessor Method
public String id() { return id; }
Bukan getId()! Accessor Record menggunakan nama komponen langsung tanpa prefix "get". Ini adalah konvensi baru yang berbeda dari JavaBean.
⚖️
equals()
public boolean equals(Object o)
Membandingkan semua komponen secara otomatis. Dua Record dengan nilai yang sama selalu equals() — berbeda dari class biasa yang default-nya membandingkan referensi.
#️⃣
hashCode()
public int hashCode()
Konsisten dengan equals() — dua Record yang equals() pasti hashCode() yang sama. Penting untuk penggunaan di HashMap/HashSet.
🖨️
toString()
public String toString()
Format: NamaRecord[komponen1=nilai1, ...]. Contoh: Customer[id=1, name=Eko, ...]. Berguna untuk logging dan debugging.
⚠️ Perhatian: Accessor Record vs JavaBean Getter

Ini perbedaan yang sering membuat developer baru tersandung. Di JavaBean (class biasa): customer.getId(). Di Record: customer.id(). Beberapa library yang mengharapkan JavaBean convention (misal Jackson JSON untuk serialisasi) mungkin perlu konfigurasi tambahan agar bisa membaca Record. Spring Boot 2.7+ dan Jackson 2.12+ sudah mendukung Record secara native.

❌ Salah — Pakai konvensi JavaBean getter
record Customer(String id, String name) {}

var c = new Customer("1", "Eko");
// ❌ Ini TIDAK ada pada Record!
c.getId();   // compile error
c.getName(); // compile error
✅ Benar — Accessor tanpa prefix "get"
record Customer(String id, String name) {}

var c = new Customer("1", "Eko");
// ✅ Accessor = nama komponen langsung
c.id();    // "1"
c.name();  // "Eko"

Chapter 3
🔧 Tiga Jenis Constructor Record

Record mendukung tiga jenis constructor: canonical (kustom), compact (ringkas untuk validasi), dan alternate (dengan parameter berbeda). Semuanya ada di Customer.java dan Point.java.

Kode — Customer.java & Point.java
// Customer.java — menampilkan TIGA jenis constructor sekaligus
public record Customer(String id, String name, String email, String phone)
    implements SayHello {

  // ─── Jenis 1: Canonical Constructor (custom) ─────────────────────────
  // Nama + parameter SAMA PERSIS dengan deklarasi record
  // Digunakan untuk: validasi, normalisasi data, logging
  public Customer(String id, String name, String email, String phone) {
    System.out.println("Create Customer");  // Side effect saat pembuatan
    this.id    = id.toLowerCase();          // Normalisasi: selalu lowercase
    this.name  = name;                      // Simpan apa adanya
    this.email = email != null ? email.toLowerCase() : null; // Null-safe normalize
    this.phone = phone != null ? phone.toLowerCase() : null;
  }

  // ─── Jenis 2: Alternate Constructor ──────────────────────────────────
  // Parameter lebih sedikit — WAJIB delegasikan ke canonical constructor
  // menggunakan this(...)
  public Customer(String id, String name, String email) {
    this(id, name, email, null); // phone = null secara default
  }

  public Customer(String id, String name) {
    this(id, name, null);        // email = null, phone = null
  }

  @Override
  public String sayHello(String name) {
    return "Hello " + name + ", my name is " + this.name;
  }
}

// ─────────────────────────────────────────────────────────────────────────
// Point.java — menampilkan COMPACT Constructor
public record Point(@Valid int x, @Valid int y) {

  // ─── Jenis 3: Compact Constructor ────────────────────────────────────
  // Tidak ada parameter list, tidak ada this.x = x (dilakukan otomatis!)
  // Digunakan untuk: validasi ringan, side effect, logging
  // Setelah blok ini selesai, assignment x = x dan y = y dilakukan otomatis
  public Point {
    System.out.println("Create Point");
    // Tempat yang tepat untuk validasi:
    // if (x < 0) throw new IllegalArgumentException("x harus >= 0");
  }
}
Bedah Tiga Jenis Constructor
JenisSintaksKapan DigunakanKunci
Canonical public Customer(String id, ...) Butuh normalisasi data (lowercase, trim), validasi kompleks, logging pembuatan objek Nama & parameter harus identik dengan deklarasi record. Harus assign semua field (this.x = ...).
Compact public Point { ... } Validasi sederhana, side effect ringan. Tidak perlu assign field secara manual — JVM melakukannya otomatis setelah blok. Tidak ada (parameter) dan tidak ada this.x = x. Kamu bisa modifikasi nilai parameter sebelum di-assign: x = Math.abs(x);
Alternate public Customer(String id, String name) Buat objek dengan parameter lebih sedikit (optional fields). Harus memanggil canonical via this(...) sebagai baris pertama. WAJIB panggil this(...) ke canonical atau alternate lain sebagai baris pertama — mirip aturan super() di inheritance.
Test: Canonical Constructor — Normalisasi Data
// CustomerTest.java
@Test
void canonicalConstructor() {
    // Input email dalam UPPERCASE
    var customer = new Customer("1", "Eko", "EKO@LOCALHOST");
    assertNotNull(customer);

    assertEquals("1",            customer.id());
    assertEquals("Eko",          customer.name());
    // Canonical constructor mengubah email ke lowercase!
    assertEquals("eko@localhost", customer.email()); // "EKO@LOCALHOST" → "eko@localhost"
    assertNull(customer.phone());                    // Alternate constructor: phone = null
}

@Test
void constructor() {
    // Alternate constructor dengan 3 parameter (tanpa phone)
    var customer = new Customer("1", "Eko", "eko@localhost");
    assertNull(customer.phone()); // phone otomatis null
}
🔗 Analogi PHP Constructor Chaining

Di PHP, constructor chaining dilakukan via self::__construct() atau biasanya dengan parameter default: public function __construct(string $id, string $name, ?string $email = null, ?string $phone = null). Java Record memisahkan konstruktor dengan jumlah parameter berbeda secara eksplisit. Compact Constructor Java mirip dengan menempatkan logika validasi di awal __construct sebelum assignment. Keduanya bertujuan sama: memastikan objek selalu dalam state yang valid sejak penciptaannya.

❌ Salah — Alternate constructor tidak delegasi
public record Customer(String id, String name, String email) {
  // COMPILE ERROR: alternate constructor WAJIB
  // panggil this(...) sebagai baris PERTAMA
  public Customer(String id, String name) {
    this.id = id;    // ← error: baris pertama harus this(...)
    this.name = name;
    this.email = null;
  }
}
✅ Benar — Delegasi ke canonical via this()
public record Customer(String id, String name, String email) {
  // ✅ Delegasi ke canonical constructor
  public Customer(String id, String name) {
    this(id, name, null); // WAJIB baris pertama!
    // Tidak ada kode lain yang boleh sebelum this(...)
  }
}

Chapter 4
⚙️ Method Tambahan & Implementasi Interface

Record bukan hanya wadah data pasif. Kamu bisa menambahkan method instance, dan Record bisa mengimplementasikan Interface — persis seperti class biasa. Bahkan kamu bisa override toString() atau accessor yang otomatis dibuat.

Record yang Mengimplementasikan Interface
// SayHello.java — interface biasa
public interface SayHello {
  String sayHello(String name);
}

// Customer.java — Record mengimplementasikan interface
public record Customer(String id, String name, String email, String phone)
    implements SayHello {    // ← implements persis seperti class biasa!

  // ... constructor ...

  // Implementasi method dari interface
  @Override
  public String sayHello(String name) {
    return "Hello " + name + ", my name is " + this.name;
    //                                                ↑ ini field Record (this.name)
    //                               parameter name ↑ menghide field, jadi butuh this.name
  }
}

// CustomerTest.java
@Test
void recordMethod() {
    var customer = new Customer("1", "Eko", "EKO@LOCALHOST");
    assertEquals("Hello Budi, my name is Eko", customer.sayHello("Budi"));
}
Bedah Baris per Baris
KodePenjelasan
implements SayHello Record bisa implements satu atau lebih interface — sintaksnya identik dengan class. Record TIDAK bisa extend class lain (sudah implisit extends java.lang.Record).
public String sayHello(String name) Method instance biasa yang ditambahkan ke Record. Bisa mengakses semua komponen Record via this.namaKomponen atau langsung via accessor: this.name() atau name().
this.name vs name Perhatikan dalam method sayHello(String name), parameter name meng-shadow (menyembunyikan) komponen record name. Untuk mengakses komponen record, gunakan this.name (field) atau this.name() (accessor). Ini adalah gotcha yang perlu diwaspadai!
Override Accessor — Kasus Khusus

Kamu juga bisa meng-override accessor yang otomatis dibuat, misalnya untuk menambahkan transformasi atau validasi saat membaca nilai:

public record Temperature(double celsius) {

  // Override accessor untuk custom behavior saat read
  @Override
  public double celsius() {
    return Math.round(celsius * 100.0) / 100.0; // Bulatkan ke 2 desimal
  }

  // Tambah accessor turunan (bukan komponen record, tapi method biasa)
  public double fahrenheit() {
    return celsius * 9.0 / 5.0 + 32;
  }

  public double kelvin() {
    return celsius + 273.15;
  }
}

// Penggunaan
var t = new Temperature(36.6666);
System.out.println(t.celsius());    // 36.67 (dibulatkan)
System.out.println(t.fahrenheit()); // 97.8
System.out.println(t.kelvin());     // 309.8166
💡 Aturan: Apa yang Bisa dan Tidak Bisa di Record

BISA: Tambah instance method, static method, override accessor, implements interface, tambah inner class. TIDAK BISA: Extend class lain (sudah extends Record), tambah instance field di luar komponen, buat instance mutable (field selalu final), buat record abstract, buat record inner class non-static.

🔗 Analogi PHP Interface Implementation

PHP: readonly class Customer implements SayHello { public function sayHello(string $name): string { return "Hello $name, my name is {$this->name}"; } }. Java Record melakukan hal yang sama — implementasi interface tidak berbeda dari class biasa. Satu hal yang berbeda: di Java, kamu tidak bisa extends class lain dalam Record, karena Record sudah secara implisit extends java.lang.Record. Ekuivalennya di PHP: readonly class tidak bisa extend class yang punya mutable property.

🧪 Mini Quiz

Dalam method instance sebuah Record, kenapa kadang perlu menulis this.name bukan langsung name?

A. Karena Record selalu butuh this untuk mengakses field
B. Karena parameter method mungkin memiliki nama yang sama dengan komponen record, sehingga shadowing terjadi — this.name memastikan yang diakses adalah field record, bukan parameter
C. Karena akses field Record selalu butuh qualifier
D. Karena name saja mengembalikan null di Record
Chapter 5
📌 Static Member dalam Record

Record bisa memiliki static field (konstanta) dan static method — berguna untuk nilai default, factory method, dan helper. Lihat bagaimana Point.java menggunakannya.

Kode — Point.java
// Point.java
public record Point(@Valid int x, @Valid int y) {

  // Compact Constructor (validasi/side effect)
  public Point {
    System.out.println("Create Point");
  }

  // ─── Static Field (Konstanta) ──────────────────────────────────────────
  // Konstanta dalam Record WAJIB dideklarasikan sebagai static
  // (instance field di luar komponen tidak diizinkan)
  public static final Point ZERO = new Point(0, 0);
  // "Origin point" yang sering dibutuhkan, tidak perlu buat berkali-kali

  // ─── Static Method (Factory Method) ───────────────────────────────────
  // Pola Factory Method: beri nama yang lebih ekspresif dari "new Point()"
  public static Point create(int x, int y) {
    return new Point(x, y);
    // Manfaat factory method: bisa tambahkan validasi, caching, atau
    // logika lain tanpa mengubah constructor
  }
}

// PointTest.java
@Test
void staticMember() {
    // Akses static field langsung dari nama class
    assertEquals(0, Point.ZERO.x()); // (0,0) sudah tersedia sebagai konstanta
    assertEquals(0, Point.ZERO.y());

    // Gunakan factory method sebagai alternatif new Point()
    var point = Point.create(10, 10);
    assertEquals(10, point.x());
    assertEquals(10, point.y());
}
Bedah Baris per Baris
KodePenjelasanMengapa Harus Static
public static final Point ZERO Konstanta dalam Record. Harus static karena Record tidak bisa punya instance field tambahan di luar komponen yang dideklarasikan. final agar nilainya tidak bisa diganti. Record melarang instance field non-komponen untuk menjaga immutability dan kesederhanaan. Static field tidak melanggar prinsip ini karena bukan bagian dari "state" instance.
public static Point create(int x, int y) Static factory method — alternatif dari new Point(x, y). Manfaat: nama lebih ekspresif (Point.create() vs new Point()), bisa ditambahkan validasi tanpa menyentuh constructor, bisa return cached instance. Pola Factory Method sangat umum di Java. Contoh familiar: List.of(), Map.of(), Optional.of() — semuanya static factory method.
🔗 Analogi PHP Static Method

Di PHP: class Point { public static Point $ZERO; public static function create(int $x, int $y): self { return new self($x, $y); } }. Konsep identik — static member tetap ada dalam Record Java sama seperti dalam class PHP. Perbedaan: Java lebih strict — kamu tidak bisa tambahkan instance property biasa di Record. Di PHP readonly class, kamu masih bisa tambahkan method dan property (tapi property tidak bisa diubah setelah init).

✅ Pattern: Factory Method di Record

Factory method sangat berguna saat kamu butuh membuat Record dari format lain. Misalnya: public static Point fromString(String s) { var parts = s.split(","); return new Point(Integer.parseInt(parts[0]), Integer.parseInt(parts[1])); } — sehingga bisa dipanggil Point.fromString("10,20"). Ini lebih ekspresif dan memisahkan logika parsing dari konstruktor utama.

🧪 Mini Quiz

Kenapa field tambahan di dalam Record harus dideklarasikan sebagai static?

A. Karena semua field dalam Record harus bisa diakses dari mana saja
B. Karena Record tidak mengizinkan instance field di luar komponen yang dideklarasikan — hanya static field yang diperbolehkan sebagai tambahan
C. Karena field static lebih hemat memori dari instance field
D. Karena field instance di Record akan konflik dengan constructor
Chapter 6
🏷️ Generics & Annotation pada Record

Record mendukung generics seperti class biasa, dan annotation pada komponen Record secara otomatis diterapkan ke field, accessor, dan parameter constructor — fitur yang sangat berguna untuk framework validasi.

Record dengan Generics — Data.java
// Data.java — Record generic paling sederhana
public record Data(T data) {
  // T adalah type parameter — bisa berisi tipe apa saja
  // Sama persis dengan generic class biasa
}

// DataTest.java
@Test
void generic() {
    // Data — T = String
    var data = new Data("Eko");
    assertEquals("Eko", data.data()); // accessor mengembalikan String

    // Data — T = Integer
    var data2 = new Data(100);
    assertEquals(100, data2.data()); // accessor mengembalikan Integer
}

// Contoh penggunaan di API response wrapper:
// Data customerData = new Data<>(customer);
// Data> productsData = new Data<>(productList);
// Data> configData = new Data<>(config);
Annotation pada Komponen — Point.java

Ketika kamu menaruh annotation pada komponen Record, annotation tersebut dipropagasikan ke tiga tempat sekaligus: field, accessor method, dan parameter constructor. Ini diatur oleh @Target pada annotation itu sendiri.

// Valid.java — Custom Annotation
@Target({
    ElementType.FIELD,      // bisa dipakai pada field
    ElementType.METHOD,     // bisa dipakai pada method
    ElementType.PARAMETER   // bisa dipakai pada parameter
})
@Retention(RetentionPolicy.RUNTIME) // Tersedia saat runtime (untuk reflection)
@Documented
public @interface Valid {
}

// Point.java — menggunakan annotation pada komponen
public record Point(@Valid int x, @Valid int y) {
  // @Valid pada komponen x dan y akan otomatis dipropagasikan ke:
  // 1. Field: private final int x (karena @Target includes FIELD)
  // 2. Method: public int x() (karena @Target includes METHOD)
  // 3. Constructor param: Point(int x, ...) (karena @Target includes PARAMETER)
  public Point {
    System.out.println("Create Point");
  }
}

// PointTest.java — membuktikan propagasi annotation via Reflection
@Test
void annotation() throws NoSuchFieldException, NoSuchMethodException {
    // Cek annotation pada FIELD
    assertNotNull(Point.class.getDeclaredField("x").getAnnotation(Valid.class)); // ✅
    assertNotNull(Point.class.getDeclaredField("y").getAnnotation(Valid.class)); // ✅

    // Cek annotation pada METHOD (accessor)
    assertNotNull(Point.class.getDeclaredMethod("x").getAnnotation(Valid.class)); // ✅
    assertNotNull(Point.class.getDeclaredMethod("y").getAnnotation(Valid.class)); // ✅

    // Cek annotation pada CONSTRUCTOR PARAMETER
    assertNotNull(Point.class.getConstructors()[0]
        .getParameters()[0].getAnnotation(Valid.class)); // ✅ param x
    assertNotNull(Point.class.getConstructors()[0]
        .getParameters()[1].getAnnotation(Valid.class)); // ✅ param y
}

💡 Praktis: Jakarta Validation dengan Record

Dengan propagasi annotation ini, kamu bisa langsung menggunakan Jakarta Validation (@NotNull, @NotBlank, @Email) pada komponen Record, dan framework seperti Spring Boot akan secara otomatis memvalidasinya saat menerima request body:

// DTO Request menggunakan Record + Jakarta Validation
import jakarta.validation.constraints.*;

public record CreateCustomerRequest(
    @NotBlank(message = "ID tidak boleh kosong")
    String id,

    @NotBlank @Size(min = 2, max = 100)
    String name,

    @Email(message = "Format email tidak valid")
    String email
) {}

// Di Spring Boot Controller:
@PostMapping("/customers")
public ResponseEntity<Customer> create(
    @RequestBody @Valid CreateCustomerRequest request
) {
    // Jika validasi gagal → 400 Bad Request otomatis!
    var customer = new Customer(request.id(), request.name(), request.email(), null);
    return ResponseEntity.ok(customer);
}

Di Java Spring Boot, Record + @Valid + Jakarta Validation annotation mencapai hal yang sama tapi dengan pendekatan type-safe berbasis annotation. Keuntungan Java: aturan validasi berada langsung di deklarasi field (lebih dekat dengan data), type-safe, dan langsung terlihat di IDE saat penggunaan.

🎯 Record Patterns — Destructuring di Java 21

Record Patterns (Java 21) adalah fitur yang memungkinkan destructuring langsung saat pattern matching dengan instanceof. Ini membuat kode yang memproses hierarki data jauh lebih ekspresif dan aman dari null.

Kode — PointTest.java
// PointTest.java
// Data Records yang digunakan
public record Point(int x, int y) {}
public record Line(Point start, Point end) {} // Record nested di dalam Record

// Method yang memproses objek berbeda tipe
public void printObject(Object object) {

    // ─── Record Pattern: Destructuring langsung di instanceof ─────────────
    // Tidak perlu: instanceof check → cast → akses field satu per satu
    // Langsung: instanceof + destructure semua field sekaligus!

    // Kasus 1: Jika object adalah Line → destructure langsung sampai ke Point
    if (object instanceof Line(Point(int startX, int startY), Point(int endX, int endY))) {
        // startX, startY, endX, endY LANGSUNG tersedia di sini!
        // Tidak perlu: ((Line)object).start().x() — itu sudah di-extract otomatis
        System.out.println(startX); // 0
        System.out.println(startY); // 0
        System.out.println(endX);   // 10
        System.out.println(endY);   // 10
    }

    // Kasus 2: Jika object adalah Point → destructure field x dan y
    else if (object instanceof Point(int x, int y)) {
        System.out.println(x); // langsung bisa dipakai!
        System.out.println(y);
    }

    else {
        System.out.println(object);
    }
}

@Test
void beforeRecordPatterns() {
    printObject(new Point(10, 10));
    // Output: 10, 10

    printObject(new Line(new Point(0, 0), new Point(10, 10)));
    // Output: 0, 0, 10, 10
}
Evolusi: Cara Lama vs Record Patterns
// ─── CARA LAMA (sebelum Record Patterns) — verbose ──────────────────────
if (object instanceof Line) {
    Line line = (Line) object;              // Cast manual
    Point start = line.start();             // Akses komponen
    Point end   = line.end();
    int startX  = start.x();               // Akses nested komponen
    int startY  = start.y();
    int endX    = end.x();
    int endY    = end.y();
    System.out.println(startX + ", " + startY);
    System.out.println(endX + ", " + endY);
}

// ─── CARA BARU (Java 21, Record Patterns) — ringkas ──────────────────────
if (object instanceof Line(Point(int startX, int startY), Point(int endX, int endY))) {
    System.out.println(startX + ", " + startY); // Langsung tersedia!
    System.out.println(endX + ", " + endY);
}
// Hemat 6 baris, tidak ada cast, tidak ada akses nested bertingkat,
// dan LEBIH AMAN: tidak ada ClassCastException yang mungkin
Bedah Sintaks Record Pattern
ElemenPenjelasan
object instanceof Point(int x, int y) Pengecekan tipe + destructuring sekaligus. Jika object adalah Point, variabel x dan y langsung tersedia dalam scope blok if. Jika bukan Point, blok dilewati.
Line(Point(int startX, int startY), Point(int endX, int endY)) Nested destructuring — Line punya dua komponen bertipe Point, dan masing-masing Point juga di-destructure. Ini bisa nested sedalam yang diperlukan selama semua tipe adalah Record.
Nama variabel bebas Nama variabel di dalam pattern (startX, startY) bebas ditentukan — tidak harus sama dengan nama komponen record. Yang penting urutan dan tipenya cocok.
✅ Record Patterns Bekerja dengan Switch Expression

Record Pattern juga bekerja dengan switch expression (Java 21 sealed class + switch) yang lebih powerful:

// Record Pattern dalam switch expression
String describe(Object shape) {
    return switch (shape) {
        case Point(int x, int y)
            -> "Titik di (%d, %d)".formatted(x, y);
        case Line(Point(int x1, int y1), Point(int x2, int y2))
            -> "Garis dari (%d,%d) ke (%d,%d)".formatted(x1, y1, x2, y2);
        default
            -> "Bentuk tidak dikenal: " + shape;
    };
}

System.out.println(describe(new Point(5, 10)));
// Output: Titik di (5, 10)

System.out.println(describe(new Line(new Point(0,0), new Point(10,10))));
// Output: Garis dari (0,0) ke (10,10)
🔗 Analogi PHP match + Destructuring

PHP tidak memiliki pattern matching bawaan yang sekuat Java. Padanan terdekat adalah kombinasi match(true) + instanceof + manual property access: match(true) { $obj instanceof Point => "{$obj->x}, {$obj->y}", ... }. Di Python ada match-case dengan structural pattern matching yang mirip: match point: case Point(x=x, y=y): print(x, y). Java 21 Record Patterns lebih powerful karena fully type-safe dan terintegrasi dengan compiler — jika tipe berubah, compiler langsung error.

🔍 Reflection & Keterbatasan Record

Java Reflection API mendapat dukungan khusus untuk Record — kamu bisa mengidentifikasi Record dan mengiterasi komponennya secara programatik. Di sisi lain, Record memiliki batasan yang sengaja dirancang untuk menjaga sifat immutable-nya.

Reflection pada Record
// CustomerTest.java
@Test
void reflection() {
    // Cek apakah sebuah class adalah Record
    assertTrue(Customer.class.isRecord()); // ✅ true untuk Record

    // Dapatkan semua komponen Record (bukan field biasa, tapi RecordComponent)
    RecordComponent[] components = Customer.class.getRecordComponents();
    assertEquals(4, components.length); // id, name, email, phone = 4 komponen

    for (RecordComponent component : components) {
        System.out.println(component.getName()); // "id", "name", "email", "phone"
        System.out.println(component.getType()); // class java.lang.String (x4)
        // Juga bisa: component.getAccessor() → Method objek accessor
        // component.getAnnotations() → semua annotation pada komponen
    }
}

Keterbatasan Record — Sengaja Dirancang
🚫
Tidak bisa extends class lain
Record sudah implisit extends java.lang.Record. Java tidak mendukung multiple inheritance untuk class. Solusi: gunakan interface untuk berbagi perilaku antar Record.
🚫
Tidak bisa tambah instance field di luar komponen
private String computed; di dalam body Record → compile error. Ini untuk menjaga konsistensi: semua "state" Record harus terlihat dari deklarasinya. Solusi: gunakan computed method (bukan field).
🚫
Selalu immutable — field tidak bisa diubah
Semua komponen bersifat final — tidak ada setter. Jika butuh "update" satu field, kamu harus buat Record baru. Solusi: buat method seperti withName(String name) yang mengembalikan Record baru dengan nilai yang diubah.
🚫
Tidak bisa abstract
abstract record Shape(...) → compile error. Record adalah final secara implisit — tidak bisa di-extend atau di-abstract. Solusi: gunakan sealed interface jika butuh hierarki tipe.
🚫
Inner Record harus static
Record yang dideklarasikan di dalam class otomatis static — tidak bisa mengakses instance dari enclosing class. Ini konsisten dengan sifat Record sebagai data carrier yang mandiri.
Pattern: Record dengan "Wither" Method

Karena Record immutable, untuk "mengubah" satu nilai, buat Record baru dengan nilai yang dimodifikasi:

public record Customer(String id, String name, String email, String phone) {

  // "Wither" method: mengembalikan Record baru dengan satu field berbeda
  public Customer withName(String newName) {
    return new Customer(this.id, newName, this.email, this.phone);
  }

  public Customer withEmail(String newEmail) {
    return new Customer(this.id, this.name, newEmail, this.phone);
  }
}

// Penggunaan
var original = new Customer("1", "Eko", "eko@test.com", null);
var updated  = original.withName("Budi").withEmail("budi@test.com");
// original tidak berubah — immutable!
System.out.println(original.name()); // "Eko" — tidak berubah
System.out.println(updated.name());  // "Budi" — Record baru
🔗 Analogi PHP Reflection

Di PHP, $rc = new ReflectionClass(Customer::class); $rc->getProperties(); untuk mengakses informasi class secara programatik. Java Reflection lebih powerful karena ada API khusus Record: getRecordComponents() yang langsung mengembalikan komponen sesuai urutan deklarasi, beserta informasi accessor dan annotation-nya. Framework seperti Jackson menggunakan ini untuk auto-serialisasi Record ke JSON tanpa konfigurasi tambahan.

📋 Peta Lengkap Java Record

Semua yang perlu kamu ketahui tentang Java Record dalam satu tampilan.

Ringkasan Semua Fitur Record
📦
Deklarasi & Auto-generation public record NamaRecord(TipeA namaA, TipeB namaB) {} — compiler otomatis membuat: field private final, canonical constructor, accessor method (namaA() bukan getNamaA()), equals(), hashCode(), toString().
🔧
Tiga Jenis Constructor 1. Canonical: parameter persis seperti deklarasi, untuk normalisasi. 2. Compact: tanpa parameter list, tanpa manual assignment — untuk validasi ringan. 3. Alternate: parameter lebih sedikit, wajib delegasi ke canonical via this(...) sebagai baris pertama.
⚙️
Method & Interface Record bisa tambahkan instance method, mengimplementasikan interface (implements SayHello), override accessor dan toString(). TIDAK BISA extends class lain — sudah extends java.lang.Record.
📌
Static Member Hanya static field dan static method yang diperbolehkan sebagai tambahan — instance field di luar komponen dilarang. Pola umum: public static final Point ZERO = new Point(0,0); dan factory method create().
🏷️
Generics & Annotation Record mendukung type parameter: record Data<T>(T data) {}. Annotation pada komponen dipropagasikan ke field, accessor method, dan parameter constructor — sesuai @Target annotation tersebut. Berguna untuk Jakarta Validation, Jackson, Hibernate.
🎯
Record Patterns (Java 21) Destructuring langsung di instanceof: if (obj instanceof Point(int x, int y)). Bisa nested: instanceof Line(Point(int x1, int y1), Point(int x2, int y2)). Juga bekerja di switch expression. Tidak perlu cast manual, tidak ada ClassCastException.
🔍
Reflection Class.isRecord() → cek apakah Record. Class.getRecordComponents() → array RecordComponent yang punya getName(), getType(), getAccessor(), getAnnotations(). Digunakan oleh framework Jackson, Spring, dll untuk auto-processing Record.

🏆 Checklist Penguasaan Java Record
  • ✅Paham mengapa Record ada: eliminasi boilerplate kelas data (field, constructor, getter, equals, hashCode, toString)
  • ✅Tahu bahwa accessor Record adalah nama() bukan getNama() — perbedaan dari JavaBean convention
  • ✅Bisa membuat Canonical Constructor untuk normalisasi data (lowercase, trim, null check)
  • ✅Bisa membuat Compact Constructor untuk validasi sederhana tanpa menulis manual assignment
  • ✅Tahu aturan Alternate Constructor: WAJIB panggil this(...) ke canonical sebagai baris pertama
  • ✅Record bisa implements interface dan tambahkan method instance
  • ✅Field tambahan dalam Record HARUS static (instance field di luar komponen dilarang)
  • ✅Record mendukung generics: record Data<T>(T data) {}
  • ✅Annotation pada komponen Record dipropagasikan sesuai @Target: ke field, accessor, dan/atau constructor parameter
  • ✅Bisa menggunakan Record Patterns untuk destructuring di instanceof (Java 21)
  • ✅Tahu API Reflection Record: isRecord(), getRecordComponents()
  • ✅Tahu pola "Wither" method untuk "mengubah" Record yang immutable — return Record baru
  • ✅Tahu kapan gunakan Record vs class biasa: Record untuk data carrier (DTO, value object, response), class biasa untuk entity dengan behavior kompleks
