Java Sealed Class untuk Developer PHP/Laravel

Sealed Class adalah fitur Java 17 yang memungkinkan kamu mengontrol secara eksplisit siapa saja yang boleh meng-extend atau mengimplementasi sebuah class/interface. Mirip konsep "restricted inheritance" — kamu menentukan daftar putih subclass yang diizinkan.

🧠 Masalah yang Dipecahkan Sealed Class

Sebelum Java 17, kamu hanya punya dua pilihan ekstrem:

final class ShapeTidak bisa di-extend sama sekali — terlalu ketat

Chapter 1

🔒 Sealed Class

Keyword sealed pada class diikuti permits yang berisi daftar class yang diizinkan untuk meng-extend-nya. Class lain di luar daftar akan mendapat compile error.

// Employee.java — Class induk yang di-seal
public sealed class Employee permits Manager {
  // Hanya class Manager yang boleh extends Employee.
  // Class lain yang coba extends Employee → COMPILE ERROR!

  private String id;
  private String name;

  public String getId()           { return id; }
  public void setId(String id)    { this.id = id; }
  public String getName()         { return name; }
  public void setName(String name){ this.name = name; }
}

// Manager.java — Satu-satunya yang boleh extends Employee
// WAJIB pilih salah satu: sealed / non-sealed / final
public non-sealed class Manager extends Employee {
  private String department;

  public String getDepartment()           { return department; }
  public void setDepartment(String dept)  { this.department = dept; }
}

// EmployeeTest.java
@Test
void employee() {
  var employee = new Employee(); // OK
}

@Test
void manager() {
  var manager = new Manager(); // OK
}
🚨 Class selain Manager yang coba extends Employee → Error! 
// Contoh di luar package yang sama:
public class Director extends Employee { // COMPILE ERROR!
  // java: class is not allowed to extend sealed class:
  // programmerzamannow.sealedclass.data.Employee
}
📐 Aturan Penting Sealed Class
AturanPenjelasan
Class permitted harus dalam package yang samaAtau modul yang sama (Java 9+ module system)
Class anak WAJIB pilih salah satu modifiersealed, non-sealed, atau final
permits bisa dihilangkanJika semua subclass ada di file yang sama, Java auto-detect
🟣 Analogi Laravel/PHP PHP tidak punya sealed class. Padanan terdekatnya adalah konvensi dokumentasi seperti @internal atau @final di PHPDoc — hanya peringatan, tidak di-enforce oleh compiler. Sealed class Java di-enforce saat compile: jika tidak ada di daftar permits, kode tidak bisa dikompilasi sama sekali. Ini jauh lebih kuat karena merupakan kontrak yang di-enforce secara teknis, bukan hanya konvensi tim.
🧠 Mini Quiz — Chapter 1

Jika Employee dideklarasikan sebagai sealed class Employee permits Manager, apa yang terjadi jika class Director mencoba extends Employee?

🅐 Runtime error saat program dijalankan
🅑 Compile error — Java langsung menolak saat kode dikompilasi
🅒 Tidak ada error, tapi Director tidak mendapat method dari Employee
Chapter 2

🔗 Sealed Interface

Sealed juga bisa diterapkan pada interface. Ini membatasi siapa saja yang boleh mengimplementasi interface tersebut — sangat berguna untuk membuat type hierarchy tertutup yang bisa dieksploitasi oleh pattern matching.

// SayHello.java — Sealed Interface
public sealed interface SayHello permits Human, Dog, Cat {
  String hello();
}

// Human.java — record yang implements SayHello
public record Human() implements SayHello {
  @Override
  public String hello() {
    return "hello";
  }
}

// Dog.java
public record Dog() implements SayHello {
  @Override
  public String hello() {
    return "guk";
  }
}

// Cat.java
public record Cat() implements SayHello {
  @Override
  public String hello() {
    return "meow";
  }
}
// Shape.java — Sealed Interface lain
public sealed interface Shape permits Circle, Rectangle, Triangle {
  Long area();
}

// Rectangle.java — final: tidak bisa di-extend lagi
public final class Rectangle implements Shape {
  @Override
  public Long area() {
    return null;
  }
}

// Circle.java — non-sealed: membuka inheritance ke siapa saja
public non-sealed class Circle implements Shape {
  @Override
  public Long area() {
    return null;
  }
}

// Triangle.java — non-sealed
public non-sealed class Triangle implements Shape {
  @Override
  public Long area() {
    return null;
  }
}
🌲 Hierarki Lengkap Contoh Kode
sealed interface SayHello permits Human, Dog, Cat
  ├── record Human() implements SayHello ✅
  ├── record Dog() implements SayHello ✅
  └── record Cat() implements SayHello ✅

sealed interface Shape permits Circle, Rectangle, Triangle
  ├── non-sealed class Circle implements Shape → siapa saja bisa extends Circle
  ├── final class Rectangle implements Shape → tidak bisa di-extend
  └── non-sealed class Triangle implements Shape

sealed class Employee permits Manager
  └── non-sealed class Manager extends Employee
      ├── class ManagerOther extends Manager ✅ (karena Manager non-sealed)
      └── final class ManagerTest extends Manager ✅
💡 Kenapa Sealed Interface + Pattern Matching adalah Kombinasi Killer? Karena compiler tahu semua kemungkinan implementasi dari sealed interface, switch expression (Java 21) bisa mendeteksi apakah semua kasus sudah ditangani — mirip exhaustive matching di Kotlin/Rust. Tidak perlu default jika semua permits sudah di-handle! 
// Pattern matching dengan sealed interface (Java 21)
String result = switch (sayHello) {
  case Human h -> "Manusia berkata: " + h.hello();
  case Dog d   -> "Anjing berkata: " + d.hello();
  case Cat c   -> "Kucing berkata: " + c.hello();
  // Tidak perlu default! Compiler tahu hanya ada 3 kemungkinan
};
🟣 Analogi Laravel/PHP Sealed interface seperti union type PHP 8 (Human|Dog|Cat) tapi dengan kontrol di sisi definisi type-nya, bukan hanya di parameter. Di PHP kamu bisa tulis function greet(Human|Dog|Cat $animal) untuk membatasi input, tapi di Java sealed interface membatasi siapa yang bisa jadi tipe itu sama sekali — lebih fundamental. Ini sangat berguna di domain modeling seperti DDD (Domain-Driven Design).
🧠 Mini Quiz — Chapter 2

Apa keuntungan menggunakan sealed interface dibanding interface biasa saat dipakai bersama switch expression di Java 21?

🅐 Switch jadi lebih cepat dieksekusi
🅑 Compiler bisa memvalidasi bahwa semua implementasi sudah di-handle — tidak perlu default dan tidak ada kasus yang terlewat
🅒 Interface sealed bisa punya method dengan body (default method)
Chapter 3A

🔓 Non-Sealed & Final — Dua Pilihan untuk Subclass

Setiap class yang di-permit oleh sealed class/interface wajib mendeklarasikan salah satu dari tiga modifier: sealed (lanjut restrict), non-sealed (buka kembali), atau final (tutup rapat).

🔓 non-sealed — Membuka Kembali
// Manager: non-sealed
// → siapa saja bisa extends Manager
public non-sealed class Manager
    extends Employee {
  private String department;
}

// ManagerOther & ManagerTest bisa
// extends Manager tanpa restrict!
public class ManagerOther
    extends Manager { }

public final class ManagerTest
    extends Manager { }
Gunakan kalau subclass dari kelas ini boleh bebas di-extend oleh siapa saja.
🔒 final — Tutup Rapat
// Rectangle: final
// → tidak bisa di-extend siapapun
public final class Rectangle
    implements Shape {
  @Override
  public Long area() {
    return null;
  }
}

// ERROR! Rectangle sudah final
public class Square
    extends Rectangle { }
// → COMPILE ERROR!
Gunakan kalau class ini sudah "sempurna" dan tidak perlu ada turunan lebih lanjut.
Modifier SubclassBisa di-extend lagi?Kapan Dipakai
sealed ... permits ...✅ Tapi hanya oleh yang di-permitHierarki multi-level yang tetap terkontrol
non-sealed✅ Oleh siapa sajaBagian dari hierarki yang ingin dibuka untuk extensi bebas
final❌ Tidak bisa sama sekaliLeaf node — class paling bawah, tidak perlu turunan
⚠️ Wajib Pilih Salah Satu! Class yang ada di daftar permits WAJIB memakai salah satu dari tiga modifier ini. Jika tidak ditulis, Java akan memberikan compile error. Ini memastikan setiap level hierarki punya keputusan eksplisit tentang extensibility-nya. 
// ERROR! Manager tidak punya modifier
public class Manager extends Employee { }
// → COMPILE ERROR: 'Manager' must have a modifier
// (sealed, non-sealed, or final)
🧠 Mini Quiz — Chapter 3A

Class Manager dideklarasikan non-sealed dan extend sealed class Employee. Lalu ManagerOther extends Manager tanpa modifier khusus. Apakah ini valid?

🅐 Valid — karena Manager sudah non-sealed, hierarki di bawahnya bebas seperti inheritance biasa
🅑 Tidak valid — semua class dalam hierarki harus pakai non-sealed juga
🅒 Tidak valid — hanya class yang di-permit Employee yang boleh ada
Chapter 3B

📦 Record + Sealed — Kombinasi Sempurna

Record (Java 16+) secara implisit adalah final — tidak bisa di-extend. Ini membuatnya sangat cocok sebagai anggota sealed interface karena memenuhi syarat "wajib pilih modifier" secara otomatis.

// SayHello.java — Sealed interface
public sealed interface SayHello permits Human, Dog, Cat {
  String hello();
}

// Human, Dog, Cat adalah RECORD yang implements SayHello
// Record secara implisit = final → tidak perlu tulis 'final' atau 'non-sealed'

public record Human() implements SayHello {
  @Override
  public String hello() { return "hello"; }
}

public record Dog() implements SayHello {
  @Override
  public String hello() { return "guk"; }
}

public record Cat() implements SayHello {
  @Override
  public String hello() { return "meow"; }
}

// Penggunaan
SayHello animal = new Dog();
System.out.println(animal.hello()); // "guk"

// Pattern matching (Java 21) dengan exhaustive check
String suara = switch (animal) {
  case Human h -> h.hello(); // "hello"
  case Dog d   -> d.hello(); // "guk"
  case Cat c   -> c.hello(); // "meow"
  // Tidak perlu default — compiler tahu semua kasus tercakup!
};
💡 Record = Implicitly Final
  • Record tidak bisa di-extend (selalu final)
  • Record otomatis generate: constructor, getter, equals(), hashCode(), toString()
  • Ideal sebagai data carrier dalam sealed hierarchy — misal: Result type, ADT (Algebraic Data Type)
🟣 Analogi Laravel/PHP Kombinasi sealed interface + record sangat mirip dengan pola PHP Enum dengan interface (PHP 8.1+). Misalnya: interface Animal { public function sound(): string; } lalu enum Pet: string implements Animal { case Dog = 'guk'; }. Bedanya, sealed + record jauh lebih fleksibel — bisa punya data berbeda di setiap implementasi (tidak hanya nilai enum sederhana).
🧠 Mini Quiz — Chapter 3B

Mengapa record tidak perlu mendeklarasikan modifier final secara eksplisit saat menjadi anggota sealed interface?

🅐 Karena record tidak bisa implement interface
🅑 Karena record secara implisit sudah final — ini memenuhi syarat wajib memilih modifier untuk subclass sealed
🅒 Karena compiler Java mengecualikan record dari aturan sealed
Chapter 3C

🔍 Reflection API untuk Sealed Class

Java Reflection API mendukung sealed class — kamu bisa memeriksa secara programatik apakah sebuah class/interface sealed, dan mendapatkan daftar subclass yang di-permit.

// SayHelloTest.java
class SayHelloTest {

  @Test
  void reflection() {
    // Cek apakah SayHello adalah sealed interface
    assertTrue(SayHello.class.isSealed()); // true

    // Dapatkan semua subclass yang di-permit
    Class<?>[] subclasses = SayHello.class.getPermittedSubclasses();
    assertEquals(3, subclasses.length); // Human, Dog, Cat

    // Verifikasi urutan sesuai deklarasi 'permits'
    assertEquals(Human.class, subclasses[0]);
    assertEquals(Dog.class,   subclasses[1]);
    assertEquals(Cat.class,   subclasses[2]);
  }
}
Method ReflectionReturnDeskripsi
Class.isSealed()booleanCek apakah class/interface ini sealed
Class.getPermittedSubclasses()Class<?>[]Dapatkan semua class yang di-permit (dalam urutan deklarasi)
💡 Kapan Reflection Sealed Berguna? Framework dan library bisa menggunakan ini untuk auto-discovery. Misalnya: serialization library bisa otomatis tahu semua subtipe dari sealed class dan mendaftarkan deserializer-nya — tanpa konfigurasi manual. Spring dan Jackson sudah mulai memanfaatkan ini untuk polymorphic JSON serialization.
🧠 Mini Quiz — Chapter 3C

Apa yang dikembalikan oleh SayHello.class.getPermittedSubclasses() jika SayHello adalah sealed interface ... permits Human, Dog, Cat?

🅐 Mengembalikan semua class yang mengimplementasi SayHello di runtime
🅑 Mengembalikan array [Human.class, Dog.class, Cat.class] — persis sesuai urutan di permits
🅒 Mengembalikan null karena interface tidak punya subclass
Final Chapter

📝 Summary — Sealed Class Cheat Sheet

Sealed Class adalah fitur kecil tapi sangat powerful untuk domain modeling yang eksplisit dan aman.

⚡ Cheat Sheet Lengkap
// ✅ SEALED CLASS — hanya class di permits yang boleh extend
public sealed class Shape permits Circle, Rectangle, Triangle { }

// ✅ SEALED INTERFACE — hanya class di permits yang boleh implement
public sealed interface SayHello permits Human, Dog, Cat { }

// ✅ Subclass WAJIB pilih salah satu:

// 1. final → tidak bisa di-extend sama sekali
public final class Rectangle implements Shape { }

// 2. non-sealed → membuka kembali inheritance bebas
public non-sealed class Circle implements Shape { }
public class SubCircle extends Circle { } // valid!

// 3. sealed → lanjutkan restrict ke level berikutnya
public sealed class Circle implements Shape permits FilledCircle { }

// ✅ Record → implicitly final, cocok sebagai permitted subclass
public record Human() implements SayHello { }

// ✅ Reflection API
SayHello.class.isSealed();               // true
SayHello.class.getPermittedSubclasses(); // [Human, Dog, Cat]
🧠 Kapan Pakai Sealed Class?
✅
Domain modeling yang tertutup. Misalnya: sealed interface PaymentMethod permits CreditCard, BankTransfer, Wallet — kamu tahu semua metode pembayaran yang didukung sistem.
✅
Result/Error type. sealed interface Result permits Success, Failure — mirip Either di Haskell atau Result di Rust. Tidak ada kasus yang terlewat.
✅
State machine. Setiap state sebagai sealed subclass — compiler memastikan semua state di-handle di switch expression.
❌
Jangan pakai untuk extensibility yang memang terbuka. Kalau kamu ingin orang lain bisa extend class-mu dari library/project berbeda, jangan seal — gunakan interface biasa atau abstract class.
