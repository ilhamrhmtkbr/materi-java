☕ Belajar Java IO

Dari PHP/Laravel ke Java — step by step, tanpa ribet. Kita pelajari cara Java baca & tulis file, dan kenapa cara kerjanya berbeda dari PHP.

Apa itu Java IO?

Di PHP kamu biasa pakai fungsi seperti file_get_contents(), fopen(), fwrite(). Di Java, konsepnya sama tapi dibalut dalam object-oriented API yang lebih terstruktur.

🧠 Mindset Utama Di PHP, fungsi IO bisa langsung dipanggil global. Di Java, semuanya adalah objek. Kamu buat objek stream, gunakan, lalu tutup. Ini lebih verbose tapi lebih aman dan lebih mudah di-test.

Chapter 1
📁 Path & File API

Sebelum bisa baca/tulis file, kamu perlu tahu cara Java merepresentasikan lokasi file. Ada dua cara: cara lama (File) dan cara modern (Path).

📄 Cara Lama: Class File
// FileTest.java
File file = new File("file.txt");           // Line 1
Assertions.assertEquals("file.txt", file.getName());  // Line 2
Assertions.assertFalse(file.exists());                 // Line 3

File file2 = new File("src/main/resources/application.properties");  // Line 4
Assertions.assertTrue(file2.exists());                               // Line 5
Line 1new File("file.txt") — Buat objek yang merepresentasikan path file. PERHATIAN: ini belum membuat file di disk! Ini cuma "alamat".
Line 2file.getName() — ambil nama file saja (tanpa direktori).
Line 3file.exists() — cek apakah file benar-benar ada di disk. File "file.txt" belum ada, jadi false.
Line 4Path bisa juga menyertakan direktori. Karakter pemisah direktori di sini pakai / yang aman di semua OS.
Line 5application.properties sudah ada karena dibuat Spring Boot, jadi exists() = true.
✨ Cara Modern: Class Path + Files

Sejak Java 7, ada NIO2 (New IO 2) yang lebih powerful. Gunakan ini untuk kode baru!

// PathTest.java
Path path = Path.of("file.txt");           // Line 1
Assertions.assertEquals("file.txt", path.toString());  // Line 2
Assertions.assertFalse(path.isAbsolute()); // Line 3

Path path2 = Path.of("pom.xml");
Assertions.assertTrue(Files.exists(path2)); // Line 4
Line 1Path.of("file.txt") — cara modern buat representasi path. Lebih bersih dari new File().
Line 2path.toString() — kembalikan path sebagai String.
Line 3isAbsolute() — path relatif (tidak dimulai dari root/drive). Di PHP ini seperti membedakan ./file.txt vs /var/www/file.txt.
Line 4Files.exists(path) — class Files adalah utility class untuk operasi file. Semua method-nya static.
🗂️ Membuat & Menghapus File/Direktori
// FileManipulationTest.java
Path path = Path.of("file.txt");
Files.createFile(path);                     // Line 1
Assertions.assertTrue(Files.exists(path));  // Line 2
Files.delete(path);                         // Line 3
Assertions.assertFalse(Files.exists(path)); // Line 4

// Buat direktori
Path dir = Path.of("contoh");
Files.createDirectory(dir);                  // Line 5
Assertions.assertTrue(Files.isDirectory(dir)); // Line 6
Files.delete(dir);                           // Line 7
Line 1Files.createFile(path) — benar-benar buat file kosong di disk. Seperti touch file.txt di terminal atau fopen($path, 'w') di PHP.
Line 2Setelah dibuat, exists() = true.
Line 3Files.delete(path) — hapus file. Jika file tidak ada, akan throw exception.
Line 5Files.createDirectory() — buat satu direktori. Kalau mau buat nested direktori sekaligus, pakai Files.createDirectories().
Line 6Files.isDirectory(path) — cek apakah path adalah direktori (bukan file).
🐘
Analogi Laravel/PHP
Path.of("file.txt") itu seperti string path di PHP — hanya representasi. Files.createFile() itu seperti Storage::put() di Laravel. Class Files (static utility) itu seperti Storage facade di Laravel.

Chapter 2
🔒 Closeable & Try-with-Resources

Ini salah satu konsep paling penting di Java IO. Stream harus selalu ditutup setelah digunakan, karena jika tidak, akan terjadi resource leak (memori/file handle bocor).

❌ Cara Lama (verbose & rawan bug)
// ClosableTest.java — cara lama
Path path = Path.of("pom.xml");
InputStream inputStream = null;                     // Line 1
try {
    inputStream = Files.newInputStream(path);        // Line 2
    // lakukan operasi...
} catch (IOException exception) {
    Assertions.fail(exception);                      // Line 3
} finally {
    if (inputStream != null) {                       // Line 4
        try {
            inputStream.close();                     // Line 5
        } catch (IOException e) {
            Assertions.fail(e);
        }
    }
}
Line 1Deklarasi di luar try agar bisa diakses di blok finally.
Line 2Buka stream — bisa throw IOException.
Line 3Assertions.fail() dipakai di unit test untuk menandai test gagal jika ada exception.
Line 4-5Harus cek null dulu sebelum close, karena mungkin stream tidak pernah berhasil dibuka. Lalu close juga bisa throw exception! Ini sudah sangat ribet.
✅ Cara Modern: Try-with-Resources (WAJIB PAKAI INI!)
// ClosableTest.java — cara modern
Path path = Path.of("pom.xml");
try (InputStream inputStream = Files.newInputStream(path);     // Line 1
     InputStream inputStream2 = Files.newInputStream(path);    // Line 2
     InputStream inputStream3 = Files.newInputStream(path)) {  // Line 3
    // lakukan apapun dengan input stream
} catch (IOException exception) {
    Assertions.fail(exception);   // Line 4
}
// Semua stream otomatis di-close di sini!
Line 1-3Deklarasi resource di dalam tanda kurung try(...). Bisa deklarasi banyak resource sekaligus, dipisah titik koma.
OtomatisJava akan otomatis memanggil .close() untuk semua resource — bahkan jika ada exception. Urutannya terbalik (stream3 ditutup duluan, lalu stream2, lalu stream1).
Line 4Catch tetap ada untuk menangani exception dari operasi IO.
💡 Kenapa ini bisa bekerja? Semua class IO di Java mengimplementasikan interface AutoCloseable (atau Closeable). Try-with-resources bekerja dengan interface ini. Siapapun yang implement AutoCloseable bisa dipakai di try-with-resources.
⚠️ Common Mistake
❌ Salah
InputStream stream = Files.newInputStream(path);
// lupa close!
// resource leak terjadi
✅ Benar
try (InputStream stream = Files.newInputStream(path)) {
// otomatis close
}
🐘
Analogi PHP
Di PHP kamu juga perlu fclose($handle) setelah selesai. Tapi PHP sering "dimaafkan" karena script-nya short-lived. Di Java yang berjalan terus-menerus (server), lupa close = memory/file leak yang serius. Try-with-resources adalah solusinya.

Chapter 3
📥 InputStream — Baca Data Byte

InputStream dipakai untuk membaca data dalam format byte (binary). Cocok untuk gambar, PDF, file biner, atau teks yang ingin dibaca secara low-level.

Cara 1: Baca Satu Byte Sekaligus (lambat)
// InputStreamTest.java
Path path = Path.of("pom.xml");
try (InputStream stream = Files.newInputStream(path)) {   // Line 1
    StringBuilder builder = new StringBuilder();           // Line 2
    int data;                                             // Line 3
    while ((data = stream.read()) != -1) {                // Line 4
        builder.append((char) data);                       // Line 5
    }
    System.out.println(builder.toString());
}
Line 1Buka stream ke file pom.xml. Gunakan try-with-resources agar otomatis close.
Line 2StringBuilder dipakai untuk membangun string secara efisien. Lebih baik dari String += di loop.
Line 3Tipe int, bukan byte! Karena stream.read() return int 0-255, atau -1 jika end of file.
Line 4Loop selama masih ada data. -1 = tanda EOF (End Of File).
Line 5Cast int ke char untuk ubah byte ke karakter teks.
⚠️ Kenapa tipe-nya int bukan byte? byte di Java adalah -128 sampai 127. Tapi stream.read() perlu bisa return nilai -1 sebagai sinyal EOF, yang tidak muat di byte. Makanya dipakai int (0-255 untuk data valid, -1 untuk EOF).
Cara 2: Baca Buffer (jauh lebih cepat!)
// InputStreamTest.java — readBytes
try (InputStream stream = Files.newInputStream(path)) {
    StringBuilder builder = new StringBuilder();
    byte[] bytes = new byte[1024];          // Line 1 — buffer 1KB
    int length;
    while ((length = stream.read(bytes)) != -1) {  // Line 2
        builder.append(new String(bytes, 0, length));  // Line 3
    }
    System.out.println(builder.toString());
}
Line 1Alokasi buffer 1024 byte (1 KB). Tiap iterasi, stream mengisi array ini.
Line 2stream.read(bytes) — baca data sebanyak mungkin ke dalam buffer, return jumlah byte yang berhasil dibaca.
Line 3new String(bytes, 0, length) — penting! Jangan pakai new String(bytes) saja, karena byte terakhir mungkin tidak penuh. Pakai 0, length untuk baca hanya yang valid.
⚠️ Common Mistake
❌ Salah
builder.append(new String(bytes));
// Ikut serta "sampah" di akhir buffer
✅ Benar
builder.append(new String(bytes, 0, length));
// Hanya baca yang valid
🐘
Analogi PHP
stream.read() per byte = fgetc($handle)
stream.read(bytes) dengan buffer = fread($handle, 1024)
  • Selalu pakai buffer untuk file besar — jauh lebih cepat dari baca 1 byte sekaligus
  • Ukuran buffer 4096 atau 8192 byte biasanya optimal untuk I/O file
  • InputStream cocok untuk data binary (gambar, audio), untuk teks lebih baik pakai Reader

Chapter 4
📤 OutputStream — Tulis Data Byte

Kebalikan dari InputStream. Dipakai untuk menulis data byte ke file atau tujuan lainnya.

// OutputStreamTest.java
Path path = Path.of("output.txt");
try (OutputStream stream = Files.newOutputStream(path)) {  // Line 1
    for (int i = 0; i < 100; i++) {
        stream.write("Hello World\n".getBytes());  // Line 2
        stream.flush();                             // Line 3
    }
}
Line 1Files.newOutputStream(path) — buka file untuk menulis. Jika file tidak ada, dibuat baru. Jika sudah ada, isinya ditimpa!
Line 2"Hello World\n".getBytes() — konversi String ke array byte. Method write() menerima array byte.
Line 3stream.flush() — paksa data yang ada di buffer untuk benar-benar ditulis ke disk. Tanpa flush, data mungkin masih di memori buffer.
💡 Apa itu buffer & kenapa perlu flush? Stream sering menggunakan buffer internal untuk efisiensi — data dikumpulkan di memori dulu, baru ditulis ke disk sekaligus. flush() memaksa penulisan sekarang. Saat menggunakan try-with-resources, close() juga otomatis memanggil flush().
🐘
Analogi PHP
Files.newOutputStream(path) = fopen($path, 'w')
stream.write(data) = fwrite($handle, $data)
stream.flush() = fflush($handle)
🧠 Mini Quiz — OutputStream

Apa yang terjadi jika kamu buka file yang sudah ada menggunakan Files.newOutputStream(path) tanpa option tambahan?

Chapter 5
📝 Reader & Writer — IO Berbasis Karakter

InputStream/OutputStream bekerja dengan byte. Reader/Writer bekerja dengan karakter (text). Ini lebih cocok untuk membaca/menulis file teks karena menangani encoding (UTF-8, dll) secara otomatis.

Reader — Baca File Teks
// ReaderTest.java
Path path = Path.of("output.txt");
try (Reader reader = Files.newBufferedReader(path)) {  // Line 1
    StringBuilder builder = new StringBuilder();
    int character;
    while ((character = reader.read()) != -1) {         // Line 2
        builder.append((char) character);
    }
    System.out.println(builder.toString());
}
Line 1Files.newBufferedReader(path) — buka file sebagai BufferedReader (sudah ada buffering-nya). Otomatis pakai encoding default sistem (biasanya UTF-8).
Line 2Mirip InputStream tapi membaca per karakter, bukan per byte. Ini penting untuk karakter multi-byte (emoji, aksara Asia).
Baca Chunks (lebih efisien)
// ReaderTest.java — readChars
try (Reader reader = Files.newBufferedReader(path)) {
    StringBuilder builder = new StringBuilder();
    char[] chars = new char[1024];              // Line 1
    int length;
    while ((length = reader.read(chars)) != -1) {  // Line 2
        builder.append(chars, 0, length);           // Line 3
    }
}
Line 1Buffer array of char (bukan byte!) sebesar 1024 karakter.
Line 2Baca banyak karakter sekaligus ke buffer, return jumlah karakter yang dibaca.
Line 3Append ke StringBuilder, hanya sebanyak yang dibaca (0, length).
Writer — Tulis File Teks
// WriterTest.java
Path path = Path.of("writer.txt");
try (Writer writer = Files.newBufferedWriter(path)) {  // Line 1
    for (int i = 0; i < 100; i++) {
        writer.write("Hello World\n");  // Line 2
        writer.flush();
    }
}
Line 1Files.newBufferedWriter(path) — buka file untuk menulis teks. Langsung bisa terima String, tidak perlu konversi ke byte.
Line 2writer.write(String) — tulis String langsung, tanpa .getBytes(). Ini keunggulan Writer vs OutputStream.
AspekInputStream/OutputStreamReader/Writer
Unit databyte (0-255)char (Unicode)
EncodingManual (getBytes)Otomatis
Cocok untukBinary (gambar, PDF)Text (txt, csv, json)
Class utamaInputStream, OutputStreamReader, Writer

Chapter 6
🔍 Scanner — Baca Input Baris per Baris

Scanner adalah class high-level yang bisa membaca dari berbagai sumber (file, System.in, String) dengan cara yang mudah — bisa baca per token, per baris, per angka, dll.

Baca Input dari User (keyboard)
// InputApp.java
Scanner scanner = new Scanner(System.in);        // Line 1

System.out.print("Masukkan nama: ");
String name = scanner.nextLine();                // Line 2

System.out.println("Halo " + name);             // Line 3
Line 1new Scanner(System.in) — System.in adalah InputStream dari keyboard. Scanner membungkusnya agar mudah dibaca. System.in di Java = STDIN di PHP.
Line 2scanner.nextLine() — baca satu baris hingga Enter ditekan. Ada juga: nextInt(), nextDouble(), next() (per kata).
Line 3Konkatenasi string dengan + — sama seperti PHP.
Baca File dengan Scanner
// ScannerTest.java
Path path = Path.of("print.txt");
try (InputStream stream = Files.newInputStream(path);
     Scanner scanner = new Scanner(stream)) {    // Line 1

    while (scanner.hasNextLine()) {              // Line 2
        String line = scanner.nextLine();        // Line 3
        System.out.println(line);
    }
}
Line 1Scanner bisa menerima InputStream sebagai input. Scanner implements Closeable jadi bisa dipakai di try-with-resources.
Line 2scanner.hasNextLine() — cek apakah masih ada baris berikutnya. Seperti !feof($handle) di PHP.
Line 3scanner.nextLine() — baca satu baris (tanpa newline di akhir).
💡 Kapan pakai Scanner vs BufferedReader? Scanner lebih mudah dan fleksibel (bisa parse int, double langsung). BufferedReader lebih cepat untuk file teks besar. Untuk input user, Scanner lebih umum dipakai.

Chapter 7
🖨️ PrintStream — Output yang Ramah

PrintStream adalah OutputStream yang ditambahkan kemampuan print teks dengan mudah. Kamu sudah sering pakai ini tanpa sadar!

// PrintStreamTest.java

// System.out ADALAH PrintStream!
PrintStream stream = System.out;    // Line 1
stream.println("Hello World");      // Line 2
stream.println("Hello World");
stream.println("Hello World");
Line 1System.out yang kamu pakai setiap hari adalah instance dari PrintStream! Ini menulis ke console/terminal.
Line 2println() — print + newline otomatis. Ada juga print() (tanpa newline) dan printf() (format string).
PrintStream ke File
// PrintStreamTest.java
Path path = Path.of("print.txt");
try (OutputStream outputStream = Files.newOutputStream(path);
     PrintStream stream = new PrintStream(outputStream)) {  // Line 1

    stream.println("Hello World");  // Line 2
    stream.println("Hello World");
    stream.println("Hello World");
}
Line 1new PrintStream(outputStream) — bungkus OutputStream dengan PrintStream. Ini pola Decorator Pattern — PrintStream menambahkan fitur print ke OutputStream biasa.
Line 2Sekarang bisa pakai println() untuk nulis ke file, sama seperti nulis ke console.
💡 Insight: Decorator Pattern Java IO banyak menggunakan Decorator Pattern — class seperti PrintStream, BufferedOutputStream, ObjectOutputStream membungkus stream lain untuk menambah fitur. Ini kenapa kamu sering lihat new SomeStream(otherStream).

Chapter 8
⚡ Small File Utilities — Baca/Tulis Singkat

Kalau file kecil dan mau baca/tulis sekaligus, gak perlu repot buka/tutup stream. Class Files punya shortcut yang sangat mudah!

// SmallFileTest.java

// TULIS file kecil
Path path1 = Path.of("small1.txt");
byte[] bytes = "Hello World".getBytes();
Files.write(path1, bytes);                // Line 1 — tulis dari byte[]

Path path2 = Path.of("small2.txt");
Files.writeString(path2, "Hello World"); // Line 2 — tulis dari String (lebih mudah!)

// BACA file kecil
byte[] readBytes = Files.readAllBytes(path1);      // Line 3
String content1 = new String(readBytes);

String content2 = Files.readString(path2);         // Line 4 — paling simpel!
Line 1Files.write(path, bytes) — tulis array byte ke file sekaligus. File dibuat jika belum ada.
Line 2Files.writeString(path, string) — tulis String langsung. Paling mudah untuk file teks.
Line 3Files.readAllBytes(path) — baca seluruh isi file sebagai byte[]. Hati-hati untuk file besar!
Line 4Files.readString(path) — baca seluruh isi file sebagai String. Paling simple untuk file teks kecil.
⚠️ Kapan JANGAN pakai ini? readAllBytes() dan readString() membaca seluruh file ke memori. Untuk file kecil (< beberapa MB), fine. Untuk file besar (log file, dump database), gunakan InputStream/Reader dengan buffer!
🐘
Analogi PHP
Files.readString(path) = file_get_contents($path)
Files.writeString(path, str) = file_put_contents($path, $str)
Sama persis! Dan sama-sama tidak cocok untuk file sangat besar.

Chapter 9
🔧 Open Options — Kontrol Cara Buka File

StandardOpenOption adalah enum yang mengontrol perilaku saat membuka file — apakah ditimpa? ditambahkan? dibuat baru?

// OpenOptionTest.java
Path path = Path.of("append.txt");
try (Writer writer = Files.newBufferedWriter(path,
        StandardOpenOption.CREATE,    // Line 1
        StandardOpenOption.APPEND)) { // Line 2

    writer.write("Hello World\n");
    writer.flush();
}
Line 1StandardOpenOption.CREATE — buat file jika belum ada. Jika sudah ada, lanjutkan.
Line 2StandardOpenOption.APPEND — data baru ditambahkan di akhir file, bukan menimpa. Tiap kali test ini dijalankan, "Hello World" ditambahkan.
OptionEfekAnalogi PHP
CREATEBuat file jika belum adafopen('a'), fopen('w')
CREATE_NEWError jika file sudah adafopen('x')
APPENDTambah di akhir filefopen('a')
TRUNCATE_EXISTINGKosongkan file dulu (default)fopen('w')
READBuka untuk bacafopen('r')
WRITEBuka untuk tulisfopen('w')
🐘
Analogi PHP
Di PHP kamu pakai mode string di fopen() seperti 'r', 'w', 'a', 'x'. Di Java, ini digantikan dengan enum StandardOpenOption yang lebih eksplisit dan bisa dikombinasikan.

Chapter 10
💾 Memory Stream — IO di Memori

Tidak semua IO harus ke file! StringWriter dan ByteArrayOutputStream memungkinkan kamu "menulis" ke memori, lalu ambil hasilnya sebagai String atau byte array.

// MemoryStreamTest.java
StringWriter writer = new StringWriter();          // Line 1
for (int i = 0; i < 10; i++) {
    writer.write("Hello World\n");                 // Line 2
}

String content = writer.getBuffer().toString();    // Line 3
System.out.println(content);
Line 1new StringWriter() — buat Writer yang menulis ke memori (bukan ke file). Tidak perlu close! Tidak ada resource fisik yang dibuka.
Line 2Tulis ke "memori" persis seperti menulis ke file biasa.
Line 3writer.getBuffer().toString() — ambil semua yang sudah ditulis sebagai String.
💡 Kapan Memory Stream berguna?
  • Membangun string dinamis yang panjang secara efisien
  • Testing — mock output tanpa perlu file sungguhan
  • Menangkap output dari library yang menulis ke Stream
  • Membangun response HTTP dari berbagai sumber sebelum dikirim
🐘
Analogi PHP
StringWriter mirip dengan ob_start() di PHP — kamu "menangkap" output ke buffer memori, lalu ambil hasilnya dengan ob_get_clean().

Chapter 11
📦 Object Serialization — Simpan Objek ke File

Serialisasi adalah proses mengubah objek Java menjadi stream byte agar bisa disimpan ke file atau dikirim via network. Deserialisasi adalah kebalikannya.

Step 1: Buat Class yang Bisa Diserialisasi
// Person.java
public class Person implements Serializable {           // Line 1

    public static final long serialVersionUID = 1L;    // Line 2

    private String id;
    private String name;

    // getter & setter...
}
Line 1implements Serializable — "menandai" class ini boleh di-serialize. Interface ini tidak punya method apapun (marker interface). Tanpa ini, akan throw NotSerializableException.
Line 2serialVersionUID — "version ID" untuk class. Saat deserialisasi, Java memeriksa apakah UID yang tersimpan di file cocok dengan class saat ini. Jika tidak cocok, gagal. Ini penting saat class berubah.
Step 2: Simpan Objek ke File
// ObjectStreamTest.java — savePerson
Person person = new Person();
person.setId("1");
person.setName("Eko");

Path path = Path.of("eko.person");
try (OutputStream stream = Files.newOutputStream(path);
     ObjectOutputStream objectOutputStream = new ObjectOutputStream(stream)) {  // Line 1

    objectOutputStream.writeObject(person);  // Line 2
    objectOutputStream.flush();
}
Line 1new ObjectOutputStream(stream) — lagi-lagi Decorator Pattern! Membungkus OutputStream biasa dengan kemampuan serialize objek.
Line 2writeObject(person) — konversi objek Person menjadi byte dan tulis ke stream. Semua field (id, name) ikut tersimpan.
Step 3: Baca Kembali Objek dari File
// ObjectStreamTest.java — getPerson
Path path = Path.of("eko.person");
try (InputStream stream = Files.newInputStream(path);
     ObjectInputStream objectInputStream = new ObjectInputStream(stream)) {

    Person person = (Person) objectInputStream.readObject();  // Line 1

    Assertions.assertEquals("1", person.getId());
    Assertions.assertEquals("Eko", person.getName());
} catch (IOException | ClassNotFoundException exception) {    // Line 2
    Assertions.fail(exception);
}
Line 1readObject() return tipe Object, jadi harus di-cast ke Person. Ini karena Java butuh tahu tipe spesifiknya saat compile time.
Line 2Catch dua jenis exception: IOException (masalah IO) dan ClassNotFoundException (class Person tidak ditemukan saat deserialisasi). Ini multi-catch dengan |.
⚠️ Peringatan Keamanan Serialisasi Java Serialization memiliki risiko keamanan — jangan deserialisasi data dari sumber yang tidak dipercaya! Di aplikasi modern, lebih baik gunakan JSON (Jackson/Gson) atau protobuf untuk menyimpan/transfer data objek.

Summary
✅ Rangkuman Java IO
1
📁 Path & File
Gunakan Path.of() dan Files.* (NIO2) untuk semua operasi file. Lebih modern dari class File lama.
2
🔒 Try-with-Resources
SELALU gunakan try-with-resources untuk stream. Ini memastikan stream ditutup otomatis dan mencegah resource leak.
3
📥📤 InputStream & OutputStream
Untuk data binary. Baca/tulis dalam bentuk byte. Gunakan buffer array untuk performa optimal.
4
📝 Reader & Writer
Untuk data teks. Menangani encoding (UTF-8) secara otomatis. Lebih mudah dari InputStream/OutputStream untuk file teks.
5
🔍 Scanner
High-level reader yang bisa parse token, baris, angka. Cocok untuk input user (System.in) dan membaca file terstruktur.
6
⚡ Small File Utils
Files.readString() dan Files.writeString() untuk file kecil. Seperti file_get_contents() dan file_put_contents() di PHP.
7
🔧 Open Options
Gunakan StandardOpenOption untuk kontrol detail: CREATE, APPEND, TRUNCATE_EXISTING, dll.
8
📦 Serialization
Implement Serializable untuk simpan objek ke file. Di aplikasi modern, pertimbangkan JSON sebagai alternatif yang lebih aman.
9
🧩 Decorator Pattern di IO
Java IO menggunakan Decorator Pattern — stream dibungkus stream lain untuk menambah fitur. Contoh: new ObjectOutputStream(new BufferedOutputStream(stream)).
