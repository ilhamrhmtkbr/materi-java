☕ Java CSV Course

☕ Belajar Java CSV

Modul pembelajaran interaktif untuk developer PHP / Laravel yang migrasi ke Java & Spring Boot.
Materi: Apache Commons CSV — membuat, membaca, dan memformat file CSV dengan benar.

Java 17+ Spring Boot Apache Commons CSV JUnit 5 Untuk ex-Laravel Dev

Selamat datang! Sebelum masuk ke kode, ada beberapa perbedaan mindset fundamental antara Java dan PHP yang wajib kamu pahami terlebih dahulu.

Di PHP/Laravel, kamu bisa menulis:

// PHP — tidak ada type check saat "compile"
$nama = "Eko";
$nama = 42; // valid! PHP tidak protes

Di Java, setiap variabel harus punya tipe data yang dideklarasikan secara eksplisit. Tipe itu tidak bisa berubah:

// Java — strongly-typed
String nama = "Eko";
nama = 42; // ERROR! compiler menolak sebelum kode dijalankan

Keuntungannya: bug tipe data terdeteksi saat kompilasi, bukan saat aplikasi sudah live di production. Ini yang disebut "fail fast".

PHP diinterpretasi langsung — server membaca file .php baris per baris saat request masuk. Java dikompilasi lebih dulu menjadi bytecode (.class), lalu dieksekusi oleh JVM (Java Virtual Machine). Proses build di Spring Boot (Maven / Gradle) mirip seperti menjalankan composer install + php artisan optimize digabung menjadi satu langkah wajib.

Di Java, ada konsep Checked Exception — error yang secara tipe sistem dipaksakan untuk kamu tangani. Ketika kamu membuka file, Java "memaksa" kamu mendeklarasikan throws IOException atau menambahkan try-catch. Di PHP, exception bisa kamu abaikan begitu saja (sampai server error 500). Java membuatnya eksplisit agar tidak ada "silent failure".

Maven, Spring Boot, dan struktur project

Library open-source dari Apache untuk membaca dan menulis CSV. Mirip seperti package league/csv di ekosistem PHP — kamu tidak perlu membuat parser CSV sendiri dari nol.

Chapter 02
✍️ Menulis CSV Dasar
CSVPrinter, StringWriter, dan CSVFormat.DEFAULT

Langkah pertama yang paling fundamental: membuat (menulis) data CSV. Kita mulai tanpa header terlebih dahulu agar kamu mengerti mekanisme dasarnya.

Kode: createCSV()
@Test
void createCSV() throws IOException {
    StringWriter writer = new StringWriter();              // (1)

    CSVPrinter printer = new CSVPrinter(writer, CSVFormat.DEFAULT); // (2)
    printer.printRecord("Eko", "Khannedy", 100);          // (3)
    printer.printRecord("Budi", "Nugraha", 95);           // (4)
    printer.flush();                                       // (5)

    String csv = writer.getBuffer().toString();             // (6)
    System.out.println(csv);
}
Penjelasan Baris per Baris
(1) StringWriter StringWriter adalah buffer di memory (RAM) — bukan file di disk. Ini seperti ob_start() di PHP: kamu "menangkap" output ke dalam string, bukan langsung mencetak ke layar atau file. Berguna untuk testing atau ketika kamu ingin memanipulasi string CSV sebelum disimpan.
(2) CSVPrinter CSVPrinter adalah engine penulis CSV. Ia membutuhkan dua hal: tujuan output (si writer) dan format CSV (CSVFormat.DEFAULT). CSVFormat.DEFAULT artinya menggunakan koma sebagai pemisah kolom dan mengikuti standar RFC 4180.
(3-4) printRecord() Menulis SATU baris record CSV. Setiap argumen yang dipisah koma menjadi satu kolom. Java menerima tipe data campuran (String dan int) karena method ini menerima Object... (varargs). Output baris (3): Eko,Khannedy,100
(5) flush() Krusial. Java menggunakan buffer I/O — data tidak langsung ditulis ke tujuan akhir, melainkan dikumpulkan dulu di buffer untuk efisiensi. flush() memaksa semua data di buffer untuk segera ditulis ke writer. Tanpa ini, data bisa hilang.
(6) getBuffer().toString() Mengambil isi StringWriter sebagai String Java biasa. Hasilnya adalah teks CSV siap pakai.
📤 Output yang Dihasilkan: 
Eko,Khannedy,100
Budi,Nugraha,95
⚠️ Kenapa throws IOException?
Operasi I/O (Input/Output) di Java — membaca file, menulis file, akses network — bisa gagal karena alasan di luar kendali program (disk penuh, koneksi putus, dll). Java memiliki Checked Exception: compiler mewajibkan kamu mendeklarasikan throws IOException di signature method, atau menambahkan try-catch. Ini berbeda dengan PHP di mana exception bisa saja tidak tertangani dan baru ketahuan saat runtime.
❌ Salah — Lupa flush()
CSVPrinter printer = new CSVPrinter(
    writer, CSVFormat.DEFAULT);
printer.printRecord("Eko", "Khannedy", 100);
// Lupa flush() — data bisa hilang!
String csv = writer.getBuffer().toString();
// csv mungkin kosong atau tidak lengkap
✅ Benar — Selalu flush() sebelum membaca buffer
CSVPrinter printer = new CSVPrinter(
    writer, CSVFormat.DEFAULT);
printer.printRecord("Eko", "Khannedy", 100);
printer.flush(); // ← wajib ada
String csv = writer.getBuffer().toString();
// csv dijamin berisi semua data
❌ Salah — Mindset PHP: String concat manual
// Cara PHP yang di-port ke Java — jangan lakukan ini
String csv = "";
csv += "Eko,Khannedy,100\n";
csv += "Budi,Nugraha,95\n";
// Tidak handle koma dalam nilai, quoting, dll
✅ Benar — Gunakan CSVPrinter
// Library yang handle edge case: nilai dengan koma,
// newline di dalam nilai, quoting otomatis, dll
printer.printRecord("Eko, Ph.D", "Khannedy", 100);
// Output: "Eko, Ph.D",Khannedy,100 ← auto-quoted!
⚡ Analogi Laravel

Di Laravel, kamu bisa membuat response CSV dengan Response::stream() atau package maatwebsite/excel. CSVPrinter di Java berperan seperti package tersebut — abstraksi yang menangani semua detail teknis format CSV (escaping, quoting, delimiter) sehingga kamu hanya perlu fokus pada data. StringWriter mirip seperti ob_get_clean(): menangkap output ke buffer.

Chapter 03
📖 Membaca CSV dari File
Path, Reader, CSVParser, dan iterasi record

Setelah bisa menulis, kini saatnya membaca CSV dari file. Java menyediakan cara yang aman dan eksplisit untuk membuka file dengan Path dan Files.

📁 Asumsi File sample.csv
Test ini mengasumsikan ada file sample.csv di working directory saat test dijalankan. Isinya: 
First Name,Last Name,Value
Eko,Khannedy,100
Budi,Nugraha,95
Kode: readCSV()
@Test
void readCSV() throws IOException {
    Path path = Path.of("sample.csv");                          // (1)
    Reader reader = Files.newBufferedReader(path);              // (2)

    CSVParser parser = new CSVParser(reader, CSVFormat.DEFAULT); // (3)
    for (CSVRecord record : parser) {                          // (4)
        System.out.println("First Name : " + record.get(0));   // (5)
        System.out.println("Last Name : "  + record.get(1));
        System.out.println("Value : "      + record.get(2));
    }
}
Penjelasan Baris per Baris
(1) Path.of() Membuat representasi path file di filesystem. Ini adalah cara modern (Java 11+) — lebih aman dan ekspresif dibanding new File("sample.csv") yang lama. Ekuivalen dengan storage_path('sample.csv') di Laravel, tapi tanpa magic string helper.
(2) Files.newBufferedReader() Membuka file untuk dibaca sebagai karakter (bukan byte mentah). Menggunakan buffered reader artinya Java membaca file dalam blok-blok besar ke memory sekaligus — jauh lebih efisien daripada membaca karakter satu per satu. Ini seperti fopen($path, 'r') di PHP tapi dengan buffering otomatis.
(3) CSVParser Engine pembaca CSV. Ia membungkus reader dan tahu cara mem-parsing teks CSV sesuai CSVFormat. Hasilnya adalah stream record yang bisa diiterasi.
(4) for-each loop CSVParser mengimplementasikan interface Iterable<CSVRecord>, sehingga bisa digunakan langsung di loop for-each. Setiap iterasi menghasilkan satu CSVRecord (satu baris CSV). Di balik layar, parser membaca file secara lazy — tidak langsung load semua baris ke memory (cocok untuk file besar).
(5) record.get(index) Mengambil nilai kolom berdasarkan index berbasis 0. Kolom pertama = index 0, kedua = 1, dst. Ini rawan kesalahan jika urutan kolom berubah — itulah mengapa ada cara yang lebih baik menggunakan nama header (dibahas di Chapter 4).
⚠️ Masalah: Header Ikut Terbaca
Karena menggunakan CSVFormat.DEFAULT, baris pertama file CSV (yang seharusnya header) akan ikut dibaca sebagai data biasa. Jika file kamu punya header, output pertama akan jadi:
First Name : First Name — bukan yang diinginkan! Solusinya ada di Chapter 4.
❌ Salah — Index Magic Number
// Tiba-tiba ada kolom baru di posisi ke-2
// Semua record.get(2) jadi salah tanpa error!
record.get(0); // first name
record.get(1); // last name
record.get(2); // ← seharusnya value, tapi bisa jadi kolom lain
✅ Benar — Gunakan nama header (lihat Chapter 4)
// Tidak terpengaruh perubahan urutan kolom
record.get("First Name");
record.get("Last Name");
record.get("Value");
⚡ Analogi Laravel

Membaca CSV dengan loop ini mirip seperti menggunakan SplFileObject di PHP atau membaca dengan Laravel Excel's ToCollection concern. Perbedaannya: di Java, tipe data setiap tahap (Path → Reader → Parser → Record) eksplisit dan terstruktur. Di PHP, kamu bisa langsung fgetcsv() dan itu langsung mengembalikan array — lebih cepat ditulis tapi kurang ekspresif soal apa yang terjadi di dalam.

Chapter 04
🏷️ CSV dengan Header
CSVFormat.builder(), setHeader(), dan akses kolom by name

Mengakses kolom dengan index angka seperti record.get(0) sangat rawan bug jika struktur file berubah. Solusinya: gunakan header agar kolom bisa diakses dengan nama yang bermakna.

Kode: readCSVWithHeader()
@Test
void readCSVWithHeader() throws IOException {
    Path path = Path.of("sample.csv");
    Reader reader = Files.newBufferedReader(path);

    CSVFormat format = CSVFormat.DEFAULT.builder()
            .setHeader()                                           // (1)
            .build();                                               // (2)
    CSVParser parser = new CSVParser(reader, format);
    for (CSVRecord record : parser) {
        System.out.println("First Name : " + record.get("First Name")); // (3)
        System.out.println("Last Name : "  + record.get("Last Name"));
        System.out.println("Value : "      + record.get("Value"));
    }
}
Penjelasan Baris per Baris
(1) .setHeader() Tanpa argumen = "baca baris pertama file sebagai header". Parser akan skip baris pertama dari iterasi data, dan menyimpannya sebagai mapping nama kolom → index. Sekarang record.get("First Name") tahu kalau "First Name" adalah kolom ke-0.
(2) .build() Pola Builder Pattern — cara Java membuat objek dengan banyak konfigurasi opsional secara terstruktur. Daripada constructor dengan 10 parameter, kamu memanggil method secara berantai lalu menutupnya dengan build(). Di PHP/Laravel, ini mirip seperti query builder: DB::table('users')->where(...)->get().
(3) record.get("nama") Mengakses kolom berdasarkan nama — jauh lebih aman dan readable. Jika nama kolom tidak ditemukan, Java akan throw IllegalArgumentException yang jelas, bukan silent undefined behavior.
Kode: createCSVWithHeader()
@Test
void createCSVWithHeader() throws IOException {
    StringWriter writer = new StringWriter();

    CSVFormat format = CSVFormat.DEFAULT.builder()
            .setHeader("First Name", "Last Name", "Value")     // (A)
            .build();
    CSVPrinter printer = new CSVPrinter(writer, format);
    printer.printRecord("Eko", "Khannedy", 100);
    printer.printRecord("Budi", "Nugraha", 95);
    printer.flush();

    String csv = writer.getBuffer().toString();
    System.out.println(csv);
}
(A) setHeader("col1","col2",...) Ketika menulis CSV, setHeader() dengan argumen berarti: "tuliskan baris header ini terlebih dahulu, kemudian tulis data di bawahnya." Output akan dimulai dengan First Name,Last Name,Value sebelum data record.
📤 Output yang Dihasilkan: 
First Name,Last Name,Value
Eko,Khannedy,100
Budi,Nugraha,95
🔑 Builder Pattern — Pola Desain yang Wajib Kamu Kenal
Builder Pattern sangat umum di Java. Kamu akan menemukannya di mana-mana: Spring, Lombok (@Builder), OkHttp, dsb. Prinsipnya: pisahkan konstruksi objek yang kompleks menjadi langkah-langkah kecil yang bisa dikustomisasi sebelum objek final dibuat dengan build().
❌ Salah — setHeader() saat baca vs tulis tertukar
// Saat MEMBACA: setHeader() tanpa argumen
// → baca baris pertama file sebagai header
// Saat MENULIS: setHeader() dengan argumen
// → tulis baris header ke output

// Kesalahan umum: pakai setHeader("col") saat baca
// → parser mengabaikan baris pertama file
// → kehilangan record pertama yang valid!
✅ Benar — Bedakan konteks membaca vs menulis
// MEMBACA: setHeader() tanpa argumen
CSVFormat.DEFAULT.builder()
    .setHeader()  // ← ambil dari file
    .build();

// MENULIS: setHeader() dengan argumen
CSVFormat.DEFAULT.builder()
    .setHeader("Col1","Col2")  // ← tulis ke output
    .build();
⚡ Analogi Laravel

Builder Pattern di Java sangat mirip dengan Fluent Interface di Laravel. Contoh: CSVFormat.DEFAULT.builder().setHeader().build() seperti User::query()->where('active', true)->orderBy('name')->get() — kamu merangkai konfigurasi, lalu menutupnya dengan method terminasi (build() / get()). Perbedaannya: di Java, build() menghasilkan objek immutable yang bisa direuse, bukan langsung mengeksekusi query.

🧪 Mini Quiz — Chapter 4

Q1: Apa perbedaan .setHeader() (tanpa argumen) vs .setHeader("Col1", "Col2") (dengan argumen)?

A. Keduanya sama saja, hanya gaya penulisan berbeda

Chapter 05
⇥ Custom Delimiter — TSV / TDF
CSVFormat.TDF dan pemisah kolom selain koma

CSV (Comma-Separated Values) tidak selalu harus menggunakan koma sebagai pemisah. Format lain yang umum adalah TSV/TDF (Tab-Separated Values/Delimiter Format) — menggunakan karakter tab (\t) sebagai pemisah kolom. Apache Commons CSV mendukung ini dengan preset CSVFormat.TDF.

Kode: createCSVWithTab()
@Test
void createCSVWithTab() throws IOException {
    StringWriter writer = new StringWriter();

    CSVFormat format = CSVFormat.TDF.builder()            // (1)
            .setHeader("First Name", "Last Name", "Value")
            .build();
    CSVPrinter printer = new CSVPrinter(writer, format);
    printer.printRecord("Eko", "Khannedy", 100);
    printer.printRecord("Budi", "Nugraha", 95);
    printer.flush();

    String csv = writer.getBuffer().toString();
    System.out.println(csv);
}
Penjelasan
(1) CSVFormat.TDF Preset format TDF (Tab Delimited Format). Ini adalah konstanta yang sudah dikonfigurasi dengan tab (\t) sebagai delimiter, bukan koma. Semua method lainnya sama persis — kamu hanya mengubah format preset di awal.
📤 Output yang Dihasilkan (tab digambarkan sebagai →): 
First Name→Last Name→Value
Eko→Khannedy→100
Budi→Nugraha→95
Perbandingan Format yang Tersedia
Konstanta Delimiter Use Case
CSVFormat.DEFAULT Koma (,) File CSV umum, Excel export
CSVFormat.TDF Tab (\t) TSV, data interchange antar sistem
CSVFormat.EXCEL Koma (,) Kompatibel dengan Microsoft Excel
CSVFormat.RFC4180 Koma (,) Standar RFC 4180 yang ketat
CSVFormat.MYSQL Tab (\t) MySQL LOAD DATA INFILE format
💡 Custom Delimiter Sendiri
Jika tidak ada preset yang cocok, kamu bisa membuat format custom: 
CSVFormat customFormat = CSVFormat.DEFAULT.builder()
        .setDelimiter(';')   // Semicolon — umum di negara Eropa
        .setHeader("Col1", "Col2")
        .build();
❌ Salah — Baca TSV dengan DEFAULT format
// File adalah TSV (tab-separated)
// Tapi kita pakai DEFAULT (koma-separated)
CSVParser parser = new CSVParser(
    reader, CSVFormat.DEFAULT); // ← salah format!
// Seluruh baris dianggap 1 kolom, tidak ter-parse
✅ Benar — Sesuaikan format dengan isi file
// File adalah TSV → gunakan TDF
CSVParser parser = new CSVParser(
    reader, CSVFormat.TDF); // ← cocok!
// Kolom ter-parse dengan benar
⚡ Analogi Laravel

Memilih CSVFormat di Java mirip seperti memilih disk driver di Laravel Filesystem (config/filesystems.php): kamu pilih "preset" yang sesuai dengan konteks (local, s3, dll), dan interface-nya tetap sama. Di sini, interface-nya tetap CSVPrinter/CSVParser, yang berubah hanya preset format-nya (DEFAULT, TDF, dll). Ini adalah prinsip Open/Closed Principle — terbuka untuk ekstensi (format baru), tertutup untuk modifikasi (interface tidak berubah).

Key Takeaways untuk ex-Laravel Dev
1
Tipe Data itu Kontrak
Java memaksamu berpikir soal tipe setiap variabel. Ini bukan hambatan — ini dokumentasi yang diperiksa compiler. Semakin ketat tipe datamu, semakin sedikit bug yang lolos ke production.
2
Builder Pattern = Fluent Interface
CSVFormat.DEFAULT.builder().setHeader().build() adalah pola yang akan kamu temukan di seluruh ekosistem Java. Kenali polanya dan kamu akan cepat membaca kode Java orang lain.
3
flush() adalah Kewajiban I/O
Selalu panggil flush() (atau gunakan try-with-resources agar otomatis) setelah operasi tulis. Buffer I/O adalah fitur performa, bukan bug — tapi kamu harus tahu kapan mengosongkannya.
4
Gunakan Nama, Bukan Angka
Akses kolom CSV dengan record.get("Nama Kolom"), bukan record.get(0). Kode yang dibaca bertahun-tahun kemudian akan berterima kasih padamu.
5
Library = Ekosistem Maven Central
Apache Commons CSV adalah salah satu dari ribuan library di Maven Central — "Packagist"-nya Java. Selalu cari library yang sudah teruji sebelum menulis implementasi sendiri dari nol.
