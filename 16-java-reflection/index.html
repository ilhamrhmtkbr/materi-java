🔍 Java Reflection API

Modul pembelajaran interaktif untuk developer PHP / Laravel yang migrasi ke Java.
Reflection adalah kemampuan program untuk memeriksa dan memanipulasi dirinya sendiri saat runtime — fondasi dari framework seperti Spring, Hibernate, dan JUnit.

java.lang.reflect Class<T> Field / Method / Constructor Annotation Processing Dynamic Proxy Generics at Runtime

Sebelum masuk ke kode, kamu perlu memahami mengapa Reflection ada dan kapan kamu boleh (dan tidak boleh) menggunakannya.

Secara normal, Java adalah bahasa yang sangat statis — semua tipe data harus diketahui saat kompilasi. Tapi bagaimana jika kamu ingin menulis kode yang bisa bekerja dengan class manapun tanpa tahu class-nya terlebih dahulu?

Contoh nyata: Spring saat startup tidak tahu class-class mana yang akan kamu buat. Tapi ia bisa scan, inject dependency, dan menjalankan semua @Service-mu secara otomatis. Caranya? Reflection.

Reflection memungkinkan program untuk bertanya pada dirinya sendiri saat runtime: "Kelas ini punya method apa saja? Field-nya apa? Ada annotation-nya tidak?" — lalu bertindak berdasarkan jawaban tersebut.

FrameworkPenggunaan Reflection
Spring BootComponent scanning, Dependency Injection, @Autowired
Hibernate / JPAMembaca @Entity, @Column untuk mapping ORM
JUnit 5Menemukan dan menjalankan semua method @Test
Jackson / GsonSerialisasi JSON ↔ Java Object secara otomatis
LombokGenerate getter/setter/builder via Annotation Processing

Reflection memiliki tiga kelemahan utama:

  • Performa: Jauh lebih lambat dari pemanggilan method biasa — JVM tidak bisa mengoptimasi.
  • Type Safety hilang: Error tipe data baru ketahuan saat runtime, bukan saat kompilasi.
  • Keamanan: setAccessible(true) bisa bypass private — melanggar enkapsulasi.

Aturan praktis: Gunakan Reflection di dalam framework / library / infrastructure code, bukan di business logic sehari-hari. Kalau ada cara biasa untuk melakukannya, pakai cara biasa.

⚡ Analogi Laravel

Di PHP, Reflection digunakan oleh Laravel Service Container untuk melakukan automatic dependency resolution — saat kamu type-hint sebuah class di constructor, Laravel membaca type hint tersebut via ReflectionClass PHP dan secara otomatis meng-inject instance yang tepat. Java melakukan hal yang sama dengan cara yang lebih eksplisit dan type-safe.

Chapter 01
🔍 Class Object — Gerbang Utama Reflection
ClassTest.java · 3 cara mendapat Class<T> · inspeksi metadata

Semua Reflection di Java dimulai dari satu objek: Class<T>. Ini adalah representasi sebuah class Java di dalam memory — semacam "kartu identitas" dari sebuah class yang menyimpan semua informasi tentangnya.

3 Cara Mendapatkan Class Object
@Test
void testCreateClass() throws ClassNotFoundException {

    // Cara 1: Class literal — paling umum dan aman (compile-time check)
    Class<Person> personClass1 = Person.class;               // (A)

    // Cara 2: Class.forName() — dari string nama class (runtime)
    Class<?> personClass2 = Class.forName(                    // (B)
        "programmerzamannow.reflection.data.Person");

    // Cara 3: Dari instance yang sudah ada
    Person person = new Person();
    Class<? extends Person> personClass3 = person.getClass(); // (C)
}
(A) .class literal Cara paling direkomendasikan. Person.class adalah ekspresi yang dievaluasi saat kompilasi — jika class tidak ada, compiler langsung error. Type parameter <Person> terjaga sepenuhnya, memberikan type safety maksimal.
(B) Class.forName() Menerima nama class sebagai String — artinya class baru dicari saat runtime. Sangat berguna ketika nama class tidak diketahui saat kompilasi (misalnya dari konfigurasi file, database, atau plugin system). Tipe kembalinya adalah Class<?> (wildcard) karena compiler tidak tahu class apa yang dimaksud. Melempar ClassNotFoundException jika nama class salah.
(C) .getClass() Mendapat Class dari instance yang sudah ada. Tipe kembalinya adalah Class<? extends Person> bukan Class<Person>, karena objek di runtime bisa jadi subclass dari Person. Ini penting di polymorphism.
Inspeksi Metadata Class
@Test
void testClassMethod() {
    Class<Person> personClass = Person.class;

    personClass.getSuperclass();           // → class java.lang.Object
    personClass.getInterfaces();           // → [Nameable, Serializable]
    personClass.getDeclaredConstructors(); // → semua constructor Person
    personClass.getDeclaredMethods();      // → semua method Person
    personClass.getDeclaredFields();       // → semua field Person
    personClass.getModifiers();            // → angka bitmask (public=1, final=16, ...)
    personClass.getPackage();              // → programmerzamannow.reflection.data
    personClass.getName();                 // → fully qualified: programmerzamannow...Person
    personClass.getSimpleName();           // → "Person" saja
}
⚠️ getDeclared* vs get* — Perbedaan Krusial!
  • getDeclaredFields() → semua field di class ini saja (termasuk private), tapi tidak termasuk warisan dari superclass
  • getFields() → hanya field public, tapi termasuk yang diwarisi dari superclass
  • Aturan yang sama berlaku untuk getDeclaredMethods() vs getMethods() dan getDeclaredConstructors() vs getConstructors()
⚡ Analogi Laravel

Class<T> di Java adalah ekuivalen dari ReflectionClass di PHP. Operasi seperti Person.class → new ReflectionClass(Person::class), dan Class.forName("nama.class") → new ReflectionClass('NamaClass'). Di Java, setiap class otomatis memiliki "Class object"-nya sendiri yang diload oleh JVM — tidak perlu membuat instance Reflection secara manual seperti di PHP.

Chapter 02
🧩 Fields — Membaca & Memanipulasi Properti
FieldTest.java · PrimitiveTypeTest.java · setAccessible · get/set

Setelah bisa mendapatkan Class object, langkah berikutnya adalah mengakses field (properti/attribute) dari class tersebut. Ini adalah fondasi dari fitur seperti serialisasi JSON, ORM mapping, dan validasi otomatis.

Membaca Nama & Tipe Semua Field
@Test
void testGetFields() {
    Class<Person> personClass = Person.class;

    Field[] fields = personClass.getDeclaredFields();    // (1)
    for (Field field : fields) {
        System.out.println(field.getName()                 // (2)
            + " : " + field.getType().getName());          // (3)
    }
}
Output firstName : java.lang.String
lastName : java.lang.String
hobbies : java.util.List
age : int
Membaca Nilai Field (termasuk private)
@Test
void testGetFieldValue() throws NoSuchFieldException, IllegalAccessException {
    Class<Person> personClass = Person.class;
    Field firstName = personClass.getDeclaredField("firstName"); // (A)
    firstName.setAccessible(true);                              // (B)

    Person person1 = new Person("Eko", "Kurniawan");
    String result = (String) firstName.get(person1);            // (C)
    System.out.println(result); // Eko
}
(A) getDeclaredField("nama") Mencari satu field berdasarkan nama. Akan melempar NoSuchFieldException jika nama salah — ini adalah tanda bahwa type safety sedang dikompromikan (nama field sebagai string tidak dicek compiler). Perhatikan bahwa field ini bersifat private di class Person.
(B) setAccessible(true) Kunci utama Reflection. Secara default, JVM menegakkan aturan akses (private, protected). setAccessible(true) menonaktifkan pengecekan akses untuk field ini, memungkinkan kita membaca/menulis nilai private dari luar class. Ini adalah "bypass keamanan" yang harus digunakan dengan sangat hati-hati.
(C) field.get(instance) Membaca nilai field dari sebuah instance objek. Mengembalikan Object, sehingga kamu perlu melakukan casting ke tipe yang benar. Jika salah cast → ClassCastException saat runtime.
Mengubah Nilai Field
@Test
void testSetFieldValue() throws NoSuchFieldException, IllegalAccessException {
    Field firstName = Person.class.getDeclaredField("firstName");
    firstName.setAccessible(true);

    Person person1 = new Person("Eko", "Kurniawan");
    firstName.set(person1, "Joko"); // ekuivalen: person1.setFirstName("Joko")
    System.out.println(person1.getFirstName()); // Joko
}
Primitive Types — Field Khusus
@Test
void testGetFieldValue() throws NoSuchFieldException, IllegalAccessException {
    Field age = Person.class.getDeclaredField("age");

    System.out.println(age.getType().isPrimitive()); // true

    age.setAccessible(true);
    Person person = new Person("Eko", "Khannedy");
    person.setAge(25);

    System.out.println(age.getInt(person)); // (!) bukan .get() biasa
}
💡 Primitive vs Object — Cara Akses Berbeda
Untuk field bertipe primitif (int, long, boolean, dll), gunakan method khusus seperti field.getInt(), field.getLong(), field.getBoolean() — bukan field.get() biasa. Ini karena tipe primitif bukan Object di Java (tidak bisa di-cast ke Object secara langsung tanpa auto-boxing).
❌ Salah — Lupa setAccessible untuk field private
Field firstName = personClass
    .getDeclaredField("firstName");
// Lupa setAccessible(true)!

String val = (String) firstName.get(person);
// → IllegalAccessException saat runtime!
✅ Benar — Selalu setAccessible untuk private field
Field firstName = personClass
    .getDeclaredField("firstName");
firstName.setAccessible(true); // ← wajib

String val = (String) firstName.get(person);
// → "Eko" ✓
⚡ Analogi Laravel

Operasi field.get(object) dan field.set(object, value) di Java persis seperti $reflection->getValue($object) dan $reflection->setValue($object, $value) di PHP's ReflectionProperty. setAccessible(true) di Java = $prop->setAccessible(true) di PHP — keduanya bypass enkapsulasi dengan cara yang sama.

Chapter 03
⚡ Methods & Parameters — Invoke Dinamis
MethodTest.java · ParameterTest.java · Method.invoke()

Setelah Field, kini giliran Method. Reflection memungkinkan kamu memanggil method apapun secara dinamis — bahkan tanpa mengetahui nama method-nya saat kompilasi. Ini adalah inti dari mekanisme seperti JUnit (menjalankan method @Test) dan Spring AOP.

Inspeksi Semua Method
@Test
void testGetMethods() {
    Method[] methods = Person.class.getDeclaredMethods();
    for (Method method : methods) {
        System.out.println(method.getName());                          // nama method
        System.out.println(method.getReturnType());                     // tipe return
        System.out.println(Arrays.toString(method.getParameterTypes())); // tipe parameter
        System.out.println(Arrays.toString(method.getExceptionTypes())); // exception yang dideklarasikan
    }
}
Memanggil (Invoke) Method Tanpa Parameter
@Test
void testGetMethodValue() throws NoSuchMethodException, InvocationTargetException, IllegalAccessException {
    Method getFirstName = Person.class
        .getDeclaredMethod("getFirstName");          // (1)

    Person person = new Person("Eko", "Khannedy");
    String firstName = (String) getFirstName.invoke(person); // (2)
    System.out.println(firstName); // "Eko"
}
(1) getDeclaredMethod("nama") Mencari method berdasarkan nama. Jika ada overloaded method (nama sama, parameter berbeda), kamu harus menyertakan tipe-tipe parameter sebagai argumen tambahan untuk disambiguasi — lihat contoh berikutnya.
(2) method.invoke(instance, args...) Memanggil method pada instance tertentu. Argumen pertama adalah objek targetnya (seperti this). Argumen berikutnya adalah parameter method (varargs). Return type adalah Object — perlu casting. Untuk void method, invoke() mengembalikan null.
Invoke Method Dengan Parameter + Overload
@Test
void testInvokeMethodWithParameter() throws ... {
    // Disambiguasi overload: sertakan tipe parameter
    Method setFirstName = Person.class
        .getDeclaredMethod("setFirstName", String.class); // (A)

    Person person = new Person("Eko", "Khannedy");
    setFirstName.invoke(person, "Joko");               // (B)
    System.out.println(person.getFirstName()); // "Joko"
}

// Untuk primitive type, gunakan tipe primitive-nya langsung:
Method setAge = Person.class
    .getDeclaredMethod("setAge", int.class); // (C) BUKAN Integer.class!
setAge.invoke(person, 25);
(A) Disambiguasi overload Argumen kedua dan seterusnya di getDeclaredMethod() adalah tipe-tipe parameter untuk memilih overload yang tepat. Jika kamu menulis getDeclaredMethod("setFirstName") saja tanpa parameter type, dan ada lebih dari satu setFirstName, kamu akan mendapat exception.
(B) invoke dengan argumen Argumen method diberikan setelah instance. Varargs membuatnya fleksibel: method.invoke(obj, arg1, arg2, arg3).
(C) int.class vs Integer.class Jebakan umum! int.class (primitive) ≠ Integer.class (wrapper/boxed). Jika method signature-nya setAge(int age), kamu HARUS pakai int.class. Memakai Integer.class akan membuat getDeclaredMethod() melempar NoSuchMethodException.
Inspect Parameter Detail
@Test
void getGetParameters() {
    Method[] methods = Person.class.getDeclaredMethods();
    for (Method method : methods) {
        Parameter[] parameters = method.getParameters();
        for (Parameter parameter : parameters) {
            System.out.println("Name: " + parameter.getName());  // ⚠️ perlu flag compiler
            System.out.println("Type: " + parameter.getType());
        }
    }
}
⚠️ Nama Parameter Butuh Flag Compiler Khusus
Secara default, Java compiler tidak menyimpan nama parameter ke dalam bytecode (untuk menghemat ukuran). Method parameter.getName() akan mengembalikan nilai generik seperti arg0, arg1, dll. Untuk mendapatkan nama asli, tambahkan flag -parameters ke compiler Java (di Maven: <compilerArg>-parameters</compilerArg>). Spring Boot secara default sudah mengaktifkan ini.
💡 InvocationTargetException — Error yang Terbungkus
Ketika method yang di-invoke melempar exception, Reflection membungkusnya dalam InvocationTargetException. Untuk mendapatkan exception aslinya, panggil e.getCause(). Ini adalah pola yang sering membingungkan pemula — stack trace akan menunjuk ke kode Reflection, padahal error sesungguhnya ada di dalam method target.
❌ Salah — int.class vs Integer.class tertukar
// Signature method: setAge(int age)
Method setAge = Person.class
    .getDeclaredMethod("setAge",
        Integer.class); // ← SALAH!
// → NoSuchMethodException!
✅ Benar — Cocokkan exact signature
// Signature method: setAge(int age)
Method setAge = Person.class
    .getDeclaredMethod("setAge",
        int.class); // ← BENAR: int primitive
setAge.invoke(person, 25);
⚡ Analogi Laravel

method.invoke(object, args) di Java adalah ekuivalen langsung dari $reflectionMethod->invoke($object, ...$args) di PHP. Perbedaan utama: PHP lebih toleran soal type coercion (bisa auto-convert int ke string), sedangkan Java sangat ketat — tipe argumen harus cocok persis dengan signature method. Salah tipe = IllegalArgumentException saat runtime.

🧪 Mini Quiz — Chapter 3

Chapter 04
🏗️ Constructors — Membuat Object Secara Dinamis
ConstructorTest.java · Constructor.newInstance()

Reflection juga memungkinkan pembuatan objek secara dinamis — tanpa menggunakan new secara langsung di kode. Ini adalah fondasi dari Dependency Injection di Spring: container membuat instance class-class-mu tanpa pernah menulis new MyService() secara eksplisit.

Inspeksi & Invoke Constructor
@Test
void testCreateObjectUsingConstructor() throws ... {
    Class<Person> personClass = Person.class;

    // Constructor tanpa parameter (no-arg constructor)
    Constructor<Person> constructor =
        personClass.getConstructor();                        // (1)

    // Constructor dengan dua parameter String
    Constructor<Person> constructorWithParams =
        personClass.getConstructor(String.class, String.class); // (2)

    Person person1 = constructor.newInstance();               // (3)
    Person person2 = constructorWithParams.newInstance(        // (4)
        "Eko", "Khannedy");

    System.out.println(person1); // Person{firstName='null', lastName='null', age=0}
    System.out.println(person2); // Person{firstName='Eko', lastName='Khannedy', age=0}
}
(1) getConstructor() Mengambil constructor tanpa parameter. Perhatikan perbedaan: getConstructor() (bukan getDeclared) — artinya hanya constructor public yang bisa diakses. Untuk private constructor (seperti di Singleton pattern), pakai getDeclaredConstructor() + setAccessible(true).
(2) getConstructor(types...) Disambiguasi overloaded constructor dengan menyertakan tipe parameter. Prinsip sama dengan getDeclaredMethod().
(3-4) constructor.newInstance(args...) Membuat instance baru — ekuivalen dengan new Person() atau new Person("Eko", "Khannedy"). Tipe return adalah T (berkat type parameter Constructor<Person>), sehingga tidak perlu casting!
Inspect Semua Constructor
@Test
void testGetConstructors() {
    Constructor<?>[] constructors =
        Person.class.getDeclaredConstructors();

    for (Constructor<?> ctor : constructors) {
        System.out.println(ctor.getName());
        System.out.println(Arrays.toString(ctor.getParameterTypes()));
    }
}
// Output:
// programmerzamannow.reflection.data.Person
// []
// programmerzamannow.reflection.data.Person
// [class java.lang.String, class java.lang.String]
💡 Mengapa Perlu No-Arg Constructor?
Banyak framework Java (Hibernate, Jackson, Spring) memerlukan no-arg constructor (constructor tanpa parameter) untuk membuat instance via Reflection sebelum mengisi field-nya satu per satu. Itulah mengapa class Person memiliki public Person() {} meskipun terkesan "tidak berguna" — ini adalah infrastructure requirement, bukan kebutuhan bisnis.
❌ Salah — Hanya punya parameterized constructor
public class Person {
    private String name;

    // Tidak ada no-arg constructor!
    public Person(String name) {
        this.name = name;
    }
}
// Jackson/Hibernate akan throw:
// No suitable constructor found
// for type Person
✅ Benar — Sediakan no-arg constructor
public class Person {
    private String name;

    public Person() {} // ← wajib ada

    public Person(String name) {
        this.name = name;
    }
}
// Framework dapat membuat instance
// via constructor.newInstance()
⚡ Analogi Laravel

constructor.newInstance(args) di Java sama dengan $reflectionClass->newInstance(...$args) di PHP. Prinsip yang sama digunakan oleh Laravel Service Container saat melakukan automatic resolution: ia membaca constructor class via Reflection, menentukan dependency yang dibutuhkan, lalu memanggil newInstance() dengan dependency yang sudah di-resolve. Di Java, Spring melakukan hal yang persis sama.

🧪 Mini Quiz — Chapter 4

Q: Mengapa class entity di Hibernate (atau model di Spring Data JPA) wajib memiliki no-arg constructor?

A. Karena Java tidak mengizinkan class tanpa no-arg constructor
B. Hibernate menggunakan constructor.newInstance() (Reflection) untuk membuat instance, lalu mengisi field satu per satu — butuh no-arg constructor agar bisa membuat objek kosong dulu
C. Supaya bisa di-serialize ke JSON dengan Jackson
D. Hanya convention, tidak ada alasan teknis
Chapter 05
🏷️ Modifiers & Package
ModifierTest.java · PackageTest.java · bitmask access flags

Reflection juga bisa membaca access modifier (public, private, static, final, dll) dari class, field, atau method — dan mengakses informasi package termasuk annotation yang ada di level package.

Membaca Modifier
@Test
void testModifier() {
    Class<Person> personClass = Person.class;

    Modifier.isPublic(personClass.getModifiers());  // true  (Person is public)
    Modifier.isFinal(personClass.getModifiers());   // true  (Person is final)
    Modifier.isStatic(personClass.getModifiers());  // false (bukan static class)
}
💡 Modifier sebagai Bitmask Integer
getModifiers() mengembalikan int — bukan String, melainkan sebuah bitmask. Setiap bit merepresentasikan satu modifier: public=1, private=2, protected=4, static=8, final=16, dll. Class utilitas Modifier menyediakan method statis (isPublic(), isFinal(), dll) untuk mengurai bitmask tersebut dengan mudah tanpa harus manual bit-masking.
Package — Termasuk Annotation di Level Package
@Test
void testGetPackage() {
    Package aPackage = Person.class.getPackage();

    System.out.println(aPackage.getName());
    // "programmerzamannow.reflection.data"

    System.out.println(Arrays.toString(aPackage.getAnnotations()));
    // [@programmerzamannow.reflection.annotation.SampleAnnotation()]
}
📦 Package-level Annotation — Dideklarasikan di package-info.java
File khusus package-info.java (satu per package) memungkinkan kamu menambahkan annotation dan Javadoc di level package. Ini digunakan Spring untuk feature seperti @NonNullApi (agar semua method di package dianggap non-null secara default). 
/**
 * Package ini berisikan data-data
 */
@SampleAnnotation
package programmerzamannow.reflection.data;
⚡ Analogi Laravel

Di PHP, modifier (visibility) bisa dicek via $method->isPublic(), $method->isPrivate(), dll pada ReflectionMethod. Di Java, semua modifier dikompresi menjadi satu integer bitmask yang dibaca via Modifier.isXxx() — lebih efisien di memory tapi perlu utilitas untuk dibaca. Konsep package-info.java tidak ada padanannya di PHP karena PHP tidak punya sistem package yang se-formal Java.

Chapter 06
📦 Interface & Superclass — Hierarki Class
InterfaceTest.java · SuperClassTest.java · getInterfaces() · getSuperclass()

Reflection juga memungkinkan kamu menelusuri hierarki class — interface apa yang diimplementasikan, siapa superclass-nya, sampai puncak hierarki (Object). Ini penting untuk framework yang perlu memvalidasi "apakah class ini mengimplementasikan interface tertentu?"

Menelusuri Superclass Chain
@Test
void testGetSuperClass() {
    Class<Person> personClass = Person.class;
    System.out.println(personClass);
    // class programmerzamannow.reflection.data.Person

    Class<? super Person> objectClass = personClass.getSuperclass();
    System.out.println(objectClass);
    // class java.lang.Object  ← superclass terakhir sebelum null

    Class<? super Person> nullClass = objectClass.getSuperclass();
    System.out.println(nullClass);
    // null  ← Object tidak punya superclass
}
💡 Semua Class Mewarisi java.lang.Object
Di Java, setiap class secara implisit mewarisi java.lang.Object — mirip seperti di PHP di mana setiap class bisa memanggil method seperti get_class(). Object adalah akar dari semua hierarki, dan getSuperclass() pada Object.class mengembalikan null sebagai penanda puncak hierarki.
Inspect Interface yang Diimplementasikan
@Test
void testSuperInterfaces() {
    // Lihat interface yang langsung diimplementasikan Person
    System.out.println(Arrays.toString(
        Person.class.getInterfaces()));
    // [interface programmerzamannow.reflection.data.Nameable,
    //  interface java.io.Serializable]
}

@Test
void testClass() {
    Class<Nameable> nameableClass = Nameable.class;
    System.out.println(nameableClass.isInterface()); // true
    System.out.println(nameableClass.getSuperclass()); // null! Interface tidak punya superclass
    System.out.println(Arrays.toString(
        nameableClass.getInterfaces())); // [] — tidak ada super-interface
}
⚠️ Interface: getSuperclass() Selalu null
Interface tidak punya superclass dalam arti yang sama dengan class. Nameable.class.getSuperclass() mengembalikan null. Untuk memeriksa apakah sebuah interface extends interface lain, gunakan getInterfaces() — bukan getSuperclass().
✅ Cara Memeriksa Hierarki Secara Programatik
Untuk mengecek apakah sebuah class mengimplementasikan interface tertentu, gunakan: 
// Cara 1: isAssignableFrom (paling direkomendasikan)
boolean isNameable = Nameable.class.isAssignableFrom(Person.class); // true

// Cara 2: instanceof pada instance
Person p = new Person();
boolean isNameable2 = p instanceof Nameable; // true
⚡ Analogi Laravel

Di PHP, kamu bisa memeriksa hierarki class dengan $reflection->getParentClass() dan $reflection->getInterfaceNames(). Di Java, ekuivalennya adalah getSuperclass() dan getInterfaces(). Bedanya: di Java, interface bisa memiliki implementasi default (default method), sehingga hierarki bisa lebih kompleks dari PHP.

Chapter 07
🔖 Annotations & Custom Validator
NotBlank.java · Validator.java · AnnotationTest.java · studi kasus dunia nyata

Ini adalah chapter paling praktis dan paling dekat dengan dunia nyata. Di sini kita akan membuat annotation custom, lalu membuat validator yang menggunakan Reflection untuk membaca annotation tersebut dan melakukan validasi otomatis — persis seperti cara kerja Bean Validation (@NotNull, @Size, dll) di Java EE / Spring.

Step 1 — Mendefinisikan Custom Annotation
// File: NotBlank.java
@Documented                           // (A)
@Target({ ElementType.FIELD })         // (B)
@Retention(RetentionPolicy.RUNTIME)   // (C)
public @interface NotBlank {
    boolean allowEmptyString() default false; // (D)
}
(A) @Documented Annotation ini akan muncul di Javadoc yang di-generate. Opsional, tapi best practice untuk annotation yang ditujukan untuk pengguna library.
(B) @Target Meta-annotation terpenting. Mendefinisikan di mana annotation ini boleh dipakai. ElementType.FIELD = hanya pada field. Opsi lain: TYPE (class/interface), METHOD, PARAMETER, PACKAGE, dll. Compiler akan error jika annotation digunakan di tempat yang salah.
(C) @Retention(RUNTIME) Kunci agar Reflection bisa membacanya. Ada 3 pilihan: SOURCE (hanya ada di source code, hilang setelah compile — seperti @Override), CLASS (ada di bytecode, tapi tidak accessible via Reflection), RUNTIME (ada di bytecode DAN bisa dibaca via Reflection saat program jalan). Untuk validator yang berjalan saat runtime, HARUS RUNTIME.
(D) allowEmptyString() Annotation dapat memiliki "atribut" — method-like declaration dengan default value. Cara pakai: @NotBlank(allowEmptyString = true). Tanpa argumen, nilai default (false) digunakan otomatis.
Step 2 — Menggunakan Annotation pada Class
// File: Person.java
public final class Person implements Nameable, Serializable {

    @NotBlank                              // allowEmptyString = false (default)
    private String firstName;

    @NotBlank(allowEmptyString = true)   // izinkan empty string ""
    private String lastName;

    private List<String> hobbies;          // tidak ada @NotBlank → tidak divalidasi
    private int age;
    // ...
}
Step 3 — Validator via Reflection (Inti dari Chapter ini)
// File: Validator.java
public class Validator {

  public static void validateNotBlank(Object object)
      throws IllegalAccessException {

    Class<?> aClass = object.getClass();         // (1)
    Field[] fields = aClass.getDeclaredFields(); // (2)

    for (Field field : fields) {
      NotBlank notBlank =
          field.getAnnotation(NotBlank.class);    // (3)

      if (notBlank != null) {                     // (4)
        field.setAccessible(true);
        String value = (String) field.get(object); // (5)

        if (!notBlank.allowEmptyString()) {        // (6)
          value = value.trim();
        }

        if ("".equals(value)) {                    // (7)
          throw new RuntimeException(
              field.getName() + " must not blank");
        }
      }
    }
  }
}
(1) object.getClass() Method validateNotBlank menerima Object — bisa digunakan untuk class APAPUN, bukan hanya Person. Inilah kekuatan Reflection: satu validator untuk semua class.
(2) getDeclaredFields() Ambil semua field — termasuk private. Validator harus bisa membaca semua field tanpa peduli aksesibilitasnya.
(3) field.getAnnotation(NotBlank.class) Membaca annotation @NotBlank dari field ini. Jika field tidak punya annotation tersebut, mengembalikan null. Ini bekerja karena kita mendefinisikan @Retention(RUNTIME) — tanpa itu, hasil selalu null.
(4) if (notBlank != null) Hanya proses field yang memiliki annotation @NotBlank. Field tanpa annotation (hobbies, age) dilewati begitu saja — opt-in validation.
(5) field.get(object) Baca nilai field dari objek yang sedang divalidasi. Cast ke String karena kita tahu @NotBlank hanya bisa ditaruh di field String (bisa diperkuat dengan pengecekan type).
(6) notBlank.allowEmptyString() Baca nilai atribut annotation — persis seperti memanggil method. Ini adalah cara Java mengakses "parameter" dari annotation. Jika allowEmptyString=false, lakukan trim sebelum pengecekan.
(7) "".equals(value) Best practice Java: Selalu panggil equals() pada string literal, bukan pada variabel. Ini mencegah NullPointerException jika value adalah null (karena "" tidak pernah null).
Step 4 — Menggunakan Validator
@Test
void testValidateUsingAnnotation() throws IllegalAccessException {
    Person person = new Person("Eko", ""); // lastName = ""
    Validator.validateNotBlank(person);
    // ✅ TIDAK THROW — karena @NotBlank(allowEmptyString=true) pada lastName
    // Jika firstName = "", AKAN throw: "firstName must not blank"
}
🎯 Studi Kasus: Inilah Cara Spring Validator Bekerja
Framework Bean Validation (Hibernate Validator) yang kamu pakai via @Valid, @NotNull, @Size di Spring Boot bekerja dengan prinsip yang persis sama: ia membaca semua annotation Reflection dari object yang divalidasi, kemudian menjalankan logic validasi yang sesuai. Kamu baru saja menulis mini-implementasinya sendiri!
🚨 @Retention — Jebakan Paling Sering
Jika kamu lupa menambahkan @Retention(RetentionPolicy.RUNTIME) pada annotation custom, field.getAnnotation(NotBlank.class) akan selalu mengembalikan null — seolah-olah tidak ada annotation. Tidak ada error, tidak ada warning. Ini adalah silent bug yang sulit di-debug.
❌ Lupa @Retention

    // default: CLASS retention
    // field.getAnnotation(NotBlank.class)
    // → selalu null saat runtime!
}
✅ Wajib RUNTIME untuk Reflection

    // field.getAnnotation(NotBlank.class)
    // → instance NotBlank yang benar ✓

⚡ Analogi Laravel

Di PHP/Laravel, Form Request Validation menggunakan annotation-like (sebenarnya method rules()) untuk mendefinisikan aturan validasi. Di Java, annotation @NotBlank, @NotNull, @Size adalah cara yang lebih deklaratif — validasi langsung ditempel pada property di class, bukan didefinisikan terpisah. Efeknya sama dengan 'name' => 'required|string|max:255' di Laravel, tapi lebih type-safe karena dibaca saat kompilasi (untuk IDE support) dan runtime (untuk eksekusi).

Chapter 08
🧬 Generics & ParameterizedType
TypeVariableTest.java · ParameterTypeTest.java · Type Erasure

Ini adalah chapter paling advanced. Java menggunakan Type Erasure untuk implementasi Generics — informasi generic type (<String>, <Person>) dihapus saat kompilasi dari bytecode. Namun, ada pengecualian: Reflection menyimpan informasi generic di beberapa tempat tertentu.

Type Erasure — Mengapa Generics Menghilang
// Di source code:
List<String> names = new ArrayList<>();

// Di bytecode setelah type erasure (yang JVM benar-benar lihat):
List names = new ArrayList(); // <String> hilang!

// Akibatnya:
names.getClass() == ArrayList.class; // true, bukan ArrayList<String>.class
⚠️ Tapi Ada Pengecualian: Generic Info Tersimpan di Metadata
Walaupun type argument dihapus dari bytecode utama, Java menyimpannya di metadata khusus untuk: (1) field declarations, (2) method return types, (3) method parameter types, dan (4) class/interface declarations. Inilah yang dieksploitasi oleh Jackson untuk mengetahui bahwa List<String> berisi String.
Membaca Generic Type dari Field
// Person punya: private List<String> hobbies;
@Test
void testFieldGeneric() throws NoSuchFieldException {
    Field hobbies = Person.class.getDeclaredField("hobbies");

    Type type = hobbies.getGenericType();                    // (1)
    System.out.println(type.getClass()); // ParameterizedTypeImpl

    if (type instanceof ParameterizedType) {               // (2)
        ParameterizedType pt = (ParameterizedType) type;
        System.out.println(pt.getRawType());               // interface java.util.List
        System.out.println(pt.getOwnerType());              // null
        System.out.println(Arrays.toString(
            pt.getActualTypeArguments()));               // [class java.lang.String]
    }
}
(1) getGenericType() Berbeda dari field.getType() yang mengembalikan Class (sudah di-erase, hanya List), getGenericType() mengembalikan Type yang mempertahankan informasi generic jika ada. Untuk List<String>, ini mengembalikan ParameterizedType.
(2) instanceof ParameterizedType Cek apakah type ini adalah parameterized (generic) type. Perlu dicek karena tidak semua field punya generic — int age menghasilkan type biasa, bukan ParameterizedType.
TypeVariable — Inspect Generic Parameter di Class Declaration
// Data.java: public class Data<T extends AutoCloseable & Serializable>
@Test
void testGetTypeVariables() {
    TypeVariable<Class<Data>>[] typeVariables =
        Data.class.getTypeParameters();

    for (TypeVariable<Class<Data>> variable : typeVariables) {
        System.out.println(variable.getName());         // T
        System.out.println(Arrays.toString(variable.getBounds()));
        // [interface java.lang.AutoCloseable, interface java.io.Serializable]
        System.out.println(variable.getGenericDeclaration()); // class ...Data
    }
}
💡 Bounded Type Parameter: T extends AutoCloseable & Serializable
Ini adalah multiple bounds di Java — type parameter T harus mengimplementasikan KEDUA interface tersebut sekaligus. Di PHP tidak ada ekuivalen langsung. Di Java, ini memberikan jaminan bahwa apapun yang masuk ke Data<T> pasti bisa di-close() (AutoCloseable) DAN bisa di-serialize (Serializable). getBounds() via Reflection bisa membaca constraint ini saat runtime.
⚡ Analogi Laravel

Type Erasure adalah salah satu perbedaan besar Java vs PHP. PHP menyimpan type hint generically (via PHPDoc @template), tapi tidak di bytecode. Java juga menghapusnya dari bytecode utama, tapi menyimpannya di metadata signature — yang hanya bisa dibaca via Reflection. Framework seperti Jackson memanfaatkan ini lewat TypeReference<>: new TypeReference<List<Person>>(){} — anonymous subclass yang "membekukan" type argument sehingga bisa dibaca via Reflection.

🧪 Mini Quiz — Chapter 8

🎲 Enum, Array & Record
EnumTest.java · ArrayTest.java · RecordTest.java · type-type khusus Java

Selain class dan interface biasa, Java memiliki beberapa tipe khusus: Enum, Array, dan (sejak Java 16) Record. Ketiganya memiliki dukungan Reflection khusus.

Enum via Reflection
// Gender.java: public enum Gender { MALE("Male"), FEMALE("Female"); }
@Test
void testEnum() {
    Class<Gender> genderClass = Gender.class;

    genderClass.getName();         // ...data.Gender
    genderClass.getSuperclass();   // class java.lang.Enum  ← semua enum extends ini
    genderClass.isEnum();          // true
    genderClass.getEnumConstants(); // [MALE, FEMALE]  ← semua konstanta enum
    genderClass.getDeclaredFields();// MALE, FEMALE, description
    genderClass.getDeclaredConstructors(); // private constructor (selalu private di enum)
    genderClass.getDeclaredMethods();     // getDescription, values, valueOf
}
💡 Enum di Java adalah Class Penuh
Berbeda dengan PHP di mana enum relatif sederhana (PHP 8.1+), Enum Java adalah class yang memperluas java.lang.Enum. Setiap enum bisa punya constructor, field, dan method sendiri — seperti Gender.MALE.getDescription(). Di Reflection, getEnumConstants() mengembalikan semua value enum sebagai array.
Array via Reflection
@Test
void testArrayManipulation() {
    Class<String[]> stringArrayClass = String[].class;

    // Buat array baru secara dinamis via Reflection
    String[] array = (String[]) Array.newInstance(            // (1)
        stringArrayClass.getComponentType(), 10);           // (2)

    // Set dan get element via Reflection
    Array.set(array, 0, "Eko");                             // (3)
    System.out.println(Array.get(array, 0));               // (4) → "Eko"
}
(1) Array.newInstance() Membuat array baru secara dinamis saat runtime. Berguna ketika tipe elemen array tidak diketahui saat kompilasi (misalnya dari konfigurasi).
(2) getComponentType() Untuk String[].class, getComponentType() mengembalikan String.class (tipe elemen array). Untuk int[].class, mengembalikan int.class.
(3-4) Array.set() / Array.get() Utility class java.lang.reflect.Array untuk manipulasi array via Reflection. Berbeda dari akses array biasa (array[0]), ini berguna saat tipe array tidak diketahui di compile time.
Record via Reflection (Java 16+)
// Product.java: public record Product(String id, String name, Long price) {}
@Test
void testGetRecordValueByComponent()
    throws InvocationTargetException, IllegalAccessException {

    RecordComponent[] components =
        Product.class.getRecordComponents();                // (1)

    Product product = new Product("1", "Apple iPhone", 20000000L);

    for (RecordComponent component : components) {
        Method accessor = component.getAccessor();             // (2)
        System.out.println(accessor.getName());              // id, name, price
        System.out.println(accessor.invoke(product));        // 1, Apple iPhone, 20000000
    }
}
✅ Record — Immutable Data Class Bawaan Java
record Product(String id, String name, Long price) adalah cara ringkas Java untuk membuat immutable data class. Java otomatis generate: constructor, getter dengan nama sama persis dengan field (product.id() bukan product.getId()), equals(), hashCode(), dan toString(). Di PHP/Laravel, ini seperti punya DTO (Data Transfer Object) dengan semua boilerplate sudah di-generate, tapi lebih ringkas.
⚡ Analogi Laravel

Java Record adalah padanan dari PHP 8.2 readonly class atau Laravel DTO dengan Spatie Data — immutable object yang hanya bisa diisi saat konstruksi. Perbedaan: Reflection pada Record menggunakan getRecordComponents() (bukan getDeclaredFields()) untuk mendapatkan komponen-komponennya beserta accessor method-nya secara langsung.

Chapter 10
🪆 Dynamic Proxy — AOP Ala Sendiri
ProxyTest.java · InvocationHandler · Proxy.newProxyInstance()

Dynamic Proxy adalah fitur Reflection paling powerful — dan paling sering digunakan secara tidak langsung. Spring AOP, @Transactional, @Cacheable, Hibernate lazy loading, dan banyak fitur framework lainnya dibangun di atas Dynamic Proxy.

Masalah yang Dipecahkan Dynamic Proxy

Bayangkan kamu ingin menambahkan logging ke setiap pemanggilan method pada sebuah interface, tanpa mengubah implementasinya. Dynamic Proxy memungkinkan kamu mencegat (intercept) setiap pemanggilan method dan menambahkan logika sebelum/sesudahnya.

Kode Lengkap Dynamic Proxy
// Car interface: void run(); String getName();
@Test
void testProxy() {
    // (1) Buat InvocationHandler — "interseptor" untuk semua method call
    InvocationHandler handler = new InvocationHandler() {
        @Override
        public Object invoke(Object proxy,          // (2)
                                Method method,
                                Object[] args) throws Throwable {

            if (method.getName().equals("getName")) { // (3)
                return "Car Proxy";
            }
            if (method.getName().equals("run")) {     // (4)
                System.out.println("Car is running");
            }
            return null;
        }
    };

    // (5) Buat Proxy object yang mengimplementasikan Car
    Car car = (Car) Proxy.newProxyInstance(
        ClassLoader.getSystemClassLoader(),    // ClassLoader
        new Class[]{ Car.class },               // Interface yang di-proxy
        handler                                  // Handler yang menangani semua call
    );

    System.out.println(car.getClass()); // com.sun.proxy.$Proxy0 ← bukan Car!
    System.out.println(car.getName()); // "Car Proxy" ← dari handler
    car.run();                           // "Car is running" ← dari handler
}
(1) InvocationHandler Interface dengan satu method: invoke(). Ini adalah "catch-all" yang dipanggil ketika method manapun di proxy object dipanggil. Semua logika interceptor ada di sini.
(2) Parameter invoke() proxy = objek proxy itu sendiri, method = Method yang dipanggil (via Reflection), args = argumen yang diberikan. Dari sini kamu bisa: membaca nama method, parameter, annotation-nya, lalu memutuskan apa yang harus dilakukan.
(3-4) Dispatch berdasarkan nama method Pengecekan manual berdasarkan method.getName(). Dalam implementasi AOP yang sesungguhnya, ini digantikan dengan pengecekan annotation atau pointcut expression yang lebih elegan.
(5) Proxy.newProxyInstance() JVM secara dinamis membuat bytecode untuk class baru yang mengimplementasikan semua interface yang diberikan. Class ini tidak pernah ada sebelumnya di disk — dibuat di memory saat runtime. Itulah mengapa car.getClass() mengembalikan $Proxy0, bukan Car.
🎯 Bagaimana Spring @Transactional Bekerja (Simplified)

Ketika kamu menulis @Transactional di service, Spring tidak memodifikasi class-mu. Ia membuat proxy object yang menggantikan bean-mu di container. Ketika method dipanggil:

  1. Proxy invoke() dipanggil
  2. Spring membuka transaksi database
  3. Spring memanggil method aslimu: method.invoke(realObject, args)
  4. Jika sukses → commit. Jika exception → rollback
🚨 Limitasi Dynamic Proxy: Hanya Interface!
java.lang.reflect.Proxy hanya bisa membuat proxy untuk interface, bukan class biasa. Jika kamu perlu proxy untuk class (bukan interface), kamu butuh library bytecode manipulation seperti CGLIB atau ByteBuddy — yang memang digunakan Spring di balik layar untuk kasus ini.
❌ Salah — Proxy untuk Class, bukan Interface
class MyCar implements Car { ... }

// Mencoba proxy class biasa:
Car car = (Car) Proxy.newProxyInstance(
    cl,
    new Class[]{ MyCar.class }, // ← SALAH!
    handler
);
// → IllegalArgumentException:
//   MyCar is not an interface!
✅ Benar — Proxy harus pakai Interface
// Gunakan interface, bukan class:
Car car = (Car) Proxy.newProxyInstance(
    cl,
    new Class[]{ Car.class }, // ← interface ✓
    handler
);
// Untuk proxy class biasa → CGLIB/ByteBuddy
⚡ Analogi Laravel

Dynamic Proxy di Java adalah cara implementasi AOP (Aspect-Oriented Programming) — konsep yang sama dengan Laravel Middleware (mencegat request) atau Event Listener. Tapi AOP beroperasi di level method call, bukan HTTP request. Ini seperti jika setiap pemanggilan method di PHP bisa di-intercept oleh sebuah "middleware". Di Laravel, @Transactional tidak ada built-in — kamu harus manually wrap dengan DB::transaction(). Di Spring, ini ditangani oleh Dynamic Proxy secara otomatis.

Key Takeaways untuk ex-Laravel Dev
1
Reflection = Tulang Punggung Framework
Setiap magic yang kamu rasakan di Spring Boot (@Autowired, @Transactional, @Valid) ditenagai Reflection. Memahami Reflection berarti kamu mengerti mengapa framework bekerja, bukan sekadar bagaimana cara menggunakannya.
2
@Retention(RUNTIME) adalah Wajib
Annotation custom untuk runtime processing HARUS punya @Retention(RetentionPolicy.RUNTIME). Lupa ini = silent failure = bug yang susah di-trace. Jadikan ini kebiasaan pertama saat mendefinisikan annotation baru.
3
getDeclared* vs get* — Bedakan Selalu
getDeclared*() = class ini saja, semua visibility. get*() = public only, termasuk warisan. Salah pilih = missing fields/methods yang tidak kamu sadari.
4
Gunakan Reflection Hanya di Infrastructure, Bukan Business Logic
Reflection itu lambat dan kehilangan type safety. Tulis business logic dengan cara Java biasa. Pakai Reflection hanya untuk library/framework/utility code yang perlu bekerja secara generik.
5
Dynamic Proxy = AOP = Middleware-nya Java
@Transactional, @Cacheable, logging, security check — semua bisa diimplementasikan via Dynamic Proxy tanpa mengubah business code. Ini adalah aplikasi nyata dari prinsip Open/Closed: terbuka untuk behavior baru (via proxy), tertutup untuk modifikasi class asli.
