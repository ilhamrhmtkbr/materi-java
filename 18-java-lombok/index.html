Java Lombok
Hentikan nulis getter, setter, constructor, equals, hashCode secara manual. Lombok generate semua itu dengan satu annotation. Modul ini membedah setiap annotation dari kode nyata.

Lombok 1.18+

Lombok adalah library Java yang menggunakan annotation processing untuk men-generate boilerplate code saat kompilasi. Kode yang dihasilkan tidak terlihat di file .java kamu, tapi ada di bytecode .class-nya. Hasil akhirnya: class lebih ringkas, niat lebih jelas, bug lebih sedikit.

Chapter 0
🧠 Intro — Masalah Boilerplate & Solusi Lombok
Sebelum Lombok, setiap POJO Java wajib punya puluhan baris kode yang tidak ada nilai bisnisnya. Lombok hadir untuk menghilangkan "ceremony" tersebut.
Tanpa Lombok — 60 Baris untuk 3 Field
❌ Tanpa Lombok — Verbose
public class Customer {
    private String id;
    private String name;

    public Customer() {}

    public Customer(String id, String name) {
        this.id = id;
        this.name = name;
    }

    public String getId() { return id; }
    public void setId(String id) { this.id = id; }
    public String getName() { return name; }
    public void setName(String name) { this.name = name; }

    @Override
    public boolean equals(Object o) {
        if (this == o) return true;
        if (!(o instanceof Customer)) return false;
        Customer c = (Customer) o;
        return Objects.equals(id, c.id);
    }
    @Override
    public int hashCode() {
        return Objects.hash(id);
    }
    // + toString(), jika perlu...
}

30+ baris. Harus update setiap kali ada field baru. Sumber bug kalau lupa update equals/hashCode.

✅ Dengan Lombok — Ekspresif
@Getter
@Setter
@NoArgsConstructor
@AllArgsConstructor
@EqualsAndHashCode(exclude = {"name"})
public class Customer {
    private String id;
    private String name;
}

7 baris. Lombok generate semua saat kompilasi. Tambah field baru? Otomatis ter-cover.

Cara Kerja Lombok — Annotation Processing
1
Kamu tulis Customer.java dengan annotation Lombok
2
Saat compile, Java Annotation Processor membaca annotation
3
Lombok memodifikasi AST (Abstract Syntax Tree) sebelum bytecode digenerate
4
Customer.class berisi getter/setter/constructor lengkap seolah kamu menulisnya manual
✓
IDE (IntelliJ / VS Code dengan plugin Lombok) bisa auto-complete semua generated method
⚠️ Wajib install plugin Lombok di IDE! Tanpa plugin, IDE tidak bisa "melihat" generated method sehingga semua pemanggilan getter/setter dianggap error meski kompilasi berhasil. Di IntelliJ: File → Settings → Plugins → cari "Lombok" → Install. Di VS Code: install extension Lombok Annotations Support for VS Code.
🐘 Analogi Laravel / PHP

Lombok di Java = Magic method PHP (__get, __set) + PHP 8 Constructor Promotion dikombinasikan. Tapi Lombok lebih kuat: hasilnya adalah kode nyata yang di-generate saat compile, bukan runtime magic. Juga mirip dengan Eloquent's fillable/casts yang menghilangkan kebutuhan menulis setiap accessor/mutator secara manual.

Chapter 1
⚙️ Setup — Maven Dependency & Spring Boot
Project ini menggunakan Spring Boot sebagai base, dengan Lombok sebagai dependency. Memahami setup Maven adalah pintu masuk sebelum menggunakan annotation apapun.
Dependency di pom.xml
<!-- pom.xml -->
<dependencies>

    <!-- Spring Boot Starter (optional, Lombok bisa dipakai tanpa Spring) -->
    <dependency>
        <groupId>org.springframework.boot</groupId>
        <artifactId>spring-boot-starter</artifactId>
    </dependency>

    <!-- Lombok — scope "provided" karena hanya butuh saat compile -->
    <dependency>
        <groupId>org.projectlombok</groupId>
        <artifactId>lombok</artifactId>
        <optional>true</optional>
    </dependency>

    <!-- JUnit untuk testing -->
    <dependency>
        <groupId>org.springframework.boot</groupId>
        <artifactId>spring-boot-starter-test</artifactId>
        <scope>test</scope>
    </dependency>

</dependencies>

<!-- Plugin build — exclude Lombok dari JAR final -->
<build>
    <plugins>
        <plugin>
            <groupId>org.springframework.boot</groupId>
            <artifactId>spring-boot-maven-plugin</artifactId>
            <configuration>
                <excludes>
                    <exclude>
                        <groupId>org.projectlombok</groupId>
                        <artifactId>lombok</artifactId>
                    </exclude>
                </excludes>
            </configuration>
        </plugin>
    </plugins>
</build>
<optional>true</optional> Lombok hanya diperlukan saat kompilasi, bukan saat runtime. Menandai optional mencegah Lombok ikut ter-bundle ke dalam JAR aplikasi final. Ini best practice karena bytecode yang sudah di-generate tidak membutuhkan Lombok lagi untuk berjalan. excludes plugin Konfigurasi Spring Boot Maven Plugin untuk memastikan Lombok tidak masuk ke executable JAR. Double protection bersama optional.
Entry Point — BelajarJavaLombokApplication.java
@SpringBootApplication
public class BelajarJavaLombokApplication {
    public static void main(String[] args) {
        SpringApplication.run(BelajarJavaLombokApplication.class, args);
    }
}

Ini adalah entry point Spring Boot standar. Di project ini Spring Boot dipakai sebagai "scaffolding" agar bisa pakai JUnit test dengan mudah, bukan karena Lombok memerlukan Spring.

💡 Lombok tanpa Spring Boot: Lombok adalah library pure Java — bisa dipakai di proyek Maven/Gradle biasa tanpa Spring. Cukup tambahkan dependency Lombok ke pom.xml dan install plugin IDE.
Chapter 2
📝 @Getter & @Setter — dengan AccessLevel
Annotation paling dasar Lombok. @Getter generate semua getter, @Setter generate semua setter. Bisa dipakai di level class (semua field) atau field individual (field tertentu saja), dengan kontrol access level.
@Getter & @Setter di Level Class — Customer.java
// Customer.java
@Getter           // ← generate getId() dan getName()
@Setter           // ← generate setId() dan setName()
@NoArgsConstructor
@AllArgsConstructor
@EqualsAndHashCode(exclude = {"name"})
public class Customer {
    private String id;
    private String name;
}
Apa yang Di-generate Lombok
// Kode yang SEOLAH ditulis Lombok (tidak ada di .java, ada di .class):
public String getId()   { return this.id; }
public String getName() { return this.name; }

public void setId(String id)     { this.id = id; }
public void setName(String name) { this.name = name; }
AccessLevel — Kontrol Visibilitas per Field — Login.java
// Login.java — kasus yang lebih kompleks
@Getter
@AllArgsConstructor(staticName = "create")
@NoArgsConstructor(staticName = "createEmpty")
@ToString(exclude = {"password"})
public class Login {

    @Setter(value = AccessLevel.PROTECTED)  // ← setter hanya bisa dipanggil dari subclass!
    private String username;

    @Setter(value = AccessLevel.PROTECTED)  // ← sama, setter protected
    private String password;
}
@Getter (class level) Generate getter untuk semua field dengan access level PUBLIC. Nama method mengikuti JavaBean convention: field name → getName(), field isActive (boolean) → isActive() bukan getIsActive(). @Setter (field level) @Setter bisa diletakkan di field spesifik dengan AccessLevel berbeda: PUBLIC (default), PROTECTED, PACKAGE, PRIVATE, atau NONE (tidak generate setter). AccessLevel.PROTECTED Setter hanya bisa dipanggil dari dalam class sendiri atau subclass-nya. Ini membuat username dan password hanya bisa diset melalui constructor (yang kita kontrol via Lombok), tidak bisa di-set sembarangan dari luar.
🧪 CustomerTest.java — Verifikasi Getter & Setter
@Test
void testCustomer() {
    var customer = new Customer();    // NoArgsConstructor
    customer.setId("100");            // generated setter
    customer.setName("Eko");          // generated setter

    System.out.println(customer.getId());   // generated getter → "100"
    System.out.println(customer.getName()); // generated getter → "Eko"
}

@Test
void testCustomerConstructor() {
    var customer = new Customer("ID", "NAME"); // AllArgsConstructor
    Assertions.assertEquals("ID",   customer.getId());
    Assertions.assertEquals("NAME", customer.getName());
}
❌ Jangan — @Setter di semua field sensitif
@Getter
@Setter // ← semua field bisa di-set dari mana saja
public class Login {
    private String username;
    private String password; // ← rawan! siapa saja bisa set password
}
✅ Benar — Batasi akses setter sensitif
@Getter
public class Login {
    // Setter hanya untuk subclass atau konstruksi internal
    @Setter(AccessLevel.PROTECTED)
    private String username;

    @Setter(AccessLevel.NONE) // tidak ada setter publik sama sekali
    private String password;
}
🐘 Analogi Laravel / PHP

@Getter = accessor di Eloquent (getNameAttribute()) atau PHP 8.1 readonly. @Setter(AccessLevel.PROTECTED) = protected function setPasswordAttribute() di Eloquent — setter yang tidak bisa dipanggil dari luar model. Bedanya Lombok tidak perlu kamu tulis method-nya sama sekali.

Chapter 3
🏗️ Constructor Annotations — @NoArgs, @AllArgs, @RequiredArgs
Tiga annotation constructor Lombok menutup semua kebutuhan: constructor kosong, constructor semua field, dan constructor hanya field yang wajib (final / @NonNull). Plus fitur staticName untuk factory method pattern.
Perbandingan Tiga Constructor Annotation
@NoArgsConstructor

Generate constructor tanpa parameter. Wajib ada untuk framework seperti JPA/Hibernate yang butuh instansiasi object kosong.

// Generate:
public Customer() {}
@AllArgsConstructor

Generate constructor dengan parameter untuk semua field, urut sesuai deklarasi field di class.

// Generate:
public Customer(String id, String name) {
    this.id = id;
    this.name = name;
}
@RequiredArgsConstructor

Generate constructor hanya untuk field final dan field @NonNull yang tidak punya initializer.

// Untuk Merchant (id = final):
public Merchant(String id) {
    this.id = id;
}
@RequiredArgsConstructor — Merchant.java
// Merchant.java
@Getter
@Setter
@RequiredArgsConstructor   // ← hanya generate constructor untuk field final
public class Merchant {

    private final String id;   // ← FINAL → masuk ke RequiredArgs constructor!

    private String name;       // ← tidak final → tidak masuk constructor, perlu setter
}
private final final = field yang wajib diset saat konstruksi dan tidak bisa diubah setelah itu. @RequiredArgsConstructor mendeteksi ini dan membuat parameter constructor untuknya. @Setter pada field final akan diabaikan Lombok — tidak mungkin ada setter untuk field final. private String name Non-final, tidak @NonNull → tidak masuk @RequiredArgsConstructor. Harus di-set via setter setelah konstruksi. Ini pola yang umum di JPA: id di-set via constructor, property lain via setter.
staticName — Factory Method Pattern — Login.java
// Login.java
@Getter
@AllArgsConstructor(staticName = "create")      // ← bukan "new Login()", tapi "Login.create()"
@NoArgsConstructor(staticName = "createEmpty")  // ← "Login.createEmpty()"
@ToString(exclude = {"password"})
public class Login {
    @Setter(value = AccessLevel.PROTECTED)
    private String username;

    @Setter(value = AccessLevel.PROTECTED)
    private String password;
}
// Yang di-generate Lombok:
// Constructor asli menjadi PRIVATE:
private Login() {}
private Login(String username, String password) { ... }

// Factory method static PUBLIC:
public static Login createEmpty() { return new Login(); }
public static Login create(String username, String password) {
    return new Login(username, password);
}
🧪 LoginTest.java — Verifikasi staticName
@Test
void testCreate() {
    // Pakai factory method, bukan "new Login()"
    var login1 = Login.createEmpty();
    Assertions.assertNull(login1.getUsername());
    Assertions.assertNull(login1.getPassword());

    var login2 = Login.create("eko", "rahasia");
    Assertions.assertEquals("eko",    login2.getUsername());
    Assertions.assertEquals("rahasia", login2.getPassword());
}

@Test
void testToString() {
    var login = Login.create("eko", "rahasia");
    System.out.println(login);
    // Output: Login(username=eko)  ← password tidak muncul karena @ToString(exclude)
}
💡 Keuntungan staticName: Constructor jadi private → tidak bisa diinstansiasi sembarangan dengan new. Factory method bisa punya nama yang lebih ekspresif (Login.create() lebih jelas dari new Login()). Ini adalah Static Factory Method Pattern ala Effective Java oleh Joshua Bloch.
🐘 Analogi Laravel / PHP

staticName = "create" = static function make() atau Model::create([]) di Laravel. Kamu sudah terbiasa dengan factory method di Laravel — Lombok membuatnya mudah di Java tanpa menulis kode factory secara manual. @RequiredArgsConstructor juga adalah cara standar Spring Boot melakukan constructor injection tanpa @Autowired.

Chapter 4
🔍 @ToString & @EqualsAndHashCode
Dua annotation yang paling sering salah dipakai — terutama di konteks inheritance. @EqualsAndHashCode(callSuper = true) dan exclude adalah detail penting yang wajib dipahami.
@ToString — Login.java & Product.java
// Login.java
@ToString(exclude = {"password"})  // ← sembunyikan password dari toString()
public class Login {
    private String username;
    private String password;
}
// Output Login.create("eko","rahasia").toString():
// Login(username=eko)   ← password tidak muncul!

// Product.java
@ToString(exclude = {"price"})  // ← sembunyikan price dari toString()
public class Product {
    private final String id;
    private String name;
    private Long price;
}
// Output: Product(id=P001, name=Laptop)   ← price tidak muncul
exclude Array nama field yang dikecualikan dari output toString(). Berguna untuk: field sensitif (password, token), field yang bisa menyebabkan infinite recursion (bidirectional relationship), atau field yang nilainya terlalu panjang/besar untuk di-log. Format default Format Lombok: ClassName(field1=value1, field2=value2). Bisa dikustomasi dengan @ToString(of = {"id", "name"}) untuk memilih field yang DIIKUTSERTAKAN (kebalikan dari exclude).
@EqualsAndHashCode — Customer.java (exclude field)
// Customer.java
@EqualsAndHashCode(exclude = {"name"})  // ← name diabaikan saat equals/hashCode
public class Customer {
    private String id;
    private String name;
}
🧪 CustomerTest.java — testEquals()
@Test
void testEquals() {
    var customer1 = new Customer("ID", "NAME 1"); // id sama, name beda
    var customer2 = new Customer("ID", "NAME 2"); // id sama, name beda

    // equals hanya cek field id (name di-exclude)
    Assertions.assertEquals(customer1, customer2);         // ← TRUE! name diabaikan
    Assertions.assertEquals(customer1.hashCode(), customer2.hashCode()); // ← sama
}
@EqualsAndHashCode + Inheritance — Employee & Manager
// Employee.java — parent class
@Getter @Setter @NoArgsConstructor
@EqualsAndHashCode               // ← hanya cek field Employee sendiri
public class Employee {
    private String id;
    private String name;
}

// Manager.java — child class
@Getter @Setter @NoArgsConstructor
@EqualsAndHashCode(callSuper = true)  // ← !! wajib jika mau ikutsertakan field parent
public class Manager extends Employee {
    private Integer totalEmployee;
}
🚨 Jebakan callSuper! 
// Tanpa callSuper = true di Manager:
var m1 = new Manager(); m1.setId("1"); m1.setTotalEmployee(10);
var m2 = new Manager(); m2.setId("2"); m2.setTotalEmployee(10);

m1.equals(m2); // ← TRUE! (salah!) — hanya cek totalEmployee, id diabaikan!
// karena callSuper default = false → field dari parent TIDAK dicek

// Dengan callSuper = true:
m1.equals(m2); // ← FALSE (benar) — id berbeda, jadi tidak sama
Aturan: Jika class extends class lain (bukan Object), selalu gunakan @EqualsAndHashCode(callSuper = true).
❌ Salah — lupa callSuper
@EqualsAndHashCode  // callSuper default false
public class Manager extends Employee {
    private Integer totalEmployee;
}
// equals() tidak cek id dan name dari Employee!
// Dua Manager berbeda bisa dianggap sama
✅ Benar — callSuper = true
@EqualsAndHashCode(callSuper = true)
public class Manager extends Employee {
    private Integer totalEmployee;
}
// equals() cek SEMUA field: id, name, totalEmployee
🐘 Analogi Laravel / PHP

@EqualsAndHashCode = override __equals() di PHP (tidak ada standar bawaan). Di Laravel, dua Eloquent Model dianggap sama jika primary key-nya sama ($model->is($other)). Lombok memberi kamu kontrol penuh: field mana yang ikut dalam perbandingan, termasuk field dari parent class.

Chapter 5
📦 @Data & @NonNull
@Data adalah "mega-annotation" yang menggabungkan @Getter + @Setter + @RequiredArgsConstructor + @ToString + @EqualsAndHashCode sekaligus. @NonNull menambahkan null-check otomatis. Bersama-sama di class Member.
@Data — Shortcut untuk Semua — Member.java
// Member.java
@Data              // ← generate: getter, setter, requiredArgsConstructor, toString, equals, hashCode
public class Member {

    @NonNull           // ← field ini tidak boleh null — generate null-check di constructor & setter
    private String id;

    @NonNull
    private String name;

    public String sayHello(@NonNull String name) {  // ← parameter method pun bisa @NonNull
        return "Hello " + name + ", my name is " + this.name;
    }
}
Apa yang Di-generate @Data
// @Data setara dengan menulis semua ini secara manual:

// Dari @Getter:
public String getId()   { return this.id; }
public String getName() { return this.name; }

// Dari @Setter (dengan null-check karena @NonNull):
public void setId(@NonNull String id) {
    if (id == null) throw new NullPointerException("id is marked @NonNull but is null");
    this.id = id;
}
public void setName(@NonNull String name) {
    if (name == null) throw new NullPointerException("name is marked @NonNull but is null");
    this.name = name;
}

// Dari @RequiredArgsConstructor (karena @NonNull = required):
public Member(@NonNull String id, @NonNull String name) {
    if (id == null)   throw new NullPointerException(...);
    if (name == null) throw new NullPointerException(...);
    this.id = id;
    this.name = name;
}

// Dari @ToString:
public String toString() { return "Member(id=" + id + ", name=" + name + ")"; }

// Dari @EqualsAndHashCode:
public boolean equals(Object o) { ... }
public int hashCode() { ... }

// @NonNull di parameter method:
public String sayHello(@NonNull String name) {
    if (name == null) throw new NullPointerException("name is marked @NonNull but is null");
    return "Hello " + name + ", my name is " + this.name;
}
🧪 MemberTest.java — Verifikasi @NonNull
@Test
void testConstructorNull() {
    // @NonNull → NullPointerException saat constructor dipanggil dengan null
    Assertions.assertThrows(NullPointerException.class, () -> {
        var member = new Member(null, null); // ← NPE dilempar Lombok
    });
}

@Test
void testSetterNull() {
    Assertions.assertThrows(NullPointerException.class, () -> {
        var member = new Member("Eko", "Eko");
        member.setName(null); // ← NPE di setter karena @NonNull
    });
}

@Test
void testMethodNull() {
    Assertions.assertThrows(NullPointerException.class, () -> {
        var member = new Member("Eko", "Eko");
        member.sayHello(null); // ← NPE di parameter karena @NonNull
    });
}
⚠️ Kapan TIDAK pakai @Data? @Data generate @EqualsAndHashCode dengan callSuper = false. Jika class extends class lain (bukan Object), kamu perlu menambahkan @EqualsAndHashCode(callSuper = true) secara eksplisit yang akan override behavior @Data. Juga, @Data tidak cocok untuk JPA Entity karena lazy-loaded field bisa menyebabkan masalah di equals/hashCode.
💡 @NonNull vs Java Optional vs assert:
@NonNull Lombok = fail-fast saat null masuk → NullPointerException dengan pesan yang jelas.
Objects.requireNonNull() = cara manual yang sama.
Keduanya lebih baik dari membiarkan NPE terjadi di tempat lain yang lebih susah di-debug.
🐘 Analogi Laravel / PHP

@Data = PHP 8 Constructor Promotion + readonly + #[Required] validation attribute sekaligus. @NonNull = Laravel Form Request 'field' => 'required' tapi di level class, bukan di layer HTTP. Bedanya Lombok bekerja saat runtime biasa, tidak hanya saat handle HTTP request.

Chapter 6
🔨 @Builder & @Singular — Builder Pattern Otomatis
Builder Pattern adalah cara terbaik membuat object kompleks dengan banyak field. Lombok men-generate seluruh Builder class beserta method-nya. @Singular adalah fitur khusus untuk field collection di Builder.
@Builder — Person.java
// Person.java
@Data
@Builder              // ← generate static inner class PersonBuilder
@AllArgsConstructor
@NoArgsConstructor
public class Person {
    private String id;
    private String name;
    private Integer age;

    @Singular             // ← generate method hobby() untuk add satu per satu ke list
    private List<String> hobbies;
}
Cara Menggunakan Builder
// PersonTest.java — createViaBuilder
var person = Person.builder()   // Person.builder() → PersonBuilder instance
    .id("id")
    .name("name")
    .age(30)
    .hobby("Game")      // ← @Singular: tambah satu elemen
    .hobby("Read")      // ← tambah lagi
    .hobby("Traveling") // ← tambah lagi
    .build();           // ← bangun Person object final

System.out.println(person);
// Person(id=id, name=name, age=30, hobbies=[Game, Read, Traveling])
Apa yang Di-generate @Builder + @Singular
// Lombok generate inner class PersonBuilder (disederhanakan):
public static class PersonBuilder {
    private String id;
    private String name;
    private Integer age;
    private ArrayList<String> hobbies; // internal list untuk @Singular

    public PersonBuilder id(String id)     { this.id = id; return this; }
    public PersonBuilder name(String name) { this.name = name; return this; }
    public PersonBuilder age(Integer age)  { this.age = age; return this; }

    // @Singular generate method SINGULAR (hobby, bukan hobbies):
    public PersonBuilder hobby(String hobby) {
        if (this.hobbies == null) this.hobbies = new ArrayList<>();
        this.hobbies.add(hobby);
        return this;
    }
    // Juga generate bulk method:
    public PersonBuilder hobbies(Collection<String> hobbies) {
        this.hobbies.addAll(hobbies);
        return this;
    }
    // Dan clear method:
    public PersonBuilder clearHobbies() { this.hobbies = null; return this; }

    public Person build() {
        // List di-wrap jadi unmodifiable sebelum diserahkan ke Person
        List<String> finalHobbies = this.hobbies == null
            ? Collections.emptyList()
            : Collections.unmodifiableList(this.hobbies);
        return new Person(id, name, age, finalHobbies);
    }
}

// Entry point:
public static PersonBuilder builder() { return new PersonBuilder(); }
@Singular Annotation field-level di field Collection. Lombok mendeteksi nama field (hobbies) → generate method singular (hobby()) untuk add satu elemen. Aturan naming: menghapus 's' di akhir. Untuk nama tidak beraturan, kamu bisa tentukan manual: @Singular("addHobby"). return this Setiap method builder mengembalikan this (instance Builder) → memungkinkan method chaining fluent API. Chapter 7
🔒 @Value & @With — Immutable Object
@Value adalah versi immutable dari @Data — semua field jadi final, tidak ada setter, class final. @With menambahkan "wither" method untuk membuat salinan object dengan satu field berbeda.
@Value + @With — Register.java
// Register.java
@Value   // ← @Data versi immutable: semua field final, tidak ada setter, class final
@With    // ← generate withXxx() method untuk "update dengan copy"
public class Register {
    String username;   // ← otomatis jadi "private final String username"
    String password;
}
Apa yang Di-generate @Value & @With
// @Value setara dengan:
public final class Register {              // ← class jadi final
    private final String username;         // ← semua field final
    private final String password;

    // @AllArgsConstructor (public)
    public Register(String username, String password) {
        this.username = username;
        this.password = password;
    }

    // @Getter (tidak ada setter!)
    public String getUsername() { return this.username; }
    public String getPassword() { return this.password; }

    // @ToString, @EqualsAndHashCode
    public String toString()    { return "Register(username=" + username + ", password=" + password + ")"; }
    public boolean equals(Object o) { ... }
    public int hashCode() { ... }
}

// @With generate method "copy-with-one-change":
public Register withUsername(String username) {
    return this.username == username ? this : new Register(username, this.password);
}
public Register withPassword(String password) {
    return this.password == password ? this : new Register(this.username, password);
}
🧪 RegisterTest.java — Verifikasi @With

    Assertions.assertEquals(register1.getPassword(), register2.getPassword()); // ← TRUE

    // register1.setUsername("other"); // ← tidak bisa, tidak ada setter!

💡 Mengapa Immutable Object? Object immutable adalah thread-safe secara alami — tidak perlu synchronization. Lebih mudah di-reason karena state tidak bisa berubah setelah konstruksi. Cocok untuk: DTO (Data Transfer Object), Value Object di Domain-Driven Design, object yang di-share antar thread.

🐘 Analogi Laravel / PHP

@Value = PHP 8.1 readonly class (semua property readonly). @With = pattern clone $obj; $clone->field = $value; di PHP, atau Eloquent $model->replicate()->fill(['field' => 'value']). Pola immutable + wither sangat umum di functional programming dan semakin populer di Java modern (Java 16+ Records adalah versi nativenya).

Chapter 8
🪵 @Slf4j, @Cleanup & @SneakyThrows
Tiga annotation yang menangani aspek berbeda: logging, manajemen resource, dan checked exception. Bersama di class FileHelper — contoh nyata membaca file dengan kode bersih.
FileHelper.java — Tiga Annotation Sekaligus
// FileHelper.java
@Slf4j                  // ← generate field: private static final Logger log = LoggerFactory.getLogger(FileHelper.class);
public class FileHelper {

    @SneakyThrows       // ← checked exception (IOException) jadi unchecked — tidak perlu try-catch atau throws
    public static String loadFile(String file) {
        log.info("Load file {}", file);  // ← pakai logger yang di-generate @Slf4j

        @Cleanup FileReader fileReader = new FileReader(file);  // ← auto-close saat keluar scope
        @Cleanup Scanner scanner = new Scanner(fileReader);     // ← auto-close juga

        StringBuilder builder = new StringBuilder();
        while (scanner.hasNextLine()) {
            builder.append(scanner.nextLine()).append("\n");
        }
        return builder.toString();
    }
}
@Slf4j — Logger Otomatis
// Tanpa @Slf4j — harus tulis ini di setiap class:
private static final Logger log = LoggerFactory.getLogger(FileHelper.class);

// Dengan @Slf4j — cukup taruh di atas class, Lombok generate field "log":
@Slf4j
public class FileHelper {
    public void doSomething() {
        log.info("Proses dimulai");          // ← langsung pakai
        log.debug("Debug: {}", someValue);   // ← SLF4J format {} bukan %s seperti printf
        log.warn("Hati-hati: {}", warning);
        log.error("Error: {}", e.getMessage(), e);
    }
}
@Slf4j Generate field logger SLF4J (Simple Logging Facade for Java). SLF4J adalah abstraksi logging — implementasi aktual bisa Logback (default Spring Boot), Log4j2, java.util.logging, dll. Format {} di pesan log adalah placeholder yang diisi saat log dipanggil, bukan saat string dibuat (lazy evaluation untuk performa). log.info("Load file {}", file) Lebih baik dari log.info("Load file " + file) karena string concatenation tidak terjadi jika level INFO dimatikan. Format {} hanya di-evaluate jika log level aktif.
@Cleanup — Auto-Close Resource
// Tanpa @Cleanup — verbose try-with-resources
public static String loadFile(String file) throws IOException {
    try (FileReader fileReader = new FileReader(file);
         Scanner scanner = new Scanner(fileReader)) {
        // ...
    }
}

// Dengan @Cleanup — lebih ringkas, Lombok generate try-finally di balik layar
@SneakyThrows
public static String loadFile(String file) {
    @Cleanup FileReader fileReader = new FileReader(file); // auto-close
    @Cleanup Scanner scanner = new Scanner(fileReader);    // auto-close
    // ...
}

// Yang di-generate Lombok (sama dengan try-with-resources):
FileReader fileReader = new FileReader(file);
try {
    Scanner scanner = new Scanner(fileReader);
    try {
        // ... logika
    } finally {
        scanner.close();  // ← selalu dipanggil
    }
} finally {
    fileReader.close(); // ← selalu dipanggil
}
@SneakyThrows — Bypass Checked Exception
// Java punya checked exception yang WAJIB di-handle:
// new FileReader(file) bisa throw IOException → wajib try-catch atau "throws IOException"

// Tanpa @SneakyThrows:
public static String loadFile(String file) throws IOException {  // ← wajib deklarasi
    // ...
}

// Dengan @SneakyThrows:
@SneakyThrows
public static String loadFile(String file) {  // ← tidak perlu "throws IOException"
    // Lombok bungkus exception dalam trick bytecode tanpa wrap ke RuntimeException
    // Exception masih dilempar dengan tipe aslinya saat runtime!
}
⚠️ Kapan TIDAK pakai @SneakyThrows? @SneakyThrows menyembunyikan informasi bahwa method bisa throw checked exception. Caller tidak tahu perlu handle exception apa. Gunakan hanya ketika kamu yakin exception tidak akan terjadi, atau kamu ingin sengaja "up-level" exception handling ke pemanggil yang lebih tinggi. Jangan pakai sembarangan hanya untuk menghindari try-catch.

Chapter 9
🔐 @Synchronized — Thread-Safe Method
@Synchronized adalah versi lebih aman dari keyword synchronized bawaan Java. Perbedaan kunci: lock object yang digunakan private, bukan this — mencegah deadlock dari luar class.
Counter.java — @Synchronized dengan Custom Lock
// Counter.java
public class Counter {

    private final Object counterLock = new Object(); // ← object khusus sebagai lock

    private Long counter = 0L;

    @Synchronized(value = "counterLock")  // ← pakai counterLock, bukan this
    public void increment() {
        counter = counter + 1;
    }

    @Synchronized(value = "counterLock")  // ← lock yang sama untuk read
    public Long getCounter() {
        return counter;
    }
}
Perbedaan @Synchronized vs synchronized Biasa
⚠️ synchronized(this) — Lock Publik
public synchronized void increment() {
    counter++;
}
// Lock pada "this" — siapapun bisa lock object ini dari luar:
Counter c = new Counter();
synchronized(c) {
    // Block ini menahan lock yang sama dengan increment()
    // → bisa sebabkan deadlock yang susah di-debug!
    Thread.sleep(10_000);
}
✅ @Synchronized — Lock Private
private final Object counterLock = new Object();

@Synchronized("counterLock")
public void increment() { counter++; }

// Lock pada counterLock yang private → tidak bisa diakses dari luar class
// Tidak ada risiko deadlock dari kode eksternal!
Yang Di-generate Lombok
// @Synchronized(value = "counterLock") setara dengan:
public void increment() {
    synchronized(this.counterLock) {  // ← lock pada private field
        this.counter = this.counter + 1;
    }
}

public Long getCounter() {
    synchronized(this.counterLock) {
        return this.counter;
    }
}
🧪 CounterTest.java — 100 Thread × 100 Increment
@Test
void testSynchronized() throws InterruptedException {
    // Buat 100 thread, masing-masing increment 100x = total harus 10.000
    for (int i = 0; i < 100; i++) {
        new Thread(() -> {
            for (int j = 0; j < 100; j++) {
                counter.increment(); // ← thread-safe karena @Synchronized
            }
        }).start();
    }

    Thread.sleep(5_000L); // tunggu semua thread selesai
    System.out.println(counter.getCounter());
    // Tanpa @Synchronized: bisa 9.743, 9.918, dll. (race condition)
    // Dengan @Synchronized: selalu 10.000 ✅
}
💡 Race Condition: Terjadi ketika dua thread membaca dan mengubah data yang sama secara bersamaan. counter = counter + 1 sebenarnya 3 langkah: (1) baca nilai, (2) tambah 1, (3) simpan hasil. Tanpa synchronization, thread A dan B bisa membaca nilai yang sama, keduanya menambah 1, dan menyimpan nilai yang sama — increment hilang!
🐘 Analogi Laravel / PHP

PHP umumnya single-threaded per request — race condition di level memory hampir tidak terjadi. Di Java, satu aplikasi bisa punya ratusan thread berjalan bersamaan. @Synchronized adalah padanan database lock di Laravel (lockForUpdate()) tapi di level memory Java, bukan di level database.
