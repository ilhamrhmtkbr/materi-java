Chapter 1
🧱 Class & Object
Class adalah blueprint (cetak biru). Object adalah instance-nya. Di Java, setiap kode harus berada di dalam class — tidak ada kode mengambang di luar class seperti PHP.
// File: src/Person.java
class Person {
    String name;      // field / atribut
    String address;
    final String country = "Indonesia";  // nilai tidak bisa diubah setelah assign
    // ... constructor dan method ...
}
Penjelasan Baris per Baris
class Person
Mendefinisikan class. Di Java, nama class HARUS sama dengan nama file (Person.java). Aturan ini keras — di PHP kamu bebas menaruh banyak class dalam satu file.
String name; String address;
Deklarasi field. Tipe data wajib dideklarasikan. String ditulis kapital karena dia adalah class di Java, bukan tipe primitif seperti int atau boolean.
final String country = "Indonesia";
Keyword final membuat field tidak bisa diubah setelah diassign. Coba person.country = "USA" → compile error langsung. Jaminan immutability per-instance.
✅ Best Practice: Gunakan final untuk nilai yang tidak boleh berubah. Compiler menjagamu dari bug aksidental — di PHP kamu perlu disiplin sendiri, di Java compiler yang jaga.
Di Laravel kamu membuat model seperti class User extends Model. Di Java murni (tanpa framework), class-mu adalah blueprint lengkap sendiri. Person di sini setara dengan POJO (Plain Old Java Object) — model sederhana tanpa ORM.
Common Mistakes

❌ Nama class ≠ nama file

// File: MyPerson.java
class Person { ... }

Error: class Person should be declared in Person.java

✅ Nama class = nama file

// File: Person.java
class Person { ... }

Satu public class per file.

🧠 Mini Quiz

Pernyataan mana yang BENAR tentang keyword final pada field instance di Java?

A.final di Java sama dengan const PHP — konstanta global.
B.Field final harus diassign saat deklarasi atau di constructor, dan tidak bisa diubah setelahnya.
C.final membuat field bersifat shared (berbagi nilai) antar semua object.
Chapter 2
🏗️ Constructor & Keyword this
Constructor adalah method khusus yang dipanggil saat object dibuat (new Person()). Di Java constructor bisa di-overload. Keyword this() memungkinkan satu constructor memanggil constructor lain — Constructor Chaining.
class Person {
    String name;
    String address;

    Person(String name, String address) {
        this.name = name;       // this.name = field; name = parameter
        this.address = address;
    }

    Person(String name) {
        this(name, null);  // delegasi ke Person(String, String)
    }

    Person() {
        this(null);  // delegasi ke Person(String)
    }

    void sayHello(String name) {
        System.out.println("Hello " + name + ", My Name is " + this.name);
    }
}
Penjelasan Baris per Baris
Person(String name, String address)
Constructor. Namanya HARUS sama dengan nama class. Tidak ada return type (bahkan void pun tidak). Di PHP ini setara __construct().
this.name = name;
this merujuk ke object yang sedang dibuat. this.name = field object; name = parameter constructor. Tanpa this, Java mengira keduanya variable yang sama — bug halus!
this(name, null);
Constructor Chaining. Constructor ini mendelegasikan ke yang lebih lengkap. Prinsip DRY — tidak perlu mengulang logika inisialisasi. this() WAJIB di baris pertama constructor.
💡 Keyword var (Java 10+)
var person1 = new Person("Eko", "Subang"); — compiler menyimpulkan tipe secara otomatis, tapi tetap strongly typed. Kamu tidak bisa assign person1 = 42 setelahnya.
Di Laravel, public function __construct(private UserRepository $repo) {} untuk inject dependency. Di Java (tanpa Spring), constructor adalah cara memaksa object selalu punya nilai tertentu saat dibuat. Constructor chaining dengan this() mirip pola PHP di mana satu __construct memanggil helper internal.
Common Mistakes

❌ Lupa this saat nama sama

Person(String name) {
    name = name; // TIDAK ada efek!
}

Tidak error compile, tapi field tidak ter-assign!

✅ Pakai this

Person(String name) {
    this.name = name; // ✅
}
🧠 Mini Quiz

Apa yang terjadi jika this() bukan di baris pertama constructor?

A.Program tetap jalan, this() boleh di posisi mana saja.
B.Compile error — this() harus selalu berada di baris pertama constructor.
C.Runtime error saat object dibuat.
Chapter 3
🌳 Inheritance (Pewarisan)
Inheritance memungkinkan class mewarisi semua field dan method dari class lain. Di Java keyword-nya extends. Java hanya mendukung single inheritance — satu class hanya bisa extends SATU class. Untuk multiple inheritance, Java gunakan Interface.
1
Employee
2
Manager extends Employee
3
VicePresident extends Manager
class Employee {
    String name;
    Employee(String name) { this.name = name; }
    void sayHello(String name) {
        System.out.println("Hi " + name + ", My Name Is Employee " + this.name);
    }
}

class Manager extends Employee {
    String company;
    Manager(String name) {
        super(name);        // panggil constructor Employee(String) — wajib pertama!
    }
    Manager(String name, String company) {
        super(name);
        this.company = company;
    }
    void sayHello(String name) {
        System.out.println("Hi " + name + ", My Name Is Manager " + this.name);
    }
}

class VicePresident extends Manager {
    VicePresident(String name) { super(name); }
    void sayHello(String name) {
        System.out.println("Hi " + name + ", My Name Is VP " + this.name);
    }
}
Penjelasan Baris per Baris
class Manager extends Employee
Manager mewarisi semua field dan method Employee — name dan sayHello() — tanpa menulis ulang.
super(name);
super() memanggil constructor parent. Jika parent tidak punya no-arg constructor, child WAJIB panggil super(...) di baris pertama. Berbeda dari PHP di mana parent::__construct() opsional.
this.company = company;
Manager menambahkan field baru yang tidak ada di Employee — cara memperkaya class induk.
⚡ Under the Hood: Semua class Java secara implisit mewarisi dari java.lang.Object. Ini kenapa manager.toString() bisa dipanggil meski tidak pernah didefinisikan — diwarisi dari Object.
Sama seperti class AdminController extends Controller di Laravel. super() setara parent::__construct() PHP — tapi WAJIB dilakukan jika parent tidak punya constructor kosong.

❌ Lupa super()

class Manager extends Employee {
    Manager(String name) {
        // lupa super(name)!
        this.company = "X";
    }
}

Compile error jika Employee tidak punya no-arg constructor.

✅ super() di baris pertama

class Manager extends Employee {
    Manager(String name) {
        super(name);  // ✅ pertama!
        this.company = "X";
    }
}
🧠 Mini Quiz

Mengapa Java hanya mendukung single inheritance (satu class hanya bisa extends satu class)?

A.Karena Java lebih lambat dan tidak mampu menangani kerumitan multiple inheritance.
B.Karena single inheritance lebih cepat secara performa.
C.Untuk menghindari "Diamond Problem" — ambiguitas ketika dua parent punya method yang sama. Java menggantinya dengan Interface untuk kebutuhan multiple type.
Chapter 4
🔄 Method Overriding & Keyword super
Method Overriding: class anak mendefinisikan ulang method yang ada di parent. Keyword super memanggil versi method parent dari dalam child.
class Shape {
    int getCorner() { return 0; }
}

class Rectangle extends Shape {
    @Override  // sangat direkomendasikan — compiler akan error jika nama salah ketik
    int getCorner() { return 4; }

    int getParentCorner() {
        return super.getCorner();  // akses versi Shape → 0
    }
}

// Contoh super pada field (Parent.java)
class Parent {
    String name;
    void doIt() { System.out.println("Do it in parent"); }
}

class Child extends Parent {
    String name;  // "menutupi" field parent

    void doIt() {
        System.out.println("Do it in child");
        System.out.println("Parent name: " + super.name);  // field Parent
    }
}

// final method — tidak bisa di-override
class Facebook extends SocialMedia {
    final void login(String username, String password) { /* ... */ }
}
// class FakeFacebook extends Facebook {
//     void login(...) { }  // ERROR — compile!
// }
Penjelasan Baris per Baris
@Override
Meminta compiler memverifikasi ada method yang sesuai di superclass. Jika salah ketik nama method (getCornerr), compiler langsung error — mencegah bug diam-diam yang sulit dilacak.
super.getCorner()
Secara eksplisit memanggil implementasi dari class Shape, bukan Rectangle. Berguna saat kamu ingin tetap menjalankan logika parent sambil menambahkan logika sendiri.
String name; (di Child)
Child punya field name-nya sendiri yang menutupi field name Parent. child.name = field Child; super.name = field Parent. Di ParentApp.java, saat Child di-cast ke Parent, parent.name mengakses field Parent yang nilainya null!
final void login(...)
Keyword final pada method = tidak bisa di-override oleh subclass apapun. Mekanisme keamanan eksplisit di level bahasa.
Di Laravel mirip saat override method di Controller. Di PHP tidak ada @Override tapi di Java sangat dianjurkan. Analogi final method di PHP adalah private method yang tidak bisa diakses child — tapi Java lebih tegas dengan melarang override secara eksplisit.
🧠 Mini Quiz

Apa akibat jika menulis @Override tapi nama method salah ketik (getCornerr())?

A.Program tetap jalan, Java mengabaikan @Override.
B.Compile error — compiler mendeteksi tidak ada method getCornerr() di parent yang bisa di-override.
C.Runtime error saat method dipanggil.
Chapter 5
🎭 Polymorphism & instanceof
Polymorphism = satu variabel bertipe Parent bisa menampung object dari class Child mana saja. Saat method dipanggil, Java otomatis memanggil versi yang sesuai tipe object sesungguhnya — bukan tipe variabelnya. Ini disebut Dynamic Dispatch.
Employee emp = new Employee("Eko");
emp.sayHello("Budi"); // → "Hi Budi, My Name Is Employee Eko"

emp = new Manager("Eko");    // upcasting — otomatis, tidak perlu cast eksplisit
emp.sayHello("Budi");        // → "Hi Budi, My Name Is Manager Eko"  ← versi Manager!

emp = new VicePresident("Eko");
emp.sayHello("Budi");        // → "Hi Budi, My Name Is VP Eko"

// Fungsi yang menerima Employee tapi handle semua subclass:
static void sayHello(Employee employee) {
    if (employee instanceof VicePresident) {     // cek tipe spesifik dulu!
        VicePresident vp = (VicePresident) employee;  // downcasting
        System.out.println("Hello VP " + vp.name);
    } else if (employee instanceof Manager) {
        Manager mgr = (Manager) employee;
        System.out.println("Hello Manager " + mgr.name);
    } else {
        System.out.println("Hello " + employee.name);
    }
}
Penjelasan Baris per Baris
emp = new Manager("Eko");
Variabel Employee bisa menyimpan object Manager karena Manager adalah Employee via inheritance. Ini upcasting — otomatis. Tapi lewat variabel emp, hanya bisa akses method yang ada di Employee.
emp.sayHello("Budi")
Meski variabel bertipe Employee, Java memanggil versi Manager karena object sesungguhnya adalah Manager. Keputusan diambil saat runtime — Dynamic Dispatch.
employee instanceof VicePresident
Operator instanceof mengecek tipe object sesungguhnya. Urutan PENTING: cek subclass paling spesifik dulu — VicePresident sebelum Manager, karena VicePresident juga adalah Manager.
(VicePresident) employee
Downcasting — paksa variabel tipe luas ke tipe spesifik. Selalu lakukan setelah instanceof check untuk menghindari ClassCastException.
💡 Pattern Modern: instanceof dengan Pattern Variable (Java 16+)
if (employee instanceof VicePresident vp) { System.out.println(vp.name); } — gabungkan check dan cast sekaligus. Lebih bersih!
Polymorphism di Laravel tampak di Eloquent: $model->sendNotification() bisa memanggil implementasi berbeda tergantung model. Di Java konsep yang sama tapi lebih eksplisit — tipe harus dideklarasikan, casting harus sadar dilakukan.
🧠 Mini Quiz

Kenapa pengecekan instanceof VicePresident harus dilakukan SEBELUM instanceof Manager?

A.Karena VicePresident adalah subclass Manager, maka VicePresident JUGA merupakan instance Manager. Jika cek Manager dulu, VicePresident masuk branch Manager.
B.Karena VicePresident lebih "penting" secara hierarki perusahaan.
C.Urutan tidak penting, Java menangani ini otomatis.
Chapter 6
🔒 Encapsulation & Access Modifier
Encapsulation = menyembunyikan detail internal class dan hanya mengekspos apa yang perlu. Di Java dilakukan dengan Access Modifier: private, protected, public. Field biasanya private, akses via getter/setter.
public class Category {
    private String id;          // tidak bisa diakses langsung dari luar
    private boolean expensive;

    public String getId() { return id; }  // getter: hanya baca

    public void setId(String id) {        // setter: bisa ditambahkan validasi
        if (id != null) {
            this.id = id;  // simpan hanya jika tidak null
        }
    }

    public boolean isExpensive() {  // boolean getter: isXxx, BUKAN getXxx!
        return expensive;
    }

    public void setExpensive(boolean expensive) {
        this.expensive = expensive;
    }
}
Penjelasan Baris per Baris
private String id;
private = hanya bisa diakses dari dalam class ini. category.id = "xyz" dari luar = compile error langsung. Ini melindungi integritas data.
setId() dengan validasi
Kekuatan encapsulation: logika bisnis masuk ke setter. Kode luar tidak perlu tahu aturan "null tidak boleh disimpan" — mereka cukup panggil setId() dan class yang menjaga konsistensinya sendiri.
public boolean isExpensive()
Konvensi Java: getter untuk tipe boolean menggunakan prefix is, bukan get. Penting untuk kompatibilitas framework Java seperti Jackson (JSON serialization) dan Spring.

Di Eloquent Laravel kamu bisa langsung $user->name = "Eko". Di Java dengan encapsulation proper, ini tidak diizinkan jika field private. Laravel punya konsep serupa: $fillable dan $guarded untuk proteksi mass assignment — di Java proteksinya lebih ketat dan dipaksa di level bahasa.
🧠 Mini Quiz

Kenapa getter untuk field boolean di Java menggunakan prefix is bukan get?

A.Hanya konvensi estetika, tidak ada dampak teknis.
B.Banyak framework Java (Jackson, Spring, JavaBean spec) menggunakan konvensi ini untuk refleksi otomatis — misalnya serialisasi JSON, isExpensive() dikenali sebagai properti expensive.
C.Karena getExpensive() akan error compile untuk tipe boolean.
Chapter 7
⚗️ Abstract Class
Abstract class adalah class yang tidak bisa diinstansiasi langsung. Tujuannya: menjadi template yang wajib di-extends. Bisa punya abstract method (tanpa implementasi) yang WAJIB diimplementasikan subclass.
// Animal.java
public abstract class Animal {
    public String name;
    public abstract void run();  // Wajib diimplementasikan subclass!
}

// Cat.java — subclass konkret
public class Cat extends Animal {
    public void run() {
        System.out.println("Cat " + name + " is run");
        // name diwarisi dari Animal, tidak perlu dideklarasikan ulang
    }
}

// Location.java
public abstract class Location {
    public String name;  // tidak ada abstract method → subclass bebas extends saja
}

// City.java
public class City extends Location {
    // tidak ada abstract method di Location, tidak perlu implement apa-apa
}

// LocationApp.java
// var location = new Location();  // ERROR! Cannot instantiate abstract class
var city = new City();             // ✅ City adalah class konkret
city.name = "Jakarta";
Penjelasan Baris per Baris
public abstract class Animal
Keyword abstract di depan class = tidak bisa di-new langsung. Memaksa programmer membuat subclass spesifik (Cat, Dog, Bird) sebelum bisa membuat object.
public abstract void run();
Method abstract tidak punya body (tidak ada { }), hanya signature. Ini "kontrak" — setiap subclass Animal WAJIB punya implementasi run(). Jika subclass tidak implement, compile error.
Cat mengakses name dari Animal
Cat tidak mendeklarasikan name tapi bisa menggunakannya karena diwarisi dari Animal. Di AnimalApp.java: animal.name = "Puss" bisa di-set dari luar lewat variabel bertipe Animal (polymorphism!).

🧠 Mini Quiz

Apa yang terjadi jika class Dog extends Animal tapi tidak mengimplementasikan run()?

A.Compile error — Dog dianggap masih abstract karena belum implement semua abstract method. Dog harus dideklarasikan abstract atau harus implement run().
B.Runtime error saat dog.run() dipanggil.
C.Java otomatis membuat implementasi kosong untuk run().
Chapter 8
🔌 Interface
Interface adalah kontrak murni — hanya mendefinisikan apa yang HARUS bisa dilakukan, tanpa implementasi (kecuali default method). Sebuah class bisa implements banyak interface sekaligus.
// HasBrand.java
public interface HasBrand { String getBrand(); }

// IsMaintenance.java
public interface IsMaintenance { boolean isMaintenance(); }

// Car.java — interface extends interface lain
public interface Car extends HasBrand, IsMaintenance {
    void drive();
    int getTier();
    default boolean isBig() { return false; }  // default: ada implementasi default
}

// Avanza.java
public class Avanza implements Car {
    public void drive() { System.out.println("Avanza drive"); }
    public int getTier() { return 4; }
    public String getBrand() { return "Toyota"; }
    public boolean isMaintenance() { return false; }
    // isBig() tidak diimplementasikan → pakai default dari Car
}

// Bus.java
public class Bus implements Car {
    public void drive() { System.out.println("Bus drive"); }
    public int getTier() { return 8; }
    public String getBrand() { return "HINO"; }
    public boolean isMaintenance() { return false; }
    public boolean isBig() { return true; }  // override default!
}

// Anonymous class dari interface
HelloWorld english = new HelloWorld() {
    public void sayHello() { System.out.println("Hello"); }
    public void sayHello(String name) { System.out.println("Hello " + name); }
};
Penjelasan Baris per Baris
interface Car extends HasBrand, IsMaintenance
Interface bisa extend banyak interface sekaligus — solusi Java untuk multiple inheritance. Class yang implement Car wajib implement semua method dari ketiga interface.
default boolean isBig()
default method (Java 8+) memberi implementasi default. Avanza tidak override → false otomatis. Bus override → true. Memungkinkan penambahan method baru ke interface tanpa merusak semua implementornya.
new HelloWorld() { ... }
Anonymous Class — implementasi interface sekali pakai tanpa membuat class terpisah. Di Java modern, untuk interface dengan satu method biasanya diganti Lambda: () -> System.out.println("Hello").
✅ Best Practice: Program to Interface, not Implementation
Car car = new Avanza(); — variabel bertipe Car (interface), bukan Avanza. Implementasi bisa diganti: Car car = new Bus(); tanpa mengubah kode lainnya. Ini fondasi Dependency Injection di Spring Boot.
Interface di Java mirip PHP Interface di Laravel: interface PaymentGatewayInterface { public function charge($amount); }. Lalu di AppServiceProvider: $this->app->bind(PaymentGatewayInterface::class, MidtransGateway::class). Di Java/Spring, konsep sama melalui Dependency Injection.
🧠 Mini Quiz

Keuntungan utama menggunakan tipe interface (Car car = new Avanza()) dibanding tipe konkret (Avanza car = new Avanza())?

A.Program berjalan lebih cepat karena interface lebih ringan.
B.Kode lebih fleksibel — implementasi bisa diganti tanpa mengubah kode yang menggunakan variabel tersebut (Loose Coupling / Open-Closed Principle).
C.Tidak ada perbedaan, ini hanya gaya penulisan.
Chapter 9
📌 Static, Constant & Static Initializer
Member static milik class, bukan instance. Tidak perlu membuat object untuk mengaksesnya. Static initializer (static { }) dijalankan sekali saat class pertama kali dimuat JVM.
// Constant.java
public class Constant {
    public static final String APPLICATION = "Belajar Java";
    public static final int VERSION = 1;
}

// MathUtil.java
public class MathUtil {
    public static int sum(int... values) {  // varargs: terima argument sejumlah apapun
        int total = 0;
        for (var value : values) { total += value; }
        return total;
    }
}

// Application.java — static initializer block
public class Application {
    public static final int PROCESSORS;

    static {  // Dijalankan SEKALI saat class pertama kali dimuat JVM
        System.out.println("Mengakses class Application");
        PROCESSORS = Runtime.getRuntime().availableProcessors();
    }
}

// StaticApp.java
import static programmer.zaman.now.data.Constant.*;  // static import!
System.out.println(APPLICATION);               // langsung, tanpa Constant.APPLICATION
System.out.println(MathUtil.sum(1,1,1,1,1));  // → 5
System.out.println(PROCESSORS);
Penjelasan Baris per Baris
public static final String APPLICATION = "Belajar Java";
Tiga keyword: public (akses dari mana saja), static (milik class, bukan instance), final (tidak bisa diubah). Pola konstanta standar Java — mirip const APPLICATION = 'Belajar Java'; PHP di dalam class.
public static int sum(int... values)
int... values adalah varargs — menerima argument sejumlah apapun. MathUtil.sum(1,1,1) dan MathUtil.sum(1,2,3,4,5) keduanya valid. Di PHP: function sum(int ...$values).
static { ... }
Static initializer block — dijalankan satu kali saat class dimuat JVM. Dipakai untuk inisialisasi PROCESSORS yang nilainya hanya bisa diketahui saat runtime. Tidak ada padanan langsung di PHP.
import static ...Constant.*;
Static import memungkinkan penggunaan static member tanpa prefix class. Setelah import ini, APPLICATION bisa ditulis langsung, bukan Constant.APPLICATION.
Static method di Java setara helper global Laravel atau Facade: Str::upper('hello'). Static constant mirip config('app.name'). Static initializer tidak ada padanannya langsung di PHP, tapi mirip logic di AppServiceProvider::boot() yang dijalankan sekali saat bootstrap.
🧠 Mini Quiz

Kapan static initializer block dieksekusi?

A.Setiap kali object dari class tersebut dibuat.
B.Tepat satu kali, saat class pertama kali dimuat ke memory oleh JVM — bisa karena diinstansiasi, atau karena static member-nya pertama kali diakses.
C.Saat program pertama kali dijalankan (main method).
Chapter 10
🪆 Inner Class & Static Nested Class
Java mendukung class di dalam class. Dua tipe utama: Non-static Inner Class (terikat ke instance outer class) dan Static Nested Class (independen).
// Company.java — Non-static Inner Class
public class Company {
    private String name;

    public class Employee {    // terikat ke instance Company
        private String name;

        public String getCompany() {
            return Company.this.name;  // akses outer class via ClassName.this
        }
    }
}

// CompanyApp.java
Company company = new Company();
company.setName("Programmer Zaman Now");

// Butuh instance company untuk membuat Employee!
Company.Employee employee = company.new Employee();
employee.setName("Eko");
System.out.println(employee.getCompany());  // → Programmer Zaman Now

// Country.java — Static Nested Class
public class Country {
    private String name;

    public static class City {  // tidak butuh Country instance
        private String name;
        // getter/setter...
    }
}

// StaticApp.java
Country.City city = new Country.City();  // langsung! tanpa Country instance
city.setName("Subang");
Penjelasan Baris per Baris
company.new Employee();
Sintaks unik Java untuk membuat non-static inner class. Kamu butuh instance outer class karena Employee menyimpan referensi implisit ke Company yang memilikinya.
Company.this.name
Mengakses instance outer class secara eksplisit. Tanpa Company.this, name merujuk ke field name milik Employee — bukan Company.
new Country.City()
Static Nested Class diakses seperti static member — tanpa perlu instance Country. Lebih independen karena tidak punya referensi ke outer class.
⚡ Kapan Pakai Mana?
Gunakan Non-static Inner Class jika inner class perlu mengakses data instance outer class. Gunakan Static Nested Class jika inner class hanya dikelompokkan secara logis bersama outer class tapi tidak butuh state-nya.
Konsep inner class tidak umum di PHP/Laravel. Padanan terdekat adalah class di sub-namespace secara hierarkis: App\Models\Company dan App\Models\Company\Employee (file terpisah). Java memungkinkan keduanya berada dalam satu file secara fisik.
🧠 Mini Quiz

Perbedaan utama Non-static Inner Class vs Static Nested Class?

A.Non-static Inner Class butuh instance outer class untuk dibuat dan bisa akses member outer class secara implisit. Static Nested Class tidak butuh instance outer class dan tidak bisa akses member instance outer class secara langsung.
B.Static Nested Class butuh instance outer class, Non-static Inner Class tidak.
C.Keduanya sama saja, hanya beda keyword.

📋 Enum
Enum (Enumeration) adalah tipe data khusus berisi sekumpulan konstanta bernama yang tetap. Di Java, enum jauh lebih powerful dari PHP — enum bisa punya constructor, field, dan method sendiri. Setiap konstanta enum adalah object!
// Level.java
public enum Level {
    STANDARD("Standard Level"),
    PREMIUM("Premium Level"),
    VIP("VIP Level");

    private String description;

    Level(String description) {  // constructor enum
        this.description = description;
    }

    public String getDescription() { return description; }
}

// EnumApp.java
Customer customer = new Customer();
customer.setLevel(Level.PREMIUM);  // type-safe! tidak bisa assign sembarangan

System.out.println(customer.getLevel());                   // → PREMIUM
System.out.println(customer.getLevel().getDescription());  // → Premium Level

String levelName = Level.VIP.name();    // → "VIP" (nama konstanta sebagai String)
Level level = Level.valueOf("PREMIUM"); // → Level.PREMIUM (String ke enum)

for (var value : Level.values()) {  // loop semua nilai enum
    System.out.println(value);
}
Penjelasan Baris per Baris
STANDARD("Standard Level"), ...
Setiap konstanta enum memanggil constructor enum dengan argumen. STANDARD adalah object dari tipe Level dengan field description = "Standard Level". Java enum adalah objek sesungguhnya — bukan sekadar integer!
Level.valueOf("PREMIUM")
Konversi String ke enum. Berguna saat menerima data dari database atau API. Jika string tidak cocok konstanta manapun → throw IllegalArgumentException. Selalu handle exception ini!
Level.values()
Method built-in semua enum — mengembalikan array semua nilai enum. Sangat berguna untuk iterasi, dropdown pilihan, atau validasi input.
💡 Enum itu Type-Safe!
Dengan tipe Level level, kamu tidak bisa assign level = "ULTRA" — compile error. Di PHP sebelum 8.1, biasanya pakai konstanta class: const PREMIUM = 'premium'; — tidak type-safe seperti Java enum.
PHP 8.1 memperkenalkan native enum: enum Level: string { case PREMIUM = 'premium'; }. Java enum lebih tua dan powerful — bisa punya method, field, bahkan implement interface! Di Laravel sebelum PHP 8.1, pattern enum biasanya menggunakan class konstanta — tidak seaman Java enum.
🧠 Mini Quiz

Apa yang terjadi jika memanggil Level.valueOf("ULTRA") padahal "ULTRA" tidak ada di enum?

A.Mengembalikan null.
B.Throw IllegalArgumentException saat runtime karena "ULTRA" tidak ada di enum Level.
C.Compile error karena compiler tahu "ULTRA" tidak valid.
Chapter 12
📦 Record (Java 16+)
Record adalah class khusus yang immutable, dirancang untuk membawa data. Compiler otomatis menggenerate: constructor, getter, equals(), hashCode(), dan toString(). Cocok untuk DTO, request body, dan value object.
// LoginRequest.java
record LoginRequest(String username, String password) {

    // Compact Constructor: validasi/modifikasi saat record dibuat
    public LoginRequest {
        System.out.println("Membuat object LoginRequest");
        // bisa tambahkan validasi: if (username == null) throw new ...
    }

    // Constructor tambahan harus memanggil canonical constructor
    public LoginRequest(String username) {
        this(username, "");
    }

    public LoginRequest() {
        this("", "");
    }
}

// RecordApp.java
LoginRequest req = new LoginRequest("eko", "rahasia");
// Output: "Membuat object LoginRequest"

System.out.println(req.username()); // getter: nama field langsung, BUKAN getUsername()!
System.out.println(req.password());
System.out.println(req);  // toString otomatis: LoginRequest[username=eko, password=rahasia]

// req.username = "lain"; // ERROR — record bersifat immutable!
Penjelasan Baris per Baris
record LoginRequest(String username, String password)
Satu baris ini otomatis menggenerate: 2 field private final, canonical constructor, accessor username() dan password(), plus equals(), hashCode(), toString(). Ini yang biasanya butuh puluhan baris di class biasa!
public LoginRequest { ... }
Compact Constructor — dijalankan saat canonical constructor dipanggil, tanpa mendefinisikan parameter lagi (sudah implicit). Cocok untuk validasi input atau normalisasi data.
req.username()
Getter di record menggunakan nama field langsung, bukan getUsername(). Berbeda dari Java Bean convention! Perhatikan ini jika mengintegrasikan Record dengan framework yang mengharapkan pola getXxx() — butuh konfigurasi tambahan.
⚡ Record = Immutable DTO
Record tidak bisa di-extends class lain (selain Object), tidak bisa di-extends oleh class lain, dan tidak bisa menambahkan instance field baru. Gunakan Record untuk data yang tidak berubah: request body, response payload, koordinat, dll.
Record di Java mirip DTO di Laravel yang dibuat dengan class constructor dan getter. Atau mirip PHP 8.2: readonly class LoginData { public function __construct( public readonly string $username, public readonly string $password ) {} }. Di Java ini built-in dengan keyword record.
🧠 Mini Quiz

Perbedaan getter method di Record (req.username()) vs getter di POJO biasa (req.getUsername())?

A.Record menggunakan nama field langsung tanpa prefix "get". Ini bisa menyebabkan masalah kompatibilitas dengan library yang mengharapkan konvensi JavaBean (seperti Jackson konfigurasi default).
B.Keduanya sama — compiler mengkonversi otomatis.
C.Record menggunakan getXxx() seperti POJO biasa.
Chapter 13
🚨 Exception Handling
Java memiliki hierarki exception yang ketat. Ada dua kategori: Checked Exception (wajib ditangani atau dideklarasikan) dan Unchecked/RuntimeException (opsional). Di PHP tidak ada checked exception — di Java, compiler memaksamu menanganinya.
/* Hierarki Exception di project ini:
   Throwable
   ├── Error
   │   └── DatabaseError (custom — masalah level sistem)
   └── Exception (Checked)
       ├── ValidationException (custom Checked — extends Throwable)
       └── RuntimeException (Unchecked)
           ├── NullPointerException (built-in)
           └── BlankException (custom — extends RuntimeException)
*/

// Method dengan checked exception — wajib deklarasikan throws!
public static void validate(LoginRequest req)
        throws ValidationException, NullPointerException {
    if (req.username() == null) throw new NullPointerException("Username is null");
    else if (req.username().isBlank()) throw new ValidationException("Username is blank");
}

// ValidationApp.java — try-catch-finally
try {
    ValidationUtil.validate(loginRequest);
    System.out.println("Data valid");
} catch (ValidationException | NullPointerException exception) {  // multi-catch!
    System.out.println("Tidak valid: " + exception.getMessage());
} finally {
    System.out.println("Selalu dieksekusi — cocok untuk cleanup");
}

// ReadApp.java — try-with-resources (auto-close!)
try (BufferedReader reader = new BufferedReader(new FileReader("README.md"))) {
    String line;
    while ((line = reader.readLine()) != null) { System.out.println(line); }
} catch (Throwable t) {
    System.out.println("Error: " + t.getMessage());
}
// reader otomatis di-close, bahkan jika terjadi exception!
Penjelasan Baris per Baris
Checked Exception — extends Throwable/Exception
ValidationException extends Throwable = checked exception. Method yang throw-nya WAJIB mendeklarasikan throws ValidationException di signature. Caller WAJIB catch atau mendeklarasikan juga. Compiler yang memaksa.
Unchecked — extends RuntimeException
BlankException extends RuntimeException — tidak wajib di-catch atau dideklarasikan. Lebih fleksibel dan biasa dipakai di aplikasi modern (Spring Boot hampir selalu pakai RuntimeException).
catch (ValidationException | NullPointerException exception)
Multi-catch (Java 7+) — menangkap beberapa tipe exception dalam satu blok. Mengurangi duplikasi kode handling.
try (BufferedReader reader = ...)
try-with-resources — resource yang ada di tanda kurung otomatis di-close saat block try selesai (normal maupun exception). Resource harus implement AutoCloseable. Cara modern dan aman untuk I/O di Java.
Di Laravel/PHP, semua exception adalah unchecked — bebas throw tanpa deklarasi. try-with-resources mirip PHP: try { $file = fopen(...); } finally { fclose($file); } tapi lebih elegan dan otomatis. Laravel Handler di app/Exceptions/Handler.php adalah padanan catch global di Java (Spring: @ControllerAdvice).
🧠 Mini Quiz

Kenapa Error (seperti DatabaseError) sebaiknya tidak di-catch dalam kode aplikasi biasa?

A.Karena Error adalah checked exception yang terlalu sulit ditangani.
B.Error merepresentasikan kondisi serius di luar kendali aplikasi (JVM crash, OOM). Menangkapnya membuat aplikasi terus jalan dalam state tidak aman — lebih berbahaya dari crash terkontrol.
C.Compiler melarang catch untuk Error.
Chapter 14
🏷️ Annotation & Custom Annotation
Annotation adalah metadata yang dilampirkan ke class, method, field, atau parameter. Annotation sendiri tidak menjalankan kode — hanya memberi label. Yang membaca dan memanfaatkan annotation adalah framework atau kode kita sendiri via Reflection.
// Fancy.java — membuat custom annotation
@Target({ElementType.TYPE, ElementType.METHOD})  // boleh di class & method
@Retention(RetentionPolicy.RUNTIME)              // bisa dibaca saat runtime
public @interface Fancy {
    String name();           // atribut wajib — harus diisi
    String[] tags() default {};  // atribut opsional — ada default value
}

// NotBlank.java — annotation marker (tanpa atribut)
@Target({ElementType.FIELD})
@Retention(RetentionPolicy.RUNTIME)
public @interface NotBlank { }

// Cara memakai annotation
@Fancy(name = "AnimalApp", tags = {"application", "java"})
public class AnimalApp { ... }

@Fancy(name = "main", tags = {"entry-point"})
public static void main(String[] args) { ... }

public class CreateUserRequest {
    @NotBlank
    private String username;

    @NotBlank
    private String password;

    private String name;  // tanpa @NotBlank — boleh kosong
}
Penjelasan Baris per Baris
@Target({ElementType.TYPE, ElementType.METHOD})
Mendefinisikan di mana annotation boleh dipasang. TYPE = class/interface/enum, METHOD = method, FIELD = field. Jika dipasang di tempat yang salah → compile error.
@Retention(RetentionPolicy.RUNTIME)
Menentukan kapan annotation tersedia. SOURCE = hilang saat compile; CLASS = ada di .class tapi tidak runtime; RUNTIME = bisa dibaca via Reflection saat program jalan. Untuk framework, hampir selalu pakai RUNTIME.
public @interface Fancy
Syntax khusus membuat annotation. Method di dalamnya mendefinisikan atribut annotation. Tanpa default berarti wajib diisi saat memakai annotation.
💡 Annotation Sendiri Tidak Berbuat Apa-apa
Annotation @Fancy di class tidak mengubah perilaku-nya sedikitpun. Annotation hanya berguna jika ada kode yang membacanya — via Reflection, atau via framework processor seperti Spring.
PHP Attributes (PHP 8.0+) adalah padanan annotation Java: #[Route('/dashboard')]. Sebelum PHP 8, Laravel menggunakan docblock annotations. Di Java, annotation sudah ada sejak Java 5 dan menjadi fondasi framework besar: Spring Boot (@Service, @Autowired, @GetMapping).
🧠 Mini Quiz

Perbedaan RetentionPolicy.CLASS vs RetentionPolicy.RUNTIME?

A.Tidak ada perbedaan signifikan — keduanya bisa dibaca saat runtime.
B.CLASS disimpan di .class file tapi tidak bisa dibaca via Class.getAnnotation() saat runtime. RUNTIME disimpan dan bisa dibaca via Reflection saat program berjalan.
C.CLASS hanya untuk class-level annotation, RUNTIME untuk semua level.
Chapter 15
🔍 Reflection API
Reflection adalah kemampuan program memeriksa dan memanipulasi dirinya sendiri saat runtime. Kamu bisa melihat field, method, annotation dari sebuah class tanpa tahu tipe-nya secara statis. Ini teknologi di balik Spring, Hibernate, dan Jackson.
// ValidationUtil.java — validasi via Reflection
public static void validationReflection(Object object) {
    Class aClass = object.getClass();          // 1. Dapatkan Class dari object
    Field[] fields = aClass.getDeclaredFields(); // 2. Dapatkan semua field (termasuk private)

    for (var field : fields) {
        field.setAccessible(true);             // 3. Izinkan akses ke private field

        if (field.getAnnotation(NotBlank.class) != null) {  // 4. Cek annotation @NotBlank
            try {
                String value = (String) field.get(object);  // 5. Baca nilai field

                if (value == null || value.isBlank()) {
                    throw new BlankException("Field " + field.getName() + " is blank");
                }
            } catch (IllegalAccessException e) {
                System.out.println("Tidak bisa mengakses field " + field.getName());
            }
        }
    }
}

// ReflectionApp.java
CreateUserRequest request = new CreateUserRequest();
request.setUsername("eko");
request.setPassword("eko");
request.setName("eko");
ValidationUtil.validationReflection(request);  // ✅ semua @NotBlank terisi → tidak exception
Penjelasan Baris per Baris
object.getClass()
Mendapatkan objek Class yang merepresentasikan tipe dari object. Dari sinilah semua informasi bisa digali — nama class, field, method, annotation, superclass, interface, dll.
aClass.getDeclaredFields()
Mendapatkan semua field yang dideklarasikan di class ini (termasuk private), tapi tidak termasuk field dari superclass. Untuk field superclass, gunakan getFields() (hanya public) atau iterasi rekursif ke superclass.
field.setAccessible(true)
"Memaksa" field private bisa diakses dari luar class. Ini melanggar enkapsulasi secara sengaja — hanya boleh dilakukan di kode framework/utility, tidak di kode bisnis biasa.
field.getAnnotation(NotBlank.class) dan field.get(object)
Membaca annotation di field, lalu membaca nilainya dari object. Inilah cara Bean Validation Spring (@NotNull, @Size, @Valid) bekerja — scan annotation di field saat runtime, validasi otomatis!
⚡ Reflection itu Lebih Lambat
Reflection lebih lambat dari akses field/method langsung karena ada JVM overhead. Gunakan dengan bijak — biasanya hanya di layer framework/utility, bukan di hot path bisnis. Framework seperti Spring menyimpan hasil refleksi dalam cache agar tidak diulang setiap request.
PHP juga punya Reflection API: $rc = new ReflectionClass($object). Laravel menggunakannya di Container untuk auto-resolve dependency (app()->make(UserService::class)) — scan constructor parameter dan inject dependency yang sesuai. Di Java/Spring, hal yang sama terjadi saat constructor injection di @Service.
🧠 Mini Quiz

Mengapa field.setAccessible(true) diperlukan saat mengakses private field via Reflection?

A.Karena Java secara default menghormati access modifier bahkan via Reflection. setAccessible(true) secara eksplisit mengizinkan bypass mekanisme kontrol akses untuk field/method tersebut.
B.Karena tanpa itu field tidak bisa dibaca nilainya, tapi masih bisa dilihat namanya.
C.Ini hanya formalitas, tidak berpengaruh pada akses.
Chapter 16
⚖️ equals(), hashCode() & Perbandingan Object
Di Java, operator == pada object membandingkan referensi memori, bukan nilai. Untuk membandingkan nilai, harus override equals(). Method hashCode() selalu harus diimplementasikan bersama equals() — kontrak yang dijaga Java Collection.
// EqualsApp.java — jebakan == pada String
String first = "Eko";
first = first + " " + "Khannedy";  // membuat String BARU di heap
String second = "Eko Khannedy";    // String literal (masuk string pool)

System.out.println(first == second);      // → false (beda referensi!)
System.out.println(first.equals(second)); // → true  (nilai sama) ✅

String third = "Eko Khannedy";
System.out.println(second == third);      // → true (mungkin — string pool)
System.out.println(second.equals(third)); // → true ✅ SELALU pakai equals untuk String!

// Product.java — override equals() dan hashCode()
@Override
public boolean equals(Object o) {
    if (this == o) return true;
    if (o == null || getClass() != o.getClass()) return false;
    Product product = (Product) o;
    if (price != product.price) return false;
    return name != null ? name.equals(product.name) : product.name == null;
}

@Override
public int hashCode() {
    int result = name != null ? name.hashCode() : 0;
    result = 31 * result + price;  // 31 = bilangan prima, distribusi hash bagus
    return result;
}

// ProductApp.java
Product p1 = new Product("Mac Book Pro", 30000000);
Product p2 = new Product("Mac Book Pro", 30000000);
System.out.println(p1.equals(p2));                   // → true ✅
System.out.println(p1.hashCode() == p2.hashCode());  // → true ✅
Penjelasan Baris per Baris
first == second → false
first adalah String baru hasil konkatenasi (object di heap). second adalah String literal. Meskipun nilainya sama secara karakter, referensi memory-nya berbeda → == false. Jebakan klasik!
second == third → true (mungkin)
Java mengoptimalkan String literal dengan String Pool — literal yang identik bisa berbagi referensi yang sama. Tapi ini detail JVM yang tidak boleh diandalkan dalam kode bisnis. Selalu gunakan .equals()!
result = 31 * result + price
31 adalah bilangan prima yang sering dipakai dalam hashCode karena menghasilkan distribusi hash yang baik. IDE modern (IntelliJ, Eclipse) bisa generate equals() dan hashCode() otomatis.
🚨 Kontrak equals-hashCode WAJIB dijaga!
Aturan: jika a.equals(b) true, maka a.hashCode() == b.hashCode() HARUS true. Jika override equals() tapi tidak override hashCode(), object berperilaku aneh di HashMap, HashSet — object yang "sama" menurut equals() bisa dianggap berbeda oleh koleksi!
Di PHP, == membandingkan nilai property object, sedangkan === membandingkan referensi. Di Java, == SELALU membandingkan referensi untuk object. Konsep hashCode() tidak ada di PHP, tapi krusial di Java untuk struktur data berbasis hash. Di Laravel: $user1->is($user2) (cek apakah ID sama) lebih mirip equals().
🧠 Mini Quiz

Jika menambahkan dua Product bernilai sama ke HashSet, tapi Product tidak override hashCode() (meskipun override equals()), apa yang terjadi?

A.HashSet menolak duplikat karena equals() sudah benar.
B.HashSet menerima keduanya — duplikat masuk! HashSet pertama cek hashCode(); jika berbeda, equals() tidak pernah dipanggil dan dianggap object berbeda.
C.Compile error karena tidak ada hashCode().
