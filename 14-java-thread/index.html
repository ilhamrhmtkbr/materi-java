Chapter 1

🧵 Thread — Unit Eksekusi Paralel

Thread adalah unit eksekusi terkecil dalam sebuah program. Setiap program Java sudah punya satu thread — main thread. Kamu bisa membuat thread tambahan untuk menjalankan kode secara paralel menggunakan Runnable + Thread.

// ThreadTest.java
public class ThreadTest {

  @Test
  void mainThread() {
    // Setiap program Java punya main thread
    var name = Thread.currentThread().getName();
    System.out.println(name); // "main"
  }

  @Test
  void createThread() {
    // Runnable = interface yang punya satu method: run()
    // Lambda () -> {} adalah implementasi Runnable
    Runnable runnable = () -> {
      System.out.println("Hello from thread : " + Thread.currentThread().getName());
    };

    var thread = new Thread(runnable); // buat thread, belum jalan
    thread.start();                    // MULAI thread — ini non-blocking!

    System.out.println("Program Selesai"); // mungkin muncul SEBELUM output thread!
  }
}
🚨 thread.start() ≠ thread.run()
  • thread.start() → menjalankan thread di background (non-blocking), eksekusi paralel ✅
  • thread.run() → memanggil method run() di thread yang SAMA seperti method biasa ❌
Kesalahan paling umum pemula: memanggil run() dan heran kenapa tidak paralel!
🔄 Thread State — Siklus Hidup Thread
NEW → start() → RUNNABLE → sleep/wait → BLOCKED/WAITING → wakeup → RUNNABLE → selesai → TERMINATED 
@Test
void threadState() throws InterruptedException {
  var thread = new Thread(() -> {
    System.out.println(Thread.currentThread().getState()); // RUNNABLE
    System.out.println("Run in thread : " + Thread.currentThread().getName());
  });
  thread.setName("Eko"); // beri nama thread untuk debugging

  System.out.println(thread.getState()); // NEW — belum di-start

  thread.start();
  thread.join(); // tunggu thread selesai

  System.out.println(thread.getState()); // TERMINATED
}

Chapter 2

😴 Sleep, Join & Interrupt

Tiga mekanisme penting untuk mengelola lifecycle thread: sleep (jeda sementara), join (tunggu thread lain selesai), dan interrupt (sinyal untuk menghentikan thread).

// Thread.sleep() — Jeda eksekusi (melempar InterruptedException!)
@Test
void threadSleep() throws InterruptedException {
  Runnable runnable = () -> {
    try {
      Thread.sleep(2_000L); // jeda 2 detik (dalam milidetik)
      System.out.println("Hello from thread : " + Thread.currentThread().getName());
    } catch (InterruptedException e) {
      e.printStackTrace(); // sleep diinterrupt
    }
  };

  var thread = new Thread(runnable);
  thread.start();
  System.out.println("Program Selesai"); // ini muncul DULU sebelum output thread
  Thread.sleep(3_000L); // main thread nunggu 3 detik agar thread selesai
}

// thread.join() — Tunggu thread selesai, cara yang BENAR
@Test
void threadJoin() throws InterruptedException {
  var thread = new Thread(() -> {
    try {
      Thread.sleep(2_000L);
      System.out.println("Hello from thread : " + Thread.currentThread().getName());
    } catch (InterruptedException e) {
      e.printStackTrace();
    }
  });

  thread.start();
  System.out.println("Menunggu Selesai");
  thread.join(); // BLOK main thread sampai 'thread' selesai
  System.out.println("Program Selesai"); // dijamin setelah thread selesai
}
// thread.interrupt() — Kirim sinyal interrupt ke thread
// PENTING: interrupt() tidak langsung menghentikan thread!
// Itu hanya SET FLAG interrupted = true

// ❌ Cara yang kurang tepat — InterruptedException tertangkap tapi loop jalan terus!
@Test
void threadInterrupt() throws InterruptedException {
  Runnable runnable = () -> {
    for (int i = 0; i < 10; i++) {
      System.out.println("Runnable : " + i);
      try {
        Thread.sleep(1_000L);
      } catch (InterruptedException e) {
        e.printStackTrace(); // hanya print, loop tetap lanjut!
      }
    }
  };
  var thread = new Thread(runnable);
  thread.start();
  Thread.sleep(5_000);
  thread.interrupt(); // set flag interrupted
  thread.join();
}

// ✅ Cara yang benar — Cek flag interrupt dan return
@Test
void threadInterruptCorrect() throws InterruptedException {
  Runnable runnable = () -> {
    for (int i = 0; i < 10; i++) {
      if (Thread.interrupted()) { // cek flag, dan RESET flag
        return;                   // keluar dari runnable
      }
      System.out.println("Runnable : " + i);
      try {
        Thread.sleep(1_000L);
      } catch (InterruptedException e) {
        return; // saat sleep diinterrupt, langsung return
      }
    }
  };
  var thread = new Thread(runnable);
  thread.start();
  Thread.sleep(5_000);
  thread.interrupt();
  thread.join();
}
⚠️ Interrupt bukan Kill! thread.interrupt() hanya mengirim "sinyal" — bukan memaksa thread berhenti. Thread yang menerima sinyal ini harus secara aktif memeriksa dan merespons. Kalau kamu tidak cek Thread.interrupted() atau tidak handle InterruptedException dengan benar, interrupt tidak akan berpengaruh apa-apa.
MethodDeskripsiMelempar Exception?

🟣 Analogi Laravel thread.join() seperti menunggu semua job dalam queue selesai sebelum lanjut. Di Laravel kamu pakai Bus::chain() atau Bus::batch()->then() untuk ini. Di Java, join() langsung di thread level tanpa perlu middleware tambahan.

Chapter 3

⚠️ Race Condition — Bahaya Akses Bersamaan

Race Condition terjadi ketika beberapa thread mengakses dan mengubah data yang sama secara bersamaan, menyebabkan hasil yang tidak terduga. Ini adalah bug yang sangat sulit direproduksi dan di-debug!

// Counter.java — Counter TIDAK thread-safe
public class Counter {
  private Long value = 0L;

  public void increment() {
    value++; // TIDAK AMAN! value++ sebenarnya 3 operasi:
             // 1. baca nilai value
             // 2. tambah 1
             // 3. tulis kembali
             // Thread lain bisa menyela di antara langkah ini!
  }

  public Long getValue() { return value; }
}

// RaceConditionTest.java
@Test
void counter() throws InterruptedException {
  var counter = new Counter();
  Runnable runnable = () -> {
    for (int i = 0; i < 1_000_000; i++) {
      counter.increment();
    }
  };

  var thread1 = new Thread(runnable);
  var thread2 = new Thread(runnable);
  var thread3 = new Thread(runnable);

  thread1.start();
  thread2.start();
  thread3.start();

  thread1.join();
  thread2.join();
  thread3.join();

  // HARAPAN: 3_000_000
  // KENYATAAN: angka acak lebih kecil, misal: 1_847_293
  System.out.println(counter.getValue());
}
🚨 Mengapa value++ Tidak Aman? Secara internal, value++ adalah 3 instruksi terpisah di level bytecode/CPU. Thread bisa disela (preempted) di antara instruksi ini. Bayangkan: Thread1 baca value=100, Thread2 baca value=100, Thread1 tulis 101, Thread2 tulis 101 — padahal seharusnya 102. Dua increment hilang!
❌ Tidak Thread-Safe
public class Counter {
  private Long value = 0L;

  public void increment() {
    value++; // Race condition!
  }
}
// 3 thread × 1jt increment
// Hasil: ~1.8jt (tidak konsisten)
✅ Thread-Safe (3 solusi)
// 1. synchronized
synchronized (this) { value++; }

// 2. AtomicLong
AtomicLong val = new AtomicLong(0);
val.incrementAndGet();

// 3. ReentrantLock
lock.lock();
try { value++; } finally { lock.unlock(); }
// Hasil: selalu 3_000_000 ✅
🟣 Analogi Laravel Race condition di PHP jarang terjadi karena PHP biasanya single-threaded per request. Tapi kamu mungkin pernah alami ini di level database: dua request bersamaan increment stock dari 10 → keduanya baca 10, keduanya tulis 9 — stok harusnya 8. Solusinya: DB::transaction() + lockForUpdate(). Di Java, masalah yang sama terjadi di memory level, dan butuh solusi di level thread.
🧠 Mini Quiz — Chapter 3

Mengapa operasi value++ tidak thread-safe meski terlihat seperti satu operasi?

🅐 Karena operator ++ tidak didukung di multi-threading
🅑 Karena value++ sebenarnya terdiri dari 3 instruksi (baca, tambah, tulis) yang bisa disela oleh thread lain di tengah-tengah
🅒 Karena tipe Long tidak mendukung concurrency
Chapter 4

🔐 Synchronized & Deadlock

Keyword synchronized adalah cara paling dasar untuk membuat blok kode thread-safe — hanya satu thread yang bisa masuk ke blok tersebut pada satu waktu. Tapi penggunaannya yang salah bisa menyebabkan Deadlock.

// SynchronizedCounter.java — Thread-safe dengan synchronized
public class SynchronizedCounter {
  private Long value = 0L;

  public void increment() {
    synchronized (this) { // kunci objek 'this'
      value++; // hanya 1 thread yang bisa masuk blok ini sekaligus
    }
  }

  public Long getValue() { return value; }
}

// SynchronizationTest.java
@Test
void counter() throws InterruptedException {
  var counter = new SynchronizedCounter();
  Runnable runnable = () -> {
    for (int i = 0; i < 1_000_000; i++) {
      counter.increment();
    }
  };

  var thread1 = new Thread(runnable);
  var thread2 = new Thread(runnable);
  var thread3 = new Thread(runnable);

  thread1.start(); thread2.start(); thread3.start();
  thread1.join(); thread2.join(); thread3.join();

  System.out.println(counter.getValue()); // SELALU 3_000_000 ✅
}
💀 Deadlock — Dua Thread Saling Menunggu Selamanya
// Balance.java — transferDeadlock() yang menyebabkan deadlock!
public static void transferDeadlock(Balance from, Balance to, Long value)
    throws InterruptedException {
  synchronized (from) {         // Thread1 kunci 'balance1'
    Thread.sleep(1000);         // Thread2 kunci 'balance2' saat ini
    synchronized (to) {         // Thread1 tunggu 'balance2' (dipegang Thread2)
      // Thread2 juga tunggu 'balance1' (dipegang Thread1)
      // → DEADLOCK! Keduanya saling menunggu selamanya
      from.setValue(from.getValue() - value);
      to.setValue(to.getValue() + value);
    }
  }
}

// Cara AMAN — Kunci SATU objek dalam satu waktu
public static void transfer(Balance from, Balance to, Long value)
    throws InterruptedException {
  synchronized (from) {
    Thread.sleep(1000);
    from.setValue(from.getValue() - value);
  }
  // Lepas kunci 'from' DULU, baru kunci 'to'
  synchronized (to) {
    Thread.sleep(1000);
    to.setValue(to.getValue() + value);
  }
}
🚨 Deadlock — Cara Mengenalinya Deadlock adalah kondisi di mana dua atau lebih thread saling menunggu satu sama lain melepas kunci (lock) — sehingga semua thread terhenti selamanya. Programmu akan "hang" tanpa error message. Di production, kamu bisa detect ini dengan thread dump: kill -3 <pid> atau gunakan VisualVM/JStack.
💡 Cara Mencegah Deadlock
  • Urutan lock konsisten: selalu kunci objek dalam urutan yang sama (A dulu, baru B)
  • Kunci seminimal mungkin: jangan tahan lock lebih lama dari perlu
  • Gunakan tryLock(): dari ReentrantLock, bisa timeout jika gagal dapat lock
  • Hindari nested lock: jangan kunci objek baru saat masih memegang lock lain
🧠 Mini Quiz — Chapter 4

Apa yang terjadi ketika terjadi Deadlock dalam sebuah program Java?

🅐 Program melempar DeadlockException dan keluar
🅑 Thread-thread yang terlibat hang selamanya — program tidak crash tapi juga tidak maju
🅒 JVM otomatis mendeteksi dan memutus deadlock
Chapter 5

🔒 Lock & Condition

ReentrantLock adalah alternatif synchronized yang lebih fleksibel: bisa tryLock() dengan timeout, bisa fairness, dan bisa punya banyak Condition. ReadWriteLock memungkinkan banyak pembaca atau satu penulis sekaligus.

// CounterLock.java — Menggunakan ReentrantLock
public class CounterLock {
  private Long value = 0L;
  final private Lock lock = new ReentrantLock();

  public void increment() {
    try {
      lock.lock();   // ambil kunci
      value++;
    } finally {
      lock.unlock(); // SELALU unlock di finally — walaupun ada exception!
    }
  }
}

// CounterReadWriteLock.java — Banyak reader, satu writer
public class CounterReadWriteLock {
  private Long value = 0L;
  final private ReadWriteLock lock = new ReentrantReadWriteLock();

  public void increment() { // WRITE — exclusive
    try {
      lock.writeLock().lock();
      value++;
    } finally {
      lock.writeLock().unlock();
    }
  }

  public Long getValue() { // READ — bisa paralel dengan reader lain
    try {
      lock.readLock().lock();
      return value;
    } finally {
      lock.readLock().unlock();
    }
  }
}
// LockTest.java — Condition: komunikasi antar thread yang lebih terstruktur
// Condition menggantikan wait()/notify() dengan cara yang lebih eksplisit
@Test
void condition() throws InterruptedException {
  var lock = new ReentrantLock();
  var condition = lock.newCondition(); // satu lock bisa punya banyak condition

  // Thread 1 & 3: MENUNGGU signal dari thread 2
  var thread1 = new Thread(() -> {
    try {
      lock.lock();
      condition.await();        // lepas lock dan tunggu signal
      System.out.println(message);
    } catch (InterruptedException e) { e.printStackTrace(); }
    finally { lock.unlock(); }
  });

  // Thread 2: MEMBERI signal ke semua thread yang menunggu
  var thread2 = new Thread(() -> {
    try {
      lock.lock();
      Thread.sleep(2000);
      message = "Eko Kurniawan";
      condition.signalAll();    // bangunkan semua thread yang await
    } catch (InterruptedException e) { e.printStackTrace(); }
    finally { lock.unlock(); }
  });
}

🧠 Mini Quiz — Chapter 5

Apa keunggulan ReadWriteLock dibanding synchronized biasa untuk data yang lebih sering dibaca dari diubah?

🅐 Tidak ada bedanya, keduanya sama-sama hanya boleh satu thread sekaligus
🅑 ReadWriteLock mengizinkan banyak thread membaca secara paralel — hanya operasi tulis yang eksklusif, sehingga throughput lebih tinggi
🅒 ReadWriteLock lebih lambat karena butuh dua lock terpisah
Chapter 6

⚛️ Atomic — Thread-Safe Tanpa Lock

Package java.util.concurrent.atomic menyediakan tipe data yang operasinya atomic — tidak bisa disela oleh thread lain. Lebih cepat dari synchronized karena menggunakan instruksi CPU khusus (CAS - Compare And Swap).

// CounterAtomic.java — Thread-safe TANPA lock eksplisit
import java.util.concurrent.atomic.AtomicLong;

public class CounterAtomic {
  private AtomicLong value = new AtomicLong(0L);

  public void increment() {
    value.incrementAndGet(); // atomic: baca + tambah + tulis = SATU operasi
  }

  public Long getValue() {
    return value.get();
  }
}

// AtomicTest.java
@Test
void counter() throws InterruptedException {
  var counter = new CounterAtomic();
  Runnable runnable = () -> {
    for (int i = 0; i < 1_000_000; i++) {
      counter.increment();
    }
  };

  var thread1 = new Thread(runnable);
  var thread2 = new Thread(runnable);
  var thread3 = new Thread(runnable);

  thread1.start(); thread2.start(); thread3.start();
  thread1.join(); thread2.join(); thread3.join();

  System.out.println(counter.getValue()); // SELALU 3_000_000 ✅
}
Class AtomicTipeMethod Utama
AtomicIntegerintincrementAndGet(), decrementAndGet(), addAndGet(n)
AtomicLonglongincrementAndGet(), getAndSet(val)
AtomicBooleanbooleancompareAndSet(expect, update)
AtomicReference<T>ObjectcompareAndSet(expect, update)
❌ Non-Atomic — Race Condition
private Long value = 0L;
public void increment() {
  value++; // 3 operasi, tidak aman
}
✅ Atomic — Tanpa Lock
private AtomicLong value = new AtomicLong(0L);
public void increment() {
  value.incrementAndGet(); // 1 operasi atomik
}
💡 Kapan pakai Atomic vs synchronized? Gunakan Atomic untuk operasi sederhana pada satu variabel (counter, flag, reference). Gunakan synchronized/Lock ketika kamu perlu mengamankan blok kode yang lebih kompleks atau beberapa variabel sekaligus.
🧠 Mini Quiz — Chapter 6

Mengapa AtomicLong.incrementAndGet() lebih cepat dari synchronized + value++?

🅐 Karena AtomicLong menggunakan thread pool internal
🅑 Karena Atomic menggunakan instruksi CPU khusus (CAS) yang tidak perlu blocking lock — lebih ringan untuk contention rendah
🅒 Atomic selalu lebih cepat dalam semua situasi
Chapter 7

🏪 ThreadLocal — Data Privat per Thread

ThreadLocal memberikan setiap thread salinan datanya sendiri. Thread satu tidak bisa melihat/mengubah data ThreadLocal milik thread lain. Solusi elegan untuk masalah berbagi state tanpa synchronization.

// UserService.java
public class UserService {
  // ThreadLocal: setiap thread punya 'user' masing-masing
  final ThreadLocal<String> threadLocal = new ThreadLocal<>();

  public void setUser(String user) {
    threadLocal.set(user); // simpan untuk thread ini saja
  }

  public void doAction() {
    var user = threadLocal.get(); // ambil milik thread ini
    System.out.println(user + " do action");
  }
}

// ThreadLocalTest.java
@Test
void test() throws InterruptedException {
  final var userService = new UserService();
  final var executor = Executors.newFixedThreadPool(10);

  for (int i = 0; i < 50; i++) {
    final var index = i;
    executor.execute(() -> {
      userService.setUser("User-" + index); // simpan user untuk thread ini
      Thread.sleep(1000 + random.nextInt(3000));
      userService.doAction(); // akan mencetak user MILIK thread ini
      // tidak ada campur aduk antar user!
    });
  }
}
🟣 Analogi Laravel ThreadLocal sangat mirip dengan konsep Request-scoped binding di Laravel Service Container, atau data dalam session() — setiap request (thread) punya datanya sendiri. Di Spring Boot, ThreadLocal dipakai untuk menyimpan user yang sedang login per request, database transaction context, dll. Framework Spring sendiri sangat banyak pakai ThreadLocal secara internal!
⚠️ Memory Leak dengan ThreadPool + ThreadLocal! Kalau kamu pakai ThreadLocal dalam ThreadPool, thread tidak mati setelah task selesai — thread di-reuse. Nilai ThreadLocal dari task sebelumnya masih tersimpan! Selalu panggil threadLocal.remove() setelah task selesai untuk mencegah memory leak dan data "bocor" ke task berikutnya. 
// ThreadLocalRandomTest.java — Versi thread-safe dari Random
// Random biasa tidak thread-safe; ThreadLocalRandom otomatis thread-safe dan lebih cepat!
@Test
void test() throws InterruptedException {
  final var executor = Executors.newFixedThreadPool(100);

  for (int i = 0; i < 100; i++) {
    executor.execute(() -> {
      // ThreadLocalRandom — random per-thread, tidak perlu sinkronisasi
      var number = ThreadLocalRandom.current().nextInt();
      System.out.println(number);
    });
  }
}

// Bisa juga menghasilkan stream angka random
ThreadLocalRandom.current().ints(1000, 0, 1000)
    .forEach(System.out::println);

Masalah apa yang muncul jika kamu pakai ThreadLocal tanpa memanggil remove() dalam Thread Pool?

🅐 NullPointerException karena nilai ThreadLocal hilang

🅒 Thread Pool crash karena terlalu banyak data tersimpan
Chapter 8

⚡ ExecutorService & Thread Pool

Membuat thread baru setiap saat itu mahal (costly). Thread Pool adalah kumpulan thread yang sudah siap, di-reuse untuk menjalankan task. ExecutorService adalah interface utama untuk mengelola Thread Pool di Java.

// ExecutorServiceTest.java
@Test

🔮 Future & Callable — Task yang Mengembalikan Nilai

Runnable tidak bisa mengembalikan nilai dan tidak bisa melempar checked exception. Callable<T> bisa keduanya. Hasilnya dikemas dalam Future<T> yang bisa kamu ambil nanti — seperti "janji" bahwa hasilnya akan ada.

// FutureTest.java
@Test
void testFuture() throws ExecutionException, InterruptedException {
  var executor = Executors.newSingleThreadExecutor();

  // Callable = seperti Runnable, tapi bisa return value dan throw exception
  Callable<String> callable = () -> {
    Thread.sleep(5000);
    return "hi"; // nilai yang akan dikembalikan
  };

  Future<String> future = executor.submit(callable); // submit task, dapat "janji"
  System.out.println("Selesai Submit"); // langsung dieksekusi, tidak menunggu!

  // Poll status future sambil menunggu
  while (!future.isDone()) {
    System.out.println("Waiting future...");
    Thread.sleep(1000);
  }

  String value = future.get(); // BLOK sampai hasil tersedia
  System.out.println(value);   // "hi"
}

🚀 CompletableFuture — Async Non-Blocking

CompletableFuture adalah evolusi dari Future yang mendukung chaining, composing, dan callback — mirip Promise di JavaScript. Kamu bisa buat pipeline async yang elegant tanpa memblokir thread manapun.

// CompletableFutureTest.java
private ExecutorService executorService = Executors.newFixedThreadPool(10);

// Membuat CompletableFuture secara manual
public CompletableFuture<String> getValue() {
  CompletableFuture<String> future = new CompletableFuture<>();

  executorService.execute(() -> {
    try {
      Thread.sleep(2000);
      future.complete("Eko Kurniawan Khannedy"); // selesaikan dengan nilai
    } catch (InterruptedException e) {
      future.completeExceptionally(e); // selesaikan dengan exception
    }
  });

  return future; // langsung return, tidak blocking!
}

@Test
void create() throws ExecutionException, InterruptedException {
  Future<String> future = getValue();
  System.out.println(future.get()); // "Eko Kurniawan Khannedy"
}

// Pattern: Perlombaan — ambil hasil dari thread TERCEPAT
private void execute(CompletableFuture<String> future, String value) {
  executorService.execute(() -> {
    Thread.sleep(1000 + random.nextInt(5000));
    future.complete(value); // complete() hanya berpengaruh SEKALI (yang pertama menang!)
  });
}

public Future<String> getFastest() {
  CompletableFuture<String> future = new CompletableFuture<>();
  execute(future, "Thread 1");
  execute(future, "Thread 2");
  execute(future, "Thread 3");
  return future; // siapapun yang selesai duluan, itulah hasilnya
}

@Test

  // Pipeline: getValue() → toUpperCase() → split() → selesai
  String[] strings = future2.get();
  for (var value : strings) {
    System.out.println(value); // EKO, KURNIAWAN, KHANNEDY
  }
}

📬 Blocking Queue — Antrian Thread-Safe

BlockingQueue adalah antrian thread-safe yang mem-blokir thread yang mencoba memasukkan data ke antrian yang penuh, atau mengambil data dari antrian yang kosong. Pattern Producer-Consumer yang sempurna.

// BlockingQueueTest.java — ArrayBlockingQueue: bounded, FIFO
@Test
void arrayBlockingQueue() throws InterruptedException {
  final var queue    = new ArrayBlockingQueue<String>(5); // max 5 element
  final var executor = Executors.newFixedThreadPool(20);

  // Producer — 10 thread ingin PUT data
  for (int i = 0; i < 10; i++) {
    executor.execute(() -> {
      queue.put("Data"); // BLOK kalau queue penuh (kapasitas 5)!
      System.out.println("Finish Put Data");
    });
  }

  // Consumer — 1 thread mengambil data setiap 2 detik
  executor.execute(() -> {
    while (true) {
      Thread.sleep(2000);
      var value = queue.take(); // BLOK kalau queue kosong!
      System.out.println("Receive data : " + value);
    }
  });

  executor.awaitTermination(1, TimeUnit.DAYS);
}

🗺️ Concurrent Collections & CompletionService

Collections biasa (HashMap, ArrayList) tidak thread-safe. Java menyediakan versi thread-safe di package java.util.concurrent. CompletionService adalah kombinasi ExecutorService + BlockingQueue untuk mengambil hasil task sesuai urutan selesainya.

// ConcurrentMapTest.java — ConcurrentHashMap: thread-safe HashMap
@Test
void concurrentMap() throws InterruptedException {
  final var countDown = new CountDownLatch(100);
  final var map       = new ConcurrentHashMap<Integer, String>();
  final var executor  = Executors.newFixedThreadPool(100);

  // 100 thread menulis ke map bersamaan — AMAN!
  for (int i = 0; i < 100; i++) {
    final var index = i;
    executor.execute(() -> {
      map.putIfAbsent(index, "Data-" + index); // atomic: cek + put sekaligus
      countDown.countDown();
    });
  }

  executor.execute(() -> {
    countDown.await(); // tunggu semua selesai
    map.forEach((k, v) -> System.out.println(k + " : " + v));
  });
}

⬇️ CountDownLatch, CyclicBarrier & Phaser

Tiga mekanisme untuk koordinasi antar thread — menunggu beberapa thread mencapai titik tertentu sebelum melanjutkan eksekusi.

// CountDownLatchTest.java — Tunggu N thread selesai, lalu lanjut
// CountDownLatch seperti "countdown": mulai dari N, hitung mundur ke 0, lanjut
@Test
void test() throws InterruptedException {
  final var countDownLatch = new CountDownLatch(5); // tunggu 5 event
  final var executor       = Executors.newFixedThreadPool(10);

  // 5 task yang berjalan paralel
  for (int i = 0; i < 5; i++) {
    executor.execute(() -> {
      System.out.println("Start Task");
      Thread.sleep(2000);
      System.out.println("Finish Task");
      countDownLatch.countDown(); // kurangi counter 1
    });
  }

  // Task ini menunggu counter mencapai 0
  executor.execute(() -> {
    countDownLatch.await(); // BLOK sampai counter = 0
    System.out.println("Finish All Tasks"); // setelah semua 5 task selesai
  });
}

// CyclicBarrierTest.java — Semua thread tunggu di "garis start" yang sama
// Setelah SEMUA thread tiba → semua boleh lanjut bersamaan
@Test
void test() throws InterruptedException {

  final var executor       = Executors.newFixedThreadPool(10);

  for (int i = 0; i < 5; i++) {
    executor.execute(() -> {
      System.out.println("Waiting");  // thread tiba di barrier
      cyclicBarrier.await();          // tunggu 4 thread lain
      System.out.println("Done Waiting"); // semua 5 thread lanjut bersamaan
    });
  }
}

🚦 Semaphore & Exchanger

Semaphore membatasi berapa banyak thread yang bisa mengakses resource tertentu secara bersamaan. Exchanger memungkinkan dua thread bertukar data di titik tertentu.

// SemaphoreTest.java — Batasi concurrent access ke resource
@Test
void test() throws InterruptedException {
  final var semaphore = new Semaphore(10); // hanya 10 "tiket" tersedia
  final var executor  = Executors.newFixedThreadPool(100);

  for (int i = 0; i < 1000; i++) {
    executor.execute(() -> {
      semaphore.acquire(); // ambil 1 tiket — BLOK jika semua 10 tiket habis
      try {
        Thread.sleep(1000); // gunakan resource
        System.out.println("Finish");
      } finally {
        semaphore.release(); // kembalikan tiket — thread lain bisa lanjut
      }
    });
  }
  // Meski ada 1000 task dan 100 thread, hanya 10 yang "di dalam" sekaligus
}

// ExchangerTest.java — Dua thread bertukar data
@Test
void test() throws InterruptedException {
  final var exchanger = new Exchanger<String>();
  final var executor  = Executors.newFixedThreadPool(10);

  executor.execute(() -> {
    System.out.println("Thread 1 : Send : First");
    Thread.sleep(1000);
    var result = exchanger.exchange("First"); // kirim "First", TUNGGU thread lain
    System.out.println("Thread 1 : Receive : " + result); // dapat "Second"
  });

  executor.execute(() -> {
    System.out.println("Thread 2 : Send : Second");
    Thread.sleep(2000);
    var result = exchanger.exchange("Second"); // kirim "Second", TUNGGU thread lain
    System.out.println("Thread 2 : Receive : " + result); // dapat "First"
  });
}

🍴 ForkJoin & Parallel Stream

ForkJoinPool adalah thread pool khusus untuk algoritma divide and conquer — bagi tugas jadi lebih kecil (fork), kerjakan paralel, gabungkan hasilnya (join). Parallel Stream menggunakan ForkJoinPool secara otomatis di balik layar.

// ForkJoinTest.java — RecursiveAction (tidak return nilai)
public static class SimpleForkJoinTask extends RecursiveAction {
  private List<Integer> integers;

  public SimpleForkJoinTask(List<Integer> integers) { this.integers = integers; }

  @Override
  protected void compute() {
    if (integers.size() <= 10) {
      doExecute(); // cukup kecil → langsung kerjakan
    } else {
      forkCompute(); // terlalu besar → bagi dua
    }
  }

  private void forkCompute() {
    var half   = integers.size() / 2;
    var left   = new SimpleForkJoinTask(integers.subList(0, half));
    var right  = new SimpleForkJoinTask(integers.subList(half, integers.size()));
    ForkJoinTask.invokeAll(left, right); // jalankan paralel dan tunggu
  }

  private void doExecute() {
    integers.forEach(i -> System.out.println(Thread.currentThread().getName() + ":" + i));
  }
}

// RecursiveTask — ForkJoin yang mengembalikan nilai
public static class TotalRecursiveTask extends RecursiveTask<Long> {
  @Override
  protected Long compute() {
    if (integers.size() <= 10) {
      return doCompute(); // hitung subtotal
    } else {
      var task1 = new TotalRecursiveTask(left);
      var task2 = new TotalRecursiveTask(right);
      ForkJoinTask.invokeAll(task1, task2);
      return task1.join() + task2.join(); // gabungkan subtotal
    }
  }
}

// Menjalankan ForkJoin Task
var pool = ForkJoinPool.commonPool(); // shared pool berbasis jumlah CPU core
var task = new SimpleForkJoinTask(integers);
pool.execute(task);

// Parallel Stream — ForkJoin tanpa boilerplate!
Stream<Integer> stream = IntStream.range(0, 1000).boxed();
stream.parallel().forEach(integer -> {
  System.out.println(Thread.currentThread().getName() + " : " + integer);
  // Diproses oleh beberapa thread dari ForkJoinPool.commonPool() secara otomatis!
});

// Custom pool untuk parallel stream (agar tidak berbagi commonPool)
var pool = new ForkJoinPool(4); // hanya 4 thread
ForkJoinTask<?> task = pool.submit(() -> {
  stream.parallel().forEach(integer -> { /* diproses oleh pool ini */ });
});
task.join();
💡 Kapan pakai Parallel Stream? Parallel Stream cocok untuk operasi yang: (1) CPU-intensive (bukan I/O), (2) data besar (ratusan ribu elemen+), (3) operasinya independen (tidak saling bergantung). Jangan pakai untuk stream kecil — overhead pembagian task lebih besar dari keuntungannya!
⚠️ Hati-hati dengan ForkJoinPool.commonPool() stream.parallel() menggunakan ForkJoinPool.commonPool() yang dipakai bersama seluruh aplikasi. Kalau kamu melakukan I/O blocking di parallel stream (HTTP call, DB query), kamu bisa memblokir semua core CPU untuk I/O wait. Untuk I/O, tetap pakai ExecutorService terpisah!
🧠 Mini Quiz — Chapter 14A

Kapan tidak sebaiknya menggunakan Parallel Stream?

🅐 Ketika data sangat besar (jutaan elemen)
🅑 Ketika operasinya melibatkan I/O blocking (database, HTTP), atau ketika data terlalu kecil sehingga overhead lebih besar dari keuntungannya
🅒 Ketika dijalankan di server dengan banyak CPU core

📡 Reactive Stream & Timer

Reactive Stream (Java 9+) adalah standar untuk async stream dengan backpressure — consumer bisa memberi tahu producer untuk memperlambat kalau kewalahan. Timer adalah cara sederhana untuk menjalankan task setelah delay atau secara periodik.

// TimerTest.java — Timer: cara simpel untuk delayed/periodic task
@Test
void delayedJob() throws InterruptedException {
  var task = new TimerTask() {
    @Override
    public void run() {
      System.out.println("Delayed Job"); // dijalankan setelah 2 detik
    }
  };

  var timer = new Timer();
  timer.schedule(task, 2000); // jalankan SEKALI setelah 2000ms
  Thread.sleep(3000L);
}

@Test
void periodicJob() throws InterruptedException {
  var task = new TimerTask() {
    @Override
    public void run() { System.out.println("Periodic Job"); }
  };

  var timer = new Timer();
  timer.schedule(task, 2000, 2000); // mulai setelah 2 detik, lalu setiap 2 detik
  Thread.sleep(10_000L); // lihat 4 kali output
}

// ReactiveStreamTest.java — Publisher-Subscriber dengan backpressure
@Test
void publish() throws InterruptedException {
  var publisher   = new SubmissionPublisher<String>();
  var subscriber1 = new PrintSubscriber("A", 1000L); // lambat, 1 item/detik
  var subscriber2 = new PrintSubscriber("B", 500L);  // cepat, 2 item/detik

  publisher.subscribe(subscriber1); // daftarkan subscriber
  publisher.subscribe(subscriber2);

  // Publish 100 item — SubmissionPublisher otomatis tangani backpressure
  for (int i = 0; i < 100; i++) {
    publisher.submit("Eko-" + i); // kalau subscriber lambat, submit akan BLOK
    System.out.println("Send Eko-" + i);
  }
}

// Dengan Processor — transform data di pipeline
@Test
void processor() throws InterruptedException {
  var publisher  = new SubmissionPublisher<String>();
  var processor  = new HelloProcessor(); // transform String → String baru
  var subscriber = new PrintSubscriber("A", 1000L);

  publisher.subscribe(processor);  // publisher → processor
  processor.subscribe(subscriber); // processor → subscriber
  // Pipeline: publisher → [transform] → subscriber
}

Di Spring Boot modern, reactive programming diimplementasi via Project Reactor (Mono, Flux) yang merupakan implementasi Reactive Streams yang jauh lebih kaya fitur.

Apa tujuan dari konsep "backpressure" dalam Reactive Stream?

🅐 Mempercepat producer agar tidak ada data yang terlewat
🅑 Memberi consumer kemampuan untuk memberi sinyal ke producer agar memperlambat pengiriman data, mencegah consumer kewalahan (overwhelmed)

🧠 Key Mindset — PHP vs Java Concurrency
1️⃣
PHP single-thread per request, Java multi-thread dalam satu proses. Race condition yang kamu anggap tidak mungkin di PHP, sangat mungkin terjadi di Java ketika beberapa thread mengakses shared state.
2️⃣
Jangan buat thread baru setiap saat. Selalu gunakan Thread Pool (ExecutorService). Membuat thread itu mahal — ada overhead memory dan CPU untuk context switching.
3️⃣
Prefer immutable objects. Data yang tidak bisa diubah tidak perlu synchronization. Di Java, gunakan final field dan desain class agar tidak mutable.
4️⃣
Gunakan class dari java.util.concurrent. Jangan re-invent the wheel. AtomicLong, ConcurrentHashMap, BlockingQueue sudah ditest dan dioptimasi oleh para ahli.
5️⃣
Deadlock lebih berbahaya dari race condition. Race condition menghasilkan data salah — masih bisa terdeteksi. Deadlock membuat aplikasi hang selamanya tanpa log error yang jelas.
6️⃣
ThreadLocal.remove() selalu! Di Thread Pool, thread di-reuse. Data ThreadLocal lama akan "bocor" ke request berikutnya jika tidak di-remove — bug yang sangat sulit ditemukan!
