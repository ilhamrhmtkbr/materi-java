Chapter 0
🧠 Mindset — PHP Array vs Java Collections
Di PHP, satu array bisa melakukan segalanya. Di Java, ada tipe koleksi khusus untuk setiap kebutuhan — dan ini adalah kekuatan, bukan kerumitan.
Masalah dengan "One-Size-Fits-All"

PHP array adalah Swiss Army Knife — bisa list, bisa hashmap, bisa stack, bisa queue, semuanya pakai satu tipe. Fleksibel, tapi tidak mengkomunikasikan niat kode. Di Java, kamu memilih tipe koleksi yang tepat untuk kasus yang tepat.

🐘 PHP — Satu array untuk segalanya
// PHP: array bisa jadi apa saja, niat tidak jelas
$list   = ["Eko", "Budi"];        // list
$map    = ["name" => "Eko"];      // hashmap
$stack  = [];                      // stack?
array_push($stack, "a");
$top    = array_pop($stack);       // sepertinya stack...
$queue  = [];
array_push($queue, "a");
$front  = array_shift($queue);     // queue? susah tahu!
☕ Java — Tipe berbeda, niat jelas
// Java: tipe koleksi mengkomunikasikan niat
List<String> list = new ArrayList<>();   // jelas: list
Map<String, String> map = new HashMap<>(); // jelas: key-value
Deque<String> stack = new LinkedList<>(); // jelas: stack (LIFO)
Queue<String> queue = new ArrayDeque<>(); // jelas: queue (FIFO)
💡 Manfaat langsung: Saat kamu lihat Queue<T> di kode orang lain, kamu langsung tahu ini FIFO tanpa baca dokumentasi. Kode yang menggunakan tipe yang tepat adalah self-documenting code.
Generics — <T> Itu Apa?

Hampir semua koleksi Java menggunakan Generics — parameter tipe yang ditulis di dalam < >. Ini adalah cara Java memastikan type safety di koleksi.

// Tanpa generics (Java lama, tidak direkomendasikan):
List list = new ArrayList();
list.add("Eko");
list.add(123);           // ← bisa campur tipe!
String name = (String) list.get(0); // harus cast manual, rawan ClassCastException

// Dengan generics (Java modern, WAJIB):
List<String> names = new ArrayList<>(); // ← <String> = hanya String!
names.add("Eko");
// names.add(123);       // ← ERROR KOMPILASI, Java tidak izinkan
String name = names.get(0); // ← tidak perlu cast, compiler sudah tahu tipenya
<String> Tipe parameter generics. Dibaca: "List yang berisi String". Di PHP ini tidak ada padanannya karena PHP array tidak typed. Di Laravel kamu mungkin pakai Collection yang juga tidak enforce tipe. new ArrayList<>() Diamond operator <> kosong di sebelah kanan — compiler menginfer tipe dari sebelah kiri. Ini shorthand Java 7+ agar tidak perlu menulis new ArrayList<String>().
🐘 Analogi Laravel

Laravel Collection (collect([])) adalah API yang nyaman tapi tidak enforce tipe elemen. Java Collections + Generics adalah versi typed-nya. Bayangkan Laravel Collection tapi compiler error kalau kamu coba masukkan tipe yang salah.

Chapter 1
🌳 Hierarki Java Collections Framework
JCF bukan sekedar kumpulan class acak — ini adalah hierarki interface yang terstruktur dengan baik. Memahami pohon ini adalah kunci memahami mengapa setiap class berperilaku berbeda.
Pohon Hierarki Lengkap
java.lang.Iterable<E>            ← bisa di-looping dengan for-each
└─ java.util.Collection<E>       ← add, remove, contains, size
├─ java.util.List<E>             ← ordered, boleh duplikat, akses by index
│    ├─ ArrayList<E>             ← dynamic array, random access O(1)
│    ├─ LinkedList<E>            ← doubly linked list
│    └─ Vector<E>                ← legacy, thread-safe ArrayList
│         └─ Stack<E>            ← legacy LIFO, pakai Deque sebagai gantinya
│
├─ java.util.Set<E>              ← tidak ada duplikat
│    ├─ HashSet<E>               ← urutan tidak terjamin
│    ├─ LinkedHashSet<E>         ← urutan insertion terjamin
│    ├─ EnumSet<E>               ← khusus Enum, sangat cepat
│    └─ SortedSet<E>             ← selalu terurut
│         └─ NavigableSet<E>     ← navigasi lower/higher/floor/ceiling
│               └─ TreeSet<E>    ← Red-Black Tree implementation
│
└─ java.util.Queue<E>            ← FIFO, offer/poll/peek
├─ PriorityQueue<E>              ← heap-based, priority order
├─ ArrayDeque<E>                 ← resizable array deque
└─ Deque<E>                      ← double-ended queue (Stack & Queue)
└─ LinkedList<E>                 ← implements List AND Deque!

──── Map hierarchy (TERPISAH, bukan turunan Collection) ────
java.util.Map<K,V>                 ← key-value pairs, key unik
├─ HashMap<K,V>                    ← paling umum, urutan tidak terjamin
├─ LinkedHashMap<K,V>              ← urutan insertion terjamin
├─ IdentityHashMap<K,V>            ← key equality pakai == bukan .equals()
├─ WeakHashMap<K,V>                ← key bisa di-GC jika tidak ada referensi
├─ EnumMap<K,V>                    ← khusus key Enum
├─ Hashtable<K,V>                  ← legacy, thread-safe HashMap
└─ SortedMap<K,V>                  ← key selalu terurut
└─ NavigableMap<K,V>               ← navigasi key
└─ TreeMap<K,V>                    ← Red-Black Tree implementation
💡 Tip membaca hierarki ini: Biru = Interface (kontrak), Hijau = Class konkret (implementasi yang kamu new), Kuning = Legacy (hindari di kode baru, masih ada untuk backward compatibility).
Prinsip Pemilihan Koleksi
Butuh urutan + akses index?
List<T> → ArrayList
Tidak boleh ada duplikat?
Set<T> → HashSet
Key → Value lookup?
Map<K,V> → HashMap
FIFO (antrian)?
Queue<T> → ArrayDeque
LIFO (tumpukan)?
Deque<T> → ArrayDeque
Selalu terurut?
TreeSet / TreeMap

Chapter 2
🔗 Iterable, Iterator & Collection Interface
Fondasi dari semua koleksi Java. Iterable membuat koleksi bisa di-loop, Iterator adalah mekanisme internal loopingnya, dan Collection menambahkan operasi dasar seperti add, remove, contains.
Iterable & Iterator — IterableApp.java
Iterable<String> names = List.of("Eko", "Kurniawan", "Khannedy");

// Cara 1: for-each (pakai Iterable di balik layar)
for (var name : names) {
    System.out.println(name);
}

// Cara 2: Iterator manual (lebih verbose, tapi lebih fleksibel)
Iterator<String> iterator = names.iterator();
while (iterator.hasNext()) {          // apakah masih ada elemen berikutnya?
    String name = iterator.next();    // ambil elemen dan maju ke berikutnya
    System.out.println(name);
    // iterator.remove(); ← bisa hapus elemen saat iterasi (aman!)
}
for-each Syntactic sugar di atas Iterator. Java compiler otomatis mengubah for (var x : collection) menjadi panggilan iterator(), hasNext(), next(). Persis seperti foreach di PHP. iterator.remove() Satu-satunya cara yang aman untuk menghapus elemen saat sedang iterasi. Menghapus elemen dari koleksi langsung saat loop for-each akan throw ConcurrentModificationException. Iterator remove tidak masalah.
⚠️ Jebakan Iterator — ConcurrentModificationException: 
List<String> list = new ArrayList<>(List.of("A","B","C"));

// ❌ BAHAYA — hapus langsung saat for-each
for (var item : list) {
    if (item.equals("B")) list.remove(item); // ConcurrentModificationException!
}

// ✅ AMAN — pakai Iterator
Iterator<String> it = list.iterator();
while (it.hasNext()) {
    if (it.next().equals("B")) it.remove(); // aman
}
Collection Interface — CollectionApp.java
Collection<String> collection = new ArrayList<>();

// Menambah
collection.add("Eko");
collection.add("Kurniawan");
collection.addAll(List.of("Programmer", "Zaman", "Now")); // tambah banyak sekaligus

// Menghapus
collection.remove("Eko");             // hapus by value (bukan index!)
collection.remove("Budi");            // tidak ada = tidak error, return false
collection.removeAll(List.of("Zaman", "Now")); // hapus banyak sekaligus

// Cek keberadaan
collection.contains("Kurniawan");     // → true
collection.containsAll(List.of("Khannedy", "Programmer")); // semua ada?

// Info
collection.size();   // jumlah elemen
collection.isEmpty(); // apakah kosong?
collection.clear();  // hapus semua
remove(value) Di Collection, remove() menerima value (bukan index). remove("Budi") tidak melempar exception meski "Budi" tidak ada — ia hanya return false. Ini berbeda dengan List.remove(int index) yang by index! addAll Menerima Collection apapun, termasuk List.of(). Di PHP: array_merge(). Perbedaan: addAll mengubah koleksi yang ada (mutate), tidak membuat koleksi baru.
Default Methods — CollectionDefaultMethodApp.java

Java 8 menambahkan default method ke interface Collection untuk mendukung functional programming. Ini menggunakan Anonymous Class sebagai callback:

List<Integer> numbers = new ArrayList<>(); // isi 1..100

// replaceAll — ubah semua elemen (seperti array_map di PHP)
numbers.replaceAll(new UnaryOperator<Integer>() {
    @Override
    public Integer apply(Integer integer) {
        return integer * 10; // setiap angka dikali 10
    }
});

// forEach — iterasi dengan callback (seperti array_walk)
numbers.forEach(new Consumer<Integer>() {
    @Override
    public void accept(Integer integer) {
        System.out.println(integer);
    }
});

// removeIf — hapus yang memenuhi kondisi (seperti array_filter tapi in-place)
numbers.removeIf(new Predicate<Integer>() {
    @Override
    public boolean test(Integer integer) {
        return integer > 500; // hapus semua yang > 500
    }
});
💡 Anonymous Class → Lambda: Kode di atas verbose karena menggunakan Anonymous Class. Di Java 8+, semua ini bisa ditulis jauh lebih singkat dengan Lambda Expression: 
numbers.replaceAll(n -> n * 10);     // UnaryOperator
numbers.forEach(n -> System.out.println(n)); // Consumer
numbers.removeIf(n -> n > 500);      // Predicate
// Bahkan lebih pendek:
numbers.forEach(System.out::println); // method reference
Studi kasus ini sengaja pakai Anonymous Class agar kamu memahami struktur aslinya sebelum "disingkat" oleh lambda.
🐘 Analogi Laravel Collection

forEach ≈ ->each(), replaceAll ≈ ->transform(), removeIf ≈ ->reject(). Bedanya, method Laravel Collection mengembalikan Collection baru (immutable chain), sedangkan method Java Collection ini langsung memodifikasi list yang ada (mutable).

Chapter 3
📋 List — Ordered Collection dengan Index
List adalah tipe koleksi paling sering dipakai. Ordered, boleh duplikat, dan bisa diakses by index. Tiga implementasi utama: ArrayList, LinkedList, dan Vector (legacy).
ArrayList vs LinkedList — ListApp.java
// ArrayList: pilihan default untuk hampir semua kasus
List<String> strings = new ArrayList<>();

// ArrayList juga bisa diganti LinkedList tanpa ubah kode lain
// List<String> strings = new LinkedList<>();

strings.add("Eko");          // tambah di akhir
strings.add("Kurniawan");    // tambah di akhir

strings.set(0, "Budi");      // ubah elemen di index 0 (Eko → Budi)

strings.remove(1);           // hapus by INDEX (bukan by value!)
System.out.println(strings.get(0)); // akses by index → "Budi"

for (var value : strings) {
    System.out.println(value);
}
🚨 Jebakan: remove(int) vs remove(Object) di List! 
List<Integer> numbers = new ArrayList<>(List.of(10, 20, 30));

numbers.remove(1);           // ← hapus elemen di INDEX 1 → [10, 30]
numbers.remove(Integer.valueOf(10)); // ← hapus VALUE 10 → [30]
// numbers.remove(10);       // ← ambiguous? Java pilih remove(int index)!
Di PHP unset($arr[1]) selalu by key. Di Java, remove(int) = by index, remove(Object) = by value. Untuk List<Integer>, selalu wrap dengan Integer.valueOf() jika ingin hapus by value!
Konversi Array ↔ List — ArrayApp.java
// List → Array
List<String> names = List.of("Eko", "Kurniawan", "Khannedy");

Object[] objects = names.toArray();              // konversi ke Object[]
String[] strings = names.toArray(new String[]{}); // konversi ke String[] (typed)

System.out.println(Arrays.toString(objects)); // pretty print array
System.out.println(Arrays.toString(strings));

// Array → List
String[] arr = {"A", "B", "C"};
List<String> fromArray = Arrays.asList(arr);  // fixed-size list (tidak bisa add/remove!)
List<String> mutable   = new ArrayList<>(Arrays.asList(arr)); // mutable copy
Arrays.toString() Helper static method di class Arrays untuk print array secara readable: [Eko, Kurniawan, Khannedy]. Tanpa ini, System.out.println(array) hanya mencetak alamat memori seperti [Ljava.lang.String;@1b6d3586. Arrays.asList() Membuat List dengan ukuran tetap — tidak bisa add() atau remove(), tapi bisa set(). Untuk List yang fully mutable, bungkus dengan new ArrayList<>().
Vector & Stack — Legacy Classes
// Vector — thread-safe ArrayList (legacy, ada sejak Java 1.0)
List<String> list = new Vector<>();
list.add("Eko");
// Pakai ArrayList untuk single-thread, CopyOnWriteArrayList untuk multi-thread

// Stack — LIFO dengan Vector (legacy, pakai Deque sebagai gantinya)
Stack<String> stack = new Stack<>();
stack.push("Eko");
stack.push("Kurniawan");
stack.push("Khannedy");

// pop() tanpa try-catch → EmptyStackException jika kosong!
for (var value = stack.pop(); value != null; value = stack.pop()) {
    System.out.println(value); // output: Khannedy, Kurniawan, Eko (LIFO)
}
⚠️ Jangan pakai Stack di kode baru! java.util.Stack adalah class lama yang extends Vector (synchronized). Untuk stack modern, gunakan Deque<T> stack = new ArrayDeque<>() dengan push()/pop().
🐘 Analogi Laravel

ArrayList = collect([]) di Laravel — dynamic list yang bisa tumbuh. List.of() = collect([])->freeze() atau PHP SplFixedArray — immutable. Arrays.asList() = array_values() yang hasilnya tidak bisa di-push.

Chapter 4
🎯 Set — No Duplicates Allowed
Set adalah koleksi yang menjamin tidak ada elemen duplikat. Cocok untuk menyimpan kumpulan unik: tag, permission, ID unik. Implementasi berbeda memberikan trade-off antara urutan dan performa.
HashSet vs LinkedHashSet — SetApp.java
// HashSet — paling cepat (O(1) add/remove/contains), urutan TIDAK terjamin
// Set<String> names = new HashSet<>();

// LinkedHashSet — sedikit lebih lambat, urutan INSERTION terjamin
Set<String> names = new LinkedHashSet<>();

names.add("Eko");
names.add("Kurniawan");
names.add("Khannedy");
names.add("Eko");        // ← duplikat! diabaikan secara diam-diam, tidak error
names.add("Kurniawan");  // ← duplikat! diabaikan juga

// Output: Eko, Kurniawan, Khannedy (hanya 3 elemen, duplikat dibuang)
for (var name : names) {
    System.out.println(name);
}
💡 Set untuk deduplikasi cepat: 
// Cara tercepat deduplikasi list di Java:
List<String> withDuplicates = List.of("A","B","A","C","B");
Set<String> unique = new LinkedHashSet<>(withDuplicates);
List<String> deduplicated = new ArrayList<>(unique);
// → [A, B, C]
EnumSet — Khusus Enum
public static enum Gender { MALE, FEMALE, NOT_MENTION }

// EnumSet.allOf — semua nilai enum
Set<Gender> allGenders = EnumSet.allOf(Gender.class);
// → [MALE, FEMALE, NOT_MENTION]

// EnumSet.of — pilih yang spesifik (duplikat diabaikan otomatis)
Set<Gender> some = EnumSet.of(Gender.MALE, Gender.FEMALE, Gender.FEMALE);
// → [MALE, FEMALE]

// Mengapa EnumSet? Implementasinya pakai bit manipulation — jauh lebih cepat
// dan hemat memori dibanding HashSet untuk tipe Enum.
SortedSet & NavigableSet
// SortedSet — elemen selalu terurut secara natural (atau Comparator)
SortedSet<Person> people = new TreeSet<>(new PersonComparator());
people.add(new Person("Eko"));
people.add(new Person("Budi"));
people.add(new Person("Joko"));
// Otomatis terurut: Budi, Eko, Joko (alphabetical via PersonComparator)

// NavigableSet — API navigasi yang lebih kaya
NavigableSet<String> names = new TreeSet<>();
names.addAll(Set.of("Eko", "Kurniawan", "Khannedy", "Now", "Zaman"));

NavigableSet<String> reversed = names.descendingSet(); // urutan terbalik
NavigableSet<String> fromK = names.tailSet("Kurniawan", true);
// → semua elemen ≥ "Kurniawan": Kurniawan, Now, Zaman
TreeSet Implementasi SortedSet & NavigableSet menggunakan Red-Black Tree. Operasi add/remove/contains O(log n), lebih lambat dari HashSet O(1), tapi selalu terurut. tailSet(key, inclusive) Mengembalikan "view" dari Set yang berisi semua elemen mulai dari key (inclusive jika true). Ini adalah live view — perubahan pada NavigableSet asli akan terlihat di sini. PersonComparator Class yang mengimplementasikan Comparator<Person>. TreeSet membutuhkan Comparator untuk tipe yang tidak punya natural ordering. Kita lihat implementasinya di Chapter 8.
🐘 Analogi Laravel

PHP tidak punya Set bawaan. Di Laravel kamu mungkin pakai collect()->unique() untuk deduplikasi. Di Java, gunakan langsung HashSet — lebih efisien karena Set tidak pernah menyimpan duplikat dari awal, sedangkan unique() masih menyimpan duplikat lalu memfilternya.

Chapter 5
🗺️ Map — Koleksi Key-Value
Map adalah struktur data key-value yang sangat sering dipakai. Java punya banyak varian Map untuk kebutuhan spesifik: urutan, tipe key, GC behavior, thread-safety. Di sini kita bedah semuanya.
HashMap — Paling Umum
// HashMapApp.java
Map<String, String> map = new HashMap<>();
map.put("name.first",  "Eko");
map.put("name.middle", "Kurniawan");
map.put("name.last",   "Khannedy");

// get — O(1) lookup
System.out.println(map.get("name.first"));  // "Eko"
System.out.println(map.get("tidak.ada"));   // null (tidak throw exception!)

// Operasi lain yang berguna:
map.getOrDefault("tidak.ada", "default");   // null-safe get
map.putIfAbsent("name.first", "Other");     // hanya put jika key belum ada
map.containsKey("name.first");              // true
map.containsValue("Eko");                   // true (O(n)!)
map.remove("name.last");                    // hapus by key
map.size();                                 // jumlah entry
Iterasi Map — EntryApp.java
Map<String, String> map = new HashMap<>();
map.put("Eko", "Eko Value");
map.put("Budi", "Budi Value");

// Cara 1: entrySet() — dapat key DAN value sekaligus (paling efisien)
Set<Map.Entry<String, String>> entries = map.entrySet();
for (var entry : entries) {
    System.out.println(entry.getKey() + " : " + entry.getValue());
}

// Cara 2: keySet() — dapat key saja, value harus get() lagi
for (var key : map.keySet()) {
    System.out.println(map.get(key)); // dua lookup = kurang efisien
}

// Cara 3: forEach dengan BiConsumer (functional)
map.forEach(new BiConsumer<String, String>() {
    @Override
    public void accept(String key, String value) {
        System.out.println(key + ":" + value);
    }
});
// Lambda version: map.forEach((k, v) -> System.out.println(k + ":" + v));
💡 Best Practice iterasi Map: Gunakan entrySet() ketika butuh key DAN value. Gunakan keySet() ketika hanya butuh key. Hindari keySet() + map.get(key) di dalam loop — ini O(2n) secara lookup, padahal entrySet() bisa O(n).
Varian HashMap — Perbandingan
Map<String, String> map = new LinkedHashMap<>();
map.put("first",  "Eko");
map.put("last",   "Khannedy");
map.put("middle", "Kurniawan");

// Output keySet: first, last, middle (urutan insertion, bukan alphabetical)
for (var key : map.keySet()) System.out.println(key);

Digunakan ketika urutan insertion penting — misal membuild JSON yang urutan field-nya harus konsisten.

Map<String, String> map = new IdentityHashMap<>();

String key1 = "name.first";                       // string literal (interned)
String key2 = "name" + "." + "first";             // string baru di heap

System.out.println(key1.equals(key2)); // true  — isi sama
System.out.println(key1 == key2);      // false — referensi BERBEDA

map.put(key1, "Eko");
map.put(key2, "Eko");

System.out.println(map.size()); // 2! (bukan 1) karena key1 != key2 by reference

Kasus penggunaan: object graph traversal, serialization, di mana kamu ingin tahu apakah dua variabel menunjuk ke object yang sama persis di memori.

Map<Integer, Integer> map = new WeakHashMap<>();
for (int i = 0; i < 1_000_000; i++) {
    map.put(i, i);
}
System.gc(); // paksa Garbage Collector berjalan
System.out.println(map.size()); // bisa jauh lebih kecil dari 1_000_000!

Di WeakHashMap, key disimpan sebagai Weak Reference. Jika tidak ada referensi lain ke key tersebut, GC bebas menghapus entry-nya. Berguna untuk cache yang tidak boleh mencegah GC.

public static enum Level { FREE, STANDARD, PREMIUM, VIP }

Map<Level, String> map = new EnumMap<Level, String>(Level.class);
map.put(Level.FREE, "Eko");
map.put(Level.VIP,  "Kurniawan");

for (var key : map.keySet()) {
    System.out.println(map.get(key));
}
// EnumMap menggunakan array sederhana di balik layar, bukan hash table
// → O(1) semua operasi, lebih cepat dari HashMap untuk key Enum
SortedMap & NavigableMap
// SortedMapApp.java — TreeMap dengan custom Comparator (reverse order)
Comparator<String> reverseComparator = new Comparator<String>() {
    @Override
    public int compare(String o1, String o2) {
        return o2.compareTo(o1); // ← o2 vs o1 = urutan terbalik!
    }
};
SortedMap<String, String> sortedMap = new TreeMap<>(reverseComparator);
sortedMap.put("Eko",  "Eko");
sortedMap.put("Joko", "Joko");
sortedMap.put("Budi", "Budi");
// keySet: Joko, Eko, Budi (Z→A)

// NavigableMapApp.java — navigasi ke tetangga key
NavigableMap<String, String> navMap = new TreeMap<>();

🚦 Queue, Deque & Stack
Queue (FIFO) dan Deque (double-ended) adalah fondasi dari banyak algoritma. Java menyediakan interface yang jelas dengan method yang ekspresif: offer, poll, peek.
Queue — FIFO (First In, First Out)
// QueueApp.java
// PriorityQueue — elemen keluar sesuai natural ordering (bukan insertion order!)
Queue<String> queue = new PriorityQueue<>();

queue.add("Eko");
queue.add("Kurniawan");
queue.add("Khannedy");

// poll — ambil dan hapus elemen terdepan (return null jika kosong, tidak exception)
for (String next = queue.poll(); next != null; next = queue.poll()) {
    System.out.println(next);
}
// Output PriorityQueue: Eko, Khannedy, Kurniawan (alphabetical, bukan insertion!)
Queue Method API — offer vs add, poll vs remove, peek vs element
OperasiThrows ExceptionReturn null/falseKeterangan
Tambahadd(e)offer(e)Prefer offer untuk Queue berkapasitas terbatas
Ambil & Hapusremove()poll()Prefer poll — lebih aman, tidak exception
Lihat sajaelement()peek()Prefer peek — lihat elemen terdepan tanpa hapus
Deque — Stack & Queue dalam Satu Interface
// DequeApp.java — LinkedList implements Deque
// Deque bisa dipakai sebagai Stack (LIFO) ATAU Queue (FIFO)

// Sebagai STACK (LIFO) — offerLast + pollLast
Deque<String> stack = new LinkedList<>();
stack.offerLast("Eko");        // push ke akhir
stack.offerLast("Kurniawan");
stack.offerLast("Khannedy");

System.out.println(stack.pollLast());  // "Khannedy" — ambil dari akhir
System.out.println(stack.pollLast());  // "Kurniawan"
System.out.println(stack.pollLast());  // "Eko"

// Sebagai QUEUE (FIFO) — offerLast + pollFirst
Deque<String> queue = new LinkedList<>();
queue.offerLast("Eko");        // masuk dari belakang
queue.offerLast("Kurniawan");
queue.offerLast("Khannedy");

System.out.println(queue.pollFirst()); // "Eko" — keluar dari depan
System.out.println(queue.pollFirst()); // "Kurniawan"
System.out.println(queue.pollFirst()); // "Khannedy"
offerLast / pollLast Deque punya operasi di kedua ujung: offerFirst/Last (masuk), pollFirst/Last (keluar). Stack = last in last out → offerLast + pollLast. Queue = first in first out → offerLast + pollFirst. LinkedList implements Deque Ini contoh polymorphism — LinkedList mengimplementasikan dua interface sekaligus: List dan Deque. Bergantung tipe variabel yang digunakan, API yang tersedia berbeda.
❌ Stack Legacy (hindari)
Stack<String> stack = new Stack<>();
stack.push("A");
String top = stack.pop();
// Extends Vector, synchronized overhead,
// anti-pattern di kode modern
✅ Deque Modern (gunakan ini)
Deque<String> stack = new ArrayDeque<>();
stack.push("A");    // = offerFirst
String top = stack.pop(); // = pollFirst
// ArrayDeque lebih cepat, tidak synchronized
🐘 Analogi PHP

PHP Stack: array_push + array_pop. PHP Queue: array_push + array_shift. Di Java, Deque menyediakan keduanya dengan API yang jelas niatnya. ArrayDeque adalah implementasi terbaik untuk keduanya — lebih cepat dari LinkedList karena operasi memori lebih lokal (cache friendly).

🔒 Immutable Collections & Defensive Copy
Immutable collection tidak bisa diubah setelah dibuat. Ini adalah teknik penting untuk mencegah bug yang muncul dari shared mutable state — salah satu masalah paling umum dalam pemrograman.
Cara Membuat Immutable Collections — ImmutableApp.java
// List
List<String> one       = Collections.singletonList("Satu"); // tepat 1 elemen
List<String> empty     = Collections.emptyList();           // 0 elemen

List<String> mutable   = new ArrayList<>();
mutable.add("Eko"); mutable.add("Kurniawan");
List<String> immutable = Collections.unmodifiableList(mutable); // wrapper immutable

List<String> elements  = List.of("Eko", "Kurniawan", "Khannedy"); // Java 9+, truly immutable

// Set
Set<String> emptySet   = Collections.emptySet();
Set<String> oneSet     = Collections.singleton("Eko");
Set<String> immutSet   = Collections.unmodifiableSet(mutable_set);
Set<String> modernSet  = Set.of("Eko", "Kurniawan");         // Java 9+

// Map
Map<String,String> emptyMap     = Collections.emptyMap();
Map<String,String> singletonMap = Collections.singletonMap("name","Eko");
Map<String,String> immutMap     = Collections.unmodifiableMap(mutable_map);
Map<String,String> modernMap    = Map.of(                    // Java 9+
    "first", "Eko", "middle", "Kurniawan", "last", "Khannedy"

🚨 Jebakan Collections.unmodifiableList(): Ini hanya wrapper, bukan salinan. Jika list aslinya diubah, list immutable juga akan berubah! 
List<String> mutable   = new ArrayList<>(List.of("A","B"));
List<String> immutable = Collections.unmodifiableList(mutable);

mutable.add("C");                       // ubah list asli
System.out.println(immutable);          // [A, B, C] ← ikut berubah! 😱

// Solusi: buat salinan dulu
List<String> trulyImmutable = Collections.unmodifiableList(new ArrayList<>(mutable));
// Atau langsung pakai List.of() / List.copyOf()
Defensive Copy — MutableApp.java

Ini adalah teknik melindungi internal state class dari modifikasi tak sengaja oleh kode luar:

// data/Person.java
public class Person {
    private String name;
    private List<String> hobbies;

    public Person(String name) {
        this.name    = name;
        this.hobbies = new ArrayList<>();
    }

    public void addHobby(String hobby) { hobbies.add(hobby); }

    // Defensive copy — return WRAPPER, bukan list asli
    public List<String> getHobbies() {
        return Collections.unmodifiableList(hobbies);
    }
}

// MutableApp.java — kenapa defensive copy penting
Person person = new Person("Eko");
person.addHobby("Game");
person.addHobby("Coding");

doSomethingWithHobbies(person.getHobbies());

// Method ini mencoba memodifikasi hobbies:
public static void doSomethingWithHobbies(List<String> hobbies) {
    hobbies.add("Bukan Hobby"); // ← UnsupportedOperationException! Protected!
}
unmodifiableList Getter mengembalikan Collections.unmodifiableList(hobbies) — wrapper yang melempar UnsupportedOperationException jika ada yang coba add() atau remove(). Internal list hobbies tetap mutable, tapi tidak bisa diakses dari luar. Prinsip Ini implementasi dari prinsip Tell, Don't Ask. Alih-alih membiarkan outsider memodifikasi internal state, class menyediakan method spesifik (addHobby) yang menjadi satu-satunya pintu masuk perubahan.
🐘 Analogi Laravel

Defensive copy di Java = readonly property di PHP 8.1+ atau mengembalikan clone di getter. Di Laravel Model, $hidden dan $guarded adalah bentuk perlindungan serupa — mencegah akses dan modifikasi sembarangan ke data sensitif.

🔢 Sorting, Comparator & Collections Utilities
Java menyediakan API sorting yang sangat fleksibel. Kamu bisa sort dengan natural ordering, custom Comparator, reverse order, bahkan binary search. Semua tersedia di class Collections (utilitas statis).
Sorting dengan Comparator — SortingApp.java
List<String> list = new ArrayList<>(
    List.of("Eko", "Kurniawan", "Khannedy", "Programmer", "Zaman", "Now")
);

// Sort dengan natural ordering (alphabetical untuk String)
Collections.sort(list);
// → [Eko, Khannedy, Kurniawan, Now, Programmer, Zaman]

// Sort dengan custom Comparator — reverse order
Comparator<String> reverseComparator = new Comparator<String>() {
    @Override
    public int compare(String o1, String o2) {
        return o2.compareTo(o1); // ← o2.compareTo(o1) = reverse dari o1.compareTo(o2)
    }
};
Collections.sort(list, reverseComparator);
// → [Zaman, Programmer, Now, Kurniawan, Khannedy, Eko]

// Lambda version:
list.sort((o1, o2) -> o2.compareTo(o1));

// Built-in reverse:
list.sort(Comparator.reverseOrder());

Chapter 9
🔧 Custom Collection — Membuat Queue Sendiri
Chapter paling advanced: bagaimana membuat koleksi custom yang sepenuhnya kompatibel dengan JCF. Menggunakan AbstractQueue dan Generic class untuk membuat SingleQueue yang hanya bisa menyimpan satu elemen.
SingleQueue.java — Implementasi AbstractQueue
// collection/SingleQueue.java
public class SingleQueue<E> extends AbstractQueue<E> {
//                   ↑                      ↑
//              Generic type E         Abstract class yang menyederhanakan implementasi Queue

    private E data;  // hanya menyimpan SATU elemen

    @Override
    public Iterator<E> iterator() {
        return Collections.singleton(data).iterator(); // iterator untuk 1 elemen
    }

    @Override
    public int size() {
        return data == null ? 0 : 1; // ternary: kosong → 0, ada data → 1
    }

    @Override
    public boolean offer(E e) {
        if (data == null) {
            data = e;
            return true;   // berhasil masukkan
        }
        return false;       // penuh! hanya bisa 1 elemen
    }

    @Override
    public E poll() {
        E temp = data;  // simpan dulu
        data = null;    // kosongkan
        return temp;    // kembalikan yang lama
    }

    @Override
    public E peek() {
        return data;    // lihat tanpa hapus
    }
}
class SingleQueue<E> <E> adalah type parameter — placeholder tipe yang akan diisi saat class dipakai. E bisa berupa String, Integer, atau tipe apapun. Ini mirip seperti Template di PHP atau TypeScript generics. extends AbstractQueue<E> AbstractQueue adalah abstract class yang sudah mengimplementasikan sebagian besar method Queue (seperti add, remove, element) di atas offer/poll/peek. Kita hanya perlu implement 5 method abstract yang tersisa. Collections.singleton(data) Membuat Set dengan tepat satu elemen, lalu ambil iterator-nya. Cara cepat membuat iterator untuk single element tanpa menulis Iterator custom. offer vs add Di Queue, add() melempar exception jika gagal, offer() return false. AbstractQueue.add() memanggil offer() di balik layar dan throw exception jika return false. Jadi dengan mengimplementasikan offer(), kita otomatis dapat add() juga!
Menggunakan SingleQueue — SingleQueueApp.java
Queue<String> queue = new SingleQueue<>();

System.out.println(queue.size());     // 0

System.out.println(queue.offer("Eko"));       // true
System.out.println(queue.offer("Kurniawan")); // false — sudah penuh!
System.out.println(queue.offer("Khannedy")); // false — masih penuh

System.out.println(queue.size());     // 1

System.out.println(queue.peek());     // "Eko" — lihat tanpa hapus
System.out.println(queue.poll());     // "Eko" — ambil dan hapus
System.out.println(queue.poll());     // null  — sudah kosong
System.out.println(queue.poll());     // null

System.out.println(queue.size());     // 0
💡 Kekuatan JCF Integration: Karena SingleQueue mengimplementasikan interface Queue<E>, ia bisa dipakai di mana saja Queue diharapkan. Kode yang terima Queue<T> sebagai parameter akan bekerja dengan SingleQueue<T> tanpa modifikasi. Ini adalah polymorphism JCF dalam praktik.
