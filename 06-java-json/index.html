Chapter 1
🚀 Intro & Mindset: Java vs PHP
Pahami perbedaan mindset fundamental antara Java dan PHP sebelum nulis kode. Ini kunci agar kamu tidak frustrasi!
Entry Point Aplikasi Spring Boot

Di Java Spring Boot, setiap aplikasi punya satu "pintu masuk" utama yang disebut main method. Berbeda dengan PHP yang file-nya langsung dieksekusi oleh web server per-request.

package programmerzamannow.json;                     // Line 1

import org.springframework.boot.SpringApplication;
import org.springframework.boot.autoconfigure.SpringBootApplication;

@SpringBootApplication                               // Line 2
public class BelajarJavaJsonApplication {            // Line 3

    public static void main(String[] args) {         // Line 4
        SpringApplication.run(
            BelajarJavaJsonApplication.class, args   // Line 5
        );
    }
}
Line 1

package programmerzamannow.json; — Sama seperti namespace di PHP. Di Java, struktur folder WAJIB cocok dengan package. Ini aturan keras kompiler!

Line 2

@SpringBootApplication menggabungkan 3 annotation: @Configuration, @EnableAutoConfiguration, dan @ComponentScan. Satu annotation mengaktifkan seluruh ekosistem Spring Boot!

Line 3

Nama class HARUS sama persis dengan nama file (BelajarJavaJsonApplication.java). Melanggarnya = compile error!

Line 4

public static void main(String[] args) — Method yang dijalankan pertama kali. static = bisa dipanggil tanpa instance. void = tidak mengembalikan nilai.

Line 5

SpringApplication.run() — Perintah "nyalakan mesin" Spring Boot. Scan semua Bean, konfigurasi Jackson, siapkan embedded Tomcat. Setara kombinasi bootstrap/app.php + artisan serve di Laravel.

🐘 Analogi Laravel

Di Laravel, php artisan serve menjalankan aplikasi. Di Spring Boot, fungsi serupa dilakukan oleh main() + SpringApplication.run(). Kalau di Laravel ada bootstrap/app.php yang menyiapkan Application instance, di Spring Boot itu dilakukan otomatis oleh @SpringBootApplication.

💡 Kenapa Java Lebih Verbose?

Verbosity di Java adalah fitur, bukan bug — kode menjadi self-documenting dan error tertangkap saat kompilasi, bukan saat production. Di PHP kamu bisa buat variable tanpa deklarasi tipe; di Java kamu dipaksa berpikir tentang tipe data sejak awal, yang membuat refactoring jauh lebih aman di tim besar.

Chapter 2
📦 Java Bean & POJO
Fondasi dari segalanya. Pahami POJO, Java Bean, private field, dan getter/setter — karena Jackson bekerja berdasarkan konvensi ini!
POJO vs Java Bean

POJO = class Java biasa tanpa aturan khusus. Java Bean = POJO yang mengikuti konvensi: field private, ada getter/setter, ada no-arg constructor. Jackson menggunakan konvensi Java Bean untuk memetakan JSON ke/dari object.

// FILE: Address.java
public class Address {

    private String street;                          // Line 1 — SELALU private
    private String city;                            // Line 2
    private String country;                         // Line 3

    // Getter — Jackson pakai saat SERIALISASI (Java → JSON)
    public String getStreet() { return street; }    // Line 4

    // Setter — Jackson pakai saat DESERIALISASI (JSON → Java)
    public void setStreet(String street) {          // Line 5
        this.street = street;
    }

    public String getCity()               { return city; }
    public void setCity(String city)      { this.city = city; }
    public String getCountry()            { return country; }
    public void setCountry(String c)      { this.country = c; }
}
Line 1-3

Field selalu private — prinsip Encapsulation. Di PHP cukup public $street; dan langsung akses. Di Java itu melanggar konvensi Java Bean yang dibutuhkan Jackson.

Line 4

Konvensi getter: get + NamaField (kapital huruf pertama). Jackson membaca nama getter saat serialisasi: getStreet() → JSON key "street". Proses ini disebut introspection.

Line 5

this.street = field milik class, street (tanpa this) = parameter method. Jackson memanggil setter ini saat deserialisasi JSON → Java Object.

Class Person — Java Bean Lengkap
// FILE: Person.java
import com.fasterxml.jackson.annotation.*;

public class Person {
    private String id;
    private String name;

    @JsonProperty("full_name")           // → key JSON jadi "full_name"
    private String fullName;

    @JsonIgnore                           // → TIDAK masuk ke JSON output
    private String password;

    private List<String> hobbies;        // Generic: List berisi String

    private Address address;             // Nested object!

    private Date createdAt;

    @JsonFormat(pattern = "yyyy-MM-dd")  // → Format tanggal per field
    private Date updatedAt;

    // ... semua getter & setter ...
}

❌ Salah (kebiasaan PHP):

public class Person {
    public String name;  // Field public — melanggar encapsulation!
    public int age;
    // Tidak ada getter/setter = masalah serialisasi & validasi
}

✅ Benar (konvensi Java Bean):

public class Person {
    private String name;
    private int age;
    public String getName() { return name; }
    public void setName(String name) { this.name = name; }
    public int getAge() { return age; }
    public void setAge(int age) { this.age = age; }
    // Tip: IntelliJ IDEA → Alt+Insert → Getter and Setter
    // Atau gunakan Lombok @Data untuk generate otomatis!
}
🐘 Analogi Laravel

Java Bean mirip Eloquent Model tapi tanpa database magic. Di Eloquent, Laravel mengakses atribut via magic __get() sehingga bisa $person->name. Di Java harus eksplisit person.getName() — lebih verbose tapi lebih mudah di-trace saat debugging.

🔧 ObjectMapper: Jantung Jackson
ObjectMapper adalah class utama dari library Jackson. Semua operasi JSON — serialisasi, deserialisasi, konfigurasi — dilakukan melalui class ini.
Membuat ObjectMapper
import com.fasterxml.jackson.databind.ObjectMapper;
import org.junit.jupiter.api.Assertions;
import org.junit.jupiter.api.Test;

public class ObjectMapperTest {

    @Test                                           // Line 1 — JUnit 5 annotation
    void createObjectMapper() {
        ObjectMapper objectMapper = new ObjectMapper(); // Line 2
        Assertions.assertNotNull(objectMapper);         // Line 3
    }
}
Line 1

@Test dari JUnit 5 Jupiter — menandai method ini sebagai test case. Setara /** @test */ di PHPUnit. Di Spring Boot, JUnit 5 sudah include otomatis via spring-boot-starter-test.

Line 2

new ObjectMapper() — Menginisialisasi type factory, serializer/deserializer cache, annotation introspector, dll. Ini relatif mahal — jangan buat ulang setiap method!

Line 3

JUnit assertion memastikan objectMapper berhasil dibuat. Setara $this->assertNotNull($mapper) di PHPUnit.

💡 ObjectMapper Harus Singleton!
// ❌ Anti-pattern: buat baru setiap kali
public String toJson(Person p) throws Exception {
    return new ObjectMapper().writeValueAsString(p); // Boros!
}

// ✅ Benar: inject via constructor (Spring Boot)
@Service
public class JsonService {
    private final ObjectMapper objectMapper;
    public JsonService(ObjectMapper objectMapper) {  // Spring auto-inject
        this.objectMapper = objectMapper;
    }
    public String toJson(Person p) throws Exception {
        return objectMapper.writeValueAsString(p); // Reuse singleton!
    }
}

Chapter 4
🗺 JSON Object dengan Map
Cara paling fleksibel merepresentasikan JSON Object: gunakan Map<String, Object>. Setara dengan associative array di PHP, tapi strongly-typed.
Membuat JSON dari Map
@Test
void createJson() throws JsonProcessingException {
    Map<String, Object> person = Map.of(      // Line 1
            "firstName", "Budi",
            "lastName",  "Nugraha",
            "age",       30,                   // Integer literal
            "married",   true,                 // boolean literal
            "address", Map.of(                // Line 2 — nested Map
                    "street",  "Jalan belum ada",
                    "city",    "Jakarta",
                    "country", "Indonesia"
            )
    );

    ObjectMapper objectMapper = new ObjectMapper();
    String json = objectMapper.writeValueAsString(person); // Line 3
    // Output: {"age":30,"married":true,"firstName":"Budi",...}
    // ⚠️ Urutan key TIDAK dijamin — Map.of() tidak ordered!
}
Line 1

Map<String,Object>: key harus String, value bisa Object apa saja. Map.of() adalah factory method Java 9+ yang membuat immutable map. Di PHP: $person = ['firstName' => 'Budi', 'age' => 30];

Line 2

Nested Map.of() merepresentasikan nested JSON object. Jackson konversi secara rekursif otomatis.

Line 3

writeValueAsString() bisa throw JsonProcessingException — itulah kenapa ada throws JsonProcessingException di signature method test.

Membaca JSON ke Map (Deserialisasi)
@Test
void readJson() throws JsonProcessingException {
    String json = """
            {
              "age": 30,
              "firstName": "Budi",
              "lastName": "Nugraha",
              "married": true
            }
            """;
    // ↑ Text Block: fitur Java 15+, mirip Heredoc PHP (<<
Line B

new TypeReference<Map<String,Object>>(){} — Solusi untuk Type Erasure di Java Generics: saat runtime, JVM tidak bisa membedakan List<String> dan List<Integer>. TypeReference menggunakan anonymous class untuk menyimpan informasi tipe generic hingga runtime. Anggap sebagai: "beri tahu Jackson bahwa hasilnya harus Map<String,Object>".

❌ Salah: Tidak menggunakan TypeReference

// Compile OK, tapi kurang type-safe:
Map person = objectMapper.readValue(json, Map.class);
// Value semua jadi Object mentah → butuh casting manual yang error-prone

✅ Benar: Gunakan TypeReference untuk Generic Type

Map<String, Object> person = objectMapper.readValue(
    json, new TypeReference<Map<String, Object>>() {}
); // Jackson tahu persis tipe key dan value ✅
🐘 Analogi Laravel

Map<String,Object> = associative array PHP. Map.of("firstName","Budi") setara ['firstName'=>'Budi']. TypeReference tidak punya padanan di PHP karena PHP tidak mengalami Type Erasure — tipe diketahui secara dinamis.

🧠 Mini Quiz — Chapter 4

Q: Mengapa kita butuh new TypeReference<Map<String,Object>>(){}, bukan cukup Map.class?

a) Karena Map.class tidak ada di Java — Map adalah interface
b) Karena Java Generics mengalami Type Erasure saat runtime, sehingga Jackson perlu TypeReference untuk mengetahui tipe key dan value yang diinginkan
c) Karena Jackson tidak mendukung deserialisasi ke Map biasa
d) Itu hanya syntax sugar yang bisa di-skip kapan saja
Chapter 5
📋 JSON Array dengan List
JSON Array di Java direpresentasikan dengan List<T>. Pelajari cara serialize/deserialize JSON array ke/dari List Java.
Membuat & Membaca JSON Array
@Test
void createJsonArray() throws JsonProcessingException {
    List<String> hobbies = List.of("Coding","Reading","Traveling"); // Line 1
    ObjectMapper objectMapper = new ObjectMapper();
    String json = objectMapper.writeValueAsString(hobbies); // Line 2
    System.out.println(json); // Output: ["Coding","Reading","Traveling"]
}

@Test
void readJsonArray() throws JsonProcessingException {
    String json = """["Coding","Reading","Traveling"]""";
    ObjectMapper objectMapper = new ObjectMapper();
    List<String> hobbies = objectMapper.readValue(          // Line 3
        json,
        new TypeReference<List<String>>() {}               // Line 4
    );
    Assertions.assertEquals(List.of("Coding","Reading","Traveling"), hobbies);
}
Line 1

List.of() adalah factory method Java 9+ yang membuat immutable List. Tidak bisa add() atau remove() — akan throw UnsupportedOperationException saat runtime! Gunakan new ArrayList<>(List.of(...)) jika butuh mutable.

Line 3-4

Kembali butuh TypeReference<List<String>>. Tanpa ini, Jackson akan buat List<LinkedHashMap> yang tidak kita inginkan.

❌ Salah: Memanggil add() pada List.of()

List<String> hobbies = List.of("Coding","Reading");
hobbies.add("Gaming"); // ❌ UnsupportedOperationException saat runtime!

✅ Benar: Gunakan ArrayList jika perlu mutable

List<String> hobbies = new ArrayList<>(List.of("Coding","Reading"));
hobbies.add("Gaming"); // ✅ ArrayList bisa dimodifikasi
🐘 Analogi Laravel

List<String> = array numerik di PHP (['Coding','Reading']). json_encode(['Coding','Reading']) = mapper.writeValueAsString(List.of("Coding","Reading")). Perbedaan kunci: Java memaksa deklarasi tipe elemen untuk mencegah bug subtle.

🧠 Mini Quiz — Chapter 5

Q: Apa yang terjadi jika kamu memanggil .add("Gaming") pada List yang dibuat dengan List.of("Coding","Reading")?

a) List bertambah jadi 3 elemen — berfungsi normal
b) Throw UnsupportedOperationException saat runtime karena List.of() menghasilkan immutable list
c) Compile error, List.of() tidak punya method add()
d) Element diabaikan secara silent tanpa error
Chapter 6
🔄 JavaBean ↔ JSON
Use case paling umum: konversi Java Bean (POJO) ke JSON dan sebaliknya, termasuk nested object dan array.
Serialisasi: Object → JSON String
@Test
void createJsonFromObject() throws JsonProcessingException {
    Person person = new Person();               // Line 1 — buat instance
    person.setId("1");
    person.setName("Eko");
    person.setHobbies(List.of("Coding","Reading"));

    Address address = new Address();            // Line 2 — nested object
    address.setStreet("Jalan belum jadi");
    address.setCity("Jakarta");
    address.setCountry("Indonesia");
    person.setAddress(address);                 // Line 3 — set ke person

    ObjectMapper objectMapper = new ObjectMapper();
    String json = objectMapper.writeValueAsString(person); // Line 4
    // Output:
    // {"id":"1","name":"Eko","hobbies":["Coding","Reading"],
    //  "address":{"street":"Jalan belum jadi","city":"Jakarta","country":"Indonesia"}}
}
Line 1

Di Java, tipe variable dideklarasikan di kiri (Person person), baru di-assign di kanan (= new Person()). Di PHP: $person = new Person(); tanpa deklarasi tipe.

Line 2-3

Object Composition. Jackson otomatis mendeteksi relasi ini dan serialize Address menjadi nested JSON object.

Line 4

Jackson memanggil semua getter di Person. Untuk getAddress(), rekursif masuk ke Address. Untuk getHobbies(), konversi List<String> ke JSON Array. Semua otomatis!

Deserialisasi: JSON String → Object
@Test
void readObjectFromJson() throws JsonProcessingException {
    String json = """
            {
              "id": "1", "name": "Eko",
              "hobbies": ["Coding","Reading"],
              "address": {"street":"Jalan belum jadi","city":"Jakarta","country":"Indonesia"}
            }
            """;

    ObjectMapper objectMapper = new ObjectMapper();
    Person person = objectMapper.readValue(json, Person.class); // Line A

    Assertions.assertEquals("1",   person.getId());
    Assertions.assertEquals("Eko", person.getName());
    Assertions.assertEquals("Jalan belum jadi", person.getAddress().getStreet()); // Line B
}
Line A

Untuk class konkret (bukan generic), cukup pass NamaClass.class. Jackson: (1) buat new Person() via no-arg constructor, (2) untuk setiap key JSON, cari setter yang cocok, (3) panggil setter — ini reflection-based deserialization.

Line B

Jackson otomatis deteksi JSON key "address" sebagai nested object, buat new Address(), dan isi field-fieldnya. Deep deserialization — rekursif otomatis.

❌ Masalah Umum: Lupa No-Arg Constructor!

public class Person {
    public Person(String id, String name) { // hanya custom constructor
        this.id = id; this.name = name;
    }
    // ← Tidak ada Person() tanpa parameter!
    // Jackson throw: InvalidDefinitionException:
    // "No suitable constructor found for type Person"
}

✅ Solusi: Pastikan ada no-arg constructor

public class Person {
    public Person() {}  // ✅ Jackson butuh ini!
    public Person(String id, String name) { this.id=id; this.name=name; }
}
// ✅ Atau gunakan Lombok:
@NoArgsConstructor  // generate Person() {}
@AllArgsConstructor // generate Person(semua field)
public class Person { ... }
🐘 Analogi Laravel

readValue(json, Person.class) mirip mass-assignment di Eloquent: Person::fill(json_decode($json,true)). Di Laravel, $fillable mengontrol field yang boleh di-mass-assign. Di Java, Jackson default memanggil semua setter — gunakan @JsonIgnore untuk mengecualikan field tertentu.

a) Annotation @JsonDeserialize dan method fromJson()
b) Harus extend class JsonObject dan implement Serializable
c) No-argument constructor (untuk membuat instance) dan setter method (untuk mengisi field dari JSON)

Chapter 7
🏷 Jackson Annotations
Tiga annotation paling penting: @JsonProperty, @JsonIgnore, @JsonFormat — untuk mengontrol serialisasi di level field.
Overview Annotations
import com.fasterxml.jackson.annotation.*;

public class Person {
    private String id;
    private String name;

    @JsonProperty("full_name")           // Annotation 1: rename key JSON
    private String fullName;

    @JsonIgnore                           // Annotation 2: sembunyikan dari JSON
    private String password;

    private Date createdAt;

    @JsonFormat(pattern = "yyyy-MM-dd")  // Annotation 3: format tanggal per field
    private Date updatedAt;
    // ... getter & setter ...
}

Default: Jackson gunakan nama getter untuk key JSON. getFullName() → key "fullName". Dengan @JsonProperty("full_name"), key JSON jadi "full_name" (snake_case), field Java tetap fullName (camelCase).

// Tanpa @JsonProperty:
person.setFullName("Eko");
// → JSON: {"fullName": "Eko"}

// Dengan @JsonProperty("full_name"):
person.setFullName("Eko");
// → JSON: {"full_name": "Eko"}  ✅ snake_case untuk REST API!

// Deserialisasi: JSON harus pakai "full_name":
// {"full_name": "Eko"} → person.getFullName() = "Eko"  ✅
🐘 Analogi Laravel

Di Laravel API Resource: 'full_name' => $this->fullName untuk mengubah camelCase ke snake_case di JSON output. @JsonProperty melakukan hal yang sama langsung di level deklarasi field — lebih deklaratif!

@JsonIgnore
private String password;

// Saat serialisasi:
person.setPassword("rahasia");
// → {"id":"1","name":"Eko",...}   — Password TIDAK MUNCUL! ✅

// Saat deserialisasi, JSON input password juga diabaikan:
// {"id":"1","name":"Eko","password":"hacked"}
// → person.getPassword() = null  ✅ tidak bisa di-inject!

❌ Security Risk: Lupa @JsonIgnore pada field sensitif!
Di PHP mungkin kamu biasa unset($data['password']) sebelum json_encode() — langkah yang mudah terlupakan! @JsonIgnore langsung di deklarasi field jauh lebih aman karena tidak bisa terlewat.

private Date createdAt;                     // Pakai format global ObjectMapper

@JsonFormat(pattern = "yyyy-MM-dd")         // Override untuk field ini saja
private Date updatedAt;

// Dengan ObjectMapper.setDateFormat("yyyy-MM-dd HH:mm:ss"):
// Output:
// {
//   "createdAt": "2024-01-15 10:30:00",   ← format global
//   "updatedAt": "2024-01-15"             ← @JsonFormat override
// }
🐘 Analogi Laravel

Di Eloquent Model: $casts = ['updated_at' => 'datetime:Y-m-d'] untuk format tanggal per field. @JsonFormat melakukan hal yang sama — bahkan lebih eksplisit karena berada tepat di sebelah field yang ia konfigurasi.

Demo Lengkap: AnnotationTest.java
@Test
void annotation() throws JsonProcessingException {
    SimpleDateFormat dateFormat = new SimpleDateFormat("yyyy-MM-dd HH:mm:ss");
    ObjectMapper objectMapper = new ObjectMapper()
            .configure(SerializationFeature.WRITE_DATES_AS_TIMESTAMPS, false)
            .setDateFormat(dateFormat);

    Person person = new Person();
    person.setId("1");
    person.setName("Eko");
    person.setFullName("Eko Kurniawan Khannedy"); // ← @JsonProperty("full_name")
    person.setPassword("rahasia");                 // ← @JsonIgnore
    person.setCreatedAt(new Date());
    person.setUpdatedAt(new Date());               // ← @JsonFormat("yyyy-MM-dd")

    String json = objectMapper.writeValueAsString(person);
    // Output:
    // {
    //   "id": "1", "name": "Eko",
    //   "full_name": "Eko Kurniawan Khannedy",  ← @JsonProperty
    //   "createdAt": "2024-01-15 10:30:00",     ← format global
    //   "updatedAt": "2024-01-15"               ← @JsonFormat override
    //   — password tidak ada!                   ← @JsonIgnore
    // }
}

Chapter 8
📅 DateTime Handling
Handling tanggal di Java lebih kompleks dibanding PHP. Pelajari cara mengontrol format tanggal di JSON agar tidak menghasilkan angka timestamp yang membingungkan!
Masalah Default: Unix Timestamp!

Secara default, Jackson mengkonversi java.util.Date ke Unix timestamp dalam milliseconds. Hampir tidak pernah yang kita inginkan!

// Tanpa konfigurasi date:
ObjectMapper objectMapper = new ObjectMapper();
person.setCreatedAt(new Date());
String json = objectMapper.writeValueAsString(person);
// Output: {"id":"1","name":"Eko","createdAt":1705312200000}
//                                              ↑ Unix timestamp ms 😱
Solusi: Konfigurasi Format Tanggal Global
@Test
void dateFormat() throws JsonProcessingException {
    SimpleDateFormat dateFormat =
        new SimpleDateFormat("yyyy-MM-dd HH:mm:ss");  // Line 1

    ObjectMapper objectMapper = new ObjectMapper()
            .configure(
                SerializationFeature.WRITE_DATES_AS_TIMESTAMPS, // Line 2
                false  // ← MATIKAN timestamp, gunakan string!
            )
            .setDateFormat(dateFormat);                // Line 3

    // Output SETELAH konfigurasi:
    // {
    //   "createdAt": "2024-01-15 10:30:00",   ← ✅ format yang kita set!
    //   "updatedAt": "2024-01-15"             ← ✅ @JsonFormat override
    // }
}
Line 1

Pattern: yyyy=Y, MM=m, dd=d, HH=H (24jam), mm=i, ss=s. Setara date('Y-m-d H:i:s') di PHP.

Line 2

WAJIB diset ke false agar format string berlaku! Meski sudah setDateFormat(), jika feature ini masih true (default), Jackson tetap pakai timestamp. Dua langkah ini HARUS dilakukan bersama!

Line 3

Format global berlaku untuk semua field Date yang tidak punya @JsonFormat. Field dengan @JsonFormat tetap menggunakan pattern-nya sendiri (level field > level global).

💡 java.util.Date vs java.time (Modern Java)

Project ini pakai java.util.Date (sejak Java 1.0, tahun 1996!). Di Java 8+ tersedia java.time yang jauh lebih modern:

  • LocalDate — tanggal saja: 2024-01-15
  • LocalDateTime — tanggal + waktu: 2024-01-15T10:30:00
  • ZonedDateTime — tanggal + waktu + timezone: 2024-01-15T10:30:00+07:00

Untuk Jackson + java.time, tambahkan jackson-datatype-jsr310 dan register JavaTimeModule. Di Spring Boot, ini auto-konfigurasi jika dependency ada di classpath.

Chapter 9
⚙ ObjectMapper Features
Jackson punya banyak Feature yang bisa dikonfigurasi untuk mengontrol toleransi dan output. Sangat berguna saat integrasi dengan API pihak ketiga yang tidak konsisten!
1. MapperFeature — Case Insensitive
@Test
void mapperFeature() throws JsonProcessingException {
    ObjectMapper objectMapper = new ObjectMapper()
        .configure(MapperFeature.ACCEPT_CASE_INSENSITIVE_PROPERTIES, true);

    String json = """{"ID" : "1", "Name": "Eko"}""";
    // Key "ID" dan "Name" tidak cocok dengan field "id" dan "name" secara default!

    Person person = objectMapper.readValue(json, Person.class);
    Assertions.assertEquals("1",   person.getId());   // "ID" → field id   ✅
    Assertions.assertEquals("Eko", person.getName()); // "Name" → field name ✅
}

ACCEPT_CASE_INSENSITIVE_PROPERTIES membuat Jackson tidak peduli case key JSON. Berguna saat integrasi API tidak konsisten ("userId", "UserID", "USERID" → semua match ke field userId).

2. DeserializationFeature — Toleran Perubahan API
@Test
void deserializationFeature() throws JsonProcessingException {
    ObjectMapper objectMapper = new ObjectMapper()
        .configure(MapperFeature.ACCEPT_CASE_INSENSITIVE_PROPERTIES, true)
        .configure(DeserializationFeature.FAIL_ON_UNKNOWN_PROPERTIES, false)     // Line 1
        .configure(DeserializationFeature.ACCEPT_SINGLE_VALUE_AS_ARRAY, true);  // Line 2

    // "age" tidak ada di Person, "hobbies" berisi string bukan array
    String json = """{"id":"1","name":"Eko","age":30,"hobbies":"Coding"}""";

    Person person = objectMapper.readValue(json, Person.class);
    Assertions.assertEquals("1",   person.getId());
    Assertions.assertEquals("Eko", person.getName());
    Assertions.assertEquals(List.of("Coding"), person.getHobbies()); // ✅
}
Line 1

FAIL_ON_UNKNOWN_PROPERTIES, false — Default: Jackson throw UnrecognizedPropertyException jika JSON punya key yang tidak ada di class. Feature ini membuat Jackson mengabaikannya. Best practice: selalu set ke false agar aplikasi tidak rusak saat API partner menambah field baru.

Line 2

ACCEPT_SINGLE_VALUE_AS_ARRAY, true — Jika field Java bertipe List<String> tapi JSON mengirim single value ("Coding"), Jackson otomatis wrap jadi array satu elemen. Sangat berguna saat API pihak ketiga tidak konsisten.

3. SerializationFeature — Pretty Print
ObjectMapper objectMapper = new ObjectMapper()
    .configure(SerializationFeature.INDENT_OUTPUT, true);
// Output:
// {
//   "id" : "1",
//   "name" : "Eko",
//   "hobbies" : [ "Coding", "Reading" ],
//   "address" : { "street" : "...", "city" : "..." }
// }
// ⚠️ Matikan di production! Menambah ukuran response 30-50%
4. JsonInclude — Hapus Field Null dari Output
ObjectMapper objectMapper = new ObjectMapper()
    .setSerializationInclusion(JsonInclude.Include.NON_NULL);

// person.setId("1"); person.setName("Eko");
// hobbies, address, createdAt, updatedAt = null

// Tanpa NON_NULL: {"id":"1","name":"Eko","hobbies":null,"address":null,...}
// Dengan NON_NULL: {"id":"1","name":"Eko"}  ← Bersih! ✅
