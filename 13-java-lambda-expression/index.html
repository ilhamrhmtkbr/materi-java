Java Lambda Expression

Modul ini akan memandu kamu — developer PHP/Laravel — untuk memahami Lambda Expression di Java: dari alasan kehadirannya, cara kerjanya, hingga penggunaan nyata di Stream dan Collection.

🧠 Mengapa Lambda Ada di Java?

Java awalnya adalah bahasa Object-Oriented murni: semua hal harus dibungkus dalam class dan object. Akibatnya, untuk melewatkan sebuah "perilaku" (behavior) ke sebuah method, kamu harus membuat Anonymous Class yang bertele-tele. Lambda Expression (diperkenalkan di Java 8) hadir untuk menyederhanakan ini: kamu bisa melewatkan perilaku sebagai nilai, seperti melewatkan fungsi/closure di PHP.

1
Java < 8: Anonymous Class
Untuk melewatkan behavior, harus tulis kelas anonim 5–8 baris hanya untuk logika 1 baris. Verbose, berisik, susah dibaca.
Sebelum Java 8
2
Java 8: Lambda Expression
Sintaks ringkas (param) -> ekspresi. Behavior bisa ditulis satu baris. Basis dari semua fitur fungsional Java 8+.
Java 8 (2014)
3
Method Reference
Shorthand lebih lanjut: jika lambda hanya memanggil satu method, bisa dipersingkat dengan Kelas::method. Paling bersih dan ekspresif.
Java 8 (bersamaan)
4
Stream API & Functional Programming
Lambda + Stream memungkinkan gaya pemrograman fungsional: map, filter, forEach pada koleksi data — seperti array_map, array_filter di PHP, tapi lebih powerful.
Java 8+
🔗 Titik Tolak dari PHP/Laravel

Di PHP, kamu sudah akrab dengan anonymous function / closure: $fn = function($x) { return $x * 2; }; atau shorthand $fn = fn($x) => $x * 2;. Lambda Java bekerja dengan konsep yang sangat mirip. Perbedaan utama: Java bersifat strongly-typed, sehingga setiap lambda harus sesuai dengan sebuah Functional Interface (kontrak tipe) yang sudah didefinisikan. Tidak ada "function" sebagai tipe primitif di Java seperti di PHP.

Chapter 1
😫 Masalah Tanpa Lambda: Anonymous Class

Sebelum Java 8, satu-satunya cara melewatkan behavior adalah membuat Anonymous Class. Memahami masalah ini penting agar kamu benar-benar menghargai elegansnya Lambda.

Kode Tanpa Lambda — AnonymousClassApp.java

Perhatikan betapa banyak boilerplate yang dibutuhkan hanya untuk mendefinisikan logika sederhana:

// AnonymousClassApp.java — cara LAMA sebelum Java 8
import java.util.function.*;

public class AnonymousClassApp {
  public static void main(String[] args) {

    // Mendefinisikan: "apakah string ini tidak null?"
    // Butuh 5 baris untuk logika 1 baris!
    Predicate<String> predicate = new Predicate<String>() {
      @Override
      public boolean test(String s) {
        return s != null;   // <-- ini satu-satunya baris yang penting
      }
    };

    // Mendefinisikan: "ubah string ke uppercase"
    Function<String, String> function = new Function<String, String>() {
      @Override
      public String apply(String s) {
        return s.toUpperCase();  // <-- ini satu-satunya baris yang penting
      }
    };

    // Mendefinisikan: "print string ke console"
    Consumer<String> consumer = new Consumer<String>() {
      @Override
      public void accept(String s) {
        System.out.println(s);   // <-- ini satu-satunya baris yang penting
      }
    };

    // Mendefinisikan: "kembalikan string ini"
    Supplier<String> supplier = new Supplier<String>() {
      @Override
      public String get() {
        return "Programmer Zaman Now"; // <-- ini satu-satunya baris yang penting
      }
    };

    // Mendefinisikan: "apakah dua string ini sama?"
    BiPredicate<String, String> biPredicate = new BiPredicate<String, String>() {
      @Override
      public boolean test(String s, String s2) {
        return s.equals(s2);  // <-- ini satu-satunya baris yang penting
      }
    };
  }
}
⚠️ Masalah Anonymous Class

Untuk setiap logika 1 baris, kamu harus menulis ~5 baris boilerplate: new InterfaceName() { @Override public returnType methodName(params) { ... } }. Kode jadi sulit dibaca karena "sinyal" (logika sebenarnya) tenggelam dalam "kebisingan" (boilerplate). Lambda hadir untuk menghilangkan kebisingan ini.

Bedah Baris per Baris
ElemenPenjelasan
new Predicate<String>() { ... }Membuat anonymous class: kelas tanpa nama yang langsung diinstansiasi. Java perlu tahu tipe konkret apa yang dibuat, sehingga harus menulis nama interface-nya.
@OverrideAnnotation wajib yang menandai kita mengimplementasikan method dari interface. Ini adalah kontrak bahwa method ini ada di interface.
Predicate<String>Interface dari java.util.function. <String> adalah generics — type parameter yang menentukan tipe data yang diproses. Ini ekuivalen dengan PHP type hint tapi lebih ketat.
Function<String, String>Dua type parameter: pertama adalah tipe INPUT, kedua adalah tipe OUTPUT. <String, String> berarti: menerima String, mengembalikan String.
🔗 Analogi PHP

Di PHP, kamu cukup menulis $predicate = function($s) { return $s !== null; }; atau bahkan arrow function: $predicate = fn($s) => $s !== null;. Satu baris, bersih. Itulah yang Lambda Expression bawa ke Java — semua verbose di atas bisa diringkas menjadi satu baris.

😫 Sebelum Java 8 — Anonymous Class

  @Override
  public boolean test(String s) {
    return s != null;
  }
};
✨ Java 8+ — Lambda Expression

// Atau bahkan:
Predicate<String> p = s -> s != null;

Chapter 2
🔌 Functional Interface

Lambda Expression di Java hanya bisa digunakan jika ada Functional Interface sebagai "wadah"-nya. Memahami konsep ini adalah kunci untuk mengerti mengapa Lambda Java berbeda dari closure PHP.

Apa itu Functional Interface?

Functional Interface adalah interface Java yang hanya memiliki tepat satu abstract method. Ini menjadi kontrak tipe untuk Lambda Expression. Kamu bisa menandainya dengan annotation @FunctionalInterface agar compiler memvalidasinya.

// LambdaInterfaceApp.java — membuat Functional Interface sendiri
public class LambdaInterfaceApp {

  // Mendefinisikan custom Functional Interface
  @FunctionalInterface
  interface ArgsConsumer<T> {
    // Hanya boleh ada SATU abstract method!
    void consume(T... arg);
    // Jika kamu tambah method kedua → compile error!
  }

  public static void main(String[] args) {
    // Lambda langsung diassign ke tipe ArgsConsumer<String>
    // Java tahu method yang diimplementasikan adalah consume()
    // karena itu satu-satunya abstract method
    ArgsConsumer<String> consumer = LambdaInterfaceApp::printAll;
    consumer.consume("eko", "kurniawan", "khannedy");
  }

  public static void printAll(String[] args) {
    for (String value : args) {
      System.out.println(value);
    }
  }
}
Bedah Baris per Baris
KodePenjelasanUnder the Hood
@FunctionalInterface Annotation opsional tapi sangat disarankan. Jika dipasang, compiler akan error jika interface tidak memenuhi syarat Functional Interface (bukan tepat 1 abstract method). Murni compile-time check. Tidak ada runtime overhead. Mirip @Override — hanya instruksi ke compiler.
interface ArgsConsumer<T> Interface generic. T adalah type parameter yang ditentukan saat penggunaan. Saat ditulis ArgsConsumer<String>, semua T dalam interface diganti dengan String. Java Generics di-erase saat compile (type erasure) — bytecode akhirnya menggunakan Object, tapi compiler yang memastikan tipe sebelumnya.
void consume(T... arg) T... adalah varargs — bisa menerima 0 atau lebih argumen bertipe T. Pemanggil bisa melewatkan banyak argumen tanpa membuat array secara eksplisit. Varargs secara internal diubah jadi array oleh compiler: T[].
LambdaInterfaceApp::printAll Method Reference — akan dibahas detail di Chapter 5. Ini adalah cara untuk mereferensikan method printAll dari class LambdaInterfaceApp sebagai implementasi consume(). Java mencocokkan signature printAll(String[]) dengan consume(String...) karena varargs dan array adalah hal yang sama secara bytecode.
💡 Syarat Functional Interface

Interface bisa jadi Functional Interface jika memenuhi syarat: (1) hanya punya satu abstract method, (2) boleh punya banyak default method dan static method — itu tidak dihitung. Contoh: Comparator adalah Functional Interface meskipun punya banyak default method, karena abstract method-nya hanya compare().

🔗 Analogi PHP

Di PHP, closure bisa diassign ke variabel tipe apapun (atau tidak perlu tipe sama sekali). Di Java, Lambda harus punya "kontrak" berupa Functional Interface. Bayangkan seperti PHP dengan strict type hints: function prosesData(callable $fn): void { ... } — callable adalah "Functional Interface"-nya PHP. Di Java, kamu mendefinisikan kontrak yang lebih presisi: bukan hanya "callable" tapi "callable yang menerima String dan mengembalikan boolean" (itu namanya Predicate<String>).

❌ Salah — Interface dengan 2 abstract method
@FunctionalInterface  // Compile ERROR!
interface MyInterface {
  void doSomething();
  void doSomethingElse(); // ← method kedua = BUKAN FI!
}
// Error: "Invalid '@FunctionalInterface' annotation"
✅ Benar — Hanya 1 abstract method
@FunctionalInterface
interface MyInterface {
  void doSomething();       // ← satu-satunya abstract method

  default void helper() {  // default method ✅ tidak dihitung
    System.out.println("helper");
  }
}

Chapter 3
λ Sintaks Lambda Expression

Sintaks Lambda bisa ditulis dalam beberapa bentuk — dari yang paling eksplisit sampai yang paling ringkas. Pelajari urutan evolusi ini agar kamu tidak kaget ketika membaca kode orang lain.

Tiga Tahap Evolusi Penulisan Lambda

Untuk setiap Functional Interface, ada tiga cara penulisan yang ekuivalen. Mari kita lihat evolusinya menggunakan Predicate<String> sebagai contoh:

😩 Tahap 1 — Anonymous Class (sebelum Java 8)
// Paling verbose
Predicate<String> predicate = new Predicate<String>() {
  @Override
  public boolean test(String s) {
    return s != null;
  }
};
😊 Tahap 2 — Lambda dengan Block Body
// Lebih ringkas: hilangkan nama interface, @Override, nama method
// Sisakan: (parameter) -> { body; }
Predicate<String> predicate = (value) -> {
  return value != null;   // curly brace + explicit return
};
😎 Tahap 3 — Lambda Expression (paling ringkas)
// Jika body hanya satu ekspresi: hilangkan { }, return, dan titik koma
Predicate<String> predicate = (value) -> value != null;

// Jika hanya 1 parameter: tanda kurung juga bisa dihilangkan
Predicate<String> predicate = value -> value != null;
Semua Contoh dari LambdaProgram.java
// LambdaProgram.java — semua bentuk lambda dalam aksi

// 1. Predicate<T> — test(T) : boolean
Predicate<String> predicate = (value) -> value != null;
System.out.println(predicate.test("A"));    // true
System.out.println(predicate.test(null));   // false

// 2. Function<T, R> — apply(T) : R
Function<String, String> function = (value) -> value.toUpperCase();
System.out.println(function.apply("eko"));  // EKO

// 3. Consumer<T> — accept(T) : void
Consumer<String> consumer = (value) -> System.out.println(value);
consumer.accept("Hello Lambda");

// 4. Supplier<T> — get() : T  (tidak ada parameter, pakai kurung kosong)
Supplier<String> supplier = () -> "Programmer Zaman Now";
System.out.println(supplier.get());

// 5. BiPredicate<T, U> — test(T, U) : boolean (dua parameter)
BiPredicate<String, String> biPredicate = (value1, value2) -> value1.equals(value2);
System.out.println(biPredicate.test("eko", "eko"));    // true
System.out.println(biPredicate.test("eko", "bukan"));  // false

// 6. Lambda langsung sebagai argumen method (inline)
printLambda(() -> "Eko Kurniawan"); // Supplier ditulis langsung di argumen!

public static void printLambda(Supplier<String> supplier) {
  System.out.println(supplier.get());
}
Aturan Sintaks Lambda — Ringkasan
KondisiAturan RingkasContoh
0 parameterWajib pakai ()() -> "hello"
1 parameter() boleh dihilangkans -> s.toUpperCase() atau (s) -> s.toUpperCase()
2+ parameterWajib pakai ()(a, b) -> a.equals(b)

🔗 Analogi PHP Arrow Function

Sintaks Lambda Java mirip sekali dengan arrow function PHP 7.4+. Perbandingan:
PHP: $fn = fn($value) => strtoupper($value);
Java: Function<String,String> fn = value -> value.toUpperCase();
Perbedaan: PHP tidak perlu deklarasi tipe, Java butuh Functional Interface. Tapi logika penulisan param -> expression adalah identik.

❌ Salah — Lupa return di block body
// Jika pakai { }, WAJIB tulis return (untuk non-void)!
Function<String, String> fn = (s) -> {
  s.toUpperCase(); // ← COMPILE ERROR: missing return
};
// Java tidak otomatis mengembalikan nilai ekspresi terakhir
✅ Benar — Dua pilihan yang valid
// Pilihan 1: expression lambda (tanpa { })
Function<String, String> fn = s -> s.toUpperCase();

// Pilihan 2: block lambda (dengan { } + return eksplisit)
Function<String, String> fn = (s) -> {
  return s.toUpperCase(); // ← return wajib ada
};

Chapter 4
🧰 Built-in Functional Interface

Java menyediakan sekumpulan Functional Interface siap pakai di package java.util.function. Kamu tidak perlu membuat sendiri untuk kasus-kasus umum. Kenali 5 yang paling sering digunakan.

Lima Functional Interface Utama
Predicate<T>
test(T) : boolean
Menerima satu argumen, mengembalikan boolean. Digunakan untuk kondisi / filter.
Predicate<String> notNull
= s -> s != null;
Function<T, R>
apply(T) : R
Menerima satu argumen tipe T, mengembalikan tipe R. Digunakan untuk transformasi.
Function<String,String> upper
= s -> s.toUpperCase();
Consumer<T>
accept(T) : void
Menerima satu argumen, tidak mengembalikan nilai. Digunakan untuk operasi dengan side effect (print, simpan ke DB, dll).
Consumer<String> printer
= s -> System.out.println(s);
Supplier<T>
get() : T
Tidak menerima argumen, mengembalikan nilai. Digunakan untuk lazy initialization atau factory.
Supplier<String> greet
= () -> "Hello World";
BiPredicate<T, U>
test(T, U) : boolean
Seperti Predicate tapi menerima DUA argumen. Ada juga BiFunction, BiConsumer untuk versi dua-argumen lainnya.
BiPredicate<String,String> eq
= (a,b) -> a.equals(b);

BiPredicate<T,U>test(T,U)T, UbooleanPerbandingan dua nilai

BiFunction<T,U,R>apply(T,U)T, URTransformasi 2 argumen

🔗 Analogi PHP

Di PHP, semua closure hanya bertipe callable atau Closure. Tidak ada pembedaan antara "closure yang menerima string dan mengembalikan bool" vs "closure yang tidak mengembalikan nilai". Di Java, perbedaan ini penting karena sistem tipe yang strict. Gunakan ini sebagai panduan: butuh kondisi? → Predicate. Butuh transformasi? → Function. Butuh side effect? → Consumer. Butuh nilai tanpa argumen? → Supplier.

Chapter 5
🔗 Method Reference

Method Reference adalah shorthand dari Lambda Expression ketika lambda hanya melakukan satu hal: memanggil sebuah method. Sintaksnya Kelas::namaMethod atau objek::namaMethod. Ini adalah bentuk paling ekspresif dan idiomatis di Java modern.

Empat Jenis Method Reference
JenisSintaksKapan Digunakan
Static Method Kelas::staticMethod Lambda hanya memanggil method static dari suatu kelas
Instance on Param Kelas::instanceMethod Lambda memanggil method pada parameter pertamanya sendiri
Instance on Object objek::instanceMethod Lambda memanggil method pada objek spesifik yang sudah ada
Constructor Kelas::new Lambda membuat instance baru dari kelas
Kode Evolusi dari LambdaMethodApp.java
// LambdaMethodApp.java — evolusi ke Method Reference

// ─── Jenis 1: Static Method Reference ───────────────────────────────────
// isNotNull() adalah static method di LambdaMethodApp

// Tahap 1 - anonymous class
Predicate<String> p = new Predicate<String>() {
  @Override public boolean test(String s) {
    return LambdaMethodApp.isNotNull(s);
  }
};
// Tahap 2 - lambda
Predicate<String> p = (value) -> LambdaMethodApp.isNotNull(value);
// Tahap 3 - method reference ✨
Predicate<String> predicate = LambdaMethodApp::isNotNull;
// Dibaca: "gunakan method isNotNull dari LambdaMethodApp sebagai Predicate"


// ─── Jenis 2: Instance Method on Parameter (type reference) ─────────────
// isEmpty() adalah method dari OBJEK yang menjadi parameter lambda

// Lambda:
Predicate<String> p2 = (value) -> value.isEmpty();
// Method reference ✨
Predicate<String> predicate2 = String::isEmpty;
// Dibaca: "panggil isEmpty() pada parameter String yang diterima"


// ─── Jenis 3: Instance Method on Specific Object ─────────────────────────
// concat() dipanggil pada OBJEK TERTENTU (hello)

String hello = "Hello ";
// Lambda:
Function<String, String> f = (value) -> hello.concat(value);
// Method reference ✨
Function<String, String> function = hello::concat;
// Dibaca: "panggil concat() pada objek 'hello', argumen lambda jadi parameter concat"


// ─── Contoh lain: System.out::println ────────────────────────────────────
// System.out adalah objek (PrintStream), println adalah instance method-nya

// Lambda:
Consumer<String> c = (value) -> System.out.println(value);
// Method reference ✨
Consumer<String> consumer = System.out::println;
// System.out = objek spesifik, println = method-nya → Jenis 3!


// ─── BiPredicate dengan Static Method ────────────────────────────────────
// isEquals(val1, val2) adalah static method

// Lambda:
BiPredicate<String, String> bp = (v1, v2) -> LambdaMethodApp.isEquals(v1, v2);
// Method reference ✨
BiPredicate<String, String> biPredicate = LambdaMethodApp::isEquals;
Cara Cepat Membaca Method Reference
💡 Trik: Kapan Pakai Static vs Instance Reference?

Lihat isi lambda-nya: kalau kode lambda berbentuk param -> Kelas.method(param) → gunakan Kelas::method (static). Kalau berbentuk param -> param.method() → gunakan Kelas::method (instance on param). Kalau berbentuk param -> objek.method(param) → gunakan objek::method (instance on object). Aturan sederhana: siapa yang ada di kiri . sebelum method name — itulah yang kamu tulis di kiri ::.

🔗 Analogi PHP

Di PHP, kamu bisa melewatkan method sebagai callable menggunakan array: [$this, 'methodName'] atau ['ClassName', 'staticMethod']. Di Java, Method Reference jauh lebih bersih: this::methodName atau ClassName::staticMethod. Contoh ekuivalen: PHP array_map(['Str', 'upper'], $arr) → Java stream.map(String::toUpperCase).

😐 Lambda (sudah bagus, tapi bisa lebih ringkas)
// Lambda yang hanya memanggil satu method
list.forEach(value -> System.out.println(value));
names.stream().map(s -> s.toUpperCase());
biP = (v1, v2) -> MyClass.isEquals(v1, v2);
✨ Method Reference (paling idiomatis)
// Langsung ke method-nya tanpa noise
list.forEach(System.out::println);
names.stream().map(String::toUpperCase);
biP = MyClass::isEquals;

Chapter 6
📋 Lambda + Collections

Salah satu use case paling sering dari Lambda adalah iterasi Collection. Method forEach di List dan Map menerima Functional Interface, sehingga bisa diisi Lambda atau Method Reference secara langsung.

Iterasi List — Tiga Cara

Codebase menunjukkan evolusi iterasi List yang sangat informatif:

// CollectionApp.java — evolusi iterasi List

List<String> list = Arrays.asList("eko", "kurniawan", "khannedy");

// ─── Cara 1: for-each klasik ──────────────────────────────────────────────
for (String value : list) {
  System.out.println(value);
}

// ─── Cara 2: forEach + Anonymous Class ───────────────────────────────────
list.forEach(new Consumer<String>() {
  @Override
  public void accept(String s) {
    System.out.println(s);
  }
});

// ─── Cara 3: forEach + Lambda ─────────────────────────────────────────────
list.forEach((value) -> System.out.println(value));

// ─── Cara 4: forEach + Method Reference ✨ (paling idiomatis) ─────────────
list.forEach(System.out::println);
// forEach menerima Consumer<String> → accept(String) → cocok dengan println(String)
Iterasi Map — Tiga Cara
// CollectionApp.java — evolusi iterasi Map

Map<String, String> map = new HashMap<>();
map.put("a", "eko"); map.put("b", "kurniawan"); map.put("c", "khannedy");

// ─── Cara 1: entrySet() klasik ───────────────────────────────────────────
for (Map.Entry<String, String> entry : map.entrySet()) {
  System.out.println(entry.getKey() + " : " + entry.getValue());
}

// ─── Cara 2: forEach + Anonymous Class ───────────────────────────────────
map.forEach(new BiConsumer<String, String>() {
  @Override
  public void accept(String key, String value) {
    System.out.println(key + " : " + value);
  }
});

// ─── Cara 3: forEach + Lambda ─────────────────────────────────────────────
map.forEach((key, value) -> System.out.println(key + " : " + value));

// ─── Cara 4: forEach + Method Reference ✨ ─────────────────────────────
// printEntry(String key, String value) cocok dengan BiConsumer<String,String>
map.forEach(CollectionApp::printEntry);

// Method yang direferensikan:
public static void printEntry(String key, String value) {
  System.out.println(key + " : " + value);
}
Bedah Baris per Baris
KodePenjelasan
list.forEach(Consumer) Method forEach ada di interface Iterable (yang diimplementasikan oleh semua Collection). Menerima Consumer<T>. Lebih ekspresif dari for-each klasik karena bisa digabung langsung dengan method reference.
map.forEach(BiConsumer) Method forEach di Map menerima BiConsumer<K, V> — lambda dengan dua parameter (key, value). Jauh lebih bersih dari iterasi entrySet() yang verbose.
CollectionApp::printEntry Karena signature printEntry(String key, String value) cocok dengan BiConsumer<String, String>.accept(String, String), method ini bisa langsung digunakan sebagai method reference. Java mencocokkan berdasarkan jumlah dan tipe parameter.
🔗 Analogi PHP

Di PHP: array_walk($list, function($val) { echo $val; }); atau lebih singkat array_walk($list, 'echo');. Di Java dengan method reference: list.forEach(System.out::println);. Untuk Map, PHP pakai array_walk($map, function($v,$k) { echo "$k: $v"; }), Java pakai map.forEach((k,v) -> System.out.println(k+": "+v)). Perbedaan: Java lebih type-safe karena tipe key dan value diketahui dari generics Map.

😐 For-each klasik (masih valid, tapi verbose)
for (String value : list) {
  System.out.println(value);
}
for (Map.Entry<K,V> e : map.entrySet()) {
  process(e.getKey(), e.getValue());
}
✨ Lambda / Method Reference (idiomatis)

// Map — lambda

// Map — method reference

😴 Lazy Evaluation dengan Supplier

Ini adalah salah satu use case paling powerful dari Lambda yang sering diabaikan: menggunakan Supplier<T> untuk menunda eksekusi kode sampai benar-benar dibutuhkan. Teknik ini disebut Lazy Evaluation.

Kode — LazyApp.java
// LazyApp.java — Lazy Initialization Pattern dengan Supplier

public class LazyApp {
  private static ProductService productService = new ProductService();

  public static void main(String[] args) {
    // Lambda tidak langsung dieksekusi!
    // () -> productService.createNewProduct("1") hanya DISIAPKAN, belum dijalankan
    Product product1 = findOrCreate("1", () -> productService.createNewProduct("1"));
    System.out.println(product1); // CREATE NEW — karena "1" belum ada

    Product product2 = findOrCreate("2", () -> productService.createNewProduct("2"));
    System.out.println(product2); // CREATE NEW — karena "2" belum ada

    // Minta "1" lagi — kali ini TIDAK "CREATE NEW" karena sudah ada di database!
    Product product1lagi = findOrCreate("1", () -> productService.createNewProduct("1"));
    System.out.println(product1lagi); // Tidak ada output "CREATE NEW"
  }

  // Kunci: parameter newProduct adalah Supplier — bukan Product langsung!
  // Jika parameter langsung Product, createNewProduct() akan SELALU dipanggil
  // bahkan saat produk sudah ada. Dengan Supplier, pemanggilan hanya terjadi
  // jika benar-benar diperlukan (product == null).
  public static Product findOrCreate(String id, Supplier<Product> newProduct) {
    Product product = productService.findById(id);
    if (product != null) {
      return product;         // <--- Supplier.get() TIDAK pernah dipanggil
    } else {
      return newProduct.get(); // <--- Supplier.get() dipanggil HANYA di sini
    }
  }

  public static class ProductService {
    private Map<String, Product> database = new HashMap<>();

    public Product findById(String id) {
      return database.get(id); // null jika tidak ada
    }

    public Product createNewProduct(String id) {
      System.out.println("CREATE NEW"); // Side effect yang mahal!
      Product product = new Product(id, null);
      database.put(id, product);
      return product;
    }
  }
}

🌊 Stream API

Stream API adalah puncak dari ekosistem Lambda di Java. Dengan Stream, kamu bisa memproses koleksi data secara deklaratif menggunakan operasi pipeline: map, filter, forEach — mirip dengan array_map, array_filter di PHP, tapi jauh lebih powerful.

Evolusi Kode — StreamApp.java
// StreamApp.java — Evolusi kode streaming

Stream<String> names = Stream.of("eko", "kurniawan", "khannedy");

// ─── Cara 1: Anonymous class (verbose) ──────────────────────────────────
names
  .map(new Function<String, String>() {
    @Override
    public String apply(String s) {
      return s.toUpperCase();
    }
  })
  .forEach(new Consumer<String>() {
    @Override
    public void accept(String s) {
      System.out.println(s);
    }
  });

// ─── Cara 2: Lambda ───────────────────────────────────────────────────────
names
  .map((value) -> value.toUpperCase())
  .forEach((value) -> System.out.println(value));

// ─── Cara 3: Method Reference ✨ (paling idiomatis) ─────────────────────
names
  .map(String::toUpperCase)    // Function<String,String>: toUpperCase pada param
  .forEach(System.out::println); // Consumer<String>: println pada System.out


// ─── Pipeline dengan filter ───────────────────────────────────────────────
List<String> fruits = Arrays.asList("apel","melon","alpukat","jeruk","belimbing");

fruits.stream()
  .map(String::toUpperCase)          // ["APEL","MELON","ALPUKAT","JERUK","BELIMBING"]
  .filter((value) -> value.startsWith("A")) // ["APEL","ALPUKAT"]
  .forEach(System.out::println);           // print: APEL, ALPUKAT
Konsep Pipeline Stream

Stream bekerja seperti pipa — data mengalir dari sumber, diproses oleh satu atau lebih intermediate operation, dan diakhiri oleh satu terminal operation:

1
Source: list.stream() atau Stream.of(...) — titik awal pipeline
2
Intermediate ops: .map(), .filter(), .sorted(), .distinct() — lazy, tidak dieksekusi sampai ada terminal op
3
Terminal op: .forEach(), .collect(), .count(), .reduce() — memicu seluruh pipeline dieksekusi
4
Stream habis: Setelah terminal op dipanggil, stream tidak bisa digunakan lagi — harus buat stream baru dari source

🔗 Analogi PHP / Laravel Collection

Jika kamu paham Laravel Collection, kamu sudah setengah jalan! collect($arr)->map(fn($v) => strtoupper($v))->filter(fn($v) => str_starts_with($v,'A'))->values() di Laravel sangat mirip dengan list.stream().map(String::toUpperCase).filter(v -> v.startsWith("A")).collect(Collectors.toList()) di Java. Perbedaan utama: Stream Java bersifat lazy (tidak dieksekusi sampai terminal op), sedangkan Laravel Collection dieksekusi segera setiap operasi. Stream Java juga hanya bisa digunakan sekali — untuk digunakan ulang, buat stream baru.

⚠️ Stream Tidak Bisa Digunakan Ulang!

Setelah terminal operation dipanggil, stream "habis" dan tidak bisa dipakai lagi. Jika mencoba, akan dapat IllegalStateException: stream has already been operated upon or closed. Solusi: simpan sumber datanya (List, array), lalu panggil .stream() lagi setiap kali butuh stream baru.

❌ Salah — Stream dipakai dua kali
Stream<String> stream = list.stream();
long count = stream.count(); // terminal op → stream habis!
stream.forEach(System.out::println); // ← IllegalStateException!
✅ Benar — Buat stream baru setiap kali
// Simpan list-nya, bukan stream-nya
List<String> list = Arrays.asList("a","b","c");

long count = list.stream().count();        // ✅ stream #1
list.stream().forEach(System.out::println); // ✅ stream #2 (baru)

📋 Arsitektur Java Lambda Expression

Gambaran lengkap bagaimana semua komponen Lambda, Functional Interface, Method Reference, dan Stream bekerja bersama-sama.

Peta Ekosistem Lambda Java
🔌
Functional Interface — Kontrak Tipe Interface dengan tepat 1 abstract method. "Wadah" untuk Lambda. Bawaan: Predicate, Function, Consumer, Supplier, BiPredicate, dll di java.util.function. Bisa juga buat sendiri dengan @FunctionalInterface.
λ
Lambda Expression — Behavior sebagai Nilai Sintaks (param) -> ekspresi atau (param) -> { body; }. Memungkinkan behavior dilewatkan sebagai argumen method. Menggantikan Anonymous Class yang verbose.
🔗
Method Reference — Shorthand Lambda 4 jenis: Kelas::staticMethod, Kelas::instanceMethod (pada param), obj::instanceMethod (pada objek), Kelas::new (konstruktor). Digunakan ketika lambda hanya memanggil satu method.
📋
Lambda + Collections — forEach List.forEach(Consumer) dan Map.forEach(BiConsumer). Cara idiomatis modern untuk iterasi. Bisa langsung pakai method reference: list.forEach(System.out::println).
😴
Lazy Evaluation — Supplier sebagai "Resep" Gunakan Supplier<T> ketika pembuatan objek mahal dan hanya boleh dieksekusi jika benar-benar perlu. Lambda "dipaket" tanpa dieksekusi, dijalankan hanya saat .get() dipanggil.
🌊
Stream API — Pipeline Fungsional Source → Intermediate ops (lazy: map, filter, sorted) → Terminal op (eager: forEach, collect, count). Stream hanya bisa digunakan sekali. Ekuivalen Laravel Collection tapi bersifat lazy.

🔑 Effectively Final — Aturan Capture Lambda
⚠️ Variabel yang Di-capture Lambda Harus "Effectively Final"

Lambda di Java bisa mengakses variabel dari scope luar (seperti PHP use), tapi dengan syarat: variabel tersebut tidak boleh diubah nilainya setelah di-capture. Java menyebut ini effectively final — tidak harus eksplisit ditulis final, tapi nilai tidak boleh di-assign ulang. Contoh: String hello = "Hello "; Function<String,String> fn = hello::concat; — ini aman karena hello tidak diubah. Tapi jika setelahnya ada hello = "Hi ";, compiler akan error.
