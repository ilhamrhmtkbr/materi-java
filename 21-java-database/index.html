Tentang Modul Ini

Modul ini mengajarkan cara Java berkomunikasi dengan database secara langsung lewat JDBC (Java Database Connectivity). Kamu akan belajar dari raw connection sampai Repository Pattern — fondasi yang dipakai Spring Data JPA.

💡 JDBC = PDO-nya Java

Jika di PHP/Laravel kamu kenal PDO (PHP Data Objects) sebagai abstraksi koneksi database, di Java padanannya adalah JDBC. Konsep seperti prepared statement, result set, dan transaction ada di keduanya — hanya sintaksnya yang berbeda.

Sebelum bisa query database, Java perlu tahu bagaimana cara berbicara dengan MySQL. Jawabannya: JDBC Driver.

Langkah 1: Register Driver
// DriverTest.java
@Test
void testRegister() {
    try {
        // Beri tahu Java: "Gunakan MySQL Driver ini"
        Driver mysqlDriver = new com.mysql.cj.jdbc.Driver();
        DriverManager.registerDriver(mysqlDriver);
    } catch (SQLException exception) {
        Assertions.fail(exception);
    }
}
// Di Java modern (JDBC 4.0+), registrasi otomatis lewat ServiceLoader
// Tidak perlu manual jika driver ada di classpath!
💡 Auto-Registration di Java Modern

Sejak JDBC 4.0 (Java 6+), driver otomatis terdaftar saat JAR-nya ada di classpath. Kamu tidak perlu memanggil DriverManager.registerDriver() atau Class.forName() secara manual. Tapi tetap penting memahami ini agar tidak bingung saat baca kode lama.

Langkah 2: Membuat Koneksi
// ConnectionTest.java
@Test
void testConnection() {
    String jdbcUrl = "jdbc:mysql://localhost:3306/belajar_java_database"
                   + "?serverTimezone=Asia/Jakarta";
    String username = "root";
    String password = "";

    try {
        Connection connection = DriverManager.getConnection(jdbcUrl, username, password);
        System.out.println("Sukses konek ke database");
        // ⚠️ Lupa close() → connection leak!
    } catch (SQLException exception) {
        Assertions.fail(exception);
    }
}
✅ Cara Benar: try-with-resources
❌ Manual close — rawan lupa
Connection conn = DriverManager
    .getConnection(url, user, pass);
// ... kode ...
conn.close(); // Bagaimana jika exception
              // terjadi sebelum ini?
✅ try-with-resources — otomatis close
try (Connection conn = DriverManager
    .getConnection(url, user, pass)) {
    // conn.close() dipanggil OTOMATIS
    // bahkan jika ada exception!
    System.out.println("Konek!");
}
JDBC URLFormat: jdbc:[database]://[host]:[port]/[dbname]?[params]. Untuk MySQL: jdbc:mysql://localhost:3306/namadb. Mirip DSN di Laravel (mysql://root@127.0.0.1/namadb).
try-with-resourcesSintaks Java sejak Java 7. Resource apapun yang implement AutoCloseable akan otomatis di-close, bahkan jika exception terjadi. Mirip dengan use statement di PHP 8.
🔗 Analogi Laravel/PDO

JDBC URL di Java = DSN di Laravel .env:
Laravel: DB_CONNECTION=mysql DB_HOST=127.0.0.1 DB_PORT=3306 DB_DATABASE=namadb
Java JDBC: jdbc:mysql://localhost:3306/namadb?serverTimezone=Asia/Jakarta
Konsepnya identik — string yang mendeskripsikan di mana database berada.

Bab 2 · Performance
🏊 Connection Pool dengan HikariCP

Membuat koneksi database itu mahal — ada TCP handshake, autentikasi, dan alokasi resource di server. Membuat koneksi baru untuk setiap query adalah kesalahan besar di produksi.

⚠️ Masalah: Koneksi Baru per Request

Bayangkan 1000 request/detik. Tanpa connection pool, kamu buka+tutup 1000 koneksi per detik. Setiap koneksi butuh ~50-100ms. Sistem akan kolaps.

Solusi: Connection Pool

Connection Pool menyimpan sejumlah koneksi yang sudah dibuka di awal (idle connections). Saat request datang, pinjam koneksi dari pool — tidak buat baru. Setelah selesai, kembalikan ke pool.

Setup HikariCP
// ConnectionPoolTest.java & ConnectionUtil.java
HikariConfig config = new HikariConfig();

// 1. Koneksi database
config.setDriverClassName("com.mysql.cj.jdbc.Driver");
config.setJdbcUrl("jdbc:mysql://localhost:3306/belajar_java_database"
                + "?serverTimezone=Asia/Jakarta");
config.setUsername("root");
config.setPassword("");

// 2. Ukuran pool
config.setMaximumPoolSize(10);   // Maksimum 10 koneksi bersamaan
config.setMinimumIdle(5);        // Minimal 5 koneksi selalu siap (idle)

// 3. Timeout management
config.setIdleTimeout(60_000);       // Koneksi idle dihapus setelah 60 detik
config.setMaxLifetime(10 * 60_000);  // Umur maksimum koneksi: 10 menit

HikariDataSource dataSource = new HikariDataSource(config);

// Cara pakai: ambil dari pool, bukan buat baru
Connection connection = dataSource.getConnection(); // ← pinjam dari pool
// ... query ...
connection.close(); // ← kembalikan ke pool (BUKAN tutup sungguhan!)
MaximumPoolSizeBatas atas jumlah koneksi. Jika semua 10 sedang dipakai dan ada request baru, request akan menunggu. Terlalu besar → beban di MySQL server. Terlalu kecil → antrian panjang.
MinimumIdleJumlah koneksi yang selalu "hangat" dan siap pakai. Menghindari delay di saat pertama request datang.
IdleTimeoutKoneksi idle yang melebihi waktu ini akan ditutup — menjaga pool tetap segar, menghindari koneksi yang sudah expired di sisi MySQL.
MaxLifetimeBatas maksimum usia sebuah koneksi. Koneksi yang terlalu lama hidup bisa tidak stabil. Nilai ini harus lebih kecil dari wait_timeout di MySQL (SHOW VARIABLES LIKE 'wait_timeout').
connection.close()Tidak benar-benar menutup koneksi! HikariCP meng-intercept pemanggilan close() dan mengembalikan koneksi ke pool untuk dipakai lagi.
Singleton Pattern: ConnectionUtil
// ConnectionUtil.java — DataSource dibuat SATU KALI saja
public class ConnectionUtil {

  private static HikariDataSource dataSource;

  // static block: dieksekusi SATU KALI saat class pertama kali diload
  static {
    HikariConfig config = new HikariConfig();
    // ... konfigurasi ...
    dataSource = new HikariDataSource(config);
  }

  // Method statis — bisa diakses dari mana saja
  public static HikariDataSource getDataSource() {
    return dataSource;
  }
}

// Cara pakai di class lain:
Connection conn = ConnectionUtil.getDataSource().getConnection();
🔗 Analogi Laravel

Laravel sudah otomatis menggunakan connection pooling yang dikelola via konfigurasi database.php (pool section). Di Java, kamu harus setup sendiri dengan HikariCP. HikariCP adalah connection pool tercepat di ekosistem Java — dipakai secara default oleh Spring Boot.

Bab 3 · CRUD Dasar
📝 Statement — Eksekusi SQL Dasar

Statement adalah objek untuk mengirim SQL ke database. Ada dua jenis: Statement biasa (untuk SQL statis) dan PreparedStatement (untuk SQL dengan parameter).

// StatementTest.java — testExecuteUpdate
Connection connection = ConnectionUtil.getDataSource().getConnection();
Statement statement = connection.createStatement();

String sql = """
    INSERT INTO customers(id, name, email)
    VALUES ('khannedy', 'Khannedy', 'khannedy@test.com')
    """;

int rowsAffected = statement.executeUpdate(sql);
System.out.println("Rows affected: " + rowsAffected); // → 1

statement.close();
connection.close();
Text BlockTanda """...""" adalah text block Java 15+ — multi-line string literal. Mirip heredoc di PHP (<<<SQL ... SQL). Berguna untuk SQL panjang agar tetap terbaca.
executeUpdate()Untuk DML: INSERT, UPDATE, DELETE. Return int = jumlah baris terpengaruh. Jika 0, tidak ada baris yang diubah.
// StatementTest.java — testExecuteQuery
Connection connection = ConnectionUtil.getDataSource().getConnection();
Statement statement = connection.createStatement();

String sql = "SELECT * FROM customers";
ResultSet resultSet = statement.executeQuery(sql);

// Iterasi hasil — seperti foreach di PHP
while (resultSet.next()) {
    // cursor bergerak ke baris berikutnya
    String id   = resultSet.getString("id");
    String name = resultSet.getString("name");
}

// Harus close semua resource dari dalam ke luar
resultSet.close();
statement.close();
connection.close();
📌 Urutan close() yang Benar

Selalu close dari yang paling dalam ke paling luar: ResultSet → Statement → Connection. Atau lebih baik, gunakan try-with-resources untuk semua ketiganya sekaligus.

// Pattern terbaik — semua resource auto-close
try (Connection connection = ConnectionUtil.getDataSource().getConnection()) {
    String sql = "SELECT * FROM customers";
    try (Statement statement = connection.createStatement()) {
        try (ResultSet resultSet = statement.executeQuery(sql)) {
            while (resultSet.next()) {
                System.out.println(resultSet.getString("id"));
            }
        } // resultSet.close() otomatis
    } // statement.close() otomatis
} // connection.close() otomatis (kembalikan ke pool)
🔗 Analogi Laravel

Di Laravel/PHP, DB::select('SELECT * FROM customers') mengembalikan array objek langsung — resource management diurus otomatis oleh framework. Di raw JDBC Java, kamu harus urus sendiri. Inilah mengapa ORM seperti Hibernate/Spring Data JPA sangat populer di Java — mereka menyembunyikan kompleksitas JDBC ini.

Bab 4 · Security 🔒
🛡️ SQL Injection & PreparedStatement
🚨 SQL Injection — Ancaman Keamanan #1 Database

SQL Injection terjadi saat input pengguna dimasukkan langsung ke string SQL tanpa sanitasi. Penyerang bisa memanipulasi query untuk bypass autentikasi, mencuri data, bahkan menghapus seluruh tabel.

Demonstrasi SQL Injection
// SqlInjectionTest.java — KODE BERBAHAYA, JANGAN DIPAKAI!
Connection connection = ConnectionUtil.getDataSource().getConnection();
Statement statement = connection.createStatement();

// Input jahat dari pengguna
String username = "admin'; #";  // ← SQL Injection payload!
String password = "salah";

// String concatenation langsung → RENTAN INJECTION
String sql = "SELECT * FROM admin WHERE username = '" + username +
             "' AND PASSWORD = '" + password + "'";

System.out.println(sql);
// OUTPUT: SELECT * FROM admin WHERE username = 'admin'; #' AND PASSWORD = 'salah'
// Yang dieksekusi:
//   SELECT * FROM admin WHERE username = 'admin';
//   #' AND PASSWORD = 'salah'  ← ini jadi KOMENTAR, diabaikan!
// Hasilnya: login berhasil tanpa password yang benar!
🚨 Apa yang Terjadi?

Karakter '; menutup string dan mengakhiri statement pertama. Karakter # di MySQL adalah komentar — semua yang setelahnya diabaikan. Sehingga kondisi AND PASSWORD = '...' tidak pernah diperiksa. Penyerang masuk tanpa password!

✅ Solusi: PreparedStatement
// PrepareStatementTest.java — CARA YANG AMAN
Connection connection = ConnectionUtil.getDataSource().getConnection();

// Input yang sama persis — coba injection lagi
String username = "admin'; #";
String password = "salah";

// SQL dengan placeholder ? — BUKAN string concatenation
String sql = "SELECT * FROM admin WHERE username = ? AND password = ?";
PreparedStatement preparedStatement = connection.prepareStatement(sql);

// Set nilai secara terpisah — AMAN dari injection
preparedStatement.setString(1, username); // ? pertama
preparedStatement.setString(2, password); // ? kedua

ResultSet resultSet = preparedStatement.executeQuery();
if (resultSet.next()) {
    System.out.println("Sukses login");
} else {
    System.out.println("Gagal login"); // ← Ini yang terjadi! Injection GAGAL
}
?Placeholder parameter. Tidak seperti SLF4J yang pakai {}, JDBC pakai ?. Posisi parameter dihitung dari kiri, mulai dari angka 1 (bukan 0!).
setString(1, val)Mengisi placeholder ke-1 dengan nilai. Database driver otomatis escaping karakter berbahaya. Input admin'; # diperlakukan sebagai string biasa, bukan SQL.
Compile sekaliPreparedStatement dikompilasi sekali oleh database, eksekusi bisa berkali-kali dengan parameter berbeda. Lebih efisien dari Statement biasa untuk query berulang.
❌ Statement — Rentan Injection
// JANGAN PERNAH
String sql = "SELECT * FROM admin " +
  "WHERE username = '" + input + "'";
// Input apapun masuk mentah ke SQL!
✅ PreparedStatement — Aman
// SELALU gunakan ini
String sql = "SELECT * FROM admin " +
  "WHERE username = ?";
stmt.setString(1, input);
// Input di-escape otomatis ✓
🔗 Analogi Laravel

Di Laravel, Query Builder dan Eloquent otomatis menggunakan parameter binding (prepared statement di balik layar). Itulah mengapa DB::table('users')->where('id', $id)->get() aman dari SQL Injection. Di JDBC Java, kamu harus melakukan ini secara eksplisit. Pelajaran penting: raw string concatenation SQL selalu berbahaya — baik di PHP maupun Java.

ResultSet resultSet = statement.executeQuery("SELECT * FROM customers");

// Return true jika ada baris, false jika sudah habis

    String email = resultSet.getString("email");

CursorResultSet menggunakan konsep cursor — pointer yang awalnya berada sebelum baris pertama. Setiap next() menggeser cursor satu baris ke bawah.

🔗 Analogi PHP

ResultSet di Java mirip seperti PDOStatement di PHP — kamu iterasi dengan while ($row = $stmt->fetch()). Di Laravel, DB::select() sudah wrap ini jadi array, tapi di raw PDO konsepnya identik.

// AutoIncrementTest.java
Connection connection = ConnectionUtil.getDataSource().getConnection();
String sql = "INSERT INTO comments(email, comment) VALUES (?, ?)";

// ⭐ Flag khusus: minta driver simpan generated keys
PreparedStatement preparedStatement = connection.prepareStatement(
    sql,
    Statement.RETURN_GENERATED_KEYS  // ← ini kuncinya!
);

preparedStatement.setString(1, "eko@test.com");
preparedStatement.setString(2, "hi");
preparedStatement.executeUpdate();

// Ambil ID yang baru di-generate database
ResultSet resultSet = preparedStatement.getGeneratedKeys();
if (resultSet.next()) {
    int newId = resultSet.getInt(1); // kolom pertama = generated key
    System.out.println("Id Comment : " + newId); // → e.g. 3308
}

resultSet.close();
preparedStatement.close();
connection.close();
RETURN_GENERATED_KEYSFlag yang memberitahu driver untuk menyimpan nilai auto-increment yang dibuat. Tanpa flag ini, getGeneratedKeys() akan mengembalikan ResultSet kosong.
getGeneratedKeys()Method di PreparedStatement yang mengembalikan ResultSet berisi key yang di-generate. Untuk MySQL dengan satu auto_increment, ambil kolom pertama dengan index 1.
🔗 Analogi Laravel/PDO

Di Laravel: DB::table('comments')->insertGetId(['email'=>'...', 'comment'=>'...']) atau $pdo->lastInsertId() di PHP raw PDO. Bedanya di Java, kamu harus declare flag RETURN_GENERATED_KEYS di awal saat mempersiapkan statement.

Bab 6 · Data Integrity
🔄 Transaction — Commit & Rollback

Transaction memastikan sekelompok operasi database berjalan sebagai satu unit atom — semua berhasil, atau semua dibatalkan. Tidak boleh setengah-setengah.

💡 Sifat ACID Transaction
  • Atomicity — semua atau tidak sama sekali
  • Consistency — data selalu dalam state valid
  • Isolation — transaction tidak saling pengaruhi
  • Durability — data yang di-commit bertahan permanen
Commit — Simpan Semua Perubahan
// TransactionTest.java — testCommit
Connection connection = ConnectionUtil.getDataSource().getConnection();

// 1. Matikan auto-commit (default: ON — setiap executeUpdate langsung commit)
connection.setAutoCommit(false);

String sql = "INSERT INTO comments(email, comment) VALUES (?, ?)";
for (int i = 0; i < 100; i++) {
    try (PreparedStatement ps = connection.prepareStatement(sql)) {
        ps.setString(1, "eko@test.com");
        ps.setString(2, "hi");
        ps.executeUpdate(); // Belum masuk DB — hanya di memori!
    }
}

// 2. Setelah semua 100 insert berhasil, baru commit sekaligus
connection.commit(); // ← Semua 100 baris masuk DB dalam satu operasi atomik
connection.close();
Rollback — Batalkan Semua Perubahan
// TransactionTest.java — testRollback
Connection connection = ConnectionUtil.getDataSource().getConnection();
connection.setAutoCommit(false);

String sql = "INSERT INTO comments(email, comment) VALUES (?, ?)";
for (int i = 0; i < 100; i++) {
    try (PreparedStatement ps = connection.prepareStatement(sql)) {
        ps.setString(1, "eko@test.com");
        ps.setString(2, "hi");
        ps.executeUpdate();
    }
}

// Batalkan SEMUA 100 insert — tidak ada satu pun yang masuk DB
connection.rollback();
connection.close();
✅ Pattern Transaction yang Benar di Produksi
// Pattern terbaik: try-catch-finally dengan rollback on exception
Connection connection = ConnectionUtil.getDataSource().getConnection();
try {
    connection.setAutoCommit(false);

    // ... semua operasi database ...
    insertOrder(connection, order);
    deductStock(connection, product);
    chargePayment(connection, payment);

    connection.commit(); // Semua sukses → simpan
} catch (Exception e) {
    connection.rollback(); // Ada yang gagal → batalkan semua
    throw e;
} finally {
    connection.setAutoCommit(true); // Reset ke default
    connection.close();             // Kembalikan ke pool
}
setAutoCommit(false)Default JDBC: setiap statement langsung di-commit (autoCommit=true). Matikan ini untuk memulai transaction manual.
commit()Semua perubahan yang belum di-commit sejak setAutoCommit(false) atau commit() terakhir, permanen disimpan ke database.
rollback()Semua perubahan yang belum di-commit dibatalkan — seolah tidak pernah terjadi. Database kembali ke state sebelum transaction dimulai.
Reset autoCommitPenting! Connection pool me-reuse koneksi. Jika kamu lupa reset autoCommit ke true, koneksi berikutnya yang pinjam dari pool akan masuk transaction mode secara tidak sengaja.
🔗 Analogi Laravel

Di Laravel: DB::transaction(function () { ... }) otomatis handle commit dan rollback. Atau manual: DB::beginTransaction(), DB::commit(), DB::rollBack(). Konsepnya identik dengan JDBC — bedanya Laravel lebih ringkas karena framework yang handle boilerplate-nya.

Bab 7 · Performance
⚡ Batch Processing — Insert Ribuan Baris dengan Efisien

Jika kamu perlu menyimpan 1000 baris data, mengirim 1000 query terpisah sangat tidak efisien. Batch processing mengumpulkan banyak operasi dan mengirimnya ke database sekaligus.

❌ Tanpa Batch — 1000 round-trip ke DB
// Setiap loop = 1 query terpisah ke DB
// 1000 loop = 1000 network round-trip!
for (int i = 0; i < 1000; i++) {
    statement.executeUpdate(sql);
}
✅ Dengan Batch — 1 round-trip untuk 1000 query
for (int i = 0; i < 1000; i++) {
    statement.addBatch(sql); // Kumpulkan dulu
}
statement.executeBatch(); // Kirim sekaligus!
// BatchTest.java — testStatement
Connection connection = ConnectionUtil.getDataSource().getConnection();
Statement statement = connection.createStatement();

String sql = "INSERT INTO comments(email, comment) VALUES ('eko@test.com', 'hi')";

// Kumpulkan 1000 SQL
for (int i = 0; i < 1000; i++) {
    statement.addBatch(sql);
}

// Eksekusi semuanya sekaligus
statement.executeBatch();

statement.close();
connection.close();
// BatchTest.java — testPreparedStatement
Connection connection = ConnectionUtil.getDataSource().getConnection();
String sql = "INSERT INTO comments(email, comment) VALUES (?, ?)";
PreparedStatement preparedStatement = connection.prepareStatement(sql);

for (int i = 0; i < 1000; i++) {
    preparedStatement.clearParameters(); // Reset parameter sebelumnya
    preparedStatement.setString(1, "eko@test.com");
    preparedStatement.setString(2, "hi");
    preparedStatement.addBatch(); // Tambahkan ke batch (tanpa argumen)
}

// Semua 1000 insert dikirim dalam satu batch
preparedStatement.executeBatch();

preparedStatement.close();
connection.close();
clearParameters()Penting di awal setiap iterasi — bersihkan nilai parameter dari iterasi sebelumnya sebelum set nilai baru.
addBatch()Di PreparedStatement, addBatch() tanpa argumen — menyimpan state parameter saat ini ke dalam batch queue.
executeBatch()Mengirim semua query yang di-queue ke database dalam satu batch. Return int[] — array jumlah baris terpengaruh per operasi.
✅ Kombinasi Terbaik: Batch + Transaction

Untuk performa maksimal, kombinasikan batch dengan transaction: setAutoCommit(false) → loop addBatch() → executeBatch() → commit(). Ini adalah pattern yang dipakai framework seperti Spring Batch untuk memproses jutaan baris data.

🔗 Analogi Laravel

Di Laravel: DB::table('comments')->insert($arrayOf1000Rows) — Laravel otomatis menggunakan batch insert di balik layar. Di Eloquent: Comment::insert($data). Di JDBC Java, kamu handle batch secara eksplisit — memberikan kontrol penuh atas bagaimana dan kapan batch dieksekusi.

🧠 Mini Quiz — Bab 7

Apa perbedaan addBatch(sql) di Statement vs addBatch() di PreparedStatement?

A. Tidak ada perbedaan — keduanya identik
B. Statement perlu argument SQL string, PreparedStatement tidak perlu karena SQL sudah disiapkan sebelumnya dengan parameter
C. PreparedStatement.addBatch() langsung execute, Statement tidak
D. Hanya PreparedStatement yang mendukung batch

💡 Mengapa Interface?

Interface memisahkan apa yang bisa dilakukan (kontrak) dari bagaimana caranya (implementasi). Service bisa bergantung pada interface, bukan class konkret. Di testing, kamu bisa ganti implementasi JDBC dengan mock tanpa mengubah kode Service.

public class CommentRepositoryImpl implements CommentRepository {

  @Override
  public void insert(Comment comment) {
    // try-with-resources: Connection → PreparedStatement → ResultSet
    try (Connection conn = ConnectionUtil.getDataSource().getConnection()) {
      String sql = "INSERT INTO comments(email, comment) VALUES (?, ?)";
      try (PreparedStatement stmt = conn.prepareStatement(
               sql, Statement.RETURN_GENERATED_KEYS)) {
        stmt.setString(1, comment.getEmail());
        stmt.setString(2, comment.getComment());
        stmt.executeUpdate();

        // Ambil ID yang di-generate dan set ke object
        try (ResultSet rs = stmt.getGeneratedKeys()) {
          if (rs.next()) comment.setId(rs.getInt(1));
        }
      }
    } catch (SQLException e) {
      throw new RuntimeException(e); // Wrap ke unchecked exception
    }
  }

  @Override
  public Comment findById(Integer id) {
    try (Connection conn = ConnectionUtil.getDataSource().getConnection()) {
      String sql = "SELECT * FROM comments WHERE id = ?";
      try (PreparedStatement stmt = conn.prepareStatement(sql)) {
        stmt.setInt(1, id);
        try (ResultSet rs = stmt.executeQuery()) {
          if (rs.next()) {
            return new Comment(
                rs.getInt("id"),
                rs.getString("email"),
                rs.getString("comment")
            );
          } else {
            return null; // Tidak ditemukan
          }
        }
      }
    } catch (SQLException e) {
      throw new RuntimeException(e);
    }
  }

  @Override
  public List<Comment> findAll() {
    try (Connection conn = ConnectionUtil.getDataSource().getConnection()) {
      String sql = "SELECT * FROM comments";
      try (Statement stmt = conn.createStatement()) {
        try (ResultSet rs = stmt.executeQuery(sql)) {
          List<Comment> result = new ArrayList<>();
          while (rs.next()) {
            result.add(new Comment(
                rs.getInt("id"),
                rs.getString("email"),
                rs.getString("comment")
            ));
          }
          return result;
        }
      }
    } catch (SQLException e) {
      throw new RuntimeException(e);
    }
  }
}
implementsKata kunci untuk "mengimplementasikan" interface. Class wajib menyediakan implementasi untuk semua method di interface.
@OverrideAnotasi yang memberitahu compiler: "method ini adalah override dari interface/parent class". Jika signature salah, compiler akan error. Praktik terbaik — selalu pakai @Override.
RuntimeExceptionJDBC melempar SQLException (checked exception — harus di-handle). Karena boilerplate, Repository biasanya wrap ke RuntimeException (unchecked) agar caller tidak harus try-catch di mana-mana. Spring melakukan ini otomatis.
new ArrayList<>()Membuat List yang bisa di-add. Di findAll(), kumpulkan semua baris ke List ini, lalu return. Mirip $result = [] kemudian $result[] = $row di PHP.

try (Connection conn = dataSource.getConnection()) {

  // ── SELECT (executeQuery) ────────────────────────────
  try (PreparedStatement ps = conn.prepareStatement(
           "SELECT * FROM tabel WHERE id = ?")) {
    ps.setInt(1, id);
    try (ResultSet rs = ps.executeQuery()) {
      while (rs.next()) {
        rs.getInt("id");
        rs.getString("name");
        rs.getTimestamp("created_at");
      }
    }
  }

  // ── INSERT / UPDATE / DELETE (executeUpdate) ─────────
  try (PreparedStatement ps = conn.prepareStatement(
           "INSERT INTO tabel(col1, col2) VALUES (?, ?)",
           Statement.RETURN_GENERATED_KEYS)) {  // ← untuk auto_increment
    ps.setString(1, "value1");
    ps.setString(2, "value2");
    int affected = ps.executeUpdate();
    try (ResultSet keys = ps.getGeneratedKeys()) {
      if (keys.next()) int newId = keys.getInt(1);
    }
  }

  // ── TRANSACTION ──────────────────────────────────────
  conn.setAutoCommit(false);
  try {
    // ... multiple operations ...
    conn.commit();
  } catch (Exception e) {
    conn.rollback();
    throw e;
  } finally {
    conn.setAutoCommit(true);
  }

🔑 9 Golden Rules Java JDBC
1
Selalu pakai Connection Pool (HikariCP)
Jangan buat koneksi baru per request. Setup HikariDataSource sekali via Singleton, gunakan terus.
2
try-with-resources untuk semua resource
Connection, Statement, ResultSet harus selalu ditutup. try-with-resources memastikan ini terjadi otomatis.
3
PreparedStatement SELALU, Statement TIDAK PERNAH untuk input user
Statement + string concatenation = SQL Injection. PreparedStatement dengan ? adalah satu-satunya cara aman.
4
Index parameter PreparedStatement mulai dari 1, bukan 0
setString(1, val) untuk ? pertama. Kesalahan umum developer PHP yang terbiasa dengan array 0-indexed.
5
Transaction: matikan autoCommit, jangan lupa reset
setAutoCommit(false) → operasi → commit() atau rollback() → setAutoCommit(true). Connection pool me-reuse koneksi.
6
Batch untuk insert massal
addBatch() + executeBatch(). Jauh lebih cepat dari loop dengan executeUpdate() satu per satu.
7
RETURN_GENERATED_KEYS untuk ambil auto-increment ID
Flag wajib di prepareStatement() jika perlu ID yang baru dibuat database.
8
Gunakan java.sql.Timestamp untuk kolom DATETIME
Bukan java.util.Date. Di Java modern, pertimbangkan LocalDateTime yang didukung JDBC 4.2+.
9
Repository Pattern untuk memisahkan akses data dari logika bisnis
Interface + Implementasi. Ini fondasi dari Spring Data JPA yang akan meng-generate implementasinya secara otomatis.
