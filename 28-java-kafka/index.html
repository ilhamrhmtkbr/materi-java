Chapter 1

📡 Apa itu Apache Kafka?

Apache Kafka adalah distributed event streaming platform yang dirancang untuk menangani aliran data real-time dalam skala besar. Dibuat oleh LinkedIn, kini dipakai oleh Netflix, Uber, Airbnb, dan ribuan perusahaan lain untuk menghubungkan sistem-sistem mereka.

🟣 Analogi Laravel yang Paling Tepat Bayangkan kamu punya aplikasi Laravel dengan banyak service. Daripada setiap service langsung memanggil service lain (coupling ketat), kamu pakai Kafka sebagai "papan pengumuman raksasa":
  • Producer = Controller Laravel yang dispatch event (event(new OrderPlaced($order)))
  • Topic = Channel/queue spesifik (seperti nama queue di Laravel: 'orders')
  • Consumer = Listener/Worker yang proses event tersebut
  • Bedanya: 10 service berbeda bisa baca event yang SAMA secara independent — tidak seperti Laravel Queue di mana satu job hanya diproses satu worker!
📊 Kapan Sebaiknya Pakai Kafka?
✅ Pakai Kafka Kalau...
  • Volume pesan sangat besar (jutaan/hari)
  • Banyak service perlu konsumsi event yang sama
  • Butuh audit log / event history
  • Butuh replay pesan (debug, backfill data)
  • Real-time data pipeline / analytics
  • Microservice event-driven architecture
⚠️ Cukup Laravel Queue Kalau...
  • Aplikasi monolith sederhana
  • Volume job rendah-sedang
  • Tidak butuh replay atau multi-consumer
  • Tim belum siap manage Kafka cluster
  • Budget infrastruktur terbatas
🧠 Mini Quiz — Chapter 1

Apa perbedaan fundamental Kafka dengan message queue tradisional seperti Redis Queue?

🅐 Kafka lebih cepat karena menggunakan memori, bukan disk
🅑 Pesan di Kafka tetap tersimpan setelah dikonsumsi dan bisa dibaca oleh banyak consumer group secara independen — berbeda dari queue tradisional yang menghapus pesan setelah diproses
🅒 Kafka hanya bisa dipakai dengan Java, bukan PHP

📦 Struktur Sebuah Kafka Record
📨 ProducerRecord / ConsumerRecord
┌─────────────────────────────────────────────┐
│ topic : "helloworld" │
│ partition : 0 (auto atau manual) │
│ key : "0" (String) │
│ value : "Hello 0" (String) │
│ timestamp : 1716700000000 │
│ offset : 0 (ditetapkan oleh broker) │
└─────────────────────────────────────────────┘
🗂️ Topic, Partition & Offset — Cara Kafka Menyimpan Data
Topic: "helloworld" (3 partitions)

Partition 0: [msg0] [msg3] [msg6] [msg9] ← offset 0,1,2,3
                      ↑ Consumer A membaca dari sini

Partition 1: [msg1] [msg4] [msg7] ← offset 0,1,2
Partition 2: [msg2] [msg5] [msg8] ← offset 0,1,2

→ Key yang sama selalu masuk partition yang sama
→ Ordering hanya dijamin per partition, bukan lintas partition
💡 Kenapa Ada Partition? Partition adalah kunci scalability Kafka. Setiap partition bisa ditangani oleh consumer yang berbeda secara paralel. Dengan 10 partition, kamu bisa punya 10 consumer membaca topic yang sama secara bersamaan — throughput 10x lipat! Di Laravel Queue, paralelisme hanya ditentukan dari jumlah worker process.
🧠 Mini Quiz — Chapter 1B

Apa fungsi "offset" dalam Kafka?

🅐 Menentukan di broker mana pesan disimpan
🅑 Nomor urut posisi pesan dalam sebuah partition — consumer menyimpan offset untuk tahu pesan mana yang sudah dibaca
🅒 Ukuran payload pesan dalam bytes
Chapter 2

📤 Producer — Mengirim Pesan ke Kafka

Producer adalah aplikasi yang mengirim pesan (record) ke Kafka. Di Java, kita menggunakan KafkaProducer<K, V> di mana K adalah tipe key dan V adalah tipe value pesan.

// ProducerApp.java — Lengkap dengan penjelasan
package programmerzamannow.kafka;

import org.apache.kafka.clients.producer.KafkaProducer;
import org.apache.kafka.clients.producer.ProducerConfig;
import org.apache.kafka.clients.producer.ProducerRecord;
import org.apache.kafka.common.serialization.StringSerializer;

import java.util.Properties;
import java.util.concurrent.ExecutionException;

public class ProducerApp {

  public static void main(String[] args) throws ExecutionException, InterruptedException {

    // ── 1. KONFIGURASI ──────────────────────────────────────────
    Properties properties = new Properties();

    // Alamat Kafka Broker (bisa multiple: "host1:9092,host2:9092")
    properties.put(ProducerConfig.BOOTSTRAP_SERVERS_CONFIG, "localhost:9092");

    // Serializer: cara mengubah key/value Java → bytes untuk dikirim ke Kafka
    properties.put(ProducerConfig.KEY_SERIALIZER_CLASS_CONFIG,   StringSerializer.class.getName());
    properties.put(ProducerConfig.VALUE_SERIALIZER_CLASS_CONFIG, StringSerializer.class.getName());

    // ── 2. BUAT PRODUCER ────────────────────────────────────────
    // KafkaProducer
    KafkaProducer<String, String> producer = new KafkaProducer<>(properties);

    // ── 3. KIRIM 10 PESAN ───────────────────────────────────────
    for (int i = 0; i < 10; i++) {
      ProducerRecord<String, String> message = new ProducerRecord<>(
        "helloworld",        // topic — harus sudah ada di Kafka
        Integer.toString(i), // key   — "0", "1", "2", ... (menentukan partition)
        "Hello " + i         // value — payload pesan
      );

      producer.send(message).get(); // .get() = tunggu konfirmasi (synchronous)
      // Tanpa .get() = fire-and-forget (async, lebih cepat tapi tidak tahu sukses/gagal)
    }

    // ── 4. TUTUP PRODUCER ───────────────────────────────────────
    producer.close(); // flush semua pesan yang pending dan tutup koneksi
  }
}
📖 Penjelasan Baris per Baris
KomponenKeterangan
KafkaProducer<String, String>Generic type: <TipeKey, TipeValue>. Keduanya String di sini.
ProducerRecord(topic, key, value)Satu pesan yang akan dikirim. Key opsional tapi penting untuk partitioning.
producer.send(message)Async: kirim pesan, return Future<RecordMetadata>
.get()Blokir sampai broker konfirmasi pesan diterima. Jika gagal, throw exception.
producer.close()Wajib! Flush buffer yang pending dan tutup koneksi ke broker.
⚠️ Async (Fire and Forget)
// Tidak tahu berhasil atau gagal!
producer.send(message);
// Cepat, tapi bisa kehilangan pesan
// jika broker down
✅ Sync dengan Konfirmasi
// Tunggu konfirmasi dari broker
RecordMetadata meta = producer.send(message).get();
System.out.println("Offset: " + meta.offset());
System.out.println("Partition: " + meta.partition());
🟣 Analogi Laravel producer.send(message) seperti Job::dispatch() di Laravel. .get() seperti Job::dispatchSync() — tunggu sampai selesai. Tanpa .get() seperti Job::dispatch() biasa — fire and forget, tidak blocking.
⚠️ Jangan Lupa producer.close()! Producer Kafka mem-buffer pesan sebelum dikirim ke broker untuk efisiensi. Tanpa close(), pesan yang masih di buffer bisa hilang saat aplikasi keluar! close() akan flush semua buffer sebelum menutup koneksi.
🧠 Mini Quiz — Chapter 2

Apa yang terjadi jika kamu memanggil producer.send(message) tanpa .get()?

🅐 Pesan gagal dikirim karena perlu konfirmasi
🅑 Pesan dikirim secara async (fire-and-forget) — program tidak menunggu konfirmasi dari broker, lebih cepat tapi tidak tahu apakah berhasil
🅒 Compile error karena send() wajib diikuti get()
Chapter 2B

🔑 Key & Partisi — Mengontrol Routing Pesan

Key pada ProducerRecord bukan hanya label — ia menentukan partition mana yang akan menerima pesan. Semua pesan dengan key yang sama akan selalu masuk ke partition yang sama, menjamin ordering per key.

// Variasi cara mengirim pesan

// 1. Tanpa key — partition dipilih round-robin / random
ProducerRecord<String, String> msg1 = new ProducerRecord<>(
  "helloworld",  // topic
  "Hello World"  // value (tidak ada key)
);

// 2. Dengan key — partition ditentukan oleh hash(key)
ProducerRecord<String, String> msg2 = new ProducerRecord<>(
  "helloworld",  // topic
  "user-123",    // key — semua pesan dengan key "user-123" ke partition YANG SAMA
  "Hello World"  // value
);

// 3. Dengan key + partition eksplisit (override routing)
ProducerRecord<String, String> msg3 = new ProducerRecord<>(
  "helloworld",  // topic
  0,             // partition — paksa kirim ke partition 0
  "user-123",    // key
  "Hello World"  // value
);

// Callback async — tahu hasil tanpa blocking
producer.send(message, (metadata, exception) -> {
  if (exception != null) {
    System.err.println("Error: " + exception.getMessage());
  } else {
    System.out.println("Sent to partition " + metadata.partition()
        + " at offset " + metadata.offset());
  }
});
💡 Kapan Key Penting? Gunakan key ketika kamu butuh ordering per entity. Contoh: semua event untuk order-456 (created, paid, shipped, delivered) harus dalam urutan yang benar → pakai "order-456" sebagai key sehingga semua masuk ke partition yang sama dan consumer membacanya berurutan.
⚠️ Jangan Tambah Partition Sembarangan! Setelah topic dibuat, menambah partition akan mengubah routing key ke partition. Pesan dengan key yang sama mungkin masuk ke partition berbeda setelah partition ditambah — ordering bisa rusak. Rencanakan jumlah partition dari awal!
🧠 Mini Quiz — Chapter 2B

Kenapa penting menggunakan key yang konsisten untuk event dari entity yang sama (misal: order)?

🅐 Untuk menghemat bandwidth karena key dikompresi
🅑 Karena key menentukan partition — entity yang sama selalu masuk partition yang sama, menjamin ordering event dibaca berurutan oleh consumer
🅒 Key hanya dipakai untuk filtering oleh consumer, tidak ada efek teknis lain
Chapter 3

📥 Consumer — Membaca Pesan dari Kafka

Consumer adalah aplikasi yang membaca (polling) pesan dari Kafka. Di Java, kita menggunakan KafkaConsumer<K, V>. Consumer Kafka menggunakan model poll-based — bukan push — jadi consumer yang aktif meminta data.

// ConsumerApp.java — Lengkap dengan penjelasan
package programmerzamannow.kafka;

import org.apache.kafka.clients.consumer.*;
import org.apache.kafka.common.serialization.StringDeserializer;

import java.time.Duration;
import java.util.List;
import java.util.Properties;

public class ConsumerApp {

  public static void main(String[] args) {

    // ── 1. KONFIGURASI ──────────────────────────────────────────
    Properties properties = new Properties();

    // Alamat Kafka Broker
    properties.put(ConsumerConfig.BOOTSTRAP_SERVERS_CONFIG, "localhost:9092");

    // Dari offset mana mulai baca jika consumer group baru (belum ada offset tersimpan)
    // "earliest" = dari awal topic | "latest" = hanya pesan baru setelah consumer join
    properties.put(ConsumerConfig.AUTO_OFFSET_RESET_CONFIG, "earliest");

    // Deserializer: cara mengubah bytes dari Kafka → tipe Java
    properties.put(ConsumerConfig.KEY_DESERIALIZER_CLASS_CONFIG,   StringDeserializer.class.getName());
    properties.put(ConsumerConfig.VALUE_DESERIALIZER_CLASS_CONFIG, StringDeserializer.class.getName());

    // Group ID — WAJIB! Menentukan consumer group ini termasuk kelompok mana
    properties.put(ConsumerConfig.GROUP_ID_CONFIG, "java");

    // ── 2. BUAT CONSUMER ────────────────────────────────────────
    KafkaConsumer<String, String> consumer = new KafkaConsumer<>(properties);

    // ── 3. SUBSCRIBE KE TOPIC ───────────────────────────────────
    consumer.subscribe(List.of("helloworld")); // bisa subscribe ke banyak topic

    // ── 4. POLL LOOP ─────────────────────────────────────────────
    while (true) {
      // poll() — minta pesan dari Kafka, timeout 1 detik jika tidak ada pesan
      ConsumerRecords<String, String> records = consumer.poll(Duration.ofSeconds(1));

      // Iterasi setiap pesan yang diterima
      for (ConsumerRecord<String, String> message : records) {
        System.out.println("Received message: " + message.value());

        // Data lengkap yang tersedia dari setiap record:
        System.out.println("  Topic:     " + message.topic());
        System.out.println("  Partition: " + message.partition());
        System.out.println("  Offset:    " + message.offset());
        System.out.println("  Key:       " + message.key());
        System.out.println("  Value:     " + message.value());
        System.out.println("  Timestamp: " + message.timestamp());
      }
    }
  }
}
📖 Penjelasan Komponen Consumer
KomponenKeterangan
consumer.subscribe(topics)Daftarkan consumer ke satu atau lebih topic. Kafka akan assign partition ke consumer ini.
consumer.poll(duration)Minta batch pesan dari Kafka. Blokir paling lama duration jika tidak ada pesan baru. Return ConsumerRecords.
ConsumerRecordsKumpulan pesan hasil poll — bisa nol atau lebih pesan.
ConsumerRecordSatu pesan — berisi topic, partition, offset, key, value, timestamp.
while (true)Consumer umumnya berjalan terus (long-running process) — mirip queue worker Laravel.
🟣 Analogi Laravel while (true) { consumer.poll() } persis seperti php artisan queue:work --sleep=1 — loop terus, cek queue setiap sekian detik, proses kalau ada job. Di Laravel ini dihandle oleh framework, di Kafka kamu tulis polling loop-nya sendiri (atau pakai library seperti Spring Kafka yang handle ini otomatis).
⚠️ auto_offset_reset: "latest"
// "latest" = hanya baca pesan BARU
// setelah consumer join.
// Pesan lama yang sudah ada DILEWATI.
// Cocok untuk: real-time stream
// dimana pesan lama tidak relevan.
✅ auto_offset_reset: "earliest"
// "earliest" = baca dari AWAL topic
// (jika consumer group belum pernah
// baca topic ini sebelumnya).
// Cocok untuk: reprocessing data,
// consumer group baru yang perlu
// semua history pesan.

Chapter 3B

👥 Consumer Group & Offset Management

Consumer Group adalah fitur paling powerful di Kafka. Dengan GROUP_ID yang sama, beberapa instance consumer akan otomatis dibagi partisi-partisinya — paralelisme built-in. Dengan GROUP_ID berbeda, semua consumer mendapat salinan penuh pesan yang sama.

Skenario: Topic "orders" dengan 3 Partitions

Group ID: "payment-service"
  Consumer 1 → Partition 0 (proses pesanan 0,3,6,...)
  Consumer 2 → Partition 1 (proses pesanan 1,4,7,...)
  Consumer 3 → Partition 2 (proses pesanan 2,5,8,...)
  → Load balanced, tiap pesan diproses SEKALI oleh group ini

Group ID: "analytics-service"
  Consumer 1 → Partition 0,1,2 (baca SEMUA pesan)
  → Service lain yang juga perlu semua data order!

Kesimpulan: Satu topic, dua consumer group = dua service independen! 
// ── Consumer Group: group yang sama = load balanced ──────────────

// Instance 1 — Group "java" (group yang sama!)
properties.put(ConsumerConfig.GROUP_ID_CONFIG, "java");
consumer1.subscribe(List.of("helloworld"));
// → Kafka assign sebagian partition ke consumer1

// Instance 2 — Group "java" (group yang sama!)
properties.put(ConsumerConfig.GROUP_ID_CONFIG, "java");
consumer2.subscribe(List.of("helloworld"));
// → Kafka assign partition sisanya ke consumer2
// → Total: semua pesan dibagi rata, tidak ada duplikat dalam group

// ── Consumer Group berbeda = masing-masing baca semua ─────────────

// Service lain dengan group ID berbeda
properties.put(ConsumerConfig.GROUP_ID_CONFIG, "analytics");
consumerAnalytics.subscribe(List.of("helloworld"));
// → Baca SEMUA pesan dari awal, tidak terpengaruh group "java"!

// ── Manual Offset Management ──────────────────────────────────────
// Default: auto-commit offset setiap 5 detik (bisa duplicate jika crash)
// Manual: lebih aman — commit hanya setelah berhasil proses

// Matikan auto-commit
properties.put(ConsumerConfig.ENABLE_AUTO_COMMIT_CONFIG, "false");

while (true) {
  var records = consumer.poll(Duration.ofSeconds(1));
  for (var record : records) {
    // proses pesan...
    processMessage(record.value());
  }
  // Commit SETELAH semua pesan dalam batch berhasil diproses
  consumer.commitSync(); // atau commitAsync() untuk performa lebih baik
}
❌ Auto Commit (Default) — Risiko Hilang Pesan
// Auto commit offset setiap 5 detik
// Skenario masalah:
// 1. poll() → dapat 100 pesan
// 2. Auto-commit → offset di-commit
// 3. Proses pesan ke-50... CRASH!
// 4. Consumer restart → baca dari
//    offset yang sudah di-commit
// 5. Pesan 51-100 HILANG! ❌
✅ Manual Commit — At-Least-Once
// Commit hanya setelah proses selesai
// Skenario aman:
// 1. poll() → dapat 100 pesan
// 2. Proses semua 100 pesan
// 3. commitSync() → offset di-commit
// 4. Kalau crash sebelum commit:
//    Consumer restart dari offset lama
//    → pesan diproses ulang (at-least-once) ✅
💡 At-Least-Once vs Exactly-Once Manual commit memberikan at-least-once delivery — pesan mungkin diproses lebih dari sekali jika crash sebelum commit. Untuk exactly-once, kamu perlu idempotent consumer (cek apakah sudah diproses sebelumnya) atau Kafka Transactions (topik advanced). Di kebanyakan use case, at-least-once sudah cukup dengan desain consumer yang idempotent.
🟣 Analogi Laravel Consumer Group di Kafka persis seperti konsep multiple queue connection di Laravel. Bayangkan satu job bisa didengar oleh dua listener berbeda sekaligus: OrderPaymentListener dan OrderAnalyticsListener — keduanya terima semua order event secara independen. Di Laravel biasa, kamu butuh event()->listen() dengan banyak listener. Di Kafka, cukup pakai GROUP_ID berbeda!
🧠 Mini Quiz — Chapter 3B

Ada 3 consumer dengan GROUP_ID yang SAMA subscribe ke topic dengan 6 partitions. Berapa partition yang dipegang setiap consumer?

🅐 Setiap consumer dapat 6 partition (semua partition)
🅑 Setiap consumer dapat 2 partition — total 6 dibagi merata ke 3 consumer dalam group yang sama
🅒 Hanya consumer pertama yang mendapat partition, sisanya standby

consumerProps.put(ConsumerConfig.AUTO_OFFSET_RESET_CONFIG,       "earliest");
consumerProps.put(ConsumerConfig.ENABLE_AUTO_COMMIT_CONFIG,      "false"); // manual commit
consumerProps.put(ConsumerConfig.MAX_POLL_RECORDS_CONFIG,        100);     // 100 pesan per poll
🧠 Mini Quiz — Chapter 4

Config acks=all vs acks=1 — apa trade-off-nya?

🅐 acks=all lebih cepat karena langsung lanjut tanpa menunggu
🅑 acks=all lebih aman (semua replika konfirmasi) tapi lebih lambat; acks=1 lebih cepat (hanya leader konfirmasi) tapi pesan bisa hilang jika leader crash sebelum replikasi
🅒 Tidak ada bedanya untuk single-broker setup

🔧 Serializer & Deserializer

Kafka menyimpan data sebagai raw bytes. Serializer mengubah objek Java → bytes saat kirim. Deserializer mengubah bytes → objek Java saat terima. Harus simetris — serializer di producer harus ada pasangan deserializer di consumer.

// Contoh: Kirim JSON object (perlu library tambahan seperti Jackson)
// 1. Buat class model
public record OrderEvent(String orderId, String status, Long amount) {}

// 2. Custom Serializer (atau pakai JsonSerializer dari Spring Kafka)
// Producer: object → JSON string → bytes
properties.put(ProducerConfig.VALUE_SERIALIZER_CLASS_CONFIG,
    StringSerializer.class.getName()); // serialize ke String JSON dulu

// Di kode producer:
ObjectMapper mapper = new ObjectMapper();
String json = mapper.writeValueAsString(new OrderEvent("ORD-123", "PAID", 150000L));
producer.send(new ProducerRecord<>("orders", "ORD-123", json));

// 3. Consumer: bytes → JSON string → object
// Di kode consumer:
for (var record : records) {
  OrderEvent event = mapper.readValue(record.value(), OrderEvent.class);
  System.out.println("Order " + event.orderId() + " is " + event.status());
}

// ── Cara lebih elegant dengan Spring Kafka ──────────────────────
// Spring Kafka menyediakan JsonSerializer/JsonDeserializer otomatis
// sehingga kamu bisa langsung kerja dengan object Java tanpa
// manual conversion. Tapi itu topik Spring Kafka terpisah!
⚠️ Serializer harus simetris! Jika Producer menggunakan StringSerializer, Consumer wajib menggunakan StringDeserializer. Jika tidak cocok, consumer akan mendapat error saat mencoba decode bytes yang tidak kompatibel.
🧠 Mini Quiz — Chapter 4B

Producer menggunakan StringSerializer, tapi Consumer menggunakan IntegerDeserializer. Apa yang terjadi?

🅐 Kafka otomatis mengkonversi String ke Integer
🅑 Error saat consumer mencoba deserialize — bytes yang di-encode sebagai UTF-8 String tidak valid sebagai Integer bytes
🅒 Consumer mendapat null untuk setiap pesan

⚡ Cheat Sheet Kode
// ── PRODUCER ─────────────────────────────────────────────────
Properties props = new Properties();
props.put(ProducerConfig.BOOTSTRAP_SERVERS_CONFIG,   "localhost:9092");
props.put(ProducerConfig.KEY_SERIALIZER_CLASS_CONFIG,   StringSerializer.class.getName());
props.put(ProducerConfig.VALUE_SERIALIZER_CLASS_CONFIG, StringSerializer.class.getName());

KafkaProducer<String, String> producer = new KafkaProducer<>(props);

// Kirim pesan (sync)
producer.send(new ProducerRecord<>("topic", "key", "value")).get();

// Kirim pesan (async dengan callback)
producer.send(record, (metadata, ex) -> {
  if (ex != null) ex.printStackTrace();
  else System.out.println("Sent to offset: " + metadata.offset());
});

producer.close(); // JANGAN LUPA!

// ── CONSUMER ─────────────────────────────────────────────────
Properties cProps = new Properties();
cProps.put(ConsumerConfig.BOOTSTRAP_SERVERS_CONFIG,       "localhost:9092");
cProps.put(ConsumerConfig.GROUP_ID_CONFIG,                "my-group");
cProps.put(ConsumerConfig.KEY_DESERIALIZER_CLASS_CONFIG,   StringDeserializer.class.getName());
cProps.put(ConsumerConfig.VALUE_DESERIALIZER_CLASS_CONFIG, StringDeserializer.class.getName());
cProps.put(ConsumerConfig.AUTO_OFFSET_RESET_CONFIG,        "earliest");

KafkaConsumer<String, String> consumer = new KafkaConsumer<>(cProps);
consumer.subscribe(List.of("topic1", "topic2")); // bisa multi-topic

while (true) {
  ConsumerRecords<String, String> records = consumer.poll(Duration.ofSeconds(1));
  for (ConsumerRecord<String, String> record : records) {
    System.out.printf("topic=%s, partition=%d, offset=%d, key=%s, value=%s%n",
        record.topic(), record.partition(), record.offset(),
        record.key(), record.value());
  }
}
🧠 Key Concepts — Ringkasan
📡
Kafka = Distributed Event Streaming Platform. Bukan sekadar message queue — pesan tersimpan, bisa di-replay, bisa dikonsumsi oleh banyak consumer group secara independen.
🗂️
Topic + Partition = Scalability. Topic dibagi menjadi partition untuk paralelisme. Consumer dalam group yang sama dibagi partition-partition ini. Lebih banyak partition = lebih banyak consumer paralel.
🔑
Key = Routing + Ordering. Pesan dengan key yang sama selalu masuk ke partition yang sama — menjamin ordering per key. Tanpa key, routing round-robin.
👥
Consumer Group = Load Balancing built-in. GROUP_ID yang sama = partition dibagi merata (satu pesan diproses sekali). GROUP_ID berbeda = semua consumer group mendapat salinan penuh semua pesan.
📍
Offset = Bookmark posisi baca. Consumer menyimpan offset per partition untuk tahu pesan mana yang sudah diproses. Manual commit = at-least-once delivery yang lebih aman dari auto-commit.
🔧
Serializer/Deserializer harus simetris. Producer dan consumer harus setuju format encoding. Gunakan String untuk sederhana, JSON untuk object, atau Avro/Protobuf untuk schema evolution di production.
