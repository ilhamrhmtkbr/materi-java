Belajar Java Generics
Dari Generic Class sederhana sampai Variance & Type Erasure — panduan lengkap untuk PHP/Laravel developer yang ingin benar-benar paham type system Java.
🤔 Masalah Tanpa Generics: Kode Tanpa Type Safety

Bayangkan kamu punya kelas kotak yang bisa menyimpan data apapun:

// Tanpa Generics — pakai Object
public class MyData {
    private Object data;

    public Object getData() { return data; }
    public void setData(Object data) { this.data = data; }
}

// Akibatnya:
MyData box = new MyData();
box.setData("Eko");

String name = (String) box.getData(); // Harus casting manual — rawan ClassCastException!
Integer number = (Integer) box.getData(); // ❌ Runtime error: String cannot be cast to Integer

Dua masalah besar: (1) kamu harus casting manual di setiap pengambilan data, (2) error baru muncul saat runtime (bukan saat compile), artinya bug lolos ke production.

✅ Solusi: Generics — Type Safety Saat Compile
// Dengan Generics
MyData<String> box = new MyData<>("Eko");
String name = box.getData(); // Tidak perlu casting! Compiler sudah tahu tipenya String.

MyData<Integer> numBox = new MyData<>(100);
Integer num = numBox.getData(); // Aman, no casting needed

// box.setData(1000); // ❌ Compile error langsung! Integer tidak bisa masuk ke MyData<String>

Error sekarang terdeteksi saat kompilasi — jauh lebih aman. Tidak perlu casting manual. Kode lebih bersih dan self-documenting.

🐘 Analogi PHP/Laravel

PHP adalah loosely typed — variabel bisa menyimpan tipe apapun dan kamu baru tahu ada bug saat runtime. Java Generics adalah cara Java menjamin type safety di kompilasi waktu. Ini mirip dengan PHP 8 typed properties atau return type declarations, tapi jauh lebih powerful karena diterapkan di level class dan method secara generik.

// PHP: typed property (sejak PHP 7.4)
class Box {
    public string $data; // Hanya bisa String, tapi hanya untuk properti ini
}

// Java Generics jauh lebih fleksibel:
// Satu class Box<T> bisa jadi Box<String>, Box<Integer>, Box<User>, dll.
// Dengan jaminan type safety penuh di setiap varian!

Chapter 1 • Generic Class
📦 Generic Class — MyData<T>
Membuat kelas yang bisa bekerja dengan tipe data apapun — sambil tetap menjaga type safety.

Mari kita bedah kelas MyData<T> — contoh paling dasar dari Generic Class di Java.

// File: MyData.java
package programmer.zaman.now.generic;

public class MyData<T> {   // T = Type Parameter

    private T data;          // field bertipe T

    public MyData(T data) {  // konstruktor menerima T
        this.data = data;
    }

    public T getData() {     // return type adalah T
        return data;
    }

    public void setData(T data) { // parameter bertipe T
        this.data = data;
    }
}
class MyData<T>
T adalah Type Parameter — semacam "placeholder" untuk tipe data. Nama T adalah konvensi (singkatan Type). Saat class ini digunakan, T akan diganti dengan tipe konkret seperti String, Integer, User, dll.
private T data
Field bertipe T. Compiler akan memastikan field ini hanya bisa menampung tipe sesuai yang di-declare saat instantiasi. Jika MyData<String>, maka data hanya bisa menyimpan String.
public T getData()
Return type adalah T. Artinya: MyData<String>.getData() return String, MyData<Integer>.getData() return Integer — tanpa perlu casting!
💡 Cara Menggunakan MyData<T>
// File: GenericClassApp.java
public class GenericClassApp {
    public static void main(String[] args) {

        // Diamond operator <> — compiler menyimpulkan tipe dari context (Java 7+)
        MyData<String> stringMyData = new MyData<String>("Eko");
        MyData<Integer> integerMyData = new MyData<Integer>(10);

        // Tidak perlu casting!
        String stringValue = stringMyData.getData();   // Langsung String
        Integer integerValue = integerMyData.getData(); // Langsung Integer

        System.out.println(stringValue);  // Eko
        System.out.println(integerValue); // 10

        // ERROR compile: tipe tidak cocok
        // stringMyData.setData(999); // ❌ Integer tidak bisa masuk ke MyData<String>
    }
}
new MyData<String>("Eko")
Type argument: di sini kamu "mengisi" type parameter T dengan String. Mulai sini, semua kemunculan T di dalam class akan menjadi String.
new MyData<>("Eko") — Diamond Operator
Java 7+ memperkenalkan diamond operator <> — kamu bisa mengosongkan type argument di sisi kanan jika compiler bisa menyimpulkannya dari sisi kiri (type inference). Lebih ringkas.

❌ Tanpa Generics (Berbahaya)
// Raw type — hindari!
MyData rawData = new MyData("Eko");

// Casting manual, rawan error
String name = (String) rawData.getData();

// Ini compile tapi CRASH di runtime!
Integer num = (Integer) rawData.getData();
// ClassCastException!
✅ Dengan Generics (Aman)
// Typed — aman!
MyData<String> data = new MyData<>("Eko");

// Tidak perlu casting, error terdeteksi compile time
String name = data.getData();

// COMPILE ERROR langsung:
Integer num = data.getData(); // ❌
🐘 Analogi Laravel: Generic Repository

Di Laravel, kamu mungkin punya BaseRepository yang pakai $model bertipe mixed. Semua operasi dibungkus Model tapi tipe konkretnya hilang. Di Java, kamu bisa buat Repository<T> di mana T bisa jadi User, Post, dll., dan compiler akan memastikan kamu tidak meng-assign Post ke Repository<User>. Lebih type-safe dari PHP.

Chapter 2 • Multiple Type Parameters
🗝️ Pair<T, U> — Dua Type Parameter
Satu class bisa memiliki lebih dari satu type parameter — berguna untuk struktur data seperti pasangan key-value.
// File: Pair.java
package programmer.zaman.now.generic;

public class Pair<T, U> {   // Dua type parameter: T dan U

    private T first;          // field pertama bertipe T
    private U second;         // field kedua bertipe U

    public Pair(T first, U second) {
        this.first = first;
        this.second = second;
    }

    public T getFirst() { return first; }
    public void setFirst(T first) { this.first = first; }

    public U getSecond() { return second; }
    public void setSecond(U second) { this.second = second; }
}

// File: PairApp.java
public class PairApp {
    public static void main(String[] args) {

        // T = String, U = Integer
        Pair<String, Integer> pair = new Pair<String, Integer>("eko", 100);

        System.out.println(pair.getFirst());   // "eko" — tipe String
        System.out.println(pair.getSecond());  // 100 — tipe Integer

        // Contoh penggunaan lain:
        Pair<String, String> namePair = new Pair<>("firstName", "lastName");
        Pair<Integer, Boolean> indexFlag = new Pair<>(1, true);
    }
}
Pair<T, U>
Dua type parameter dipisahkan koma. T dan U adalah independent — bisa tipe yang sama (Pair<String, String>) atau berbeda (Pair<String, Integer>).
Pair<String, Integer>
Saat instantiasi, kamu memberi dua type argument. T → String, U → Integer. Compiler akan enforce: getFirst() return String, getSecond() return Integer.
💡 Pair di Java Standard Library

Java standard library sebenarnya tidak punya class Pair built-in (berbeda dari Python tuple atau PHP array pasangan). Tapi konsep ini banyak muncul di library lain (JavaFX punya javafx.util.Pair), dan kamu bisa buat sendiri seperti contoh ini. Di Java 16+, ada Record yang lebih modern: record Pair<T, U>(T first, U second) {}.

🐘 Analogi PHP: Array Asosiatif vs Typed Pair

Di PHP, kamu biasa pakai array: ['name' => 'Eko', 'age' => 25]. Tidak ada jaminan type — bisa saja value 'age' diisi String. Di Java Pair<String, Integer> menjamin secara compile time bahwa first selalu String dan second selalu Integer.

Chapter 3 • Generic Method
🔧 Generic Method — ArrayHelper
Method bisa punya type parameter sendiri, terpisah dari class-nya — membuat method yang bekerja untuk berbagai tipe array.
// File: ArrayHelper.java
package programmer.zaman.now.generic.util;

public class ArrayHelper {

    // Type parameter <T> dideklarasikan SEBELUM return type
    //       ↓↓↓
    public static <T> int count(T[] array) {
        return array.length;
    }
    //                 ↑↑↑↑↑↑↑
    // Menerima array dari tipe T apapun, return int
}
public static <T> int count(T[] array)
Posisi type parameter <T> ada di antara modifier (public static) dan return type (int). Ini menandakan bahwa T adalah type parameter milik method ini, bukan milik class. Method ini adalah generic method.
T[] array
Parameter bertipe array dari T. Satu method ini bisa menerima String[], Integer[], Person[], atau array dari tipe apapun. Java secara otomatis menentukan T dari tipe argument yang diberikan (type inference).
// File: ArrayHelperApp.java
public class ArrayHelperApp {
    public static void main(String[] args) {

        String[] names = {"Eko", "Kurniawan", "Khannedy"};
        Integer[] numbers = {1, 2, 3, 4, 5};

        // Cara 1: Explicit type argument — T diisi secara eksplisit
        System.out.println(
            ArrayHelper.<String>count(names)    // T = String → return 3
        );

        // Cara 2: Type inference — compiler menyimpulkan T dari argument
        System.out.println(
            ArrayHelper.count(numbers)           // T = Integer (disimpulkan), return 5
        );
    }
}
ArrayHelper.<String>count(names)
Explicit type argument: kamu secara manual mengisi T = String. Sintaks ini jarang dipakai karena Java biasanya bisa menyimpulkan sendiri, tapi berguna untuk dokumentasi atau saat inference gagal.
ArrayHelper.count(numbers)
Type inference: compiler melihat argument numbers adalah Integer[], lalu otomatis menyimpulkan T = Integer. Ini cara yang lebih umum dipakai.

🐘 Analogi Laravel: Helper Function Generic

Di PHP, fungsi helper seperti collect($array) menerima array apapun. Tapi tipe element-nya hilang — collect(['a','b']) dan collect([1,2]) sama-sama mengembalikan Collection tanpa tipe. Di Java, dengan generic method, kamu bisa buat ArrayHelper.<String>count(names) dan compiler tahu ini adalah String[].

Setelah access modifier, sebelum return type

Chapter 4 • Constraint / Bounded
🔒 Bounded Type Parameter — T extends Number
Membatasi tipe yang bisa digunakan sebagai type argument — hanya subtype dari kelas/interface tertentu yang diizinkan.

Terkadang kamu tidak ingin generic class menerima semua tipe. Misalnya, kelas NumberData hanya boleh menerima angka (Integer, Long, Double), bukan String atau tipe lain.

// File: ConstraintApp.java (inner class)
public static class NumberData<T extends Number> {
    //                          ^^^^^^^^^^^^^^^^
    // Bounded type: T harus subtype dari Number
    // Number adalah superclass dari: Integer, Long, Double, Float, Short, Byte

    private T data;

    public NumberData(T data) { this.data = data; }
    public T getData()        { return data; }
    public void setData(T data) { this.data = data; }
}

// Penggunaan:
NumberData<Integer> intData  = new NumberData<>(1);   // ✅ Integer extends Number
NumberData<Long>    longData = new NumberData<>(1L);   // ✅ Long extends Number
NumberData<Double>  dblData  = new NumberData<>(1.5);  // ✅ Double extends Number

// NumberData<String> strData = new NumberData<>("Eko"); // ❌ COMPILE ERROR!
// String bukan subtype dari Number
T extends Number
Upper Bounded Type Parameter. Keyword extends di sini berarti "T adalah subtype dari Number" — baik class yang meng-extend Number maupun interface yang meng-implement Number. extends digunakan untuk keduanya (bukan implements) dalam konteks generics.
Keuntungan bounded type
Selain membatasi tipe, bounded type juga memberikan akses ke method dari bound-nya. Karena T extends Number, di dalam class kamu bisa panggil data.intValue(), data.doubleValue(), dll — method yang dimiliki Number!
✅ Bonus: Akses Method dari Bound
public static class NumberData<T extends Number> {
    private T data;

    // Karena T extends Number, kita BISA akses method Number!
    public double toDouble() {
        return data.doubleValue(); // ✅ Method milik Number
    }

    public int toInt() {
        return data.intValue();    // ✅ Juga bisa
    }
}

// Tanpa bound (T saja), ini TIDAK bisa:
public static class AnyData<T> {
    private T data;
    // public double toDouble() { return data.doubleValue(); } // ❌ COMPILE ERROR
    // T bisa apa saja, tidak pasti punya method doubleValue()
}
🐘 Analogi Laravel: Type Hinting Interface

Di PHP: function process(Countable $item) — hanya objek yang implement Countable yang bisa dikirim. Java bounded generics mirip, tapi bekerja di level tipe generik: <T extends Countable> membatasi class generik agar hanya menerima tipe yang implement Countable.

🧠 Mini Quiz — Chapter 4

Pertanyaan: Dengan deklarasi class Box<T extends Number>, tipe apa saja yang valid untuk T?

Hanya Integer dan Long
Semua subclass dari Number: Integer, Long, Double, Float, Short, Byte, dan subclass Number kustom
Semua tipe termasuk String dan Object
Chapter 5 • Multiple Constraint
🔐 Multiple Constraint — T extends A & B
Type parameter bisa memiliki lebih dari satu batasan — harus merupakan subtype dari class DAN mengimplementasikan interface tertentu.
// File: MultipleConstraintApp.java
public class MultipleConstraintApp {

    // Interface
    public static interface CanSayHello {
        void sayHello(String name);
    }

    // Abstract class
    public static abstract class Employee { }

    // Subclass Employee yang TIDAK implement CanSayHello
    public static class Manager extends Employee { }

    // Subclass Employee yang JUGA implement CanSayHello
    public static class VicePresident extends Employee implements CanSayHello {
        @Override
        public void sayHello(String name) {
            System.out.println("Hello " + name);
        }
    }

    // Multiple constraint: T harus extends Employee DAN implements CanSayHello
    //                                           ↓                ↓
    public static class Data<T extends Employee & CanSayHello> {
        private T data;
        public Data(T data) { this.data = data; }
        public T getData()  { return data; }

        // Bisa panggil method dari KEDUA bound!
        public void greet(String name) {
            data.sayHello(name); // ✅ Method dari CanSayHello
        }
    }

    public static void main(String[] args) {
        // ✅ VicePresident memenuhi KEDUA constraint
        Data<VicePresident> vpData = new Data<>(new VicePresident());
        vpData.getData().sayHello("Eko"); // Hello Eko

        // ❌ COMPILE ERROR: Manager hanya extends Employee, tidak implement CanSayHello
        // Data<Manager> mgrData = new Data<>(new Manager());
    }
}
T extends Employee & CanSayHello
Operator & menggabungkan multiple bound. Aturan: maksimal satu class (harus diletakkan pertama), diikuti satu atau lebih interface. Contoh: T extends MyClass & Interface1 & Interface2 adalah valid. T extends Interface1 & MyClass — class harus selalu pertama!
Akses method dari semua bound
Di dalam class Data<T>, kamu bisa memanggil method dari Employee DAN CanSayHello karena compiler menjamin T pasti memiliki keduanya.
⚠️ Aturan Multiple Bound

1 class (pertama) + beberapa interface — urutan penting!

// ✅ Valid: class dulu, lalu interface
<T extends Employee & CanSayHello & Serializable>

// ❌ Invalid: dua class sekaligus (Java tidak support multiple inheritance class)
<T extends Employee & Manager> // Error!

// ✅ Valid: hanya interface-interface
<T extends CanSayHello & Serializable>
🐘 Analogi Laravel: Multiple Interface Hinting

Di PHP (union type PHP 8): function process(Employee&CanSayHello $obj) — sayangnya PHP tidak support intersection type seperti ini di semua versi. PHP 8.1 baru memperkenalkan intersection types. Java sudah bisa multiple constraint sejak Java 5.

Chapter 6 • Variance
🚫 Invariance — Generics Tidak Otomatis Mewarisi
Konsep paling membingungkan bagi developer baru: meski String adalah subtype dari Object, MyData<String> BUKAN subtype dari MyData<Object>.
⚠️ Konsep Penting: Invariance

Di Java, generics bersifat invariant secara default. Artinya: hubungan subtype antar class generic tidak mengikuti hubungan subtype antar type argument-nya.

// File: InvariantApp.java

public class InvariantApp {
    public static void main(String[] args) {

        // ── Subtype normal: String IS-A Object ──
        Object obj = "Eko"; // ✅ String bisa masuk ke variabel Object

        // ── Tapi dengan Generics: INVARIANT! ──
        MyData<String> stringMyData = new MyData<>("Eko");

        // doIt(stringMyData);           // ❌ COMPILE ERROR!
        // MyData<Object> objectMyData = stringMyData; // ❌ COMPILE ERROR!

        // Kenapa? Karena MyData<String> BUKAN subtype dari MyData<Object>!

        MyData<Object> objectMyData = new MyData<>(1000);

        // doItInteger(objectMyData);    // ❌ COMPILE ERROR!
        // MyData<Integer> intMyData = objectMyData; // ❌ COMPILE ERROR!

        // Meski 1000 adalah Integer dan Integer IS-A Object,
        // MyData<Object> BUKAN subtype dari MyData<Integer>!
    }

    public static void doIt(MyData<Object> objectMyData) { /* ... */ }
    public static void doItInteger(MyData<Integer> integerMyData) { /* ... */ }
}
Kenapa Invariant? — Alasan Keamanan
Bayangkan jika MyData<String> bisa diassign ke MyData<Object>: seseorang bisa memanggil objectMyData.setData(new Integer(100)) pada objek yang sebenarnya adalah MyData<String> — merusak type safety! Java sengaja melarang ini untuk menjaga keamanan.
Berbeda dengan Array!
Menariknya, array di Java bersifat covariant: String[] bisa diassign ke Object[]. Tapi ini justru menjadi sumber bug potensial (ArrayStoreException). Generics diperbaiki untuk menghindari masalah yang sama.

Hubungan Subtype: Kelas vs Generic

String → IS-A → Object ✅ Valid
MyData<String> → IS-A? → MyData<Object> ❌ TIDAK! Invariant
MyData<String> → IS-A? → MyData<?> ✅ Valid (via Wildcard)
🐘 Analogi PHP: Tidak Ada Equivalent Langsung

PHP tidak punya sistem generics yang di-enforce compiler, jadi konsep invariance tidak ada di PHP. Di PHP, kamu bisa pass Collection apapun ke fungsi yang expect Collection — type checking hanya melalui runtime type hints, bukan compile time. Invariance adalah trade-off Java untuk keamanan penuh di waktu kompilasi.

🧠 Mini Quiz — Chapter 6

Pertanyaan: Mengapa Java membuat generics bersifat invariant (tidak mengikuti hubungan subtype class)?

Karena limitasi teknis compiler Java yang tidak bisa mendeteksi relasi subtype
Untuk menjaga type safety — mencegah bug seperti memasukkan Integer ke dalam kontainer yang sebenarnya hanya untuk String
Karena generics di Java hanya untuk efisiensi performa, bukan type safety
Chapter 7 • Wildcard
❓ Wildcard — MyData<?>
Tanda tanya ? sebagai "tipe apapun" — solusi untuk menerima generic dengan type argument yang tidak diketahui.

Karena generics bersifat invariant, bagaimana caranya membuat method yang bisa menerima MyData<String>, MyData<Integer>, MyData<ApaAja> sekaligus? Jawabannya: Wildcard ?.

// File: WildcardApp.java
public class WildcardApp {
    public static void main(String[] args) {

        // Method print() menerima MyData dari tipe APAPUN
        print(new MyData<Integer>(100));          // ✅
        print(new MyData<String>("Eko"));          // ✅
        print(new MyData<Manager>(new Manager())); // ✅

    }

    // ? = Wildcard: "MyData dengan tipe apapun"
    public static void print(MyData<?> myData) {
        System.out.println(myData.getData()); // Return type: Object (tipe paling umum)
        // Tapi perhatikan:
        // myData.setData("something"); // ❌ COMPILE ERROR — tidak boleh write!
    }
}
MyData<?>
Unbounded Wildcard: tanda ? berarti "tipe apapun yang tidak diketahui". Ini berbeda dari MyData<Object>! MyData<Object> hanya menerima MyData yang tepat bertipe Object. MyData<?> menerima MyData dari tipe apapun.
getData() return Object
Karena tipe tidak diketahui, getData() hanya bisa mengembalikan Object (tipe paling umum). Kamu kehilangan informasi tipe spesifik — ini trade-off dari wildcard.
setData() dilarang — Read-Only!
Karena tipe tidak diketahui, kamu tidak boleh menulis/mengirim data ke objek wildcard. Bayangkan kamu tidak tahu isinya apa — tidak aman untuk menambahkan data baru. Wildcard membuat kontainer menjadi read-only.
💡 MyData<Object> vs MyData<?> — Perbedaan Kritis
MyData<Object> — Sempit
void process(MyData<Object> d) { }

MyData<String> s = new MyData<>("Eko");
process(s); // ❌ ERROR!
// MyData<String> bukan MyData<Object>
// (Invariance)
MyData<?> — Fleksibel
void process(MyData<?> d) { }

MyData<String> s = new MyData<>("Eko");
process(s); // ✅ OK!
// Wildcard menerima tipe apapun
🐘 Analogi PHP: mixed type

Di PHP 8, ada keyword mixed yang artinya "tipe apapun". function process(mixed $data) mirip dengan Java Wildcard MyData<?> dalam spirit — menerima semua. Bedanya: PHP tidak enforce apa-apa, sementara Java Wildcard masih type-safe (tidak boleh write, return sebagai Object).

Chapter 8 • Variance
📤 Covariance — MyData<? extends T>
"Aku bisa baca data ini, tapi tidak bisa tulis" — bounded wildcard upper bound untuk producer/read-only.
// File: CovariantApp.java
public class CovariantApp {
    public static void main(String[] args) {

        MyData<String> stringMyData = new MyData<>("Eko");

        // Kirim ke method yang menerima MyData<? extends Object>
        process(stringMyData); // ✅ String IS-A Object, Covariant!

        // Bisa juga: MyData<? extends Object> adalah "supertipe" dari MyData<String>
        MyData<? extends Object> myData = stringMyData; // ✅
        Object value = myData.getData();                  // ✅ Bisa READ

        // myData.setData("value"); // ❌ TIDAK BOLEH WRITE!
    }

    public static void process(MyData<? extends Object> myData) {
        // getData() return Object (bound atas)
        Object value = myData.getData();
        System.out.println(value);

        // TIDAK BOLEH: myData.setData(1); // ❌ Dangerous! Kita tidak tau tipe persisnya
    }
}
MyData<? extends Object>
Upper Bounded Wildcard (Covariance): ? bisa tipe apapun yang extends atau sama dengan Object. Artinya MyData<String>, MyData<Integer>, MyData<User> — semua diterima. Object adalah upper bound (batas atas).
Hanya READ — tidak boleh WRITE
Dengan covariance, kamu hanya bisa membaca (produce) data. Mengapa tidak boleh write? Karena kamu tidak tahu tipe persisnya — mungkin MyData<String>, tidak aman untuk memasukkan Integer. Ini dikenal sebagai Producer Extends dalam PECS principle.
getData() return Object
Upper bound menentukan return type getter. Karena bound adalah Object, maka getData() return Object. Jika bound-nya Number (? extends Number), maka getData() return Number.
💡 Contoh Praktis: Covariance dengan Number
// Menjumlahkan semua angka dari container apapun (Integer, Double, Float, dll)
public static double sum(MyData<? extends Number> data) {
    return data.getData().doubleValue(); // ✅ Bisa akses method Number
    // data.setData(1); // ❌ Tidak bisa write
}

sum(new MyData<Integer>(100));  // ✅
sum(new MyData<Double>(3.14));  // ✅
sum(new MyData<Float>(2.5f));   // ✅
🐘 Analogi PHP: Covariant Return Types (PHP 7.4+)

PHP 7.4+ mendukung covariant return types: jika parent mengembalikan Animal, child boleh mengembalikan Dog (subtype). Java Covariance wildcard adalah konsep serupa tapi untuk generic container — container yang lebih spesifik (MyData<String>) bisa dipakai sebagai yang lebih umum (MyData<? extends Object>).

Chapter 9 • Variance
📥 Contravariance — MyData<? super T>
"Aku bisa tulis data ini, tapi tidak bisa baca dengan tipe spesifik" — bounded wildcard lower bound untuk consumer/write-only.
// File: ContravariantApp.java
public class ContravariantApp {
    public static void main(String[] args) {

        MyData<Object> objectMyData = new MyData<>("Eko");
        objectMyData.setData(1000);

        // MyData<Object> bisa diassign ke MyData<? super String>
        // karena Object IS-A supertype dari String
        MyData<? super String> myData = objectMyData; // ✅

        process(objectMyData);                          // ✅ Juga bisa

        System.out.println(objectMyData.getData()); // Eko Kurniawan (setelah process)
    }

    public static void process(MyData<? super String> myData) {
        // getData() return Object (tidak tahu tipe pasti)
        Object value = myData.getData();
        System.out.println("Process parameter " + value);

        // BOLEH setData() dengan String atau subtype-nya!
        myData.setData("Eko Kurniawan"); // ✅ String aman untuk dimasukkan
        // myData.setData(100); // ❌ Integer tidak aman — container mungkin hanya terima String
    }
}
MyData<? super String>
Lower Bounded Wildcard (Contravariance): ? bisa tipe apapun yang merupakan supertype atau sama dengan String. Untuk String, supertypenya adalah: String, Comparable, CharSequence, Object. Sehingga MyData<Object>, MyData<CharSequence> diterima.
Bisa WRITE, tidak bisa READ spesifik
Dengan contravariance, kamu bisa menulis/mengirim data tipe T (String) atau subtype-nya. Tapi reading hanya mengembalikan Object karena tidak tahu tipe pasti. Ini dikenal sebagai Consumer Super dalam PECS principle.
Kenapa Object bisa masuk <? super String>?
MyData<Object> valid untuk MyData<? super String> karena Object adalah supertype dari String. Logikanya: jika container bisa menyimpan Object, maka pasti bisa menyimpan String (karena String IS-A Object).
💡 PECS — Producer Extends, Consumer Super

Ini adalah mnemonic populer untuk mengingat kapan pakai apa:

📤 PRODUCER — Extends

Kamu membaca dari container ini.
<? extends T>
Read-only. getData() return T.

📥 CONSUMER — Super

Kamu menulis ke container ini.
<? super T>
Write-enabled. getData() return Object.

🔄 PRODUCER+CONSUMER

Kamu baca DAN tulis.
<T> (exact type)
Tidak bisa flexible.

🐘 Analogi PHP: Contravariant Parameter Types (PHP 7.4+)

PHP 7.4 mendukung contravariant parameter types: jika parent method menerima Dog, child boleh menerima Animal (supertype lebih luas). Java contravariance wildcard adalah konsep serupa: method yang expect parameter MyData<? super String> bisa menerima container yang lebih umum dari String.

Chapter 10 • Internals
🪄 Type Erasure — Rahasia di Balik Generics
Saat runtime, informasi generic type dihapus oleh compiler — ini disebut type erasure, dan punya implikasi penting yang perlu kamu pahami.
// File: TypeErasureApp.java
public class TypeErasureApp {
    public static void main(String[] args) {

        // Raw type: tanpa type argument
        MyData myData = new MyData("Eko"); // ⚠️ Warning: raw type

        // Casting ke generic type — COMPILE OK tapi ada unchecked cast warning
        MyData<Integer> integerMyData = (MyData<Integer>) myData;

        // getData() → runtime ini sebenarnya return String "Eko"
        // tapi kita "paksa" interpret sebagai Integer
        Integer integer = integerMyData.getData(); // ❌ ClassCastException di runtime!
    }
}
Apa itu Type Erasure?
Java mengimplementasikan Generics dengan teknik type erasure: semua informasi type parameter (<T>, <String>, dll.) dihapus oleh compiler saat bytecode dikompilasi. Di runtime, MyData<String> dan MyData<Integer> adalah class yang sama: MyData. Compiler menambahkan casting secara otomatis.
Alasan Type Erasure
Generics di Java ditambahkan di Java 5 (2004), sedangkan JVM dan library sebelumnya tidak kenal Generics. Type erasure memungkinkan kode generic berjalan di JVM lama tanpa perubahan bytecode — backward compatibility. Berbeda dengan C# yang menggunakan "reified generics" (informasi tipe ada di runtime).
(MyData<Integer>) myData — Unchecked Cast
Compiler akan memberi unchecked cast warning. Ini artinya compiler tidak bisa memverifikasi keamanan cast ini. Bug hanya terlihat saat runtime ketika kamu mencoba menggunakan data tersebut — persis seperti masalah yang ingin dihindari oleh Generics!

Semua <T> diganti Object (atau bound tertinggi jika bounded). Compiler menyisipkan casting otomatis di tempat yang diperlukan.

MyData<String> data = new MyData<>("Eko");

if (data instanceof MyData) { } // ✅ Hanya ini yang bisa

    // T obj = new T(); // ❌ Tidak tahu tipe T saat runtime!
}

// 3. Tidak bisa T[] array = new T[10]
// T[] arr = new T[10]; // ❌ Sama alasannya

// 4. Tidak bisa method overload berbeda hanya di generic
// void process(MyData<String> data) { }  // ❌ Setelah erasure, keduanya sama:
// void process(MyData<Integer> data) { } // method(MyData) — duplicate!

Chapter 11 • Comparable
⚖️ Comparable<T> — Natural Ordering
Interface generic built-in untuk mendefinisikan urutan "natural" dari suatu objek — agar bisa di-sort otomatis.

Comparable<T> adalah contoh nyata pemakaian generics di Java standard library. Dengan mengimplementasikannya, kamu mendefinisikan bagaimana objek harus dibandingkan satu sama lain.

// File: Person.java
package programmer.zaman.now.generic;

public class Person implements Comparable<Person> {
//                       ↑ Implementasi Comparable dengan type argument Person

    private String name;
    private String address;

    public Person(String name, String address) {
        this.name = name;
        this.address = address;
    }

    // Getters & setters (omitted for brevity)

    @Override
    public int compareTo(Person o) {
    //         ↑↑↑↑↑↑↑↑↑↑↑↑↑↑↑↑ Signature dari Comparable<Person>
        return this.name.compareTo(o.name);
        // String.compareTo(): negatif = this lebih kecil, 0 = sama, positif = this lebih besar
    }

    @Override
    public String toString() {
        return "Person{name='" + name + "', address='" + address + "'}";
    }
}
// File: ComparableApp.java
public class ComparableApp {
    public static void main(String[] args) {

        Person[] people = {
            new Person("Eko", "Indonesia"),
            new Person("Budi", "Indonesia"),
            new Person("Joko", "Indonesia")
        };

        // Arrays.sort() memanggil compareTo() secara internal!
        Arrays.sort(people);

        // Output: Budi, Eko, Joko (urutan alphabetical by name)
        System.out.println(Arrays.toString(people));
    }
}
implements Comparable<Person>
Type argument Person membuat compareTo(Person o) — bukan compareTo(Object o). Ini type-safe: compiler memastikan kamu hanya membandingkan Person dengan Person. Tanpa generics, parameter-nya Object dan perlu casting manual.
compareTo() return int
Konvensi: negatif = this lebih kecil dari o, 0 = sama, positif = this lebih besar dari o. Bisa pakai String.compareTo(), Integer.compare(), atau hitung manual return a - b (hati-hati overflow untuk angka besar!).
Arrays.sort() + Comparable
Arrays.sort(), Collections.sort(), dan struktur data seperti TreeSet/TreeMap semua bergantung pada Comparable. Jika class tidak implement Comparable dan kamu coba sort, hasilnya ClassCastException di runtime.
📝 Signature Comparable di Source Code Java
// Interface Comparable di java.lang (sudah built-in)
public interface Comparable<T> {
    int compareTo(T o);
    // Satu method saja — ini adalah Functional Interface!
}

Semua wrapper class Java (Integer, String, Double, dll.) sudah mengimplementasikan Comparable. Makanya Collections.sort(List<String>) langsung bisa bekerja.

🐘 Analogi Laravel: sortBy & usort PHP

Di Laravel: collect($people)->sortBy('name') — sorting by string key, tapi tidak ada type checking. Di PHP: usort($arr, fn($a,$b) => strcmp($a->name, $b->name)). Di Java dengan Comparable, class mendefinisikan cara sort-nya sendiri, dan semua framework sorting (Arrays.sort, TreeSet) otomatis menggunakannya.

Chapter 12 • Comparator
📐 Comparator<T> — Custom Ordering
Ketika kamu butuh urutan berbeda dari natural ordering, atau class-nya tidak bisa dimodifikasi — Comparator adalah jawabannya.
🔄 Comparable vs Comparator

// File: ComparatorApp.java
public class ComparatorApp {
    public static void main(String[] args) {

        Person[] people = {
            new Person("Eko", "Indonesia"),
            new Person("Budi", "Indonesia"),
            new Person("Joko", "Indonesia")
        };

        // Buat Comparator menggunakan anonymous class
        Comparator<Person> comparator = new Comparator<Person>() {
            @Override
            public int compare(Person o1, Person o2) {
                return o1.getName().compareTo(o2.getName());
                // Logika sort: alphabetical by name
            }
        };

        // Inject comparator ke sort
        Arrays.sort(people, comparator);
        System.out.println(Arrays.toString(people)); // Budi, Eko, Joko

        // ─────────────── Cara Modern: Lambda ───────────────
        Arrays.sort(people, (o1, o2) -> o1.getName().compareTo(o2.getName()));

        // Atau lebih ringkas dengan method reference:
        Arrays.sort(people, Comparator.comparing(Person::getName));

        // Sort descending:
        Arrays.sort(people, Comparator.comparing(Person::getName).reversed());
    }
}
new Comparator<Person>() { ... }
Anonymous class: implementasi interface Comparator secara inline. Ini gaya lama (pre-Java 8). Di era modern, digantikan lambda karena Comparator hanya punya satu abstract method — termasuk Functional Interface.
(o1, o2) -> o1.getName().compareTo(o2.getName())
Lambda expression — gaya modern yang lebih ringkas. Karena Comparator<T> adalah Functional Interface (hanya satu abstract method: compare()), bisa ditulis sebagai lambda.
Comparator.comparing(Person::getName)
Method reference + static factory: cara paling bersih. Person::getName adalah method reference (shortcut untuk p -> p.getName()). Comparator.comparing() adalah static factory yang otomatis membangun comparator dari key extractor.
✅ Chaining Comparator (Multi-level Sort)
// Sort by address dulu, jika address sama maka sort by name
Comparator<Person> multiSort = Comparator
    .comparing(Person::getAddress)
    .thenComparing(Person::getName);

Arrays.sort(people, multiSort);

// Sort by name descending, then by address ascending
Comparator<Person> complexSort = Comparator
    .comparing(Person::getName).reversed()
    .thenComparing(Person::getAddress);
🐘 Analogi Laravel: Collection sortBy

Di Laravel: $people->sortBy('name') atau $people->sortBy(fn($p) => $p->name). Di Java: Arrays.sort(people, Comparator.comparing(Person::getName)). Konsep identik — externalized ordering logic. Bedanya: Java versi ini type-safe dan compiler akan error jika getName() tidak ada di class Person.

Summary
📊 Rangkuman Java Generics
Semua yang telah dipelajari dalam satu halaman — referensi cepat untuk Java Generics.
1
📦 Generic Class — MyData<T>
Kelas dengan type parameter <T>. Membuat satu class bisa bekerja dengan banyak tipe secara type-safe. Constructor, field, method bisa menggunakan T. Gunakan diamond operator <> untuk type inference.
2
🗝️ Multiple Type Parameters — Pair<T, U>
Class dengan lebih dari satu type parameter, dipisah koma. Setiap parameter independent. Berguna untuk struktur data pasangan (key-value, result-error).
3
🔧 Generic Method — <T> returnType method(T[] arr)
Method punya type parameter sendiri. Deklarasi <T> di antara modifier dan return type. Bisa pakai explicit Class.<Type>method() atau biarkan type inference bekerja.
4
🔒 Bounded Type — T extends Number
Membatasi type argument ke subtype tertentu. Bonus: bisa akses method dari bound di dalam class. Keyword extends untuk keduanya (class maupun interface).
5
🔐 Multiple Bound — T extends A & B
T harus subtype dari class A DAN implement interface B. Class selalu pertama, interface menyusul. Bisa akses method dari semua bound.
6
🚫 Invariance — MyData<String> ≠ MyData<Object>
Generics default invariant: relasi subtype class tidak mewarisi ke generic container. MyData<String> bukan subtype MyData<Object> meski String IS-A Object. Ini by-design untuk type safety.
7
❓ Wildcard — MyData<?>
Unbounded wildcard: menerima generic dari tipe apapun. Read-only (tidak bisa setData). getData() return Object. Berbeda dari MyData<Object> yang lebih sempit.
8
📤 Covariance — MyData<? extends T> (PRODUCER)
Upper bounded wildcard. Read-only. getData() return T. Menerima MyData dari T dan semua subtype-nya. Gunakan ketika kamu hanya MEMBACA dari container (Producer Extends dari PECS).
9
📥 Contravariance — MyData<? super T> (CONSUMER)
Lower bounded wildcard. Write-enabled untuk T dan subtype-nya. getData() return Object. Menerima MyData dari T dan semua supertype-nya. Gunakan ketika kamu hanya MENULIS ke container (Consumer Super dari PECS).
10
🪄 Type Erasure
Compiler menghapus semua info generic saat kompilasi untuk backward compatibility. Runtime hanya kenal raw type. Implikasi: tidak bisa instanceof generic, new T(), atau T[], dan overloading hanya beda generic dilarang.
11
⚖️ Comparable<T>
Built-in generic interface untuk natural ordering. Implement di class untuk mendefinisikan urutan default. compareTo() return int (negatif/0/positif). Digunakan otomatis oleh Arrays.sort, Collections.sort, TreeSet, TreeMap.
12
📐 Comparator<T>
External ordering — tidak perlu modifikasi class. Bisa multiple strategy sort. Functional Interface → bisa ditulis sebagai lambda. Gunakan Comparator.comparing() + method reference untuk kode paling bersih.

🧠 Key Insights untuk PHP Developer
🛡️ Compile-time Safety

Generics memberi type safety saat kompilasi — bug terdeteksi sebelum kode berjalan. PHP PHP 8 typed properties mendekat tapi belum se-powerful Java Generics.

🎭 Type Erasure = Runtime = Object

Saat runtime, semua generic menjadi Object. Jangan coba instanceof check terhadap generic type — tidak akan berhasil.

📦 PECS Rule

Producer Extends, Consumer Super. Hafalkan ini untuk memilih wildcard yang tepat kapanpun.

⚖️ Comparable vs Comparator

Comparable = natural order built-in di class (satu). Comparator = external, multiple strategy. Jika class milikmu → Comparable. Jika class orang lain / butuh multiple sort → Comparator.
