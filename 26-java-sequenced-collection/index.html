Java Sequenced Collections
Fitur baru Java 21 yang akhirnya menjawab pertanyaan lama: "Bagaimana cara akses elemen pertama dan terakhir dari koleksi apapun dengan cara yang seragam?"

Java 21 (LTS)

JEP 431

SequencedCollection

SequencedSet

SequencedMap


Sebelum Java 21, tidak ada cara yang konsisten dan seragam untuk mengakses elemen pertama atau terakhir dari semua jenis koleksi. Java 21 memperkenalkan tiga interface baru yang menjadi solusinya: SequencedCollection, SequencedSet, dan SequencedMap — retroactively ditambahkan ke hierarki Collections Framework yang sudah ada.

Chapter 0
🧠 Masalah Lama yang Akhirnya Selesai
Sebelum Java 21, cara akses elemen pertama/terakhir berbeda-beda di tiap tipe koleksi. Tidak ada satu API yang bisa dipakai seragam. Java 21 memperbaiki ini.
Problem — API yang Tidak Konsisten (Sebelum Java 21)
// Sebelum Java 21: cara berbeda untuk setiap tipe koleksi

// List → pakai get(0) dan get(size-1)
List<String> list = new ArrayList<>(List.of("A","B","C"));
String first = list.get(0);              // elemen pertama
String last  = list.get(list.size() - 1); // elemen terakhir — verbose!

// Deque → pakai peekFirst() / peekLast()
Deque<String> deque = new ArrayDeque<>(List.of("A","B","C"));
String first = deque.peekFirst();
String last  = deque.peekLast();

// SortedSet → pakai first() / last()
SortedSet<String> set = new TreeSet<>(Set.of("A","B","C"));
String first = set.first();
String last  = set.last();

// LinkedHashMap → tidak ada cara langsung! Harus workaround:
LinkedHashMap<String,String> map = new LinkedHashMap<>();
// Cara lama: iterasi ke elemen pertama entry set
Map.Entry<String,String> firstEntry = map.entrySet().iterator().next(); // 😱
🚨 Masalahnya: Tidak ada interface tunggal yang bisa kamu gunakan untuk seragam mengakses elemen pertama/terakhir. Ini memaksa developer menulis kode yang berbeda-beda tergantung tipe koleksi yang digunakan, dan tidak bisa polimorfis.
Solusi Java 21 — Tiga Interface Baru (JEP 431)
// Setelah Java 21: API yang seragam untuk semua koleksi berurutan

SequencedCollection<String> list  = new ArrayList<>();
SequencedCollection<String> deque = new ArrayDeque<>();

// Sama persis untuk keduanya!
list.getFirst();   deque.getFirst();
list.getLast();    deque.getLast();
list.addFirst("X"); deque.addFirst("X");
list.addLast("Z");  deque.addLast("Z");
list.removeFirst(); deque.removeFirst();
list.removeLast();  deque.removeLast();
list.reversed();    deque.reversed(); // view urutan terbalik
💡 Retroactively Fitted: Java 21 tidak membuat class baru — ia menambahkan interface baru ke class yang sudah ada. ArrayList, LinkedList, ArrayDeque, TreeSet, LinkedHashSet, TreeMap, LinkedHashMap — semua kini mengimplementasikan interface Sequenced yang baru. Kode lama tidak rusak.
🐘 Analogi Laravel / PHP

PHP array selalu punya reset($arr) (elemen pertama) dan end($arr) (terakhir) secara seragam untuk semua array. Laravel Collection punya ->first() dan ->last() yang bisa dipakai di semua Collection. Java baru mendapatkan keseragaman ini di versi 21 — dan caranya lebih elegan karena berbasis interface, bukan fungsi global.

Chapter 1
🌳 Hierarki Interface Baru di Java 21
Tiga interface baru "disisipkan" ke tengah hierarki Collections yang sudah ada. Penting untuk memahami posisinya agar tahu class mana yang bisa digunakan sebagai Sequenced*.
Hierarki Setelah Java 21
java.lang.Iterable<E> └─ java.util.Collection<E> ├─ java.util.SequencedCollection<E> ← 🆕 BARU di Java 21 │ │ getFirst(), getLast() │ │ addFirst(e), addLast(e) │ │ removeFirst(), removeLast() │ │ reversed() → SequencedCollection<E> │ │ │ ├─ java.util.List<E> │ │ ├─ ArrayList<E> ← sekarang implement SequencedCollection │ │ ├─ LinkedList<E> │ │ └─ Vector<E> │ │ │ ├─ java.util.SequencedSet<E> ← 🆕 BARU di Java 21 │ │ │ reversed() → SequencedSet<E> (override, lebih spesifik) │ │ │ │ │ ├─ java.util.SortedSet<E> │ │ │ └─ NavigableSet<E> │ │ │ └─ TreeSet<E> ← sekarang implement SequencedSet │ │ │ │ │ └─ LinkedHashSet<E> ← sekarang implement SequencedSet │ │ │ └─ Deque<E> │ ├─ ArrayDeque<E> │ └─ LinkedList<E> │ └─ java.util.Set<E> └─ HashSet<E> ← TIDAK implement SequencedCollection (urutan tidak ada) ──── Map (hierarki terpisah) ──── java.util.Map<K,V> └─ java.util.SequencedMap<K,V> ← 🆕 BARU di Java 21 │ firstEntry(), lastEntry() │ putFirst(k,v), putLast(k,v) │ reversed() → SequencedMap<K,V> │ sequencedKeySet(), sequencedValues(), sequencedEntrySet() │ ├─ LinkedHashMap<K,V> ← sekarang implement SequencedMap └─ SortedMap → NavigableMap └─ TreeMap<K,V> ← sekarang implement SequencedMap
⚠️ Perhatikan: HashSet dan HashMap tidak mengimplementasikan interface Sequenced karena keduanya tidak memiliki urutan yang terdefinisi. Sequenced Collections hanya berlaku untuk koleksi yang memiliki urutan tetap — insertion order, sorted order, atau urutan natural lainnya.

Chapter 2
📋 SequencedCollection — CollectionTest.java
Test pertama menggunakan ArrayList sebagai SequencedCollection. Di sini kita lihat seluruh API: addFirst, addLast, getFirst, getLast, reversed, removeFirst, removeLast — semuanya dalam satu test case.
Source — CollectionTest.java
@Test
void collection() {
    SequencedCollection<String> list = new ArrayList<>();

    list.addLast("Khannedy");   // ["Khannedy"]
    list.addFirst("Kurniawan"); // ["Kurniawan", "Khannedy"]
    list.addFirst("Eko");       // ["Eko", "Kurniawan", "Khannedy"]

    Assertions.assertEquals(List.of("Eko", "Kurniawan", "Khannedy"), list);

    Assertions.assertEquals("Eko",      list.getFirst()); // elemen index 0
    Assertions.assertEquals("Khannedy", list.getLast());  // elemen index terakhir

    SequencedCollection<String> reversed = list.reversed();
    Assertions.assertEquals(List.of("Khannedy", "Kurniawan", "Eko"), reversed);

    String value = list.removeFirst(); // hapus & ambil "Eko"
    Assertions.assertEquals("Eko",       value);
    Assertions.assertEquals("Kurniawan", list.getFirst()); // sekarang first = "Kurniawan"

    value = list.removeLast();  // hapus & ambil "Khannedy"
    Assertions.assertEquals("Khannedy",  value);
    Assertions.assertEquals("Kurniawan", list.getLast()); // tinggal 1 elemen
}

Penjelasan Per Operasi
addFirst(e) Menyisipkan elemen di posisi 0 — semua elemen yang ada bergeser ke kanan. Untuk ArrayList, ini O(n) karena harus geser elemen. Untuk LinkedList/ArrayDeque, ini O(1). Tapi dengan SequencedCollection, kamu tidak perlu tahu implementasinya — API-nya sama. addLast(e) Menambahkan elemen di posisi terakhir. Untuk ArrayList ini setara dengan list.add(e). Dengan Java 21, addLast() adalah cara yang lebih eksplisit dan ekspresif niatnya. getFirst() / getLast() Mengambil elemen tanpa menghapusnya. Jika koleksi kosong, keduanya throw NoSuchElementException. Ini berbeda dari peek() di Queue yang return null jika kosong — pilih sesuai kebutuhan. reversed() Mengembalikan live view dengan urutan terbalik. Ini bukan salinan — modifikasi pada list asli akan terlihat di reversed view, dan sebaliknya. Sangat efisien karena tidak mengkopi data. removeFirst() / removeLast() Mengambil sekaligus menghapus elemen. Return value adalah elemen yang dihapus. Jika kosong, throw NoSuchElementException.
❌ Sebelum Java 21 — Verbose
List<String> list = new ArrayList<>();

// addFirst? Tidak ada! Harus pakai:
list.add(0, "Eko");  // insert at index 0

// getLast? Tidak ada langsung!
String last = list.get(list.size() - 1);

// removeFirst?
String first = list.remove(0);

// removeLast?
String last = list.remove(list.size() - 1);
✅ Java 21 — Ekspresif & Seragam
SequencedCollection<String> list = new ArrayList<>();

list.addFirst("Eko");     // ← jelas
list.addLast("Budi");     // ← jelas

String last  = list.getLast();    // ← jelas
String first = list.removeFirst(); // ← jelas
String l     = list.removeLast();  // ← jelas
🐘 Analogi Laravel / PHP

addFirst() = array_unshift($arr, $value) atau collect()->prepend($value).
addLast() = array_push($arr, $value) atau collect()->push($value).
getFirst() = reset($arr) atau collect()->first().
getLast() = end($arr) atau collect()->last().
reversed() = array_reverse($arr) atau collect()->reverse() — tapi versi Java adalah live view, bukan copy!

Chapter 3
🎯 SequencedSet — SetTest.java
SequencedSet extends SequencedCollection dan Set. Menambahkan jaminan: tidak ada duplikat + memiliki urutan yang terdefinisi. Implementasi utamanya adalah TreeSet (sorted) dan LinkedHashSet (insertion-ordered).
Source — SetTest.java
@Test
void set() {
    SequencedSet<String> set = new TreeSet<>(); // TreeSet: selalu sorted alphabetical

    set.add("Eko");   // {"Eko"}
    set.add("Budi");  // {"Budi", "Eko"}         ← TreeSet sort otomatis!
    set.add("Joko");  // {"Budi", "Eko", "Joko"}

    // getFirst/getLast sekarang tersedia di Set!
    Assertions.assertEquals("Budi", set.getFirst()); // huruf B < E < J
    Assertions.assertEquals("Joko", set.getLast());

    // reversed() → view terbalik
    SequencedSet<String> reversed = set.reversed();
    Assertions.assertEquals("Budi", reversed.getLast());  // Budi tetap paling "kecil"
    Assertions.assertEquals("Joko", reversed.getFirst()); // Joko jadi paling depan di reversed

    // removeFirst/removeLast
    String value = set.removeFirst();
    Assertions.assertEquals("Budi", value); // hapus elemen terkecil

    value = set.removeFirst();
    Assertions.assertEquals("Eko", value);  // sekarang Eko jadi yang terkecil
}

TreeSet sebagai SequencedSet TreeSet selalu mengurutkan elemen secara natural (alphabetical untuk String, ascending untuk Number). Ketika digunakan sebagai SequencedSet, getFirst() selalu mengembalikan elemen terkecil, dan getLast() selalu elemen terbesar. reversed() di SequencedSet Interface SequencedSet meng-override reversed() agar return type-nya lebih spesifik: SequencedSet<E> bukan SequencedCollection<E>. Ini mempertahankan "Set-ness" — kamu tahu reversed view-nya juga tidak punya duplikat. removeFirst() pada TreeSet Menghapus elemen terkecil (karena TreeSet sorted ascending). Setara dengan TreeSet.pollFirst() — tapi sekarang tersedia via interface SequencedSet yang lebih umum.
💡 LinkedHashSet sebagai SequencedSet: Jika kamu pakai LinkedHashSet, getFirst() mengembalikan elemen yang pertama kali dimasukkan (insertion order), bukan yang paling kecil. TreeSet untuk sorted order, LinkedHashSet untuk insertion order.
TreeSet — getFirst() = elemen terkecil
SequencedSet<String> set = new TreeSet<>();
set.add("Eko"); set.add("Budi"); set.add("Joko");
set.getFirst(); // → "Budi" (B < E < J)

Urutan berdasarkan natural order (alphabetical)

LinkedHashSet — getFirst() = yang pertama dimasukkan
SequencedSet<String> set = new LinkedHashSet<>();
set.add("Eko"); set.add("Budi"); set.add("Joko");
set.getFirst(); // → "Eko" (pertama di-add)

Urutan berdasarkan insertion order

🐘 Analogi Laravel / PHP

PHP tidak punya Set bawaan, tapi SequencedSet mirip seperti collect()->unique()->sort() di Laravel — koleksi yang sudah di-dedup dan terurut, dengan akses mudah ke elemen pertama/terakhir. Bedanya TreeSet maintain sort secara otomatis setiap kali insert, tidak perlu sort() manual setelah setiap add().

Chapter 4
🗺️ SequencedMap — MapTest.java
SequencedMap memperkenalkan akses ke entry pertama/terakhir map secara seragam. Dua test case memperlihatkan dua skenario berbeda: TreeMap (sorted by key) dan LinkedHashMap (insertion order dengan putFirst/putLast).
Test 1 — TreeMap sebagai SequencedMap
@Test
void map() {
    SequencedMap<String, String> map = new TreeMap<>(); // key selalu sorted

    map.put("c", "Eko");
    map.put("b", "Kurniawan");
    map.put("a", "Khannedy");
    // Setelah sort by key: {a=Khannedy, b=Kurniawan, c=Eko}

    // firstEntry() → Map.Entry dengan key terkecil
    Assertions.assertEquals("Khannedy", map.firstEntry().getValue()); // key "a"
    // lastEntry() → Map.Entry dengan key terbesar
    Assertions.assertEquals("Eko",      map.lastEntry().getValue());  // key "c"

    // reversed() → live view dengan urutan key terbalik
    SequencedMap<String, String> reversed = map.reversed();
    // reversed: {c=Eko, b=Kurniawan, a=Khannedy}
    Assertions.assertEquals("Khannedy", reversed.lastEntry().getValue()); // key "a" sekarang terakhir
    Assertions.assertEquals("Eko",      reversed.firstEntry().getValue()); // key "c" sekarang pertama
}

Test 2 — LinkedHashMap dengan putFirst/putLast
@Test
void linkedMap() {
    SequencedMap<String, String> map = new LinkedHashMap<>();

    map.putFirst("a", "Eko");       // {a=Eko}
    map.putFirst("b", "Kurniawan"); // {b=Kurniawan, a=Eko}  ← b disisipkan di depan!
    map.putFirst("c", "Khannedy"); // {c=Khannedy, b=Kurniawan, a=Eko}

    // firstEntry() = entry yang paling awal (c, karena putFirst terakhir)
    Assertions.assertEquals("Khannedy", map.firstEntry().getValue());
    // lastEntry() = entry yang paling akhir (a, yang pertama dimasukkan)
    Assertions.assertEquals("Eko",      map.lastEntry().getValue());
}

API Lengkap SequencedMap
MethodKeterangan
firstEntry()Return Map.Entry pertama (tidak hapus). Return null jika kosong (beda dari SequencedCollection yang throw!)
lastEntry()Return Map.Entry terakhir (tidak hapus)
pollFirstEntry()Ambil dan hapus entry pertama
pollLastEntry()Ambil dan hapus entry terakhir
putFirst(k, v)Sisipkan entry di posisi pertama (LinkedHashMap)
putLast(k, v)Tambahkan entry di posisi terakhir
reversed()Live view dengan urutan entry terbalik

sequencedValues()Values sebagai SequencedCollection
sequencedEntrySet()Entries sebagai SequencedSet<Map.Entry<K,V>>
⚠️ Perhatikan perbedaan null behavior: SequencedMap.firstEntry() return null jika map kosong (konsisten dengan Map.Entry yang nullable). Sedangkan SequencedCollection.getFirst() throw NoSuchElementException. Jangan anggap keduanya identik!
🐘 Analogi Laravel / PHP

firstEntry() = collect($map)->first() atau PHP array_key_first($arr) + nilai-nya.
lastEntry() = collect($map)->last() atau PHP array_key_last($arr) + nilai-nya.
putFirst(k,v) tidak ada padanan langsung di PHP — di PHP harus $new = [$k => $v] + $arr untuk menyisipkan di depan associative array.
