☕ Modul Pembelajaran Java
Belajar Java DateTime API
Dari Legacy java.util.Date sampai Modern java.time — panduan lengkap untuk PHP/Laravel developer yang migrasi ke Java.

Selamat datang! Modul ini dirancang khusus untuk kamu yang sudah mahir di PHP/Laravel dan sekarang belajar Java. Kita akan belajar cara Java mengelola tanggal dan waktu, mulai dari cara lama (legacy) sampai cara modern yang direkomendasikan.

🗺️ Peta Belajar

Kita akan melalui perjalanan dari Legacy API (java.util.Date, Calendar) → Modern API (java.time.*) → Timezone → Instant & Clock → Duration & Period → Formatting → Temporal API (Advanced).

⚠️ Perbedaan Mindset: Java vs PHP

PHP/Laravel: tanggal adalah tipe data yang flexible. Carbon::now() bisa langsung dipakai, diformat, dibanding, diubah sesuka hati dengan method chaining.

Java: tanggal dibagi menjadi banyak kelas spesifik yang masing-masing punya purpose tersendiri. Ada yang hanya menyimpan tanggal, ada yang hanya waktu, ada yang menyimpan keduanya dengan atau tanpa timezone. Ini bukan kerumitan tanpa alasan — ini adalah type safety yang mencegah banyak bug.

Chapter 1 • Legacy API
🏛️ java.util.Date & Calendar
Mengenal API lama — penting untuk membaca kode warisan (legacy code), meski tidak direkomendasikan untuk kode baru.
Kenapa Perlu Tahu Legacy?

Di dunia kerja, kamu pasti akan menemukan codebase lama yang masih menggunakan Date dan Calendar. Memahaminya akan memudahkan proses refactoring ke API modern.

📅 java.util.Date

Kelas Date adalah representasi titik waktu (timestamp) sejak Unix Epoch (1 Januari 1970, 00:00:00 UTC) dalam satuan milidetik.

// File: DateTest.java
@Test
void create() {
    var date1 = new Date();                          // 1. Waktu sekarang
    var date2 = new Date(System.currentTimeMillis()); // 2. Sama seperti date1
    var date3 = new Date(339958800000L);              // 3. Tanggal spesifik dari epoch millis

    System.out.println(date1); // Mon Jan 08 10:30:00 WIB 2024
    System.out.println(date2);
    System.out.println(date3); // Fri Feb 10 15:00:00 WIB 1980
}
Line 1 — new Date()
Membuat objek Date dengan waktu saat ini. Secara internal, ini hanya menyimpan angka long yang merepresentasikan milidetik sejak epoch.
Line 2 — new Date(long)
System.currentTimeMillis() mengembalikan epoch millis saat ini. Hasilnya identik dengan new Date().
Line 3 — var
Keyword var adalah local variable type inference (Java 10+). Type-nya tetap Date, tapi compiler yang menyimpulkan — mirip seperti PHP yang loosely typed, tapi di Java ini BUKAN dynamic typing, tipe masih fixed saat compile.
339958800000L
Suffix L menandakan ini adalah literal long (64-bit integer), bukan int (32-bit). Penting karena angka epoch melebihi kapasitas int!
📆 java.util.Calendar

Calendar hadir untuk mengatasi keterbatasan Date — memungkinkan manipulasi komponen tanggal secara individual (tahun, bulan, hari, dst.).

// File: CalendarTest.java - Membuat dan Memodifikasi Calendar
@Test
void create() {
    Calendar calendar = Calendar.getInstance(); // Singleton factory method
    Date date = calendar.getTime();             // Konversi ke Date
    System.out.println(date);
}

@Test
void modifyCalendar() {
    Calendar calendar = Calendar.getInstance();

    // Set komponen satu per satu pakai konstanta integer
    calendar.set(Calendar.YEAR, 1980);
    calendar.set(Calendar.MONTH, Calendar.JANUARY); // MONTH dimulai dari 0!
    calendar.set(Calendar.DAY_OF_MONTH, 10);
    calendar.set(Calendar.HOUR_OF_DAY, 15);         // Format 24 jam
    calendar.set(Calendar.MINUTE, 50);
    calendar.set(Calendar.SECOND, 30);
    calendar.set(Calendar.MILLISECOND, 100);

    Date date = calendar.getTime();
    System.out.println(date);
    System.out.println(date.getTime()); // Epoch millis
}

@Test
void getCalendar() {
    Calendar calendar = Calendar.getInstance();

    System.out.println(calendar.get(Calendar.YEAR));        // e.g. 2024
    System.out.println(calendar.get(Calendar.MONTH));       // 0 = Januari!
    System.out.println(calendar.get(Calendar.DAY_OF_MONTH));
    System.out.println(calendar.get(Calendar.DAY_OF_YEAR)); // Hari ke-? di tahun ini
    System.out.println(calendar.get(Calendar.HOUR_OF_DAY));
    System.out.println(calendar.get(Calendar.MINUTE));
    System.out.println(calendar.get(Calendar.SECOND));
    System.out.println(calendar.get(Calendar.MILLISECOND));
}
Calendar.getInstance()
Factory Method Pattern: kamu tidak bisa new Calendar() karena konstruktornya protected. Ini memungkinkan Java memilih implementasi yang tepat (misalnya GregorianCalendar).
Calendar.MONTH
⚠️ Gotcha terkenal! Bulan di Calendar dimulai dari 0. JANUARY = 0, FEBRUARY = 1, ..., DECEMBER = 11. Gunakan konstanta Calendar.JANUARY daripada angka untuk menghindari bug ini.
calendar.set(field, value)
Calendar adalah objek yang mutable (bisa diubah langsung). Berbeda dengan API modern yang immutable.
🐛 Bug Klasik: Month dimulai dari 0
❌ Salah (Bug tersembunyi)
// Ini bukan Maret, ini April!
calendar.set(Calendar.MONTH, 3);
// Developer berniat bulan ke-3 (Maret)
// Tapi MARCH = 2, dan 3 = April!
✅ Benar
// Gunakan konstanta, jelas dan aman
calendar.set(Calendar.MONTH, Calendar.MARCH);
// Atau di API modern:
LocalDate.of(2024, Month.MARCH, 10);
🐘 Analogi Laravel: Carbon vs Calendar

Di Laravel, kamu pakai Carbon::now() untuk waktu sekarang, Carbon::create(1980, 1, 10) untuk tanggal spesifik, dan method chaining seperti $date->addDays(5)->subMonths(2). Di Java Legacy, ini dilakukan via calendar.set(field, value) yang terasa lebih verbose. API modern Java (java.time) jauh lebih mirip Carbon!

Chapter 2 • Legacy API
🌍 TimeZone (Legacy)
Manajemen timezone di era legacy — mutable dan rawan bug.

java.util.TimeZone adalah cara lama Java mengelola timezone. Setiap Calendar punya timezone, dan hasilnya bisa berbeda tergantung timezone yang diset.

// File: TimeZoneTest.java
@Test
void create() {
    TimeZone timeZoneDefault = TimeZone.getDefault(); // Timezone JVM
    System.out.println(timeZoneDefault); // sun.util.calendar.ZoneInfo[id="Asia/Jakarta",...]

    TimeZone timeZoneGMT = TimeZone.getTimeZone("GMT");
    System.out.println(timeZoneGMT);

    // Daftar semua timezone ID yang tersedia
    String[] availableIDs = TimeZone.getAvailableIDs();
    Arrays.asList(availableIDs).forEach(zoneId -> System.out.println(zoneId));
}

@Test
void calendar() {
    Calendar calendarJakarta = Calendar.getInstance(TimeZone.getTimeZone("Asia/Jakarta"));
    Calendar calendarGMT = Calendar.getInstance(TimeZone.getTimeZone("GMT"));

    // Jam berbeda karena timezone berbeda
    System.out.println(calendarJakarta.get(Calendar.HOUR_OF_DAY)); // e.g. 10
    System.out.println(calendarGMT.get(Calendar.HOUR_OF_DAY));     // e.g. 3

    // Bahaya! Timezone bisa diubah setelah Calendar dibuat
    calendarJakarta.setTimeZone(TimeZone.getTimeZone("GMT"));
    System.out.println(calendarJakarta.get(Calendar.HOUR_OF_DAY)); // Berubah!
}
⚠️ Bahaya Mutability: Calendar + TimeZone

Karena Calendar bersifat mutable, timezone-nya bisa diubah kapan saja via setTimeZone(). Ini berbahaya jika objek Calendar dipakai bersama di beberapa tempat — perubahan di satu tempat akan mempengaruhi semua referensi ke objek yang sama.

🐘 Analogi Laravel

Di Laravel, kamu set timezone di config/app.php dan Carbon secara otomatis ikut timezone tersebut. Di Java Legacy, setiap Calendar harus di-set timezone-nya secara manual — lebih verbose dan lebih rawan lupa.

Chapter 3 • Modern API
✨ Pengantar java.time
Java 8 merevolusi cara kerja dengan tanggal & waktu. Semua immutable, thread-safe, dan intuitif.
Revolusi Java 8

Package java.time (dikenal juga sebagai JSR-310 atau Joda-Time terinspirasi) hadir di Java 8 untuk mengatasi semua masalah API lama. Tiga prinsip utamanya:

🔒 Immutable

🧵 Thread-Safe

📐 Fluent API

💡 Immutable itu Artinya Apa?

Di PHP/Carbon: $date->addDay() mengubah $date itu sendiri (mutable by default, kecuali pakai CarbonImmutable).

Di java.time: semua operasi selalu mengembalikan objek baru. Objek asli tidak pernah berubah. Ini mirip seperti menggunakan CarbonImmutable di Laravel.

LocalDate date1 = LocalDate.now();
LocalDate date2 = date1.plusDays(5);
→ date1 masih tanggal hari ini! date2 adalah objek baru 5 hari ke depan.

🗺️ Peta Kelas java.time
Kelas Berisi Timezone? Contoh Nilai
LocalDateTanggal saja❌2024-01-15
LocalTimeWaktu saja❌10:30:45
LocalDateTimeTanggal + Waktu❌2024-01-15T10:30:45
ZonedDateTimeTanggal + Waktu + Zone✅ (Named Zone)2024-01-15T10:30:45+07:00[Asia/Jakarta]
OffsetDateTimeTanggal + Waktu + Offset✅ (Offset only)2024-01-15T10:30:45+07:00
OffsetTimeWaktu + Offset✅ (Offset only)10:30:45+07:00
InstantTitik waktu absolut✅ (UTC)2024-01-15T03:30:45Z
YearTahun saja❌2024
YearMonthTahun + Bulan❌2024-01
MonthDayBulan + Hari❌--01-15
🧠 Kapan Pakai Apa?

Database (tanggal lahir, anniversary): LocalDate — tidak perlu jam/timezone.
Jadwal harian (jam meeting): LocalTime — "09:00 pagi" tidak perlu tanggal/timezone.
Log & event global: Instant atau ZonedDateTime — perlu timezone untuk akurasi lintas zona.
API response (ISO 8601): OffsetDateTime — portable, tidak ambiguous.

Chapter 4 • Building Blocks
🗓️ Year, YearMonth, MonthDay & DayOfWeek
Unit-unit waktu yang lebih granular — blok pembangun untuk membentuk tanggal lengkap.

Java menyediakan kelas untuk setiap "potongan" tanggal yang mungkin kamu butuhkan. Ini berguna ketika kamu hanya peduli sebagian dari tanggal.

// File: YearTest.java — Tiga cara membuat objek di java.time
@Test
void create() {
    // ── Year ──
    Year year1 = Year.now();          // Tahun sekarang
    Year year2 = Year.of(1980);       // Tahun spesifik
    Year year3 = Year.parse("2020");  // Parsing dari String

    // ── YearMonth ──
    YearMonth yearMonth1 = YearMonth.now();
    YearMonth yearMonth2 = YearMonth.of(1980, Month.JUNE); // Pakai enum Month!
    YearMonth yearMonth3 = YearMonth.parse("2020-09");

    // ── MonthDay (berguna untuk ulang tahun — tanpa tahun) ──
    MonthDay monthDay1 = MonthDay.now();
    MonthDay monthDay2 = MonthDay.of(Month.DECEMBER, 18);
    MonthDay monthDay3 = MonthDay.parse("--10-09"); // Format ISO: --MM-dd
}

@Test
void name() {
    Year year = Year.now();

    // Chaining: Year → LocalDate via YearMonth → Day
    LocalDate localDate = year.atMonth(Month.DECEMBER).atDay(19);
    // year.atMonth() mengembalikan YearMonth
    // .atDay(19) mengembalikan LocalDate

    MonthDay monthDay = MonthDay.from(localDate); // Ekstrak MonthDay dari LocalDate
}

@Test
void get() {
    Year year = Year.now();
    YearMonth yearMonth = YearMonth.now();
    MonthDay monthDay = MonthDay.now();

    System.out.println(year.getValue());          // int: 2024
    System.out.println(yearMonth.getYear());      // int: 2024
    System.out.println(yearMonth.getMonth());     // Enum: JANUARY
    System.out.println(monthDay.getMonth());      // Enum: JANUARY
    System.out.println(monthDay.getDayOfMonth()); // int: 15
}
Three ways pattern
Hampir semua kelas di java.time mengikuti pola yang sama: now() untuk waktu sekarang, of(...) untuk nilai spesifik, parse(String) untuk parsing dari teks. Ini desain API yang konsisten!
Month.JUNE (Enum)
Tidak seperti Calendar legacy yang pakai konstanta integer (MONTH = 0 untuk Januari), java.time menggunakan enum Month. Ini type-safe — compiler akan error jika kamu pakai nilai yang bukan bulan valid.
MonthDay format "--10-09"
Format ISO 8601 untuk MonthDay menggunakan prefix "--" untuk menandakan tidak ada informasi tahun. Ini standar internasional yang diikuti Java.
year.atMonth().atDay()
Fluent Builder Pattern: membangun tanggal step by step. Mirip seperti query builder di Laravel: Year → YearMonth → LocalDate.
📆 DayOfWeek — Enum Hari dalam Seminggu
// File: DayOfWeekTest.java
@Test
void create() {
    DayOfWeek dayOfWeek1 = DayOfWeek.SUNDAY;      // Enum konstanta
    DayOfWeek dayOfWeek2 = dayOfWeek1.plus(7);    // +7 hari = SUNDAY lagi
    DayOfWeek dayOfWeek3 = dayOfWeek1.plus(1);    // SUNDAY + 1 = MONDAY

    System.out.println(dayOfWeek1); // SUNDAY
    System.out.println(dayOfWeek2); // SUNDAY (circular!)
    System.out.println(dayOfWeek3); // MONDAY
}
💡 DayOfWeek adalah Circular (Modular Arithmetic)

Nilai DayOfWeek secara internal adalah 1 (MONDAY) sampai 7 (SUNDAY). Operasi plus() dilakukan modulo 7, sehingga SUNDAY.plus(7) kembali ke SUNDAY. Berguna untuk logika penjadwalan mingguan.

Chapter 5 • Modern API
📅 LocalDate — Tanggal Tanpa Waktu & Timezone
Kelas paling sering digunakan untuk menyimpan tanggal (tanggal lahir, deadline, jadwal) tanpa perlu informasi jam atau timezone.
// File: LocalDateTest.java

@Test
void create() {
    LocalDate localDate1 = LocalDate.now();                     // Hari ini
    LocalDate localDate2 = LocalDate.of(1980, Month.JANUARY, 10); // Spesifik
    LocalDate localDate3 = LocalDate.parse("1980-01-10");       // Dari String ISO

    System.out.println(localDate1); // 2024-01-15
    System.out.println(localDate2); // 1980-01-10
    System.out.println(localDate3); // 1980-01-10
}

@Test
void with() {
    // with() = "ubah satu komponen, sisanya sama" — IMMUTABLE!
    LocalDate localDate1 = LocalDate.now();         // 2024-01-15
    LocalDate localDate2 = localDate1.withYear(1980);           // 1980-01-15
    LocalDate localDate3 = localDate1.withYear(1980).withMonth(1); // 1980-01-15

    // localDate1 TIDAK berubah!
    System.out.println(localDate1); // 2024-01-15 (tetap!)
    System.out.println(localDate2); // 1980-01-15
    System.out.println(localDate3); // 1980-01-15
}

@Test
void modify() {
    // plus/minus = tambah/kurangi durasi — juga IMMUTABLE
    LocalDate localDate1 = LocalDate.now();
    LocalDate localDate2 = localDate1.plusYears(10);    // 10 tahun ke depan
    LocalDate localDate3 = localDate1.minusMonths(10);  // 10 bulan ke belakang
}

@Test
void get() {
    LocalDate localDate1 = LocalDate.now();

    System.out.println(localDate1.getYear());        // int: 2024
    System.out.println(localDate1.getMonth());       // enum: JANUARY
    System.out.println(localDate1.getMonthValue());  // int: 1 (dimulai dari 1!)
    System.out.println(localDate1.getDayOfMonth());  // int: 15
    System.out.println(localDate1.getDayOfWeek());   // enum: MONDAY
    System.out.println(localDate1.getDayOfYear());   // int: 15 (hari ke-15 di tahun ini)
}
LocalDate.parse()
Default format adalah ISO 8601 (yyyy-MM-dd). Jika format berbeda, perlu DateTimeFormatter (akan dibahas di chapter 15).
getMonthValue() vs getMonth()
Perbedaan penting! getMonthValue() mengembalikan int (1-12, Januari = 1 — berbeda dari Calendar lama!). getMonth() mengembalikan enum Month.
with() vs plus()/minus()
with() = "set nilai absolut" (seperti setter tapi immutable). plus()/minus() = "tambah/kurangi relatif dari nilai sekarang".
❌ Salah (Mindset PHP)
LocalDate date = LocalDate.now();
date.plusDays(5); // SALAH!
// Hasil dibuang, date tidak berubah
System.out.println(date); // Masih hari ini!
✅ Benar (Immutable mindset)
LocalDate date = LocalDate.now();
LocalDate nextWeek = date.plusDays(5);
// Selalu tangkap hasilnya!
System.out.println(nextWeek);
🐘 Analogi Laravel: Carbon vs LocalDate

Di PHP: $date = Carbon::now(); $date->addDays(5); → $date sekarang berubah (mutable). Di Java: LocalDate date = LocalDate.now(); date.plusDays(5); → date TIDAK berubah! Kamu harus pakai LocalDate newDate = date.plusDays(5);. Ini mirip seperti menggunakan CarbonImmutable di Laravel.

Chapter 6 • Modern API
⏰ LocalTime — Waktu Tanpa Tanggal & Timezone
Untuk menyimpan waktu seperti jam operasional toko, jadwal alarm, atau batas jam pengiriman.
// File: LocalTimeTest.java
@Test
void create() {
    LocalTime localTime1 = LocalTime.now();             // Jam sekarang
    LocalTime localTime2 = LocalTime.of(10, 10, 10);   // 10:10:10
    LocalTime localTime3 = LocalTime.parse("08:08");    // Hanya jam:menit, detik default 0
}

@Test
void change() {
    // with() = ubah satu komponen, immutable
    LocalTime localTime1 = LocalTime.now();                         // e.g. 14:30:45
    LocalTime localTime2 = localTime1.withHour(10);                 // 10:30:45
    LocalTime localTime3 = localTime1.withHour(5).withMinute(10).withSecond(0); // 05:10:00
    // Chain of with() calls — setiap call mengembalikan objek baru
}

@Test
void modify() {
    // plus/minus untuk tambah/kurangi relatif
    LocalTime localTime1 = LocalTime.now();
    LocalTime localTime2 = localTime1.plusHours(10);
    LocalTime localTime3 = localTime1.plusHours(5).minusMinutes(10).minusSeconds(5);
    // Perhatikan: LocalTime bersifat circular!
    // LocalTime.of(23, 0).plusHours(2) = 01:00 (bukan 25:00)
}

@Test
void get() {
    LocalTime localTime = LocalTime.now();
    System.out.println(localTime.getHour());   // int: 0-23
    System.out.println(localTime.getMinute()); // int: 0-59
    System.out.println(localTime.getSecond()); // int: 0-59
    System.out.println(localTime.getNano());   // int: 0-999999999
}
⚠️ LocalTime adalah Circular

Jika kamu menambah jam melewati tengah malam, hasilnya akan "wrap around" kembali ke 00:xx. Contoh: LocalTime.of(23, 0).plusHours(3) = 02:00, bukan 26:00. Informasi tentang "hari berganti" hilang. Jika perlu tracking lintas hari, gunakan LocalDateTime.

🐘 Analogi Laravel

PHP tidak punya tipe data khusus untuk "waktu tanpa tanggal". Kamu biasanya pakai string "08:00" atau Carbon dengan tanggal dummy. Di Java, LocalTime adalah tipe yang proper dan type-safe untuk menyimpan waktu saja.

Chapter 7 • Modern API
📅⏰ LocalDateTime — Tanggal + Waktu
Gabungan LocalDate dan LocalTime — untuk data yang butuh tanggal DAN waktu, tapi tidak perlu timezone.
// File: LocalDateTimeTest.java
@Test
void create() {
    LocalDateTime localDateTime1 = LocalDateTime.now();
    LocalDateTime localDateTime2 = LocalDateTime.of(1980, Month.JANUARY, 8, 10, 9, 10, 456000000);
    // of(year, month, day, hour, minute, second, nanosecond)
    // 456000000 nano = 456 millisecond
    LocalDateTime localDateTime3 = LocalDateTime.parse("1980-01-08T10:09:10.456");
    // Format ISO 8601: T adalah pemisah tanggal dan waktu
}

@Test
void with() {
    LocalDateTime localDateTime1 = LocalDateTime.now();
    LocalDateTime localDateTime2 = localDateTime1.withYear(1980).withMonth(1);
    // Bisa chain with() berkali-kali
}

@Test
void modify() {
    LocalDateTime localDateTime1 = LocalDateTime.now();
    LocalDateTime localDateTime2 = localDateTime1.plusYears(5).minusHours(5);
    // Bisa chain plus dan minus
}

@Test
void get() {
    LocalDateTime localDateTime = LocalDateTime.now();
    System.out.println(localDateTime.getYear());
    System.out.println(localDateTime.getMonth());       // enum Month
    System.out.println(localDateTime.getDayOfMonth());
    System.out.println(localDateTime.getHour());
    System.out.println(localDateTime.getMinute());
    System.out.println(localDateTime.getSecond());
    System.out.println(localDateTime.getNano());        // presisi nanosecond!
}

@Test
void date() {
    // Konversi LocalDateTime <-> LocalDate + LocalTime
    LocalDateTime localDateTime = LocalDateTime.now();

    LocalDate localDate = localDateTime.toLocalDate();      // Ambil bagian tanggal
    LocalDateTime result = localDate.atTime(10, 10, 10, 10); // LocalDate + tambahkan waktu
}

@Test
void time() {
    LocalDateTime localDateTime = LocalDateTime.now();

    LocalTime localTime = localDateTime.toLocalTime();          // Ambil bagian waktu
    LocalDateTime result = localTime.atDate(LocalDate.now());   // LocalTime + tambahkan tanggal
}
ISO 8601 — "T" separator
Karakter T di "1980-01-08T10:09:10.456" adalah pemisah standar internasional antara tanggal dan waktu. Java mengikuti standar ini secara default.
456000000 nanoseconds
Java menyimpan sub-detik dalam nanosecond (bukan millisecond). 1 millisecond = 1.000.000 nanosecond. Presisi ini lebih tinggi dari PHP yang menggunakan microsecond.
toLocalDate() / toLocalTime()
Cara "memotong" LocalDateTime menjadi bagian yang lebih kecil. Kebalikannya adalah localDate.atTime() dan localTime.atDate() untuk "menggabungkan" dua objek menjadi LocalDateTime.
🐘 Analogi Laravel

LocalDateTime di Java setara dengan Carbon di Laravel dari sisi fungsi — tanggal + waktu, manipulasi, parsing. Perbedaannya: LocalDateTime tidak punya timezone. Ini seperti Carbon yang dibuat tanpa argument timezone: Carbon::create(2024, 1, 15, 10, 30, 0) tanpa timezone param.

Chapter 8 • Timezone Modern
🗺️ ZoneId & ZoneOffset
Dua cara Java merepresentasikan timezone — ZoneId untuk zona bernama, ZoneOffset untuk offset numerik.

Java memisahkan dua konsep timezone:

🗺️ ZoneId

Nama zona geografis seperti "Asia/Jakarta", "America/New_York". Mengikuti aturan DST (Daylight Saving Time) — offset bisa berubah musiman.

↔️ ZoneOffset

Offset numerik tetap dari UTC seperti "+07:00". Tidak mengikuti DST — selalu konsisten.

// File: ZoneTest.java
@Test
void createZoneId() {
    ZoneId zoneId = ZoneId.systemDefault();    // Timezone JVM saat ini
    System.out.println(zoneId);                // Asia/Jakarta

    ZoneId zoneIdGMT = ZoneId.of("GMT");
    ZoneId zoneIdJakarta = ZoneId.of("Asia/Jakarta");
    ZoneId zoneIdJapan = ZoneId.of("Asia/Tokyo");

    // Lihat semua timezone yang tersedia
    Set availableZoneIds = ZoneId.getAvailableZoneIds();
    availableZoneIds.forEach(id -> System.out.println(id));
}

@Test
void createZoneOffset() {
    ZoneOffset zoneOffset1 = ZoneOffset.of("+07:00");      // Parsing dari String
    ZoneOffset zoneOffset2 = ZoneOffset.ofHours(-7);       // Dari integer jam
    ZoneOffset zoneOffset3 = ZoneOffset.ofHoursMinutes(7, 30); // Jam + menit

    System.out.println(zoneOffset1); // +07:00
    System.out.println(zoneOffset2); // -07:00
    System.out.println(zoneOffset3); // +07:30
}
ZoneId.of("Asia/Jakarta")
Format: "Benua/Kota". Ini adalah IANA Timezone Database ID. Untuk Indonesia: Asia/Jakarta (WIB), Asia/Makassar (WITA), Asia/Jayapura (WIT).
ZoneOffset vs ZoneId
ZoneOffset extends ZoneId, jadi ZoneOffset bisa dipakai di mana pun ZoneId dibutuhkan. Namun ZoneOffset tidak tahu tentang DST karena hanya menyimpan offset numerik.
💡 ZoneOffset: +07:30?

Beberapa negara punya offset setengah jam, seperti India (+05:30) atau Nepal (+05:45). ZoneOffset.ofHoursMinutes(5, 30) berguna untuk kasus ini. Jakarta sendiri +07:00.

🐘 Analogi Laravel

Di Laravel config: 'timezone' => 'Asia/Jakarta'. Ini ekuivalen dengan ZoneId.of("Asia/Jakarta"). Format nama-nya sama karena keduanya menggunakan IANA Timezone Database.

Chapter 9 • Timezone Modern
🌏 ZonedDateTime
Representasi waktu paling lengkap — tanggal, waktu, DAN timezone lengkap dengan DST awareness.
// File: ZonedDateTimeTest.java
@Test
void create() {
    // 4 cara membuat ZonedDateTime
    ZonedDateTime zdt1 = ZonedDateTime.now();
    // Menggunakan timezone JVM default

    ZonedDateTime zdt2 = ZonedDateTime.of(LocalDateTime.now(), ZoneId.of("Asia/Jakarta"));
    // Gabungkan LocalDateTime + ZoneId

    ZonedDateTime zdt3 = ZonedDateTime.now(ZoneId.of("GMT"));
    // Waktu sekarang tapi di timezone tertentu

    ZonedDateTime zdt4 = ZonedDateTime.now(ZoneOffset.ofHours(5));
    // Gunakan ZoneOffset langsung

    System.out.println(zdt1); // 2024-01-15T10:30:45.123+07:00[Asia/Jakarta]
    System.out.println(zdt2); // 2024-01-15T10:30:45.123+07:00[Asia/Jakarta]
    System.out.println(zdt3); // 2024-01-15T03:30:45.123Z[GMT]
}

@Test
void parsing() {
    // Parse dari String dengan ZoneId named
    ZonedDateTime zdt1 = ZonedDateTime.parse("1980-10-10T10:10:10+07:00[Asia/Jakarta]");
    // Parse dari String dengan offset saja
    ZonedDateTime zdt2 = ZonedDateTime.parse("1980-10-10T10:10:10+05:00");
}

@Test
void changeZoneId() {
    ZonedDateTime zdt1 = ZonedDateTime.now();            // +07:00 Jakarta
    System.out.println(zdt1); // 2024-01-15T10:30:45+07:00[Asia/Jakarta]

    // withZoneSameLocal: timezone berubah, nilai waktu TETAP
    ZonedDateTime zdt2 = zdt1.withZoneSameLocal(ZoneId.of("GMT"));
    System.out.println(zdt2); // 2024-01-15T10:30:45Z[GMT] — jam masih 10:30!

    // withZoneSameInstant: timezone berubah, titik waktu TETAP (konversi benar)
    ZonedDateTime zdt3 = zdt1.withZoneSameInstant(ZoneId.of("GMT"));
    System.out.println(zdt3); // 2024-01-15T03:30:45Z[GMT] — jam dikonversi ke GMT!
}
withZoneSameLocal vs withZoneSameInstant
Ini perbedaan kritis! withZoneSameLocal = "label timezone berubah, waktu yang tampil sama" (berbahaya, bisa mengubah titik waktu sebenarnya). withZoneSameInstant = "konversi benar seperti kalkulator timezone online" — ini yang hampir selalu kamu inginkan.
Format output ZonedDateTime
Output: 2024-01-15T10:30:45+07:00[Asia/Jakarta]. Terdiri dari: tanggal (2024-01-15), pemisah T, waktu (10:30:45), offset (+07:00), dan zone ID dalam kurung siku ([Asia/Jakarta]).
❌ Salah: Mengubah Timezone
// Ingin konversi Jakarta → GMT
ZonedDateTime jakarta = ZonedDateTime.now();
// SALAH: waktu tidak dikonversi
ZonedDateTime gmt = jakarta.withZoneSameLocal(ZoneId.of("GMT"));
// Jam tetap 10:30 tapi sekarang "di GMT"
// Padahal jam 10:30 Jakarta = 03:30 GMT!
✅ Benar: Konversi Timezone
// Konversi yang benar
ZonedDateTime jakarta = ZonedDateTime.now();
// BENAR: sama instant, timezone berbeda
ZonedDateTime gmt = jakarta.withZoneSameInstant(ZoneId.of("GMT"));
// Jam Jakarta 10:30 → 03:30 GMT ✓

Di Laravel: $date->setTimezone('UTC') itu seperti withZoneSameInstant() — zona berubah dan waktu dikonversi dengan benar. Tidak ada equivalent langsung untuk withZoneSameLocal() di Carbon secara default.

Chapter 10 • Timezone Modern
↔️ OffsetTime & OffsetDateTime
Seperti Zoned, tapi hanya menyimpan offset numerik (bukan nama zona) — cocok untuk API/JSON portabel.

Perbedaan utama Offset* vs Zoned*: OffsetDateTime hanya menyimpan offset numerik (+07:00), tidak menyimpan nama zona (Asia/Jakarta). Ini membuat data lebih portable karena tidak bergantung pada IANA timezone database.

// File: OffsetTimeTest.java
@Test
void create() {
    // OffsetTime: waktu + offset
    OffsetTime offsetTime1 = OffsetTime.now();
    OffsetTime offsetTime2 = OffsetTime.now(ZoneId.of("Asia/Jakarta"));
    OffsetTime offsetTime3 = OffsetTime.of(10, 10, 10, 10, ZoneOffset.ofHours(7));
    // of(hour, minute, second, nanoOfSecond, offset)
    OffsetTime offsetTime4 = OffsetTime.parse("09:09:09.100+07:00");

    // OffsetDateTime: tanggal + waktu + offset
    OffsetDateTime offsetDateTime1 = OffsetDateTime.now();
    OffsetDateTime offsetDateTime2 = OffsetDateTime.now(ZoneId.of("Asia/Jakarta"));
    OffsetDateTime offsetDateTime3 = OffsetDateTime.of(LocalDateTime.now(), ZoneOffset.ofHours(7));
    // Gabungkan LocalDateTime + ZoneOffset
    OffsetDateTime offsetDateTime4 = OffsetDateTime.parse("1980-09-17T10:10:10.100+05:00");
}

@Test
void toLocalTime() {
    // Konversi dua arah: LocalTime ←→ OffsetTime
    LocalTime localTime = LocalTime.now();
    OffsetTime offsetTime = localTime.atOffset(ZoneOffset.ofHours(7)); // Tambah offset
    LocalTime localTime1 = offsetTime.toLocalTime();                    // Hapus offset
}

@Test
void toLocalDateTime() {
    // Konversi dua arah: LocalDateTime ←→ OffsetDateTime
    LocalDateTime localDateTime = LocalDateTime.now();
    OffsetDateTime offsetDateTime = localDateTime.atOffset(ZoneOffset.ofHours(7));
    LocalDateTime localDateTime1 = offsetDateTime.toLocalDateTime();
}
OffsetDateTime vs ZonedDateTime
OffsetDateTime output: 2024-01-15T10:30:45+07:00. ZonedDateTime output: 2024-01-15T10:30:45+07:00[Asia/Jakarta]. OffsetDateTime tidak menyimpan nama zone, sehingga tidak bisa menghitung DST. Untuk API response publik, OffsetDateTime lebih disarankan karena lebih portable.
atOffset() / toLocalDateTime()
Pola konversi di java.time konsisten: atXxx() untuk menambah informasi, toXxx() untuk mengurangi/mengekstrak informasi.
💡 Best Practice: OffsetDateTime untuk API

Saat mendesain REST API yang mengirimkan data waktu dalam JSON, gunakan OffsetDateTime dan format ISO 8601 (2024-01-15T10:30:45+07:00). Ini standar yang dimengerti semua bahasa pemrograman, tidak ambigu, dan tidak bergantung pada timezone database klien.

Chapter 11 • Instant & Clock
⚡ Instant — Titik Waktu Absolut
Representasi titik waktu dalam UTC — setara dengan epoch millis, tapi lebih modern dan type-safe.

Instant adalah versi modern dari System.currentTimeMillis(). Ini merepresentasikan titik waktu absolut dalam UTC, cocok untuk logging, auditing, dan pengukuran performa.

// File: InstantTest.java
@Test
void create() {
    Instant instant1 = Instant.now();              // Titik waktu sekarang di UTC
    System.out.println(instant1);                  // 2024-01-15T03:30:45.123Z

    Instant instant2 = Instant.ofEpochMilli(0);   // Unix Epoch: 1970-01-01T00:00:00Z
    System.out.println(instant2);                  // 1970-01-01T00:00:00Z
}

@Test
void modify() {
    Instant instant1 = Instant.now();
    Instant instant2 = instant1.plusMillis(1000);  // +1 detik
    Instant instant3 = instant1.minusMillis(1000); // -1 detik
    // Semua immutable — instant1 tidak berubah
}

@Test
void get() {
    Instant instant = Instant.now();
    System.out.println(instant.toEpochMilli());    // Epoch milidetik (long)
    System.out.println(instant.getEpochSecond());  // Epoch detik (long)
    System.out.println(instant.getNano());         // Nano dalam detik (int)
}

@Test
void fromInstant() {
    // Konversi Instant ke berbagai tipe dengan ZoneId
    Instant instant = Instant.now();
    ZoneId zoneId = ZoneId.of("Asia/Jakarta");

    LocalTime localTime = LocalTime.ofInstant(instant, zoneId);
    LocalDateTime localDateTime = LocalDateTime.ofInstant(instant, zoneId);
    ZonedDateTime zonedDateTime = ZonedDateTime.ofInstant(instant, zoneId);
    OffsetDateTime offsetDateTime = OffsetDateTime.ofInstant(instant, zoneId);
}

@Test
void toInstant() {
    // Konversi dari berbagai tipe ke Instant
    Instant instant1 = LocalDateTime.now().toInstant(ZoneOffset.ofHours(7));
    // LocalDateTime perlu ZoneOffset untuk tau ini jam berapa di UTC

    Instant instant2 = ZonedDateTime.now().toInstant();    // Sudah ada zone info
    Instant instant3 = OffsetDateTime.now().toInstant();   // Sudah ada offset info
}
Instant.now() output "Z"
Huruf Z di akhir timestamp berarti "Zulu time" = UTC = offset +00:00. Ini notasi ISO 8601 standar untuk UTC.
LocalDateTime.toInstant() butuh offset
Karena LocalDateTime tidak punya info timezone, untuk mengkonversinya ke Instant (yang selalu UTC), kita harus memberitahu Java "ini jam berapa di offset mana". Itulah kenapa dibutuhkan ZoneOffset sebagai parameter.
getEpochSecond() vs toEpochMilli()
Untuk kompatibilitas dengan sistem lain: UNIX timestamp biasanya dalam detik (getEpochSecond()), sementara JavaScript dan banyak database menggunakan milidetik (toEpochMilli()).
🐘 Analogi Laravel

Di PHP: time() mengembalikan Unix timestamp dalam detik. microtime(true) untuk milidetik. Di Java: Instant.now().getEpochSecond() setara time(), dan Instant.now().toEpochMilli() setara round(microtime(true) * 1000).

Chapter 12 • Instant & Clock
🕐 Clock — Sumber Waktu yang Bisa Diinjeksi
Clock abstraksi sumber waktu — kunci untuk unit testing tanggal dan waktu.

Clock adalah abstraksi dari "sumber waktu". Biasanya kita pakai waktu dari sistem (Clock.systemUTC()), tapi saat unit testing, kita bisa inject Clock palsu untuk mensimulasikan waktu tertentu.

// File: ClockTest.java
@Test
void create() {
    Clock clock1 = Clock.systemUTC();                      // Waktu sistem dalam UTC
    Clock clock2 = Clock.systemDefaultZone();              // Waktu sistem, timezone default JVM
    Clock clock3 = Clock.system(ZoneId.of("Asia/Jakarta")); // Waktu sistem, timezone Jakarta

    System.out.println(clock1); // SystemClock[Z]
    System.out.println(clock2); // SystemClock[Asia/Jakarta]
    System.out.println(clock3); // SystemClock[Asia/Jakarta]
}

@Test
void instant() throws Throwable {
    Clock clock = Clock.system(ZoneId.of("Asia/Jakarta"));

    Instant instant1 = clock.instant(); // Snapshot waktu #1
    System.out.println(instant1);       // 2024-01-15T03:30:45Z

    Thread.sleep(1_000); // Tunggu 1 detik (1000ms)
    // Note: underscore dalam integer literal Java = pemisah ribuan (Java 7+)
    // 1_000 = 1000, mudah dibaca!

    Instant instant2 = clock.instant(); // Snapshot waktu #2
    System.out.println(instant2);       // 2024-01-15T03:30:46Z (1 detik lebih)
}

@Test
void fromClock() {
    // Clock bisa dipakai sebagai argumen ke .now(clock) di semua kelas java.time
    Clock clock = Clock.system(ZoneId.of("Asia/Jakarta"));

    Year year = Year.now(clock);
    YearMonth yearMonth = YearMonth.now(clock);
    MonthDay monthDay = MonthDay.now(clock);
    LocalTime localTime = LocalTime.now(clock);
    LocalDateTime localDateTime = LocalDateTime.now(clock);
    OffsetTime offsetTime = OffsetTime.now(clock);
    OffsetDateTime offsetDateTime = OffsetDateTime.now(clock);
    ZonedDateTime zonedDateTime = ZonedDateTime.now(clock);
}
1_000 — Underscore Literal
Java 7+ memperbolehkan underscore dalam literal angka sebagai pemisah ribuan untuk keterbacaan. 1_000_000 = satu juta. Ini hanya untuk manusia, compiler mengabaikannya.
Clock sebagai dependency
Pola terbaik adalah tidak memanggil LocalDateTime.now() langsung, tapi menerima Clock sebagai dependency. Saat production, inject Clock.systemDefaultZone(). Saat testing, inject Clock.fixed(someInstant, someZone) untuk mensimulasikan waktu tertentu.
✅ Best Practice: Testable Code dengan Clock
// ❌ Buruk: Hard to test
public boolean isOfficeHours() {
    return LocalTime.now().isAfter(LocalTime.of(9, 0));
}

// ✅ Baik: Testable dengan Clock injection
public boolean isOfficeHours(Clock clock) {
    return LocalTime.now(clock).isAfter(LocalTime.of(9, 0));
}

// Test:
Clock fixedClock = Clock.fixed(
    Instant.parse("2024-01-15T02:00:00Z"), // 09:00 WIB
    ZoneId.of("Asia/Jakarta")
);
assertTrue(service.isOfficeHours(fixedClock));
🐘 Analogi Laravel: Carbon::setTestNow()

Di Laravel testing, kamu bisa "membekukan" waktu dengan Carbon::setTestNow(Carbon::create(2024, 1, 15, 9, 0, 0)). Di Java, konsep yang sama dicapai dengan menginjeksi Clock.fixed(). Keduanya membuat code yang berurusan dengan waktu menjadi mudah di-test.

Chapter 13 • Durasi
⏱️ Duration — Durasi Waktu (Jam, Menit, Detik)
Merepresentasikan selisih waktu berbasis detik/nanosecond — untuk mengukur jeda waktu dengan presisi tinggi.

Duration merepresentasikan jumlah waktu dalam unit jam, menit, detik, dan nanosecond. Berbeda dengan Period yang berbasis hari/bulan/tahun.

// File: DurationTest.java
@Test
void create() {
    Duration duration1 = Duration.ofHours(10);    // 10 jam
    Duration duration2 = Duration.ofMinutes(10);  // 10 menit
    Duration duration3 = Duration.ofMillis(10);   // 10 milidetik

    System.out.println(duration1); // PT10H  (ISO 8601 duration format)
    System.out.println(duration2); // PT10M
    System.out.println(duration3); // PT0.01S
}

@Test
void get() {
    Duration duration = Duration.ofHours(50); // 50 jam

    System.out.println(duration.toDays());    // 2 (50/24 = 2.08 → 2)
    System.out.println(duration.toHours());   // 50
    System.out.println(duration.toMinutes()); // 3000 (50 * 60)
    System.out.println(duration.toSeconds()); // 180000
    System.out.println(duration.toMillis());  // 180000000
    System.out.println(duration.toNanos());   // 180000000000000
}

@Test
void between() {
    // Duration.between(start, end) — order penting!
    Duration duration1 = Duration.between(
        LocalDateTime.now(),
        LocalDateTime.now().plusHours(10)  // end > start = positif
    );
    System.out.println(duration1.toHours());   // 10
    System.out.println(duration1.toMinutes()); // 600

    Duration duration2 = Duration.between(
        LocalDateTime.now().plusHours(10),
        LocalDateTime.now()                    // end < start = NEGATIF!
    );
    System.out.println(duration2.toHours());   // -10
    System.out.println(duration2.toMinutes()); // -600
}
Format "PT10H" — ISO 8601 Duration
P = Period, T = Time, 10H = 10 jam. Format lengkapnya: PnYnMnDTnHnMnS. Contoh: P1Y2M3DT4H5M6S = 1 tahun 2 bulan 3 hari 4 jam 5 menit 6 detik.
duration.toDays() vs toHours()
toDays() mengembalikan total hari (dibulatkan ke bawah, bukan total komponen hari saja). Duration.ofHours(50).toDays() = 2, bukan 0.
Duration bisa negatif
Jika start > end di Duration.between(), hasilnya negatif. Ini berguna untuk mengetahui "berapa lama yang lalu" suatu event terjadi.
🐘 Analogi Laravel: CarbonInterval

Di Laravel: CarbonInterval::hours(10) atau $date1->diffInHours($date2). Di Java: Duration.ofHours(10) atau Duration.between(dt1, dt2). Konsep yang sama, sintaks yang berbeda.

Chapter 14 • Durasi
📆 Period — Durasi Kalender (Tahun, Bulan, Hari)
Merepresentasikan perbedaan dalam unit kalender — berbasis tahun, bulan, dan hari (bukan detik).
⚠️ Duration vs Period — Perbedaan Krusial

Duration = waktu dalam detik/nanosecond. "10 jam" selalu tepat 36.000 detik.
Period = waktu dalam kalender. "1 bulan" bisa 28, 29, 30, atau 31 hari tergantung bulan dan tahun!

Gunakan Period untuk "umur", "masa kontrak", "selisih hari kalender". Gunakan Duration untuk "waktu eksekusi", "timeout", "selisih detik presisi".

// File: PeriodTest.java
@Test
void create() {
    Period period1 = Period.ofDays(10);    // 10 hari
    Period period2 = Period.ofWeeks(10);   // 10 minggu = 70 hari
    Period period3 = Period.ofMonths(10);  // 10 bulan
    Period period4 = Period.ofYears(10);   // 10 tahun
    Period period5 = Period.of(10, 10, 10); // 10 tahun, 10 bulan, 10 hari

    System.out.println(period1); // P10D
    System.out.println(period2); // P70D
    System.out.println(period3); // P10M
    System.out.println(period4); // P10Y
    System.out.println(period5); // P10Y10M10D
}

@Test
void get() {
    Period period = Period.of(10, 10, 10);

    System.out.println(period.getYears());  // 10 (hanya komponen tahun)
    System.out.println(period.getMonths()); // 10 (hanya komponen bulan)
    System.out.println(period.getDays());   // 10 (hanya komponen hari)
    // Note: tidak ada getTotalDays() di Period!
}

@Test
void between() {
    // Hitung selisih dua tanggal dalam unit kalender
    Period period = Period.between(
        LocalDate.of(1985, 10, 10),
        LocalDate.now()
    );

    System.out.println(period.getYears());  // e.g. 38 (tahun)
    System.out.println(period.getMonths()); // e.g. 3 (bulan sisa)
    System.out.println(period.getDays());   // e.g. 5 (hari sisa)
    // Ini seperti: "Usianya 38 tahun, 3 bulan, dan 5 hari"
}
Period.of(10, 10, 10)
Urutan parameter: (years, months, days). Period menyimpan ketiga komponen secara terpisah — tidak dikonversi ke satu unit.
getYears() hanya komponen
Berbeda dari Duration, period.getYears() hanya mengembalikan komponen tahun, bukan total tahun dari semua komponen. Period.of(0, 25, 0).getYears() = 0, bukan 2 (meski 25 bulan ≈ 2 tahun).
Period.between() untuk umur
Cara idiomatis menghitung umur seseorang di Java: Period.between(birthDate, LocalDate.now()). Akurasi kalender: sudah memperhitungkan tahun kabisat dan perbedaan panjang bulan.
✅ Use Case: Menghitung Umur

Period age = Period.between(birthDate, LocalDate.now());
System.out.println("Umur: " + age.getYears() + " tahun, "
    + age.getMonths() + " bulan, "
    + age.getDays() + " hari");

Pattern: yyyy MM dd
Huruf pattern: y = tahun, M = bulan, d = hari, H = jam (24), h = jam (12), m = menit, s = detik. Jumlah huruf menentukan lebar: MM = 01-12, M = 1-12. MMMM = nama bulan panjang, MMM = singkatan.
DateTimeFormatter.ISO_LOCAL_DATE

Locale("in", "ID")
Locale untuk Indonesia: language code "in" (bukan "id" — ini quirk historis Java), country code "ID". Dengan locale ini, bulan diformat dalam bahasa Indonesia (MMMM = "Januari", "Februari", dst.).

🐘 Analogi Laravel: Carbon Format

Di Laravel: Carbon::now()->format('Y-m-d H:i:s') menggunakan format PHP (Y = tahun 4 digit, m = bulan 2 digit, dll.). Di Java: LocalDateTime.now().format(DateTimeFormatter.ofPattern("yyyy-MM-dd HH:mm:ss")). Perbedaan: PHP pakai H untuk jam 24h tapi lowercase, Java pakai HH. PHP pakai m untuk menit tapi di Java m adalah bulan!

Advanced Topic

Semua kelas java.time yang sudah kita pelajari mengimplementasikan interface Temporal. Ini memungkinkan penulisan kode generik yang bisa bekerja dengan tipe tanggal/waktu apapun.

// File: TemporalTest.java
@Test
void temporal() {
    // Semua ini adalah implementasi Temporal
    Temporal temporal1 = LocalDate.now();
    Temporal temporal2 = LocalTime.now();
    Temporal temporal3 = ZonedDateTime.now();
    Temporal temporal4 = Year.now();
    // Bisa dipegang oleh variabel bertipe Temporal (polimorfisme)
}

@Test
void temporalAmount() {
    Temporal temporal1 = LocalDateTime.now();

    // plus(TemporalAmount) menerima Duration ATAU Period
    Temporal temporal2 = temporal1.plus(Duration.ofHours(10));  // +10 jam
    Temporal temporal3 = temporal1.plus(Period.ofDays(10));      // +10 hari
    // TemporalAmount = Duration | Period (dan implementasi kustom lainnya)
}

Interface Temporal mendefinisikan operasi dasar: plus(), minus(), with(), until(), get(). TemporalAmount adalah abstraksi untuk "jumlah waktu" (Duration/Period).

@Test
void temporalUnit() {
    // ChronoUnit.DAYS.between() menghitung selisih dalam satuan hari
    long days = ChronoUnit.DAYS.between(
        LocalDateTime.now(),
        LocalDateTime.now().plusHours(10)
    );
    System.out.println(days); // 0 (10 jam < 1 hari, dibulatkan ke bawah)

    // Contoh lain:
    long months = ChronoUnit.MONTHS.between(
        LocalDate.of(2024, 1, 1),
        LocalDate.of(2024, 6, 1)
    );
    System.out.println(months); // 5

    // Bisa dipakai di plus/minus
    LocalDate nextWeek = LocalDate.now().plus(1, ChronoUnit.WEEKS);
}

ChronoUnit tersedia: NANOS, MICROS, MILLIS, SECONDS, MINUTES, HOURS, HALF_DAYS, DAYS, WEEKS, MONTHS, YEARS, DECADES, CENTURIES, MILLENNIA.

@Test
void temporalField() {
    LocalDateTime temporal = LocalDateTime.now();

    // Akses field via enum ChronoField — generic, bisa dipakai di semua Temporal
    System.out.println(temporal.get(ChronoField.YEAR));             // 2024
    System.out.println(temporal.get(ChronoField.MONTH_OF_YEAR));    // 1
    System.out.println(temporal.get(ChronoField.DAY_OF_MONTH));     // 15
    System.out.println(temporal.get(ChronoField.HOUR_OF_DAY));      // 10
    System.out.println(temporal.get(ChronoField.MINUTE_OF_HOUR));   // 30
    System.out.println(temporal.get(ChronoField.SECOND_OF_MINUTE)); // 45
    System.out.println(temporal.get(ChronoField.MILLI_OF_SECOND));  // 123
    System.out.println(temporal.get(ChronoField.NANO_OF_SECOND));   // 123456789
}

ChronoField sangat berguna saat menulis kode generik yang harus bekerja dengan berbagai tipe Temporal, karena kamu tidak perlu tahu tipe konkretnya.

@Test
void temporalQuery() {
    Temporal temporal = LocalDateTime.now();

    // Buat TemporalQuery kustom menggunakan anonymous class
    List integers = temporal.query(new TemporalQuery>() {
        @Override
        public List queryFrom(TemporalAccessor temporal) {
            ArrayList list = new ArrayList<>();
            list.add(temporal.get(ChronoField.YEAR));
            list.add(temporal.get(ChronoField.MONTH_OF_YEAR));
            list.add(temporal.get(ChronoField.DAY_OF_MONTH));
            return list;
        }
    });

    System.out.println(integers); // [2024, 1, 15]

    // Versi lambda (lebih ringkas):
    List result = temporal.query(t -> List.of(
        t.get(ChronoField.YEAR),
        t.get(ChronoField.MONTH_OF_YEAR),
        t.get(ChronoField.DAY_OF_MONTH)
    ));
}

TemporalQuery adalah functional interface — bisa ditulis sebagai lambda. Java juga punya built-in queries: TemporalQueries.localDate(), TemporalQueries.zone(), dll.

@Test
void temporalAdjuster() {
    Temporal temporal1 = LocalDate.now(); // e.g. 2024-01-15
    System.out.println(temporal1);        // 2024-01-15

    // TemporalAdjuster kustom: set ke hari pertama bulan ini
    Temporal temporal2 = temporal1.with(new TemporalAdjuster() {
        @Override
        public Temporal adjustInto(Temporal temporal) {
            return LocalDate.of(
                temporal.get(ChronoField.YEAR),
                temporal.get(ChronoField.MONTH_OF_YEAR),
                1 // Hari pertama
            );
        }
    });
    System.out.println(temporal2); // 2024-01-01

    // TemporalAdjusters sudah menyediakan built-in yang umum
    Temporal temporal3 = temporal1.with(TemporalAdjusters.firstDayOfMonth());
    System.out.println(temporal3); // 2024-01-01

    Temporal temporal4 = temporal1.with(TemporalAdjusters.lastDayOfMonth());
    System.out.println(temporal4); // 2024-01-31
}

TemporalAdjusters built-in yang berguna: firstDayOfMonth(), lastDayOfMonth(), firstDayOfNextMonth(), firstDayOfYear(), lastDayOfYear(), next(DayOfWeek), previous(DayOfWeek), nextOrSame(DayOfWeek).

🐘 Analogi Laravel: Macro & CarbonInterface

TemporalAdjuster di Java mirip seperti Carbon Macro di Laravel: cara mendefinisikan transformasi tanggal kustom yang bisa dipakai ulang. Contoh Laravel: Carbon::macro('firstDayOfQuarter', fn() => ...). Di Java, kamu implementasikan interface TemporalAdjuster dan inject via date.with(myAdjuster).

Chapter 17 • Interoperabilitas
🔄 Legacy Interoperability
Menjembatani dunia lama dan baru — konversi antara java.util.Date/Calendar dan java.time.*

Ketika bekerja dengan kode warisan atau library pihak ketiga yang masih menggunakan API lama, kamu perlu mengkonversi antara kedua dunia. Untungnya, Java menyediakan method konversi di kedua arah.

// File: LegacyTest.java

@Test
void fromLegacy() {
    // Date → Instant
    Date date = new Date();
    Instant instant = date.toInstant(); // Date mendapat method .toInstant() di Java 8+

    // Calendar → Instant
    Calendar calendar = Calendar.getInstance();
    Instant instant1 = calendar.toInstant(); // Calendar juga mendapat .toInstant()

    // TimeZone → ZoneId
    TimeZone timeZone = TimeZone.getDefault();
    ZoneId zoneId = timeZone.toZoneId(); // TimeZone mendapat .toZoneId()
}

@Test
void toLegacy() {
    ZonedDateTime zonedDateTime = ZonedDateTime.now();

    // ZonedDateTime → Date
    Date date = Date.from(zonedDateTime.toInstant());
    // Date.from() adalah static method baru di Java 8

    // ZonedDateTime → Calendar
    Calendar calendar = GregorianCalendar.from(zonedDateTime);
    // GregorianCalendar.from() adalah static factory baru

    // ZoneId → TimeZone
    ZoneId zoneId = ZoneId.systemDefault();
    TimeZone timeZone = TimeZone.getTimeZone(zoneId);
    // TimeZone.getTimeZone() menerima ZoneId langsung
}
date.toInstant() — Bridge Method
Di Java 8, kelas-kelas legacy (Date, Calendar, TimeZone) mendapat tambahan method "bridge" untuk konversi ke API baru. Method ini sudah ada di kelas yang sama — tidak perlu library tambahan.
Date.from(instant)
Arah sebaliknya: dari API baru ke lama. Date.from(), GregorianCalendar.from() adalah static factory method baru yang ditambahkan ke kelas legacy.
Mengapa harus via Instant?
Date hanya bisa merepresentasikan titik waktu absolut (seperti Instant). Jadi konversi selalu harus melalui Instant. LocalDate tidak bisa langsung dikonversi ke Date karena tidak punya informasi timezone!

📋 Decision Tree: Pilih Kelas yang Tepat
🤔 Perlu timezone?

Tidak → LocalDate / LocalTime / LocalDateTime
Ya, nama zona (DST-aware) → ZonedDateTime
Ya, offset numerik saja → OffsetDateTime / OffsetTime
Ya, titik waktu absolut UTC → Instant

⏱️ Menghitung Selisih Waktu?

Selisih detik/jam/menit yang presisi → Duration
Selisih tahun/bulan/hari kalender → Period
Selisih dalam satu unit tertentu → ChronoUnit.X.between()

🎯 Kasus Umum

Tanggal lahir / anniversary → LocalDate
Jam operasional → LocalTime
Timestamp log/audit → Instant
Jadwal event global → ZonedDateTime
API response (JSON) → OffsetDateTime
Umur seseorang → Period.between(birthDate, LocalDate.now())
Timeout / durasi proses → Duration
Format/parse String → DateTimeFormatter

💡 Key Insights untuk PHP/Laravel Developer
🔒 Immutability First

Selalu tangkap hasil operasi tanggal dalam variabel baru. date.plusDays(5) tidak mengubah date — berbeda dari Carbon di PHP!

🔢 Bulan dimulai dari 1

Di java.time, Januari = 1 (bukan 0 seperti Calendar lama). Gunakan enum Month.JANUARY untuk kejelasan.

🧵 Thread-Safe by Default

Semua kelas java.time aman dipakai di multi-threading. DateTimeFormatter bisa dijadikan static field tanpa khawatir race condition.

💉 Inject Clock

Jangan hardcode LocalDateTime.now(). Inject Clock sebagai dependency agar mudah di-test, mirip Carbon::setTestNow() di Laravel.
